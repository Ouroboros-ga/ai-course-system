在没有现成专业名词词典的情况下，如果直接用 IK 默认分词去处理高校理工科/医学课件，结果一定是灾难性的（比如把“傅里叶变换”切成“傅里叶/变换”，搜“傅氏变换”就漏掉了）。
但好消息是：**在这个赛题的架构下，你根本不需要人工去编词典！** 你手头的 Docling 和商业 API，加上简单的算法，就能实现一套**“课件解析 -> 自动抽词 -> 动态热更新”**的闭环。
这不仅解决了你的问题，而且**“基于文档结构与大模型的动态自适应分词机制”**，完全可以作为你们赛题的核心创新点之一写进文档。
以下是三种递进的自动化词典生成方案（建议组合使用）：
---
### 方案一：基于 Docling 结构的“白嫖式”提取（零成本，最快）
Docling 最大的优势是能输出带有层级结构的 Markdown。在学术界和课件制作规范中，**出现在特定结构里的词，大概率就是专业名词或知识点**。
**实现逻辑**：
在 Docling 解析出 Markdown 后，用正则表达式直接“刮取”特定格式的内容：
1. **标题提取**：所有 `#`、`##`、`###` 后面的文本（如 `### 1.2 拉格朗日中值定理`，直接提取“拉格朗日中值定理”）。
2. **加粗/高亮提取**：所有 `**加粗文本**` 或 `*斜体*`（教师通常用加粗强调核心概念）。
3. **列表开头提取**：无序列表 `- ` 或有序列表 `1. ` 后面的短语。
**处理方式**：将这批词直接用空格隔开，追加到一个本地文本文件 `auto_dict.txt` 中。
---
### 方案二：利用商业 API 的“顺手牵羊”提取（最准，强力推荐）
赛题【智课生成模块】要求：“提取知识点与重点，生成结构化脚本”。你本来就要把 Docling 解析的内容发给商业 API 去生成脚本，**为什么不顺便让它把名词吐出来呢？**
**实现逻辑**：
修改你发给商业 API 的 System Prompt，强制要求它返回 JSON，其中包含一个 `keywords` 字段。
**Prompt 示例**：
```text
你是一个资深教务专家。请分析以下课件内容，完成两项任务：
1. 提取本页所有的专业名词、公式名称、人名、定理名称（不包括普通动词或形容词）。
2. 生成结构化讲解脚本。
请严格按以下 JSON 格式输出：
{
  "keywords": ["拉格朗日中值定理", "罗尔定理", "导数", "极值点"],
  "script": {
    "opening": "同学们好，今天我们学习拉格朗日中值定理...",
    "body": "...",
    "transition": "..."
  }
}
课件内容：
{docling_markdown_text}
```
**处理方式**：
后端拿到 API 返回的 JSON 后，解析出 `keywords` 数组，直接追加到 `auto_dict.txt` 中。这种方式提取的名词，语义完整度极高，连“偏导数”、“不定积分”这种极短但极重要的词都不会漏。
---
### 方案三：基于统计算法的兜底提取（最全面）
如果有些段落没有加粗，API 也可能偶尔漏掉，可以用传统的 NLP 算法做兜底。
**实现逻辑**：
使用 Python 的 `jieba` 库（纯 CPU，不占什么资源），开启 IDF（逆文档频率）模式。
```python
import jieba.analyse
# Docling 清洗后的纯文本
text = "..."
# 基于 TF-IDF 算法自动抽取 top 20 的关键词
keywords = jieba.analyse.extract_tags(text, topK=20, withWeight=False)
# 例如输出：['泰勒展开式', '麦克劳林公式', '逼近', '多项式']
```
**处理方式**：过滤掉长度小于 2 的词，追加到 `auto_dict.txt`。
---
### 终极关键：IK 分词器的“动态热更新”机制
你把词提取到了 `auto_dict.txt`，怎么让 Elasticsearch 感知到？**绝对不能每次重启 ES！**
IK 分词器原生支持一个极其强大的功能：**远程扩展词典**。
1. **配置 IK**：修改 ES 的 `ik/config/IKAnalyzer.cfg.xml` 文件：
   ```xml
   <?xml version="1.0" encoding="UTF-8"?>
   <!DOCTYPE properties SYSTEM "http://java.sun.com/dtd/properties.dtd">
   <properties>
       <entry key="ext_dict">custom/my_static_dict.dic</entry>
       <!-- 配置远程词典，指向你后端的一个 HTTP 接口 -->
       <entry key="remote_ext_dict">http://127.0.0.1:8080/api/es/get-dynamic-dict</entry>
   </properties>
   ```
2. **写一个极简的后端接口**（比如用 Flask 或 FastAPI）：
   ```python
   @app.route("/api/es/get-dynamic-dict")
   def get_dynamic_dict():
       # 读取前面三种方案自动生成的 auto_dict.txt
       with open("auto_dict.txt", "r", encoding="utf-8") as f:
           content = f.read()
       # ES 要求每行一个词
       return content.replace(" ", "\n")
   ```
3. **工作原理**：IK 分词器默认每隔 **60 秒** 会去请求一次这个 HTTP 接口。只要你解析了一份新的 PPT，把新词写进了 `auto_dict.txt`，**最多等 1 分钟，ES 的分词器就自动学会了这些新词，并重建索引**，全程无需人工干预！
---
### 进阶升华：自动生成“同义词图谱”（极大提升检索率）
只有词典还不够。学生搜“线代”，课件里写的是“线性代数”，IK 再怎么强也匹配不上。
你可以利用商业 API，在提取 `keywords` 的同时，顺便生成同义词：
在 Prompt 里加上：
`"synonyms": {"线性代数": ["线代", "高代"], "拉格朗日中值定理": ["拉氏定理", "中值定理"]}`
拿到同义词后，按照 Elasticsearch 的同义词格式，动态写入一个 `synonyms.txt`，并在 ES 的 Mapping 中配置 `search_analyzer` 加载这个同义词文件（ES 也支持同义词文件的远程热更新配置）。
### 总结：这套流程在答辩时怎么说？
> “针对教育场景专业术语强、各学科差异大的痛点，传统 RAG 依赖人工维护分词词典，落地可行性极低。我们创新性地设计了**动态自适应分词机制**：在课件解析阶段，利用 Docling 的结构特征提取基础术语；在智课生成阶段，利用商业大模型的逻辑能力精准抽取知识点名词及同义词。这些术语通过 HTTP 接口实时注入 Elasticsearch 的 IK 分词器，实现了**‘解析一份课件，自动丰富一分词典’**的无感热更新，彻底解决了冷启动和跨学科泛化问题。”
