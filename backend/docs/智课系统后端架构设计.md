我用「开公司做业务」的类比，给你讲明白这套项目架构，全程大白话，不用记专业术语也能完全懂。

先给个总纲：这套架构是**标准的分层式设计**，就像开一家专门做「AI智课」的公司，从前台接待、业务处理、技术支持、档案管理到公司规章制度，全部分工明确，谁也不越界，出问题一眼就能找到根源，团队开发也不会互相抢活、代码乱套。

整个`backend`文件夹，就是这家公司的**总部大楼**，我们从外到内、从底层到业务，一层一层讲。

## 一、大楼门口：根目录的3个核心文件
这几个文件在`backend`文件夹最外层，是所有人进大楼都要先接触的东西，管项目的启动、基础配置。
1.  **`requirements.txt`**：公司的「采购清单」
    项目运行需要的所有第三方工具（比如FastAPI框架、解析PPT的库、连数据库的工具、大模型SDK等），全列在这。一键执行安装命令，就能把所有需要的工具一次性配齐，不用一个个找、一个个装。
2.  **`.env.example`**：公司的「保密配置模板」
    这里放不能写死在代码里的敏感信息，比如大模型的密钥、数据库的账号密码、泛雅平台的对接参数。你复制这个文件改成`.env`就能直接用，既方便配置，又不会把私密信息泄露到代码里。
3.  **`run.py`**：公司的「一键开门营业按钮」
    新手不用敲复杂的启动命令，直接运行这个文件，就能一键启动整个后端服务，项目直接跑起来，相当于公司开门营业了。

## 二、大楼主体：`app`文件夹
这是整个项目的核心，公司所有的部门、人员、业务全在这个文件夹里，先讲最顶层的2个文件：
1.  **`__init__.py`**：公司的「营业执照」
    空文件也没关系，但必须有。它的作用是告诉Python：这个文件夹是一个正规的代码包，里面的代码可以互相导入、调用，没有它，Python就不认这个文件夹。
2.  **`main.py`**：公司的「总经理室+总调度中心」
    整个项目的入口，在这里创建FastAPI的核心实例（相当于公司总经理），然后把各个部门的接待窗口（接口）全部注册到这里。用户/前端所有的请求，都先到这里，再由它分配给对应的部门处理，项目的全局启动配置也在这里。

接下来是`app`里的7个核心部门（子文件夹），我们按「底层支撑→业务处理→对外接待」的顺序讲，逻辑最顺。

---

### 部门1：`core/` → 公司「行政总部+风控中心」
管整个公司的全局规则、核心配置、安全和异常处理，全公司所有部门都必须遵守这里的规则，是项目的底层基石。
- **`config.py`**：「公司总章程+全局配置中心」
  所有全局的固定设置全在这里，比如项目运行的端口、数据库地址、大模型的API地址、泛雅平台的对接配置。整个项目任何地方要用到全局配置，都来这里拿，不用到处写死，改配置只改这一个文件就行。还包含 `MEDIA_RESOURCE_PATHS` 媒体资源路径白名单，用于签名中间件对浏览器原生标签（`<img>`/`<audio>`）发起的GET请求豁免签名验证。
- **`security.py`**：「安保部门+权限校验岗」
  管用户权限和系统安全，比如区分老师/学生身份、校验用户能不能访问对应接口、对接泛雅平台的用户体系，防止学生乱改老师的课件、非法人员访问系统。支持通过 `Authorization` 请求头和 `?token=` 查询参数两种方式传递JWT令牌，后者专门用于浏览器原生标签无法设置请求头的场景。
- **`signature_middleware.py`**：「签名验证岗」
  所有请求必须携带 `time` 和 `enc` 参数进行MD5签名校验，防止请求被篡改和伪造。对白名单路径和媒体资源GET请求（PPT图片、TTS音频）豁免签名验证，因为这些请求由浏览器原生标签发起，无法携带签名参数，但仍需通过JWT认证。
- **`exceptions.py`**：「客服投诉中心+统一话术规范」
  整个项目出任何错误（比如课件解析失败、问答超时、权限不够），都在这里统一处理，给前端返回固定格式的错误提示，不会出现乱七八糟的报错，用户和前端一眼就能看懂哪里出了问题。

---

### 部门2：`common/` → 公司「公用技术支持部」
这里全是全公司通用的工具，哪个部门需要，直接拿来用就行，不用自己重复造轮子，也是AI核心功能的工具库。
- **`llm_client.py`**：「大模型统一对接专员」
  不管你用的是豆包、GPT还是通义千问，所有大模型的API都在这里统一封装好。其他部门要生成脚本、做问答，只需要调用这里的函数，不用管底层是哪个厂商的大模型，换模型只改这一个文件就行。
- **`tts_client.py`**：「语音合成专员」
  把生成的讲解脚本转成讲课语音，封装了语音合成API，要生成AI讲课的音频，直接调用它就行。
- **`asr_client.py`**：「语音识别专员」
  把学生的语音提问转成文字，给大模型处理，学生语音提问的功能，核心就靠它。
- **`ppt_parser.py`/`pdf_parser.py`**：「课件解析工程师」
  专门负责解析老师上传的PPT/PDF文件，把里面的文字、公式、图表、知识点全提取出来，是智课生成最核心的底层工具，没有它，就没法把静态课件转成智能课程。
- **`slide_converter.py`**：「幻灯片高清渲染工程师」
  负责将PPTX/PPT文件通过LibreOffice转为PDF，再用PyMuPDF渲染为高清PNG图片。支持PDF文件直接渲染，Office文件自动转换。有智能缓存机制，转换一次后复用PDF。若LibreOffice不可用则自动降级到文本绘制模式。

**音频存储架构**：TTS生成的音频按课程隔离存储在 `backend/audio_storage/{course_id}/` 目录下，文件名格式为 `node_{node_id}_{uuid}.mp3`。音频URL格式为 `/api/v1/document/audio/{course_id}/{filename}`，支持通过JWT token参数认证访问。重新生成音频时自动清理旧文件，避免磁盘空间浪费。`stream_audio` 端点同时兼容旧格式（无课程ID）的音频文件路径。

**自动TTS生成**：文档上传解析完成后，自动在后台启动TTS批量生成任务（`_background_synthesize_audio`），使用 `asyncio.create_task` 不阻塞上传响应。全局字典 `tts_generation_status` 跟踪生成进度，前端通过 `GET /course/{course_id}/tts-status` 轮询状态。
- **`utils.py`**：「万能工具百宝箱」
  放全项目都能用的小功能，比如处理时间格式、格式化文本、校验文件格式、生成唯一ID，杂七杂八但必须用的小工具全在这，不用每个地方都重复写一遍。

### 部门3：`models/` → 公司「档案管理中心」
管所有数据的存储，和数据库直接打交道，定义了每个「档案柜（数据表）」长什么样、存什么内容，项目里所有要长期保存的数据，都在这里定义结构。
- **`database.py`**：「数据库总管理员」
  负责和数据库建立连接、初始化数据库，比如用MySQL还是轻量的SQLite，在这里一键切换，项目里所有和数据库的交互，都要经过它。
- **`user_model.py`**：「用户档案柜」
  定义用户数据的存储结构，比如用户ID、姓名、角色（老师/学生）、对接泛雅平台的用户ID，所有用户相关的信息都存在这里。
- **`course_model.py`**：「课件&智课档案柜」
  定义课件、智课脚本的存储结构，比如课件ID、上传的老师、课件类型、解析后的知识点、生成的讲解脚本、语音文件地址，智课生成的核心数据全在这。
- **`qa_model.py`**：「问答记录档案柜」
  定义问答对话的存储结构，比如提问的学生、对应的课件、提问内容、AI回答、对话上下文，用来做多轮对话、保证问答和课件内容匹配。
- **`progress_model.py`**：「学习进度档案柜」
  定义学生学习进度、理解度的存储结构，比如学生学到的节点、提问内容、AI分析的理解程度，进度续接、节奏调整的功能全靠这里的数据。

### 部门4：`schemas/` → 公司「收发文规范部」
规定了「前端给后端发请求，必须带什么参数、什么格式」「后端给前端返回结果，必须是什么格式」，就像填表格必须按规定的格子填，不然不收，从源头防止乱传数据导致系统出错。
每个文件对应一个业务模块的规范：
- `smart_course_schema.py`：智课生成相关的请求/返回格式规范
- `qa_schema.py`：实时问答相关的请求/返回格式规范
- `progress_schema.py`：学习进度相关的请求/返回格式规范
- `user_schema.py`：用户相关的请求/返回格式规范

这是项目的**大脑**，所有真正干活的业务逻辑全在这里。前台只负责收请求和返结果，真正的业务处理，全交给这个部门，完全对应赛题要求的3大核心模块。

# FastAPI 在 AI 智课项目中的独特优势与差异

结合你这个「AI智课生成与实时问答系统」的项目，我用**「和Flask/Django比，FastAPI在这套架构里的‘专属改动’」**来讲，每个差异都对应你项目的具体文件和需求，看完就知道FastAPI为什么特别适合这个比赛项目。

---

## 一、最核心的差异：全链路「异步支持」（直接满足性能指标）

这是FastAPI和Flask（默认同步）、Django（异步支持较晚且复杂）最大的不同，**完全贴合你项目的「并发访问≥10人」「问答响应时间≤5秒」要求**。

### 对应到你的项目架构里：

1. **`app/main.py`****（入口文件）**：
    
    1. FastAPI原生支持`async def`定义路由，不用像Flask那样装额外的异步插件（如`aiohttp`），也不用像Django那样配置复杂的异步视图。
        
    2. 比如你项目里的「问答接口」「课件解析接口」都是IO密集型操作（等大模型响应、等文件读取），用`async def`可以让服务器在等待时处理其他请求，轻松满足「并发≥10人」的要求。
        
2. **`app/services/`****（业务逻辑层）**：
    
    1. 这里的核心函数（如调用大模型、解析PPT/PDF）都可以写成`async def`，比如：
        
        ```Python
        # smart_course_service.py 里的异步函数
        async def generate_course_script(ppt_content: str):
            # 异步调用大模型API，不阻塞其他请求
            script = await llm_client.async_call(prompt=ppt_content)
            return script
        ```
        
    2. Flask/Django默认同步，写这种业务逻辑很容易阻塞，导致并发上不去，而FastAPI天生适合。
        
3. **`app/common/llm_client.py`****（大模型封装）**：
    
    1. 你可以直接用大模型厂商的异步SDK（如豆包的异步API），封装成`async`函数，和FastAPI的异步路由完美配合，进一步降低问答响应时间。
        

---

## 二、`schemas/`文件夹：从「可选」变成「核心刚需」

FastAPI**强制（强烈推荐）用Pydantic做数据校验**，这和Flask（用Marshmallow，非原生）、Django（用表单/序列化器，和ORM绑定）完全不同，**直接解决你项目里「接口参数乱传」「文档难写」的问题**。

### 对应到你的项目架构里：

1. **`app/schemas/smart_course_schema.py`****（示例）**：
    
    1. 你可以直接用Pydantic定义「课件上传请求」「脚本生成响应」的格式，比如：
        
        ```Python
        from pydantic import BaseModel
        from typing import List
        
        # 定义「生成智课脚本」的请求体
        class ScriptGenerateRequest(BaseModel):
            course_id: int          # 必须传整数，传字符串自动报错
            ppt_content: str        # 必须传字符串
            teacher_note: str = "" # 可选参数，默认空字符串
        
        # 定义「返回脚本」的响应体
        class ScriptGenerateResponse(BaseModel):
            script_id: int
            structured_script: List[str] # 自动校验是列表
            audio_url: str
        ```
        
    2. **和其他框架的不同**：
        
        - Flask：你得自己写代码从`request.form`/`request.json`里取参数，还要自己写校验逻辑，漏写一个就会报错。
            
        - Django：要用Django REST Framework的序列化器，和Django ORM绑定太死，你这个项目用SQLite/MySQL切换的话，不如Pydantic灵活。
            
    3. **对比赛的好处**：评委测试接口时，传错参数会自动返回清晰的错误提示（比如「`course_id`必须是整数」），显得项目很健壮。
        
2. **自动生成API文档的核心来源**：
    
    1. FastAPI会自动读取`schemas/`里的Pydantic模型，生成交互式文档（访问`/docs`或`/redoc`），**你不用额外写一个字的接口文档**，这对比赛团队来说太省时间了。
        

---

## 三、`api/`路由层：「自动解析参数」+「依赖注入」（代码量减一半）

FastAPI的路由层比Flask/Django简洁太多，**完全对应你项目里的「10个功能接口」要求**，写接口又快又不容易错。

### 对应到你的项目架构里：

1. **`app/api/v1/qa_api.py`****（示例）**：
    
    1. FastAPI自动解析「路径参数」「查询参数」「请求体」，不用你手动取：
        
        ```Python
        from fastapi import APIRouter, Depends
        from app.schemas.qa_schema import QARequest, QAResponse
        from app.services.qa_service import qa_service
        
        router = APIRouter(prefix="/qa", tags=["实时问答"])
        
        # 路径参数：course_id，自动从URL里取
        # 请求体：qa_request，自动用Pydantic校验
        @router.post("/{course_id}/ask", response_model=QAResponse)
        async def ask_question(
            course_id: int,
            qa_request: QARequest,
            # 依赖注入：自动获取当前用户、数据库会话
            current_user = Depends(security.get_current_user),
            db = Depends(database.get_db)
        ):
            # 直接调用业务层，不用处理参数解析
            answer = await qa_service.get_answer(course_id, qa_request, current_user, db)
            return answer
        ```
        
2. **「依赖注入（Depends）」是FastAPI的杀手锏**：
    
    1. 对应你项目里的`app/core/security.py`（权限校验）和`app/models/database.py`（数据库连接）：
        
        - 你可以把「获取当前用户」「获取数据库会话」写成依赖函数，然后在路由里用`Depends()`注入，不用像Flask那样用全局变量，也不用像Django那样写中间件。
            
        - **对比赛的好处**：权限校验和数据库连接逻辑只写一次，所有接口复用，代码干净，评委看架构的时候会觉得很专业。
            

---

## 四、`models/`文件夹：官方推荐「SQLModel」（ORM+校验二合一）

FastAPI官方推荐用`SQLModel`（由FastAPI作者开发），这是Flask（用SQLAlchemy）、Django（用自己的ORM）没有的，**完美适配你项目里的「数据库模型」+「数据校验」需求**。

### 对应到你的项目架构里：

1. **`app/models/course_model.py`****（示例）**：
    
    1. 用SQLModel定义模型，**一个类同时做「数据库ORM」和「Pydantic数据校验」**：
        
        ```Python
        from sqlmodel import SQLModel, Field
        
        # 定义课件模型：既是数据库表，又是Pydantic模型
        class Course(SQLModel, table=True):
            id: int = Field(default=None, primary_key=True) # 主键
            teacher_id: int = Field(index=True)              # 索引，查询快
            course_name: str                                  # 自动校验是字符串
            file_type: str                                    # PPT/PDF
            # 既可以存到数据库，又可以直接返回给前端做校验
        ```
        
2. **和其他框架的不同**：
    
    1. Flask：你得分别定义SQLAlchemy模型和Marshmallow序列化器，代码重复。
        
    2. Django：ORM和序列化器绑定太死，你这个项目要「轻量集成泛雅平台」，SQLModel更灵活。
        
    3. **对比赛的好处**：模型定义只写一次，减少出错，数据库切换（SQLite→MySQL）只改`app/core/config.py`里的配置就行，完全符合你项目里的「数据库一键切换」要求。

## 五、额外福利：「自动生成交互式API文档」（比赛演示神器）

这是FastAPI送你的「比赛加分项」，Flask/Django都没有这么方便的原生文档。

### 对应到你的项目里：

1. **不用写任何配置**：
    
    1. 启动项目后，直接访问`http://localhost:8000/docs`（Swagger UI）或`http://localhost:8000/redoc`，就能看到：
        
        - 所有接口的列表（对应你项目里的「10个功能接口」）
            
        - 每个接口的请求参数、响应格式（自动从`schemas/`里读取）
            
        - 可以直接在网页里测试接口（比如上传PPT、提问问题），不用装Postman。
            
2. **对比赛的好处**：
    
    1. 评委演示的时候，你直接打开`/docs`就能测试所有核心功能，不用准备额外的测试工具，显得项目很完整、很专业。

## 总结：FastAPI在你项目里的「不可替代性」

|项目需求|FastAPI的对应优势|和Flask/Django的核心不同|
|---|---|---|
|并发访问≥10人|原生异步支持，IO密集型操作不阻塞|Flask默认同步，Django异步复杂|
|10个功能接口，参数规范|Pydantic自动校验，自动生成文档|Flask需手动校验，Django文档需额外配置|
|轻量集成泛雅平台|依赖注入灵活，SQLModel数据库切换方便|Django绑定太重，Flask依赖管理混乱|
|比赛演示方便|原生交互式文档，直接测试接口|需额外装Postman/写接口文档|

简单说：**用FastAPI，你可以用更少的代码，更快地完成项目，同时满足所有性能和功能要求，特别适合这个比赛场景**。
