## 一、作品阐述

**作品名称**：（待确认，候选"智溯 CS"）
**一句话定位**：以 DeepSeek（deepseek-chat）为基座的计算机学科垂类大模型与智能体应用集——通过 CS 学科知识库 +
RAG + 领域微调构建学科模型层，由备课/教学/代码/科研四类智能体承载助教、助学、助研三大场景，
让"AI 深度赋能、人机高效协同"在计算机一流学科建设中可运行、可追溯、可复制。

**解决的现实问题**：
1. 教学端：教师备课/出题/学情分析耗时高，内容质量与来源难保障；
2. 学习端：学生知识问答易得"幻觉答案"，学习路径无个性化，代码纠错缺可信执行环境；
3. 科研端：文献调研分散、综述写作门槛高、研究过程难以沉淀与追溯。

**学科选择**：计算机科学与技术（CS）——课程标准化程度高、知识图谱结构清晰、代码实验可沙箱验证，
最能体现"学科垂类模型 + 智能体 + 可追溯"的组合优势。

## 三、技术方案

### 3.1 总体架构（五层）

平台接入与应用交互层（Vue 3 shadow 前端 `/app/**`）→ 课程业务与发布层（草稿/版本/发布回滚）
→ 智能体协作层（四 Agent 物理分离 + Port/Provider/治理）→ 课程知识与证据层（DocumentIR/证据/图谱/知识包/索引）
→ 基础设施（PostgreSQL 16 + pgvector、LanceDB、Judge0、LLM Provider）。

### 3.2 学科垂类大模型（三层）

1. **基座**：DeepSeek（`LLM_PROVIDER=deepseek`，OpenAI 兼容 `https://api.deepseek.com/v1`，
   `deepseek-chat`，2026-08-20 决策并完成 10 用例实测）+ 开源/星火双轨（讯飞星火 `LLM_PROVIDER=spark`、
   豆包/通义亦可用，Provider 可插拔）；
2. **领域增强**：CS 学科知识库（112 节点/106 关系，数据结构/算法/操作系统/计算机网络/数据库/软件工程/机器学习/编译原理/计算机组成原理/离散数学/计算机图形学 11 门课，权威教材来源）→ 只读检索服务
   （BM25 风格 + CJK 二元组、中英双语、可追溯）+ 课程级 RAG（BM25 + BGE + RRF + GraphRAG + Citation 闭包三重约束）；
3. **领域微调**：LoRA/SFT 可复现管线（`backend/finetune/`：数据集生成 197+31、
   10 用例评测基准、批量评测、完整 PEFT LoRA 训练脚本；评测基准问题不进训练集，
   防对比污染）；训练需 GPU 或星火 MaaS（诚实口径：管线已交付、训练待执行）。

### 3.3 智能体（四 Agent）

- **Prep Agent**：备课提案生成，`evidence_refs` 硬门 + 教师审核双门控；
- **TeachingAgent**：22 节点 LangGraph，课程/学生/能力三重校验，六维认知个性化，高风险动作需确认；
- **CodingEduAgent**：代码诊断，Judge0 服务端验证，不猜测运行结果；
- **ResearchAgent**：Harness 条件路由，arXiv 真实检索 + EvidenceGate，工作区/记忆持久化
  （pgvector），外部结果仅补充参考。

### 3.4 可信与安全

证据锚定双门控、版本快照不可变可回滚、Course Access v1 最小权限、四域数据分离、
AI 生成内容标识、密钥不入前端/日志/仓库、沙箱隔离执行。

## 六、创新之处

1. **学科垂类三件套**：星火基座 + 学科知识库 RAG + 可复现微调管线，形成"模型可替换、
   知识可追溯、微调可复现"的完整闭环；
2. **以证据而非流畅度评价生成内容**：Citation 闭包三重约束 + 双门控审核，杜绝幻觉答案进入正式课程；
3. **四智能体协作、状态独立**：LangGraph 显式工作流（节点边界即权限边界）+ Port 契约，
   不共享跨课程可变状态；
4. **教学-科研一体化**：同一课程上下文贯通助教/助学/助研，研究结果可回流为教学素材（经教师审核）；
5. **诚实可验证**：全部能力有代码/测试/文档证据，未实现项明确标注，不做伪实现。
