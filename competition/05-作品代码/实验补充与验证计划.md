# CodeNexus 实验补充与验证计划（科研验证路线图）

> 本文档是《技术报告》的配套 **“实验补充版”**。《技术报告》描述“已实现的能力与已做的实验”；本文档把“应做而尚未做的实验”系统化为可追溯的实验规划，逐项回答：**要什么数据 → 做什么实验 → 期望什么结果 → 得到该结果证明什么提升 → 得不到说明没有提升、该如何优化**。
>
> **科研诚信红线**：已做实验填真实数据；未做实验的“实际结果”一律留空（⬜），仅保留设计骨架，不填写、不外推任何数字。未运行的结果绝不表述为系统成效。

## 2. 生成溯源组

### S1　Citation 闭包的有效性

- **假设**：启用回答级验证（`validate_response`）后，输出中每一个 `evidence_id` 都属于本轮检索结果集；关闭该机制时，模型有机会构造检索集之外证据（伪造引用）。
- **现状**：机制已实现并上线（`platform/evidence/citation.py`），但尚无量化指标。
- **所需数据**：约 30–60 个可诱导模型“编引用”的高难度查询集 + 每问的标准引用集（人工标注）。
- **实验设计**：在统一课程与权限环境下，对同一测试集运行为两组（开 vs 关验证）；统计**引用合法率** = 输出中属检索集的 evidence_id 数 / 输出 evidence_id 总数；另测**漏检数**（模型构造但未被剔除的非法引用）。
- **期望结果与提升含义**：开启组合法率趋近 100% 且漏检数为 0 —— 证明闭包机制完备，能从机制上阻止“有出处但无来源”的回答，支撑“生成溯源可信任”。
- **若未达成**（合法率 <100% 或漏检>0）→ 说明校验器存在漏报，收益不成立或无提升。优化方向：扩大检索集比对粒度、补证据 ID 规格校验、在 workflow 增加二次复核节点。
- **数据可行性**：查询集与裁判可复用典型问题测试用例（`docs/phase1/XH202620_典型问题测试案例集.md`），人工标注成本中等。

### S2　引用的语义支撑

- **假设**：引用合法率只证明“来源闭包”，不证明“引用足够支撑这句话”；需要把引用质量拆为**引用蕴含**（引用内容确实支撑回答语义）与**引用完整性**（该句的所有关键论断都有引用）。
- **现状**：无语义支撑度量。
- **所需数据**：一句话-引用对级别的标注集（抽样自真实问答，人工判断该 ID 是否真正支撑该句）。
- **实验设计**：参照 ALCE/RAGAS 的 context relevance 与 answer faithfulness，评引用蕴含率与完整性；建议独立于生成 LLM 的裁判（规则/小型 NLI + 独立 judge + 教师抽检）。
- **期望结果与提升含义**：蕴含率/完整性的薄弱项集中到某类题（如“多文档综合”），可定位 RAG 融合的上下文选择短板，指导如何改进召回与排序；若两类指标均高，则论证回答不仅“有据”而且“据实”。
- **若未达成**（蕴含率低）→ 证明当前 RAG 把“形式引用”当“语义支持”，无实质提升。优化方向：改上下文选择策略、引入论据-主张对齐的二次检索、按句召回而非按块召回。
- **数据可行性**：需新增人工标注，成本偏高；可作为 P1 迭代式小样本先跑通流程。

### S3　备课双门控的不可绕过性

- **假设**：证据门（证据 ID 硬校验）与锁定节点保护为代码层约束，无法通过 prompt 诱导绕过——即“教师把关权”是机制保障而非提示词承诺。
- **现状**：双门控已实现并有结构化重试（`controlled_prep_workflow.py`），但未做“越权/绕过”对抗测试。
- **所需数据**：一组含“诱导生成伪证据 ID、试图修改锁定节点、试图新增/删除节点”的恶意/噪声 prompt 集。
- **实验设计**：对每类对抗输入，验证（a）伪 `evidence_refs` 被拒并重试；（b）锁定节点操作被丢弃；（c）合法范围外操作白名单不命中。统计绕通率。
- **期望结果与提升含义**：绕通率 = 0 —— 证明产出约束是硬门，AI 无法越过教师审核权限，支撑“教学内容权威且可问责”。
- **若未达成**（存在绕通）→ 证明门控不完整，提升不受保障。优化方向：把校验后移到持久化写入边界（而非仅工作流内）、补权限级检查、对 `_filter_operations` 之外入口做同一白名单校验。
- **数据可行性**：测试集由现有 prep 测试用例扩展即可，成本低，建议尽快做。

## 3. 掌握度可解释组

### K1　RE-KT 六维 vs 学习型基线

- **假设**：RE-KT 的价值在“可解释 + 面向教学动作”，即便在预测任务上不显著优于数据驱动模型，也应在教学干预效用上更有价值；此假设需定量验证，而非口头声张。
- **现状**：RE-KT 为确定性 `rule_baseline` 实现，未与任何学习型基线对照。
- **所需数据**：统一预处理的学生作答序列（**student-level split**，严格防泄漏）；用于教学干预效用判定的行为数据。
- **实验设计**：以 pyKT 为公平底座，对比 RE-KT（`rule_baseline` 接口）与 BKT / DKT / AKT / simpleKT，指标含 AUC、校准（Brier/ECE）、冷启动样本下的表现、教学干预效用（预测到的薄弱点与后续练习纠正的吻合度）。
- **期望结果与提升含义**：RE-KT 在 AUC/校准上与基线可比或略低，但在**冷启动与教学干预效用**上相当或更优，且多一维“可解释” —— 说明用“可读的六维”替代“黑箱概率”不牺牲关键任务表现，为本设计取向提供证据。
- **若未达成**（RE-KT 总体明显弱）→ 证明确定性规则不足以支撑掌握度判断，无提升。优化方向：接入数据驱动估计器（接口已预留）作为第二信号，六维保留为输出视图、估计器提供数值，形成 hybrid；或调参/加特征。
- **数据可行性**：需要真实作答序列数据，当前为合成数据，需在获得授权后以假名化数据推进。

### K2　六维状态 vs 单一概率的教师判断效用

- **假设**：面向教师时，六维状态比单一概率更能支持教学决策（更快、更一致、更正确），这是 RE-KT 区别于 BKT/DKT 的可解释价值所在。
- **现状**：未做用户侧实验。
- **所需数据**：≥2 名真实目标教师（CS 专业），一组学习状态展示样例（同一学生分别以“六维”与“概率”两种形态呈现）。
- **实验设计**：对照实验，测量教师的教学判断正确率、决策时间与跨人/跨趟一致性（理论见附录 A.4 的教师实验设计）。
- **期望结果与提升含义**：六维形态下判断正确率/一致性更高或等价、决策更快 —— 证明可解释设计有可测的教学价值增量。
- **若未达成** → 证明六维未映射到真实教学判断，提升不在。优化方向：与教师共建维度定义、压缩为 3–4 个高行动相关维度、把输出对齐到具体教学动作按钮。
- **数据可行性**：与《效果验证报告》的用户试用共用样本，成本中等；依赖 K1 先具备稳定状态。

## 4. 口径对齐组

### M1　LoRA 同分布贴合 vs 学科泛化

- **假设**：LoRA 在课程同分布上收敛（困惑度 10.98→1.057），但对“课程外、学科内”的泛化分布可能回落（过拟合风险），需测泛化边界。
- **现状**：同分布已实测（真实值 10.98→1.057，train_loss 0.2032）；防污染基准短答 8 题基座与 LoRA 均 4/4（归档 `evidence/`）。**泛化测集未做**。
- **所需数据**：课程外但计算机学科内的评估集（如：未进训练/评测的教材章节题目、独立课程提问）。
- **实验设计**：在泛化分布上重跑困惑度与严格 markers 自动判定，与基座对比。
- **期望结果与提升含义**：泛化困惑度相对同分布升幅小、短答通过数不落于基座 —— 说明微调收益是“学科口径”而非“课程死记”，支撑垂类化。
- **若未达成**（泛化明显过拟合、短答低于基座）→ 证明当前 LoRA 收益限于同分布，泛化无提升。优化方向：加大评测集多样化、正则/早停、按节点难度采样、减小 LoRA 秩或扩 3127 数据覆盖面。
- **数据可行性**：评测脚本已存在（`finetune/evaluate.py`），只需补充独立测集，成本较低。

## 5. 判定可信组

### R1　复现四级语义与多 seed 统计一致性

- **假设**：nanoGPT 已具备 `executed` 与 `metric-reproduced` 两级（真实执行 + `val_loss=1.8857` 对阈值 PASS）；应推进到“同一快照重复运行统计一致”，排除“恰好跑对一次”的偶然性。
- **现状**：单 job 已 PASS（`c3e71851e513`，M4 验收）；**无多 seed 重复统计**。
- **所需数据**：固定快照、固定训练脚本与固定超参下，多次（≥5 seed）运行日志与 val_loss。
- **实验设计**：在 Repro Worker 内以不同随机种子重复训练，报告 mean/σ/95%CI，判定阈值基于统计而非单点。
- **期望结果与提升含义**：多 seed 的 val_loss 均值落在 `1.88±0.06` 且 σ 小 —— 证明复现结论稳定，PASS 可信，把“跑过一次”升级为“统计一致地复现”。
- **若未达成**（跨 seed 波动超出容差）→ 证明单点 PASS 是偶发，当前复现口径不可靠。优化方向：锁定随机种子、固定 CUDA 确定性、消除硬件浮点差异、提高容差或改用鲁棒判定。
- **数据可行性**：复用现有 Repro Worker 即可，计算成本为主（每次 CPU 训练约 20–30 分钟量级）。

### R2　确定性验证器 vs 纯 LLM 判定

- **假设**：PASS/FAIL 由确定性数值比较，比“LLM 自述成功”更可信、更可复核；这一主张需要对比实验证实而非口号。
- **现状**：确定性验证器已上线；**未与 LLM 判定做同任务对比**。
- **所需数据**：一批“复现结果有歧义/边界值”的任务输出（如 val_loss 恰在阈值边缘、日志缺 metric）。
- **实验设计**：对同一批输出，分别给确定性 verifier 与 LLM 判定，比较正确率与可复核性（判定依据能否被他人重现）。
- **期望结果与提升含义**：确定性 verifier 正确率高于或等于 LLM、且每个判定附可复核依据 —— 证明“结论不由 LLM 之口”不是口号，而是可验证的工程保证。
- **若未达成**（LLM 判定也不差且更快）→ 证明确定性路径无效率优势；但可复核性（他人能否核对依据）仍是决定性差异，据此应坚持确定性判定并强调可复核维度。
- **数据可行性**：样本较小，成本低；关键是对边界样本的设计。

## 6. 安全边界组

### X1　注入对抗子集

- **假设**：安全边界落在 effective capability 过滤、工具级自校验、一次性审批票据、独立执行沙箱上，属于运行时硬边界；即使 LLM 被提示注入诱导调用越权工具，边界仍不可跨越（理论见附录 A.3）。
- **现状**：机制已实现；**无针对本系统场景的注入对抗测试**。
- **所需数据**：面向本系统工具面的注入对抗子集（Web/arXiv/课程材料中藏攻击指令，诱导访问跨用户 Artifact、无权限课程、绕过审批执行等）。
- **实验设计**：成对抗测试，统计越权调用/绕过审批的穿透率；验证 Web/arXiv 材料均按“不可信数据进入高权限 Agent”处理。
- **期望结果与提升含义**：穿透率 = 0 —— 证明安全不是靠 system prompt，而是运行时边界兜底，支撑科研诚信与权限隔离的硬保证。
- **若未达成** → 证明存在可被注入穿透的路径，安全无提升。优化方向：加强工具级视为不信任输入、审批票据与工具耦合、对高权限工具加独立二次鉴权。
- **数据可行性**：需构造对抗样本，成本中高；建议与竞品/评审抽查思路一致。

## 7. 规模化组

### P1　规模化多用户与长时间运行稳定性

- **假设**：系统在 1–2 用户 Demo 外，能支撑更大并发与长时间在线而保持课程隔离、证据一致与判定稳定。
- **现状**：无规模化数据（当前为单/少用户 Demo 与合成数据）。
- **所需数据**：≥50 人规模化的真实（或合成假名化）使用环境，采集用户数、使用时长、成功率、失败模式。
- **实验设计**：负载与长稳测试，观测课程隔离（跨用户数据不可见）、版本一致、Worker 调度在并发下仍满足资源配额与超时语义。
- **期望结果与提升含义**：并发与长稳下功能/权限/判定保持正确 —— 证明系统从 Demo 走向可规模使用，支撑赛题“规模化使用将加分项”。
- **若未达成**（并发下权限绕过或判定抖动）→ 证明当前只适合 Demo。优化方向：中间件限流、Worker 队列化、资源配额动态化、状态存储横向扩展。
- **数据可行性**：需真实或授权假名化场地，成本高；作为 P2 与《效果验证报告》规模化项共用。

## 8. 结论与建议执行顺序

按“先证明信任机制成立，再补研究性与规模化”的原则：

1. **P0 先行**：S1（Citation 闭包）、S3（双门控不可绕过）、R1（多 seed 复现一致性）—— 这三项直接决定“生成可信 + 判定可信”两大核心卖点是否成立，且数据可行性高、成本可控。
2. **P1 支撑论点**：M1（泛化测集）、R2（确定性 vs LLM）、K1/K2（六维价值）、X1（注入对抗）—— 把技术报告中的“评估方向”升级为可验证结论，补强研究性。
3. **P2 增强现有**：S2（语义支撑）、P1（规模化）—— 面向纵深与加分项。
