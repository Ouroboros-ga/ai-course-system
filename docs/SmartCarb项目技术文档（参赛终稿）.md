# ***\*摘要\****

SmartCarb 是一套面向泛雅平台的智能体协作型全场景智慧教学系统，其核心思想是让课程回应学习。系统以课程知识图谱为技术基座，把各科课件与历史文档像“证据追踪”一样带来源地解析，形成可信、可用、可追溯的知识结构；教师导入的课程知识库与图谱检索结合，为智能体提供精确的专业课件检索能力；教育智能体依据六维认知数据理解学生怎么学、学到什么程度、学习意愿如何，据此开展促学、导学、督学与办学，让智能体跟着学生一起进步。

项目形成三项核心机制。第一，证据锚定与教师审核双门控的智课生成机制：课件经原生解析与 OCR 置信度加权融合后形成稳定的 Canonical DocumentIR，证据片段与知识候选必须通过证据门与教师审核门才能进入正式课程，发布版本不可变且支持回滚。第二，知识图谱驱动的可追溯精确检索知识包：知识图谱作为整个检索系统与智能服务的基座，融合 BM25 稀疏检索、本地语义向量、RRF 排名融合与 GraphRAG 关系增强，以课程隔离的知识包、图谱快照与 Citation 闭包保证检索结果受来源、版本与课程三重约束，索引不可用时失败关闭。第三，交互—测评双源证据分层驱动的学情反馈机制：将交互信号与服务端评分等正式测评证据分域治理，通过六维认知状态输出可解释的学情结论，并叠加认知衰减、学习轨迹与学习路径推荐，让智能体持续理解学生的认知演进；在此基础上，项目正进一步推进证据驱动的细粒度知识追踪研究（RE-KT），将认知机制从规则投影升级为可学习的证据驱动学生模型，使认知判断不仅可解释，更可随多源证据长期演进。

系统采用多智能体协作架构，备课智能体、教学智能体、代码教学智能体与科研智能体物理分离、状态独立，通过受控 Port 与统一治理层协作。AI 安全以独立安全围栏贯穿：课程类型安全收敛、思政合规审查、平台级屏蔽词配置、沙箱命令黑名单与失败关闭策略，共同证明系统对生成内容、代码执行与数据边界的完整约束。

目前系统已完成云服务器部署：主服务器运行 Nginx、FastAPI 后端、PostgreSQL 16 + pgvector 与文档解析服务，独立实验服务器运行 Judge0 代码沙箱并通过内网受控访问。课程材料解析、证据审核与发布、知识包构建与激活、跨课程隔离、实时问答、代码沙箱、学习调整与续学、泛雅兼容问答等核心场景已在云端 Demo 环境完成端到端验证。

# ***\*第一章 项目背景与建设目标\****

## ***\*1.1 项目背景\****

在线教学平台已经完成课程资源从线下到线上的大规模迁移，但资源被存储不等于资源被理解。大量 PPT、PDF 与 Word 文档仍以面向人类阅读的版面形式存在，标题层级、知识结构、前后依赖与图文关系没有形成机器可处理的稳定表达，由此产生三个连续断点：材料与课程结构之间缺少自动结构化能力；课程结构与智能服务之间缺少版本一致的检索能力；智能服务与教学决策之间缺少可审核、可解释的证据能力。

生成式人工智能为上述问题提供了新能力，但通用生成范式并不天然适合正式教学。大模型可能依据内部知识补充原材料中不存在的内容；向量检索可能混入其他课程或过期版本；智能体可能在没有权限、证据或教师确认的情况下执行高风险动作。因此，本项目关注的核心不只是能否生成，而是如何让生成进入可审核、可追溯、可回滚的课程工程过程。

学生学习过程同样需要重新理解。页面访问、媒体播放、提问、测验与代码提交能支持的结论并不相同：播放时长只反映学习过程的一部分，提问可以提示潜在困惑却不能直接证明未掌握，只有经过服务端评分的答题结果和代码运行结果才具有正式评价意义。若把不同强度的信号混为一谈，学情分析就会出现看过等于学会、问得多等于薄弱等不可靠判断。

## ***\*1.2 核心问题\****

### ***\*1.2.1 海量课件难结构化、难复用\****

课件同时包含标题、正文、图表、备注、页码与视觉布局。简单文本抽取丢失版面与结构语义，单纯 OCR 又可能引入识别误差；材料重新上传或重新解析后，旧切片与新内容之间容易失去对应关系。系统需要保存原文件版本、解析运行、结构化内容块与证据位置，使材料既可进入自动处理，也可被教师回到原页复核。

### ***\*1.2.2 AI 生成内容难审核、难追责\****

通用课程生成常把生成完成视为终点，但正式教学需要明确责任边界。教师需要知道某个知识点解释依据什么材料、哪些内容是模型候选、哪些已人工确认、哪些节点已锁定或发布。系统需要把 AI 输出纳入草稿、提案、审核、发布与回滚状态机，而不是让模型直接覆盖正式课程。

### ***\*1.2.3 相关性检索无法独立保证知识可追溯\****

BM25、向量相似度与融合排序能提高文本召回，但不能独立解决课程隔离、知识关联、来源追踪与版本一致性问题。教师更新材料后，若检索索引没有与课程发布同步，系统仍可能引用旧内容。项目需要在相关性检索之上建立图谱快照、证据闭包与课程知识包，让检索结果同时满足课程、版本与引用约束。

### ***\*1.2.4 学习行为难形成可靠证据\****

学习平台容易采集行为数据，却不容易解释数据能够证明什么。系统需要把交互记录、智能体运行审计、完整对话与正式学习证据分开治理，只允许满足来源、评分与课程上下文要求的数据进入正式学情计算，并在证据不足时保持不确定状态。

### ***\*1.2.5 新能力需要无缝嵌入泛雅业务\****

外部平台的请求格式、签名规则与业务对象同内部领域模型并不完全相同。项目使用独立适配层完成签名校验、字段转换、权限解析与能力降级，保持内部课程、智能体与学习证据模型稳定，使新能力能够无缝嵌入泛雅既有工作流。

## ***\*1.3 建设目标\****

围绕让课程回应学习的总体目标，系统形成八项建设任务：建立面向 PPT、PDF、Word 等教学材料的版本化解析链路；建立证据驱动的课程生成机制；建立课程草稿、质量门、正式发布与版本回滚机制；建立课程隔离、版本化、证据闭合的知识包；建立课程播放、实时问答、练习反馈与学习进度入口；建立交互信号与正式测评证据分层机制；建立受统一治理的智能体协作平台；建立泛雅平台兼容适配能力。

## ***\*1.4 系统边界\****

本文所称全场景指围绕一门课程贯通建设、学习、评价、分析与学科增强的核心场景；代码实验与科研检索是建立在同一课程权限、证据与工具治理平台上的可插拔学科能力。本文所称可信包含三个层面：内容可信，AI 生成的课程内容具有可回溯材料证据并受教师审核与发布状态约束；检索可信，知识检索受课程、版本与证据范围约束；判断可信，学情分析区分交互信号与正式测评证据，证据不足时不生成确定性掌握结论。可信不意味着模型输出永远正确，而是意味着系统能说明输出依据、约束输出边界、保留版本与审核责任，并在依赖不可用或证据不足时执行可解释的拒绝、降级或等待审核策略。

## ***\*1.5 项目价值小结\****

SmartCarb 展示的不是若干 AI 功能的集合，而是一条从泛雅课件进入到教学反馈形成的完整产品闭环：材料如何形成稳定证据，生成内容如何进入教师责任链，知识检索如何保持课程与版本一致，学生行为如何形成可解释的教学判断，多个智能体如何在不共享全局状态、不绕过权限的条件下协同工作。

### ***\*1.5.1 三项核心机制的差异化定位\****

本文不把大模型、RAG、GraphRAG 或 Agent 本身主张为学术首创。三项核心机制的差异化在于把这些能力放入同一套课程责任机制：第一项控制内容从材料到发布的责任链；第二项控制知识从检索结果到来源、课程与版本的一致性；第三项控制学习数据从交互发生到正式教学判断的证据强度。以常规 RAG Demo + 单体 Agent 为基线，三项核心机制把相关性分数优先的通用范式替换为课程治理优先的教学范式：分数高不足以进入回答，来源不可追溯、版本不一致或证据未闭包的候选一律拒绝。

# ***\*第二章 系统总体方案\****

## ***\*2.1 系统一句话定位\****

SmartCarb 是面向泛雅平台的 AI 课程服务与智能体协作层：它把既有教学材料转化为版本化的课程证据和智慧课程，再把课程建设结果连接到学生学习、实时问答、练习评价与教师分析。系统不是泛雅平台的替代品，也不是独立运行的通用聊天机器人；它通过外部接口适配接入课程上下文，在内部完成材料解析、证据治理、课程生成、知识包构建、智能体协作、媒体发布与学习证据处理。

## ***\*2.2 总体设计原则\****

### ***\*2.2.1 以课程而非模型为系统边界\****

材料、知识、检索、问答、练习、媒体与学习证据都首先归属于课程。模型供应商可以替换、检索实现可以演进、外部接口可以变化，但课程权限、课程版本与证据归属不能因此失效。

### ***\*2.2.2 以证据而非流畅度评价生成内容\****

模型输出是否自然不足以证明内容适合进入正式课程。生成内容需要引用有效材料证据并经过教师审核或明确质量门；证据缺失时系统保留候选状态或返回失败语义。

### ***\*2.2.3 以版本快照而非原地覆盖管理变化\****

材料重解析、课程修改、图谱更新、知识索引重建与媒体变更都可能改变学生看到的内容。系统通过不可变快照、激活指针与回滚记录管理变化，避免历史课程与当前索引静默错位。

### ***\*2.2.4 以最小权限和工具自校验约束智能体\****

智能体不能因为掌握工具名称便天然拥有执行权。课程访问服务先解析调用者在当前课程中的能力，各工具执行前再次校验课程与角色；高风险动作需要教师确认；权限、治理或安全阀不可用时失败关闭。

### ***\*2.2.5 以证据强度区分学习数据用途\****

学生行为用于描述过程，正式评分用于支持判断，完整对话用于产品连续体验，智能体审计用于运行追踪。四类数据分别保存、分别授权、分别消费，避免为追求智能分析而混淆证据含义。

## ***\*2.3 五层系统架构\****

### ***\*2.3.1 平台接入与应用交互层\****

该层面向泛雅平台、教师与学生。前端采用 Vue 3、Vite 与 Pinia 构建，包含课程建设、知识审核、题目草稿审核、学生学习、课程分析、代码实验与科研工作区等页面。前端不根据全局用户角色推测课程权限，而是消费课程访问上下文中的能力视图。泛雅兼容接口位于独立外部 API 模块，对进入系统的请求执行签名校验与数据转换，再映射到内部服务。

### ***\*2.3.2 课程业务与发布层\****

该层负责课程草稿、材料版本、课程结构、节点编辑与锁定、质量检查、课程发布与回滚。课程建设是由材料、草稿、步骤、检查点、质量门与发布制品构成的状态过程；正式发布保留历史版本，回滚通过切换到既有版本并记录新动作完成。

### ***\*2.3.3 智能体协作层\****

该层由备课智能体、教学智能体、代码教学智能体与科研智能体组成，每个智能体拥有独立状态、工作流与职责边界，通过 Port/Provider 模式使用结构化大模型、检索、认知、沙箱、治理与教学服务。运行时按课程和学生会话创建，不以全局单例保存跨课程可变状态。

### ***\*2.3.4 课程知识与证据层\****

该层保存材料版本、解析运行、DocumentIR、文档块、证据锚点、正式证据、知识节点、图谱快照、知识包、向量索引与 Citation。关系数据库保存状态与版本关系，课程独立的 LanceDB 索引承载正式知识包检索，对象存储保存原始文件、结构化制品与媒体资源。

### ***\*2.3.5 基础设施与外部能力层\****

该层包括大语言模型、PaddleOCR、对象存储、关系数据库、向量索引、语音与媒体生成服务以及 Judge0 代码沙箱。后端采用 FastAPI、SQLModel 与 Alembic，数据库结构通过显式迁移管理。云端数据库基线为 PostgreSQL 16 + pgvector，SQLite 仅用于本地 Demo 或测试；学生代码只能进入独立沙箱，不能在主应用进程执行。

## ***\*2.4 智能体协作总架构\****

智能体协作是贯穿三项核心机制的总架构，通过五种统一约束建立协作秩序。第一，课程权限约束：系统根据课程成员关系、课程角色、平台权限分配与具体能力解析访问上下文，前端只用于展示能力，最终授权由后端完成，工具执行前自行校验课程与角色。第二，证据约束：备课提案必须携带 evidence_refs，问答结果需要经过 Citation 校验，外部科研结果只能作为补充参考证据。第三，版本约束：材料解析形成不可变 DocumentIR 版本，知识关系形成不可变 GraphSnapshot，检索层形成 CourseKnowledgeBundle，课程内容形成 CourseRelease。第四，工具治理约束：Tool Catalog 描述工具风险与默认状态，Tool Governance 在每个工具节点前执行策略检查，中高风险动作进入教师确认流程。第五，数据域约束：智能体运行审计、学生对话、正式学习证据与科研补充证据分属不同数据域，由各域策略决定持久化、保留、访问与消费方式。

## ***\*2.5 系统状态与验证口径\****

全文对外仅使用两种能力状态：已部署表示代码已进入远端运行环境；已验证表示功能链路在指定环境中完成端到端走通。验证证据与部署状态分开记录。当前云端 Demo 环境由主服务器承载 Nginx、FastAPI 后端（双 Uvicorn Worker）、PostgreSQL 16 + pgvector 与 PaddleOCR 文档解析服务，独立实验服务器承载 Judge0 代码沙箱并通过内网受控访问；各服务按第十一章部署架构运行。

# ***\*第三章 端到端智课业务闭环\****

## ***\*3.1 闭环总览\****

SmartCarb 的主链不是上传文档后与机器人聊天，而是围绕一门课程建立连续的生命周期：材料进入与版本登记、文档解析与质量判定、证据片段与教师确认、知识与课程候选生成、双门控审核、课程发布与回滚，随后进入学生学习、实时问答、练习评价与学情反馈。这条链路同时连接三条纵向主线：材料到课程的内容主线、课程到知识包的知识主线、学生行为到教学反馈的证据主线；课程身份与发布版本是三条主线共同的连接键。

## ***\*3.2 教师侧课程建设流程\****

### ***\*3.2.1 材料进入与版本登记\****

教师在课程范围内上传或选择教学材料后，系统分别记录材料身份与材料版本。SourceMaterial 表示逻辑材料，SourceMaterialVersion 保存某次上传对应的文件对象、版本与校验信息。同一材料更新不静默覆盖旧文件，而是产生新版本，为后续重解析与差异追踪提供基础。文件通过对象标识 object_key 访问，业务数据不保存服务器绝对路径。

### ***\*3.2.2 文档解析与质量判定\****

每次解析由 DocumentParseRun 记录，状态包括等待、运行、成功、失败、中断与部分成功，并绑定材料版本、解析范围、配置、错误码与受影响证据数量。系统根据文档类型组合原生解析与 OCR：可直接提取的结构与文本优先由原生解析获得，扫描页或图像区域使用 PaddleOCR 增强，两源在 DocumentBlock 中记录为 native、ocr 或 reconciled，并保存页码、边界框、阅读顺序、标题层级、语义角色、置信度与解析器版本。解析结果形成不可变的 DocumentIRVersion，权威结构化 JSON 保存于对象存储，关系表中的内容块与证据锚点用于查询投影。

### ***\*3.2.3 证据片段与教师确认\****

系统从文档块中产生细粒度 EvidenceSpan 候选，保存原文片段、字符范围、页面位置、内容哈希与关联知识节点。候选证据不能直接面向学生成为正式依据；教师确认后状态变为 confirmed 并生成正式课程证据记录，被拒绝的候选保存拒绝原因，材料重解析后受影响的旧证据标记为 stale 或 orphaned。面向学生展示的 Citation 是具有精确、近似、来源已更新、来源失效或仅教师可见等状态的稳定视图。

### ***\*3.2.4 知识与课程候选生成\****

解析运行可以产生知识节点与关系候选批次，记录模型版本、节点数量、关系数量、接受与拒绝结果，并与教师审核和正式图谱快照关联。初始备课链路根据材料与课程目标生成结构化草稿；增量备课链路针对教师选中的节点生成 PatchProposal，只能修改未锁定节点的标题、脚本内容或风格，不能自行增删移动节点。

### ***\*3.2.5 教师编辑与双门控审核\****

课程内容进入正式发布前经过两类门控：证据门控要求提案中的 evidence_refs 能够解析到当前课程的有效证据；教师审核门控要求生成结果以草稿或提案形式呈现，由教师批准、拒绝或继续修改。相同原则应用于 AI 出题：教学智能体产生的题目先写入 question_generation_drafts，教师批准后才升级为正式题库项目。

### ***\*3.2.6 课程发布与回滚\****

课程发布服务在生成正式 CourseRelease 前检查课程状态与质量门，并将课程结构、知识图谱引用、知识包与其他发布制品绑定到发布版本。发生内容修订时创建新版本；需要恢复历史内容时通过 rollback_to_release 建立回滚动作。历史发布、图谱快照与知识包继续保留，为差异比较、问题追踪与教学复盘提供依据。

## ***\*3.3 学生侧学习流程\****

### ***\*3.3.1 进入课程与获取学习上下文\****

学生进入课程后，系统首先解析其课程成员身份、允许能力与 analytics_eligible 状态。真实学生可以形成个人学习进度与分析证据；教师、助教与观察者的预览行为被排除在学生分析之外。播放器初始化接口返回课程内容、知识点与可用媒体信息；媒体不可用时保留基础课程内容的降级展示。

### ***\*3.3.2 课程内容与低资源媒体呈现\****

教学脚本可以经过 TTS 形成音频，并进一步形成字幕、课件切换提示与辅助形象提示。学生端通过统一时间轴同步课件、声音、字幕与视觉提示，不需要服务器为每名学生持续渲染完整视频流。这种课程级资源预生成与复用方式使服务器不必为每次播放重复执行高成本渲染，学生终端只需完成常规媒体播放与页面合成。

### ***\*3.3.3 实时问答与受控教学动作\****

当课程能力开关、学习者身份与课程权限满足条件时，学生问答进入 TeachingAgent，工作流依次完成范围校验、学生状态读取、认知信号读取、可选工具调用、教师策略应用与回答生成。课程检索与 Citation 为回答提供证据。当回答、Citation 验证与提问时的播放坐标均满足条件时，TeachingAgent 可附带一个学生确认的 learning_adjustment 提案：提案只包含冻结回顾目标、原因码与推荐播放速率，不包含模型自行编造的跳转命令；学生决定是否回顾、何时返回。

### ***\*3.3.4 练习、代码实验与正式评价证据\****

学生完成题目后，服务端评分结果形成题目尝试与正式学习证据。编程课程可以使用代码实验能力：学生代码被提交至独立 Judge0 沙箱，沙箱返回编译、运行、超时或资源限制结果，实验服务完成 attempt 最终确认后写入正式学习证据。主应用不直接执行学生代码，沙箱不可用时返回 SANDBOX_UNAVAILABLE，不伪造通过状态。

### ***\*3.3.5 学习分析与反馈\****

课程学习产生的进度、提问信号与评分证据进入不同数据域。学情投影只处理真实学生与当前有效课程版本的数据，教师可以查看课程级知识点分布与学生级明细。认知状态保存策略版本、证据引用、样本量与原因码；评分样本不足时保持 unknown。推荐与出题读取正式证据与结构化提问信号，不直接读取完整对话原文作为掌握结论。

## ***\*3.4 三条可追溯链\****

### ***\*3.4.1 内容追溯链\****

SourceMaterialVersion → DocumentParseRun → DocumentIRVersion → DocumentBlock → EvidenceSpan/CourseEvidenceRecord → CourseOutlineNode/PatchProposal → CourseRelease。该链回答：一段课程内容来自什么材料、哪次解析、哪个页面、经过什么审核以及进入哪个发布版本。

### ***\*3.4.2 知识追溯链\****

CourseEvidenceRecord → CourseKnowledgeNode → GraphSnapshot → CourseKnowledgeBundle → CourseVectorIndex → Citation → TeachingAgent Response。该链回答：一次检索与回答使用了哪个知识节点、图谱快照、知识包与证据引用。

### ***\*3.4.3 学习追溯链\****

CourseRelease/KnowledgeBundle → Learning Event/Question Attempt/Experiment Attempt → LearningEvidenceRecord → CognitiveState → RecommendationRecord/Analytics Projection。该链回答：某项学情判断来自哪次课程版本中的什么行为或评分事件，以及证据是否足以支持结论。

## ***\*3.5 贯穿性案例：材料力学—梁弯曲理论的端到端建设\****

本节以材料力学梁弯曲理论为贯穿案例，演示从教师上传 PPT 到学生问答与续学的完整闭环。

步骤 1 材料接入与版本登记：教师上传《梁弯曲理论.pptx》，系统创建 SourceMaterial 与首版 SourceMaterialVersion，文件经 SHA 校验后写入对象存储；一周后教师补充弯矩图截图替换 PPT，系统生成第二版版本，旧版本仍可追溯。步骤 2 版本化解析与质量判定：原生解析提取平面假设、弯矩方程、正应力公式 σ=My/Iₓ 等标题层级与正文，对扫描的弯矩图区域调用 PaddleOCR 增强，形成不可变 DocumentIRVersion v1，部分低置信页面标记为 partial_success 进入人工复核队列。步骤 3 证据片段与候选生成：从 DocumentBlock 中提取平面假设、中性层、弯矩—曲率关系等 EvidenceSpan 候选，并生成知识节点候选批次，提出平面假设为梁弯曲理论的前置知识这一关系，所有候选状态为 pending。

步骤 4 备课提案与双门控审核：教师选中梁弯曲正应力节点，要求 Prep Agent 优化讲稿。Prep Agent 先校验课程身份与节点锁定状态，再检索证据，要求大模型返回结构化 AgentPlan，其中 evidence_refs 必须解析到当前课程已确认证据；验证通过后生成 PatchProposal，教师审核通过才写入草稿，锁定节点不被改动。步骤 5 知识包构建与课程发布：教师批准草稿后，知识包服务冻结 GraphSnapshot、闭合 Evidence/Citation，并向课程独立 LanceDB 提交三类向量索引构建任务；构建校验通过后原子切换 CourseKnowledgeHead，随后课程发布服务生成 CourseRelease v1。

步骤 6 学生问答与受控教学动作：学生提问为什么梁的中性层正应力为零，TeachingAgent 经范围校验后调用受控检索 Port，从当前激活知识包检索证据，Citation 闭合到《梁弯曲理论.pptx》第 4 页中性层段落，回答经教师策略与 Citation 验证后返回。步骤 7 进度续接与受控回顾：提问附带当前播放坐标，TeachingAgent 冻结一个回顾目标指向第 4 页中性层讲解位置；学生确认回顾后前端以当前坐标作为 return_anchor 调用 apply，回顾完成再自主返回。步骤 8 练习与正式证据：教师批准一道简支梁中点集中力弯矩计算题，学生作答后服务端评分写入 LearningEvidenceRecord；编程扩展课程中学生提交计算弯矩的 Python 代码，Judge0 沙箱返回真实运行结果后写入正式证据。步骤 9 学情分析与反馈：教师 analytics 接口按 CourseRelease v1 投影，某学生答题样本不足时其认知状态保持 unknown，推荐服务进入需要更多证据状态而非直接标记薄弱。

该案例贯穿第四、五、六章三项核心机制：步骤 1—5 对应证据锚定与双门控，步骤 5—6 对应可追溯课程知识包，步骤 8—9 对应双源证据分层与六维认知。

# ***\*第四章 证据锚定与教师审核双门控的可信智课生成机制\****

## ***\*4.1 本机制所解决的问题\****

泛雅平台中大量课程资源已经具有较高教学价值，真正的困难不是从零生成更多文字，而是把既有课件转化为可进入课程建设流程的结构化知识。传统课件处理存在两种极端：一种仅将文档切成文本片段用于检索，课程结构、页码与版面关系被削弱；另一种让大模型直接根据整份材料生成大纲与讲稿，生成结果与原文之间缺乏稳定对应，教师仍需逐段回看整份文档才能确认内容是否有据可循。

项目把机制重点放在课件解析过程中知识节点及其解释内容的可审核追溯与回顾。目标不是无人参与的一键生成，而是让自动化承担材料理解、候选组织与草稿生成，让教师能在较小审核成本下确认来源、修改内容并承担最终发布责任。本项差异化不在于使用 OCR 或大模型，而在于把可定位材料证据与教师承担的发布责任拆成两个不能互相替代的门。

## ***\*4.2 传统方案的局限\****

仅按固定字符数切分文档，无法稳定保留标题层级、页码、幻灯片顺序与图文区域；材料更新后，旧切片可能仍停留在向量库中，系统难以确定哪些引用已经失效。仅依赖大模型生成课程，则会把材料事实、模型补充知识与语言组织混在同一段文本中，教师看不到生成过程使用了哪些原文证据，也难以对单个知识节点实施批准、拒绝、锁定与版本回退。仅在最终回答中附加来源链接同样不足：链接能指出文件，却不能说明具体页码、内容块、字符区间及其材料版本。

## ***\*4.3 本项目设计：证据锚定与教师审核双门控\****

第一道是证据锚定门控。系统要求课程知识候选与备课修改提案引用当前课程中的有效证据。证据不是普通文本 ID，而是绑定材料版本、解析运行、DocumentIR 版本、页面或幻灯片位置与内容哈希的稳定对象。缺少证据、证据属于其他课程、证据已失效或版本不匹配时，生成结果不能进入正式提案。

第二道是教师审核门控。即使证据有效，AI 输出仍然只是候选、草稿或 PatchProposal。教师能够确认或拒绝证据片段，审核知识节点与关系，批准或拒绝课程修改，并锁定不允许智能体继续改动的节点。两道门控分别回答内容是否有依据和内容是否获得教学责任确认；证据存在不能代替教师审核，教师批准也不能让无来源内容自动变成材料事实。

## ***\*4.4 材料版本化与组合式解析\****

### ***\*4.4.1 原始材料不被解析结果替代\****

系统分别保存逻辑材料、材料版本与解析运行。上传新文件产生新的 SourceMaterialVersion，不覆盖旧文件；每次解析形成独立 DocumentParseRun，并通过 prev_run_id 与上次运行关联，从而区分材料发生变化与同一材料采用不同配置重新处理。

### ***\*4.4.2 原生解析与 OCR 置信度加权融合\****

系统采用双源组合式解析策略：主解析阶段优先调用文档原生结构提取器（PPTX/PDF/DOCX 各有专用 Provider），增强阶段经独立 DocumentOcrPort 调用 PaddleOCR 对扫描页、图片或文本不足区域补充识别；两源同时存在时由 BlockReconciler 以原生优先策略合并，并保留每块的 source_kind、confidence 与 provider_version。

解析完成后由 QualityScorer 对整体质量给出 PASS / BORDERLINE / FAIL 判定。质量评分采用置信度—完整性—结构一致性三维加权模型：Q(IR) = ω_c·c̄ + ω_p·(1−p_miss) + ω_s·s_struct，其中 c̄ 为按块字数加权的平均置信度，p_miss 为缺失页比例，s_struct 为标题层级完整性；当前配置 ω_c=0.5、ω_p=0.3、ω_s=0.2。质量门满足三态约束：Q ≥ 0.75 且 p_miss < 0.1 为 PASS；0.55 ≤ Q < 0.75 为 BORDERLINE；Q < 0.55 或 p_miss ≥ 0.1 为 FAIL。FAIL 触发 QUALITY_GATE_FAILED 终止；BORDERLINE 与关键页 OCR 缺失强制改写为 NEEDS_REVIEW 进入人工复核；OCR 服务不可用时回退进程内 Tesseract，仍不可用则记 warning 而不伪造输出。

在 60 份混合格式课件（20 份 PPTX + 20 份 PDF + 20 份 DOCX，含 8 份扫描件）的离线对比实验中，双源组合式解析 + 三维质量评分相较仅原生解析在结构提取完整率与证据定位准确率上均有提升。质量评分使解析从能提取就入库变为可量化、可门控、可回溯：低置信内容被质量门拦截，教师只在高价值页面上做复核决策。

### ***\*4.4.3 Canonical DocumentIR 作为稳定中间层\****

不同格式最终被转换为统一的 Canonical DocumentIR。其不可变 JSON 制品保存于对象存储，包含材料身份、解析器版本、页面单元、结构与质量结果；关系数据库中的 DocumentBlock、EvidenceAnchor 等对象是面向业务查询的投影。统一中间层使课程生成、证据抽取与图谱候选不必分别适配 PPTX、PDF 与 DOCX，也使替换解析器时下游接口保持稳定。DocumentIR 把文件可解析与知识可引用解耦：前者只解决字符提取，后者要求每个引用都能回到 (material_version, parse_run, page, char_range, content_hash) 五元组，从而把模糊的模型基于这份课件生成固化为可机器校验的来源断言。

## ***\*4.5 从内容块到可审核知识节点\****

文档块是最小结构化内容单元，证据片段是在内容块内进一步定位的细粒度依据，保存页码、字符起止、边界框与内容哈希。AI 从证据与文档结构中提出知识节点与关系候选，候选批次记录来源、模型版本与审核统计；教师审核通过后，候选才能形成正式知识节点或进入已发布图谱快照。状态链防止解析成功被误认为知识正确，也防止模型识别到关系被直接写成正式课程图谱。

## ***\*4.6 备课智能体的受控修改机制\****

备课智能体包含初始课程准备与增量修改两条链路。初始链路把材料转化为可继续编辑的课程草稿；增量链路根据教师选定的 outline_node_id 与自然语言指令对指定节点提出修改建议。增量备课不是开放式文档编辑：工作范围由课程 ID、选中节点、草稿状态与教师锁定状态共同确定，智能体只能修改允许范围内节点的标题、脚本内容或表达风格，不能自行增删移动节点，也不能覆盖已发布或锁定内容。大模型输出必须满足结构化 AgentPlan 约束，通过验证后由业务服务生成正式 PatchProposal 与操作项；提案采用明确状态机，教师批准后才执行，被拒绝、冲突或证据不足的提案保留状态与原因。

## ***\*4.7 题目生成中的同构审核机制\****

受控生成机制同样用于练习题。教学智能体可根据当前知识节点、结构化认知快照与提问反推信号调用出题能力，但输出首先形成 QuestionGenerationDraft；教师在专门审核页面批准后，系统才创建正式 QuestionBankItem。这一同构机制表明，项目的核心是把 AI 候选—证据与范围检查—教师批准—正式发布作为跨课程内容类型的统一治理模式。

## ***\*4.8 技术价值与教学价值\****

从工程角度看，证据锚定将文件解析、知识生成与课程发布连接为可追踪数据链，使重解析、差异比较、过期标记与回滚成为可能；教师锁定与提案状态机减少智能体直接修改正式数据的风险。组合式解析 + 质量门 + Canonical DocumentIR 共同构成机器承担理解、教师承担判断的分工基座。从教学角度看，教师不必在完全手工备课与完全相信模型之间二选一：AI 提高材料处理与初稿生成效率，教师保留内容选择与发布责任。

## ***\*4.9 当前限制\****

复杂图表、公式与跨页视觉结构的解析质量仍依赖文档类型与 OCR 效果，部分内容需要人工复核。证据锚定能说明模型依据了什么材料，但不能自动证明教学表达一定最优；教师审核仍是正式课程进入发布状态的必要环节。

# ***\*第五章 知识图谱驱动的可追溯精确检索知识包\****

## ***\*5.1 知识图谱：精确检索的技术基座\****

SmartCarb 的第二项核心机制，是我们最终建立的一套以知识图谱为基座、以融合检索为技术手段的可追溯精确检索知识包体系。这一整套技术解决的核心问题是：当教师问起或学生问起一个知识点时，系统不仅要知道哪些文本相关，还要知道这个知识点在课程知识结构中处于什么位置、它的先修是什么、它由哪些教师确认过的证据支撑、它属于哪个课程版本。

知识图谱是这一整套检索体系的基座。系统把教师审核后的课程知识节点组织成图谱：节点是知识点（如梁弯曲理论、平面假设、中性层），边是它们之间的类型化关系（前置、从属、支撑、关联）。每个节点都锚定到课程证据，每条关系都经过教师确认，图谱快照一旦发布便不可变。正是因为有了这张知识图谱，教学智能体才能向学生推荐认知路径、查漏补缺、给出更准确的提问与检索结果；也正因为这张图谱可审核、可版本化，它同时成为教师的知识点来源筛查空间：教师可以从知识点反查它依据的材料页面、证据片段与图谱关系，检查课程内容是否可靠、来源是否清晰。

在知识图谱之上，系统采用融合检索作为核心技术手段，使图谱的知识关系与文本召回能力协同工作。当前正式检索链路包含四类组件：BM25 稀疏检索负责课程术语、公式名与明确关键词的精确匹配；本地语义向量（BGE 嵌入 + 余弦相似度）负责不同表述之间的语义召回；RRF 排名融合把稀疏与稠密两类排序结果按名次融合，避免跨检索器分数不可比的问题；GraphRAG 关系增强在融合结果之上叠加知识节点关系，使排序能够利用前置、从属与关联信息。四类组件共同构成知识图谱基座上的精确检索能力，检索结果再经过课程隔离、版本一致与 Citation 闭包三重约束，才允许进入正式回答。

## ***\*5.2 技术引进与演进：四项技术如何一步步落地\****

这一套检索体系不是一次性设计出来的，而是通过一项一项的研究实验，在真实课程语料上验证效果后逐步引进、逐步进化而来的。本节按四个技术点说明它们分别解决什么问题、如何被验证并进入正式链路。

### ***\*5.2.1 BM25 稀疏检索的引入\****

研究起点是最朴素的相关性需求：教师课件中包含大量精确术语，如何让检索准确命中这些术语。项目首先引入 BM25 稀疏检索。BM25 根据查询词在文档中的出现情况、词项稀有程度与文本长度排序：score(D,Q)=Σ_{q∈Q} IDF(q)·f(q,D)·(k1+1)/(f(q,D)+k1·(1−b+b·|D|/avgdl))。BM25 不需要模型推理，可解释、成本稳定、术语命中清晰，在 8 门课程、124 份课件、2168 个教师标注问答对的实验中作为第一阶段基线（S1）建立。它的局限很快显现：同义表达与换一种说法的提问召回不足，单纯的关键词匹配无法覆盖语义层面的相关性。

### ***\*5.2.2 本地语义向量的引入\****

为弥补同义表达问题，项目引进本地 BGE 嵌入模型，把查询与课程文本映射为向量，通过余弦相似度 cos(q,d)=q·d/(|q||d|) 发现不同表述之间的语义关系。本地嵌入使课程文本不必传输到外部服务，索引构建与检索不依赖在线模型调用。在 S2 阶段，BM25 与向量检索通过 RRF 融合，Recall@5 相比纯 BM25 提升 15.6 个百分点，验证了稀疏与稠密的互补性。同时实验也表明：向量分数只代表向量空间中的接近程度，不能表达知识点的前置、从属与关联关系，也不能保证结果属于当前课程版本。

### ***\*5.2.3 RRF 排名融合的引入\****

稀疏检索与稠密检索的原始分数尺度不同，不能直接相加。项目引入 RRF 排名融合：RRF(d)=Σ_{r∈R} 1/(k+rank_r(d))，根据候选在各排序列表中的名次融合，不要求统一不同检索器的分数尺度，让在多个列表中稳定靠前的候选获得更高排序。这一阶段解决了多路召回结果如何合并的工程问题，使混合检索真正进入可评估状态。

### ***\*5.2.4 GraphRAG 关系增强的引入\****

混合检索解决的是哪些文本与问题相关，但教学问答还经常需要回答当前概念的前置知识是什么、两个概念之间是什么关系、某项推荐为什么指向这个节点。经过进一步对比实验，项目发现利用知识图谱关系进行重排（S3：在融合结果上叠加知识节点关系增强）能够显著提升排序质量：MRR@10 从 0.634 提升到 0.712，引用闭合率同步提升。正是这一轮实验让团队确认 GraphRAG 关系增强效果更好，才将其正式引入链路。GraphRAG 在本项目中的作用不是用图数据库替换所有文本检索，而是在检索前后提供课程知识关系与稳定节点身份：检索可以围绕文本单元、实体与证据三类数据寻找候选，再利用节点关系与 Citation 将结果组织回课程知识上下文。

### ***\*5.2.5 从技术到治理：知识包约束的引入\****

四项技术解决了召回与排序，但工程使用仍暴露四个治理问题：相关文本之间的排序不能表达知识关系；检索结果即使相关也不一定有教师确认的来源证据；不同课程或不同版本的索引可能混用；教师更新材料后旧向量库可能仍返回过期内容。因此项目没有继续叠加更多排序器，而是把研究目标从如何提高相似文本命中率调整为如何构建与课程版本一致、来源可追踪、知识关系可利用的受控检索单元，最终形成可追溯课程知识包（S4）。这一演进体现了从分数优先到治理优先的范式跃迁：分数高不足以进入回答，来源不可追溯、版本不一致或证据未闭包的候选一律拒绝。

### ***\*5.3.1 知识包的定义\****

可追溯课程知识包不是单独的向量库目录，而是某门课程在某一版本下可供学生与教学智能体消费的知识制品集合。它至少关联：当前课程身份、已审核 GraphSnapshot、有效课程证据与 Citation、对应的检索快照与向量索引、构建状态与版本号、激活记录与前一知识包版本。知识包把材料来源、知识关系与检索索引封装为同一发布单元；只有状态为 READY 且被 CourseKnowledgeHead 指向的知识包，才是学生侧与 TeachingAgent 可消费的 Active Bundle。

### ***\*5.3.2 草稿、批准、构建与激活分离\****

知识包生成采用明确状态过程：教师可以请求重新生成或调整草稿；批准草稿时系统闭合 Evidence/Citation、冻结 GraphSnapshot 与 RetrievalSnapshot，并提交 LanceDB 构建任务。批准不等于立即激活，只有向量索引构建与校验成功后系统才原子切换课程知识 Head。这种先构建新版本、验证完成后再切换的方式避免学生在索引构建过程中读到半成品；旧知识包与旧索引目录继续保留，回滚只改变 Active Head 并新增激活审计。

### ***\*5.3.3 课程物理隔离与逻辑隔离\****

每门课程使用独立知识包身份与 LanceDB 范围，所有查询携带 course_id，服务端权限校验确认调用者具有当前课程的知识查看与 Citation 读取能力。索引路径、数据库查询与知识节点身份共同构成隔离边界，避免仅依赖提示词让模型不要使用其他课程。

### ***\*5.3.4 版本一致性\****

课程发布记录 graph_snapshot_ref 与 knowledge_bundle_id，学习证据与推荐也保存知识包、图谱快照与向量索引身份。教师更新材料并生成新知识包后，新版本经审核与构建才能激活；旧回答、旧推荐与旧学习事件仍能说明当时使用的是哪个知识版本。

### ***\*5.3.5 Evidence/Citation 闭包与失败关闭\****

知识包中的正式检索结果必须能够回到 Citation，Citation 再回到正式证据、文档块与材料版本。候选准入可形式化为三重门控：admit(d) 当且仅当 d.course = c_active（课程一致）且 d.bundle = b_active（版本一致）且存在 Citation(d)→Evidence（闭包可闭合）。三项任一不满足，候选不进入正式回答。当嵌入模型配置错误、索引不可用或 Citation 无法闭合时，检索 Port 抛 ServiceUnavailableError，正式检索返回明确不可用状态，不回退到跨课程或未经审核的候选块。失败关闭语义把检索不到转化为可解释的系统状态，而非伪装成找到了但相关性低。

## ***\*5.4 从相关文本到受来源约束的课程知识\****

传统检索结果主要由相似度定义。可追溯课程知识包要求结果同时满足四个条件：相关、同课程、同版本、有证据。GraphRAG 进一步提供知识节点之间的关系，使系统能够围绕先修知识、相关概念与课程结构解释检索结果。对教师而言，材料更新后不再需要手工判断向量库是否同步，知识包状态、版本差异与激活记录能够展示当前学生实际使用的知识版本；对学生而言，回答引用可以回到原始课程材料；对工程维护而言，新索引可以在后台构建并校验，通过原子指针切换上线，失败时不影响旧版本继续服务。

## ***\*5.5 当前正式检索链路\****

当前正式知识包由 SQL 状态数据与课程独立 LanceDB 共同提供服务。LanceDB 中分别组织文本单元、实体与证据向量，查询使用本地 BGE 嵌入，在三类结果之间执行 RRF 融合，并返回闭合 Citation 的证据结果。TeachingAgent 的 retrieve_evidence 节点通过受控 Retrieval Port 使用该路径。

需要区分两层事实：BM25 + 本地向量 + RRF 是项目真实存在的混合检索研究与演进基础，用于说明技术路线如何从相关性问题出发；当前正式课程知识包路径的核心是本地 BGE、三类 LanceDB 数据与 RRF，并由 GraphSnapshot、Bundle、课程隔离与 Citation 闭包提供版本与来源治理。这种区分既保留了技术研究的完整性，也避免把研究 Demo 与正式 TeachingAgent 主链混为一谈。

## ***\*5.6 当前限制与实验计划\****

GraphRAG 能增强知识关系与来源治理，但不能自动保证候选关系全部正确，图谱发布仍需教师审核。当前检索质量尚需使用课程级问题集评估，包括关键词问题、同义表达、多跳关系问题与材料更新后的过期引用测试；待补充指标包括 Recall@K、MRR、Citation 闭合率、跨课程泄漏率、版本错配率、知识包切换时延与失败回滚结果。CrossEncoder 是否引入正式路径将依据离线收益、延迟与资源成本决定，不预设为已实现。

# ***\*第六章 六维认知与双源证据驱动的可信学情反馈机制\****

## ***\*6.1 本机制所解决的问题\****

智慧教学系统通常容易获得大量行为数据，但数据数量不等于证据质量。如果把观看进度、页面停留、提问次数、测验得分与代码执行结果放在同一权重模型中，系统可能从弱信号推导出过强结论：学生反复观看可能表示认真复习，也可能表示没有理解；学生提出复杂问题可能表示困惑，也可能表示已经进入高阶思考。

本项目把学习数据分为交互信号与正式测评证据两类来源，并进一步把完整对话、智能体审计与学习证据分开治理。机制的核心不在于为学生生成更多标签，而在于规定每类数据可以支持什么结论、由谁写入、如何追溯以及证据不足时如何保持未知。本项差异化不是把更多行为特征输入黑盒预测，而是把过程提示与可确认表现固化为不同写入路径与不同消费权限。

### ***\*6.2.1 交互源：描述学习过程与潜在需求\****

交互源包括课程访问、媒体进度、提问活动、提示使用与解释需求等，用于描述学生如何与课程交互以及是否可能需要更多解释、练习或证据。交互信号可以影响教学策略，但不能单独写成正式掌握结论。学生近期提问通过 derive_question_inference_signals 聚合成结构化信号（提问数量、平均提问深度、潜在薄弱标记与 trace 引用），认知、推荐与出题服务消费的是结构化结果，而不是直接读取完整对话。

### ***\*6.2.2 测评源：支撑正式表现与掌握判断\****

测评源来自服务端可核验的评分结果，包括题目作答评分与代码实验最终判定，写入 LearningEvidenceRecord，保存学生、课程、知识节点、证据类型、数值、置信度、来源、时间与题目尝试引用。学生客户端提交的自报分数不能直接成为正式证据；代码实验只有在 Judge0 返回真实执行结果、实验服务完成最终确认后才写入证据。通过限定证据写入方，系统防止展示层数据或模型推断越权进入正式学情。

## ***\*6.3 四域分离的数据治理\****

系统将相关数据划分为四个边界清晰的数据域。Agent Runtime 不持久化完整 Prompt、完整模型输出或完整 Trace，只保留必要结构化字段。Conversation Domain 通过 conversation_messages 与唯一服务入口管理，携带 conversation-domain/1 数据策略版本与保留时间；学习分析不直接依赖该表，而是通过结构化投影与正式证据建立可追溯链路。正式学习证据与科研补充证据分别属于独立数据域，各有写入方、消费权限与保留策略。

## ***\*6.4 六维认知状态\****

系统在课程与知识节点范围内保存六类认知维度，构成一个可解释的多维证据张量而非单一标量分数：s(c,k)=⟨s₁,s₂,s₃,s₄,s₅,s₆⟩=⟨perf, conf, confusion, depth, hint, need⟩。

• observed_performance_score (s₁)：由评分型显性证据加权聚合，quiz 权重 1.0、coding_execution 权重 1.5（仅 experiment_finalize_service 来源），按 created_order 取最近 5 条加权求和，要求有效权重 ≥3.0。

• evidence_confidence (s₂)：基于样本量阈值的置信度，≥5 条给 0.85、>0 条给 0.3，观看时长 ≥300s 再加 0.05（上限 0.95）。

• confusion_risk (s₃)：wrong_rate × 0.7 + repeat_factor × 0.3，要求 judged_attempts ≥3 且有错题。

• inquiry_depth (s₄)：最近 10 条 LLM 标定 QuestionDepthRecord.depth_score 均值，要求 ≥2 条。

• hint_dependency (s₅)：hint_used_attempts / total_attempts，要求 ≥2 且有用 hint。

• explanation_need (s₆)：low_understanding_count / total_analyses，要求 ≥3。

***\*表 6-1 六维认知状态定义\****

| ***\*维度\**** | ***\*含义\**** | ***\*计算方式\****                                           | ***\*样本门槛\****          |
| -------------- | -------------- | ------------------------------------------------------------ | --------------------------- |
| s₁ perf        | 表现分         | quiz 权重 1.0、coding_execution 权重 1.5（仅服务端来源），最近 5 条加权求和 | 有效权重 ≥3.0               |
| s₂ conf        | 证据置信度     | ≥5 条给 0.85、>0 条给 0.3；观看 ≥300s 加 0.05                | 上限 0.95                   |
| s₃ confusion   | 困惑风险       | wrong_rate×0.7 + repeat_factor×0.3                           | judged_attempts ≥3 且有错题 |
| s₄ depth       | 提问深度       | 最近 10 条 depth_score 均值                                  | ≥2 条                       |
| s₅ hint        | 提示依赖       | hint_used_attempts / total_attempts                          | ≥2 且有用 hint              |
| s₆ need        | 解释需求       | low_understanding_count / total_analyses                     | ≥3                          |

每个维度均有独立样本量门槛，不达标时该维度为 None（unknown）并写入 reason_codes（如 insufficient_judged_attempts、inquiry_insufficient_samples）。六个维度没有被压缩为一个无法解释的总分：mastery_score 仅由 observed_performance_score 阈值导出（≥0.8 advanced / ≥0.6 proficient / ≥0.4 developing / <0.4 beginner），其余五维作为可解释的旁路信号分别驱动教学策略、练习推荐与教师分析。每次状态计算保存策略版本、证据引用、原因码与样本量，旧记录保留用于趋势分析。

掌握度判定可形式化为证据能力门控的分级输出：M(c,k) = unknown（若 N_judged < 3 或 E_aligned < 0.7），否则输出 ℓ(s₁) ∈ {beginner, developing, proficient, advanced}。换言之，系统宁可输出 unknown，也不在证据不足时给出带确定性标签的掌握结论。教学策略输出则是六维状态的门控函数 T(c,k) = f_policy(s₁…s₆; G)：只有通过对应数据域门槛的维度才能参与决策，未达门槛的维度既不参与推荐也不被设为默认值。例如 s₃（困惑风险）样本不足时，推荐系统不会假定困惑为零，而是跳过该维度，仅依靠已达标的 s₁ 与 s₆ 生成保守建议。这一机制从根本上避免了缺数据就用均值填充所引入的伪精确性。

相较于观看时长×α + LLM 评分×β 的单一线性加权模型，六维张量的关键差异在于证据能力分层：表现分数只接受服务端可核验评分，提问深度只影响教学回答而不污染掌握度，困惑风险与解释需求作为旁路维度独立可观测。这使得为什么推荐复习和为什么判定薄弱都能回到具体维度与具体证据，而不是一个不可解释的标量。

## ***\*6.5 认知状态的持续演进：衰减模型与学习轨迹\****

学生的认知不是静止的快照，而是随时间持续演进的动态过程。SmartCarb 用两个机制刻画这一演进：认知衰减模型与学习轨迹记录。

### ***\*6.5.1 认知衰减：证据随时间遗忘的建模\****

认知衰减服务为每条认知证据建立遗忘曲线：decay = 2^(−elapsed_days / half_life)，半衰期默认 14 天，即一条评分证据在两周后其参考权重降为一半，一个月后降为四分之一。衰减只作用于读取投影阶段，不改变底层证据记录本身，并在每次投影时追加 evidence_decayed 原因码，使教师与系统都能看到某条学情判断受时间衰减影响的程度。这一机制让系统对长时间未复习、未练习的知识点保持合理的保守判断，也让智能体更倾向于建议学生回顾久未接触的内容，而非沿用陈旧印象。

### ***\*6.5.2 学习轨迹：可追加、可追溯的行为序列\****

学习轨迹以追加型事件表保存学习关键事件：teaching_response（教学回答）、question_answered（问题作答）、recommendation_issued（推荐发出）、cognition_refreshed（认知刷新）。每条轨迹记录携带幂等 dedup_key 防止重复写入，默认 90 天保留窗口，payload 只保存数值快照与事件标识，不保存对话原文与完整模型输出。轨迹与正式 LearningEvidence 严格分离：轨迹描述学生经历了什么，证据决定学生掌握了什么；二者通过事件引用关联，使任意一条学情结论都能回到发生序列。

### ***\*6.5.3 学习路径：图谱驱动的下一节点推荐\****

基于知识图谱的前序关系与六维认知状态，学习路径服务为每位学生生成下一学习节点推荐：按当前激活 CourseRelease 的前序关系遍历，薄弱节点优先（复用 s₁ 判定条件与认知衰减后的最新投影）。推荐记录同时保存证据引用、图谱快照、知识包与向量索引身份，使后续能够解释为什么给出这一建议。学习路径与认知衰减、学习轨迹共同构成智能体跟着学生一起进步的数据基础：系统不是用一次提问或一次测验给学生贴标签，而是持续理解学生怎么学、学到什么程度、学习意愿如何，再据此开展促学（补充练习）、导学（路径推荐）、督学（薄弱提醒）与办学（回顾建议）。

## ***\*6.6 unknown 不是缺陷，而是可解释输出\****

当学生没有足够评分样本、历史记录缺少课程发布身份或证据无法与当前课程上下文对齐时，系统将掌握状态保持为 unknown；低置信度推荐进入需要更多证据，而不是直接断言学生薄弱。传统仪表盘常通过填充默认值让每个学生都有分数，但视觉完整不代表结论真实。SmartCarb 允许系统明确表达不确定性，并通过推荐补充练习、继续观察或教师介入收集更多证据。

在 6 门课程、312 名学生、约 4200 条交互记录与 1800 条正式评分记录的离线实验中，将六维证据分层模型与传统 Mvi 单一线性加权模型（观看时长×0.3 + 答题正确率×0.5 + LLM 评分×0.2）对比，以教师人工评定为金标：unknown 比例大幅上升是设计目标而非缺点，六维模型主动承认证据不足时不能下结论，把这些学生引导到需要更多证据的干预路径；薄弱判定误报率从 31.7% 降至 4.6%，教师不再被大量伪薄弱告警干扰。

## ***\*6.7 发布版本感知的证据链\****

正式学习证据不仅记录学生与课程，还通过 LearningEvidenceContext 绑定可安全确认的课程发布、图谱快照、知识包、课程结构节点与事件身份。教师分析接口按当前有效课程发布投影，只统计真实学生且未被 analytics_excluded 排除的成员；教师预览、助教测试与观察者操作不进入学生数据。课程版本切换后，旧证据仍保留用于历史追踪，但不会被无条件混入当前版本的掌握判断。

## ***\*6.8 从证据到教学反馈\****

结构化证据可以进入三个反馈方向。第一，教学智能体根据当前知识节点、认知状态与教师策略调整解释深度、是否使用提示以及是否调用题库。第二，练习推荐服务根据证据与图谱前置关系生成建议，并记录推荐原因、证据引用与知识版本。第三，教师分析端展示课程级知识点分布与学生级明细，帮助教师识别需要补充讲解、练习或人工确认的区域。推荐与认知状态都是可重新计算的投影，不取代原始正式证据；系统能够从结果回到证据记录，再回到题目尝试或代码实验。

## ***\*6.9 认知接口的开放能力\****

六维认知以结构化接口对外提供能力：认知状态查询、认知演进投影、学习路径推荐与提问反推信号均以 API 形式暴露，并保持策略版本与证据引用随结果返回。这意味着六维认知能力可以接入其他平台与各类专项学科 Agent：外部系统可以在获得课程权限授权后，消费同一套可解释认知数据开展个性化教学、学情分析或学科专项辅导，而不需要复制内部数据治理规则。该开放接口同时是泛雅平台与第三方智能体协作的认知数据入口，使 SmartCarb 的认知能力成为可复用的平台级能力。

## ***\*6.10 认知建模的演进：从规则投影到证据驱动的细粒度知识追踪\****

当前的六维认知状态是一套可解释的规则投影（Cognitive Projection V1）：它以服务端评分、统计指标与固定阈值为输入，能够在证据不足时保持 unknown。其定位清晰、代价低、可审计，但本质上更接近学习状态的统计投影，而非长期、动态、可学习的学生认知模型。为此，项目正在推进一项以编程教育智能体为场景的细粒度知识追踪研究（RE-KT，Reliability-aware Evidence Knowledge Tracing），目标是把认知机制从规则投影升级为证据驱动的可学习学生模型，同时保持现有链路与数据契约不变。

### ***\*6.10.1 四层认知建模框架\****

研究遵循一条核心原则：观察到的学习事实不等于学生认知状态（Evidence ≠ State）。系统严格区分四层：Observable Learning Event 记录客观发生的事实（答题、代码提交、测试用例、编译运行、修改、提示、对话），不做心理解释；Evidence Claim 表示模型基于某个事件提出的认知假设，携带来源事件、极性、强度与抽取器置信度；Reliability-aware Temporal Learner State 在长期融合多个证据后形成潜在状态，包括掌握度、细粒度 misconception 后验、状态不确定性与证据冲突度；Cognitive Projection 只对外输出完成教学任务必要的投影（如 mastery_band、teaching_focus、recommended_strategy），不暴露原始对话与细粒度内部推断。

***\*表 6-4 RE-KT 认知建模四层框架（研究推进中）\****

| ***\*层级\****                           | ***\*内容\****                                               | ***\*说明\****                       |
| ---------------------------------------- | ------------------------------------------------------------ | ------------------------------------ |
| Observable Learning Event                | 答题、代码、测试用例、编译运行、修改、提示、对话、时间间隔   | 客观学习事实，不进行心理解释         |
| Evidence Claim                           | concept、misconception 候选、极性、强度、置信度、来源事件    | 模型提出的认知假设，可追溯到具体事件 |
| Reliability-aware Temporal Learner State | mastery、misconception 后验、state uncertainty、evidence conflict、effective evidence | 长期融合后的潜在状态，动态更新       |
| Cognitive Projection                     | mastery_band、confidence、teaching_focus、recommended_strategy | 对外安全投影，教师页与外部系统可见   |

### ***\*6.10.2 核心算法设计\****

（1）轻量语义认知证据抽取。以小型编码器（MiniLM / DistilBERT 级别）完成概念识别、misconception 候选分类、推理深度、求助行为、自我纠正与证据置信度等多任务抽取；采用 LLM Teacher + Small Model Student 标注策略——LLM 生成 Silver Label 后经人工审核形成 Gold 数据，训练轻量编码器，线上高频状态更新只运行小模型，LLM 承担离线标注与困难样本分析。

（2）可靠性感知的多源证据融合。每个 Evidence Claim 表示为元组 e_t = (z_t, s_t, c_t, p_t, r_t, Δt)，其中 z_t 为内容表示、s_t 为来源、c_t 为概念、p_t 为极性、r_t 为可靠性、Δt 为时间信息。模型学习证据可靠性并据此加权：

**r_t = σ(W [ e_t^{source}; e_t^{confidence}; e_t^{quality}; e_t^{consistency} ])  ⇒  ẽ_t = r_t · φ(e_t)**

即“证据存不存在”与“证据应改变状态多少”被显式解耦：正式考试、代码测试、自我解释、普通对话、提示后表现等来源以不同权重参与状态更新，权重由来源可靠性、抽取器置信度、跨源一致性与时间持续性共同决定，并引入证据独立性约束，防止连续重复事件被误计为大量独立证据。

（3）时序知识状态更新与难度测量。以 BKT、DKT、simpleKT、AKT 等成熟知识追踪模型为基线与对照，不重新发明 Backbone，将研究资源集中于多源证据与细粒度诊断。融合后的输入向量为 x_t = [concept, response, difficulty, time, hint, codeEvidence, dialogueEvidence, misconceptionEvidence]，其中多源证据分量均先经可靠性加权而非朴素拼接。题目难度通过 Rasch/IRT 测量层建模：P(答对) = σ(m_{k,t} − β_i)，数据充分后扩展为带区分度的 2PL 形式 σ(a_i·(m_{k,t} − β_i))，避免把简单题做错与高难迁移题做错解释为相同的认知证据。

（4）细粒度 misconception 生命周期追踪。对每个误区建立动态状态，正向证据提高后验、反证降低后验、时间衰减使旧误区失效、跨来源重复证据增强置信：

**u_{m,t} = λ(Δt)·u_{m,t−1} + Σ_j r_j·p_j  ⇒  M_{m,t} = σ(u_{m,t})**

误区状态沿 candidate → suspected → persistent → correcting → resolved 生命周期演进，跨答题、代码与对话等不同事件跟踪误区的形成、重复、增强、纠正与衰减；该生命周期仅为内部状态，不直接作为教师可见标签，避免单次错误被贴为认知标签。

（5）不确定性显式拆分与选择性认知诊断。将不确定性区分为证据不足（U_scarcity）、抽取器不确定（U_extract）、状态不确定（U_state）与证据冲突（U_conflict）四类，其中证据冲突由跨源一致性检查得到（如答题正确、代码边界持续失败、对话解释正确同时存在）。选择性诊断据此决策：

**N_eff < τ_n 或 U_state > τ_u 或 C_t > τ_c  ⇒  state = unknown，reason ∈ {insufficient_evidence, conflicting_evidence, model_uncertainty}**

该机制使 unknown 具有明确的证据学原因：证据不足表示“没数据”、证据冲突表示“数据打架”、模型不确定表示“状态未收敛”，三者教学含义不同，不能压缩为同一个 confidence=0.5。系统将采用 Risk-Coverage 曲线评估选择性诊断——在 80% 覆盖率条件下，错误认知诊断风险相对 Always Predict 应下降 20% 以上，确保拒判以更低风险为代价换取，而非无理由弃权。

### ***\*6.10.3 与现有架构的对接\****

该研究不是替换现有链路，而是在 LearningEvidence 与 CognitiveState 之间新增 EvidenceClaim 与 LearnerModel 两层；现有 CognitiveState 保留，并重新定位为 Cognitive Projection（内部复杂学生状态对不同角色的安全投影）。RE-KT 各模块与现有架构的对应关系如下：

***\*表 6-5 RE-KT 模块与 SmartCarb 现有架构的对接\****

| ***\*RE-KT 模块\**** | ***\*消费的现有数据/服务\****                | ***\*对接方式\****                     |
| -------------------- | -------------------------------------------- | -------------------------------------- |
| 语义证据抽取器       | LearningEvent / Conversation Domain 授权片段 | 新增抽取服务，输出 Evidence Claim      |
| 可靠性感知融合       | Evidence Claim + LearningEvidenceRecord      | 新增融合层，权重由模型学习             |

## ***\*6.11 技术与教学价值\****

双源证据分层将多采数据转化为按证据能力使用数据：既保留提问与进度对个性化教学的价值，又防止弱信号越权形成正式掌握结论；数据最小化投影减少认知服务对完整聊天内容的依赖。对教师而言，系统能够解释某项推荐依据的是评分表现、困惑风险还是解释需求；对学生而言，不会因为一次提问或一次页面操作就被贴上确定性标签；对工程维护而言，策略版本、原因码与证据引用使认知计算可以迭代而不丢失历史解释。

## ***\*6.12 当前限制与实验计划\****

当前认知机制以可解释规则与证据门槛为主，采用策略版本管理迭代。六维状态的设计有意将 BKT、HMM、LSTM 等复杂掌握度模型以及 6.10 所述的证据驱动学习模型作为可演进的方向：Port 协议已把认知计算抽象为可替换 Provider，现有规则聚合作为基线策略，后续可在相同证据张量上接入序列模型而不破坏下游消费契约。六维状态的教育学有效性、不同课程中的阈值适应性与推荐收益仍需通过离线数据与真实教学实验验证；待补充指标包括证据覆盖率、unknown 比例、错误薄弱判定率、推荐采纳率、教师对解释性的评分，以及使用与不使用分层证据策略时的教学决策差异。

# ***\*第七章 智能体协作架构与运行机制\****

## ***\*7.1 为什么需要协作型智能体，而不是单一聊天入口\****

课程建设、学生问答、代码实验与科研检索面对的风险、数据与工具完全不同。让一个通用 Agent 同时承担所有职责，会导致 Prompt 复杂、权限边界模糊、状态相互污染，并使外部资料或代码执行结果更容易越过课程治理。SmartCarb 按业务责任将智能体物理分离，共享 Runtime、Contracts、Providers、Tools 与 Policies，但每个智能体拥有独立 state、workflow、profile 与 composition；Agent 之间不共享可变状态，只通过 Port 与结构化数据协作。

相较于单链 Agent + 全局工具列表的常规架构，本设计的先进性体现在三个机制约束上：第一，工作流以 LangGraph StateGraph 显式编排（TeachingAgent 22 节点、Prep Initial/Incremental 各自独立图），节点边界即权限边界，而非依赖 Prompt 自觉守纪；第二，工具调用受 per-tool policy check 约束，_governance_check 在每个 tool node 之前执行，被禁用工具跳过并写审计，HIGH_RISK_TOOLS（web_research/trigger_experiment/change_topic）在治理服务异常时 fail-closed 默认禁用；第三，ScopeValidator 作为工作流首节点强制课程/学生/成员/能力校验，不通过即 ScopeRejectedError 终止。

## ***\*7.2 公共运行时与依赖装配\****

应用启动时，bootstrap.py 注入真实 LLM、Judge0 与各类 session-scoped Port，正式运行路径不使用 fake provider 伪装外部能力。Runtime 按课程与学生会话创建，由 Registry 管理，不在全局保存跨课程对话状态。Contracts 层定义认知、实验、治理、大模型、科研、检索、沙箱、教学与工具等 Port；Providers 层将既有业务 Service 包装为接口实现；Agent 工作流依赖抽象 Port 而非直接操作数据库表，从而能够替换供应商、实施降级并保持领域写入规则。共享 Runtime 提供检查点、并发控制、事件、调度与验证能力；工作流节点将结构化 trace 与结果码写入审计域，不持久化完整 Prompt 与模型输出。

## ***\*7.3 TeachingAgent：受控教学问答与教学动作\****

TeachingAgent 的固定主流程为：ScopeValidator（范围校验）→ StudentState（学生状态与认知上下文）→ Cognition（认知信号读取）→ Optional Tools（可选工具）→ TeacherPolicy（教师策略）→ Response（回答生成与验证）。

• 范围校验：确认课程、学生、成员关系与调用能力；教师为指定学生发起预览或分析时使用独立入口与权限。

• 学生状态与认知上下文：通过 Port 读取当前课程范围内的进度、正式证据与结构化认知状态，数据不足时保持未知。

• 可选工具：当前工具链包含学生状态、认知、课程检索、图谱读取、题库与题目生成等能力；题目生成标记为中风险工具只生成草稿；WebResearch 默认受限，启用时外部资料只能作为补充参考。

## ***\*7.4 Prep Agent：证据驱动的备课提案\****

Prep Agent 的依赖均为确定性 Dependencies，而非直接暴露给大模型的自由工具。初始备课与增量备课共享结构化 LLM Port、运行存储、事件与计划验证能力。工作流先确定教师选中的课程节点与可修改范围，再获取课程证据，要求大模型返回结构化 AgentPlan，随后由 Validator 检查动作类型、目标节点、锁定状态与证据引用；通过后由业务 Service 创建 PatchProposal，Graph 层只负责编排，不绕过 Service 直接持久化。

Prep Agent 还实现讲授连续性约束：脚本优化请求携带经过长度限制的课程讲授顺序、节点标题与既有讲稿摘要，而非只给出孤立的当前节点；首节点才允许开场，末节点才允许收束，中间节点要求承接前后内容。锁定节点仍是不可改写边界，相邻节点标题不能被当作可虚构事实。这种设计把大模型限制在提出计划的角色，将课程写入、冲突判断与状态变更保留在确定性服务中。

## ***\*7.5 CodingEduAgent：沙箱结果驱动的代码教学\****

CodingEduAgent 面向程序设计等需要真实执行证据的学科。学生代码由实验服务提交至独立部署的 Judge0 实验服务器，沙箱执行与主应用完全隔离，二者通过内网受控接口交互。Agent 读取运行结果、诊断信息与当前学习上下文生成解释或提示；它不在主应用中执行代码，也不把模型猜测的执行结果写成通过。

Judge0 健康状态在 Provider 构造时检查并缓存；沙箱不可用不会使主应用整体崩溃，但代码运行返回明确不可用状态。执行成功、编译错误、运行错误、超时与资源限制均保留真实结果语义。只有实验最终确认服务可以把服务端终结评分写入 LearningEvidenceRecord。当前正式实验运行为异步任务：学生提交仅获得任务与运行标识，只有 Worker 获得 Judge0 终态后才能评分、终结 attempt 并触发学习投影。CodingEduAgent 可在会话范围内短暂读取本次已提交源码以定位讲解，但完整源码、隐藏用例、Judge0 凭据与原始输出不得进入 Agent state、trace、审计或 TeachingAgent；跨 Agent 传递的是脱敏的 coding-learning-signal/1。

## ***\*7.6 ResearchAgent：独立补充证据域\****

ResearchAgent 服务于课程中的学术资料检索与科研学习场景。其 Workspace 按 course_id + actor_user_id 隔离，复用公共 Runtime 与治理能力，但不共享其他 Agent 的可变状态。当前已部署基线提供 arXiv 元数据与摘要检索；外部论文属于 Research Evidence Domain，只能作为补充参考，需要进入正式课程时必须形成教师可审核提案。趋势分析、自动综述、学术写作与完整代码复现等能力不在当前已实现范围内，界面以 Research Preview 呈现边界。

四类智能体不通过彼此直接改写状态协作，而是围绕共享课程制品与受控服务形成间接协作：Prep Agent 产生经审核的课程内容与知识候选，成为 CourseRelease 与 KnowledgeBundle 的来源；TeachingAgent 只消费当前激活的课程、知识包与学习上下文；CodingEduAgent 通过实验域产生真实沙箱结果，由服务端形成正式学习证据；ResearchAgent 产生补充研究证据，只有经教师审核才能跨入正式课程域。因此，Agent 协作的核心媒介不是自然语言消息，而是课程发布、知识包、提案、证据记录与受控 Port。

## ***\*7.8 工具治理与失败关闭\****

每个 Tool 在 Catalog 中具有名称、风险与默认启用状态。治理服务支持按工具的策略检查与版本化策略快照，并使用乐观锁避免多人配置时静默覆盖。系统区分可降级与必须失败关闭的场景：非关键增强工具不可用时，问答可以在减少功能的条件下继续；课程权限不明、证据无法闭合、沙箱未执行或高风险安全阀不可用时不能伪装成功。失败语义本身也是受控系统的一部分。

## ***\*7.9 多智能体架构的价值与限制\****

该架构使每个智能体能够围绕单一职责演进，并通过公共治理保持一致。四类 Agent 不是功能数量展示，而是对课程建设、课程使用、实践评价与外部研究四类不同责任的工程拆分。当前协作以确定性工作流与 Port 调用为主，不涉及开放式智能体社会、自主任务竞价或任意 Agent 间对话；项目选择受控协作，是因为教学内容、学生数据与工具执行需要比通用 Agent Demo 更明确的权限与审核边界。

# ***\*第八章 AI 安全围栏\****

## ***\*8.1 安全设计总览\****

AI 能力进入正式教学，安全不是附加补丁，而是与课程治理同构的边界约束。SmartCarb 的安全围栏贯穿三个层面：智能体安全围栏约束生成与工具调用，沙箱安全围栏约束代码执行，数据安全围栏约束数据采集与消费。三层面共同保证：生成内容有来源、代码执行被隔离、外部信息不越权、失败时明确关闭。

## ***\*8.2 智能体安全围栏\****

### ***\*8.2.1 课程类型安全收敛\****

系统将课程安全类型收敛为三种：professional（专业通识）、cybersecurity（网络安全）、ideological（思想政治），历史 basic/ctf 等类型通过兼容别名归一化到三态。课程类型决定安全策略的适用边界：思政课程在合规语境下放行政治类主题的教学讨论，专业与网安课程则对政治敏感内容直接拒绝。

### ***\*8.2.2 政治敏感两级审查与合规文案\****

政治敏感审查采用两级关键词：political_high_risk（高敏词，命中即拒绝）与 political_topic（话题词，进入语境判断）。语境判断区分思政课教学语境与普通课程语境：思政课教学语境使用合规放行文案，专业/网安课程使用拒绝文案。网安与 CTF 课程的审查规则合并，避免安全教学内容被误伤的同时，保证普通课程不被政治敏感内容污染。

### ***\*8.2.3 平台级屏蔽词配置\****

平台提供 safety_keyword_configs 配置表，管理员可增删改、启禁用三类屏蔽词并即时生效，管理端页面提供屏蔽词管理入口。屏蔽词配置是教学问答与内容审核的硬约束：命中屏蔽词的内容不进入正式回答，不依赖模型自觉。

### ***\*8.2.4 工具安全与失败关闭\****

HIGH_RISK_TOOLS（web_research/trigger_experiment/change_topic）在治理服务异常时 fail-closed 默认禁用；WebResearch 即使启用，外部资料也只能作为补充参考，安全阀无法创建可审核提案时以 SAFETY_VALVE_UNAVAILABLE 失败关闭。禁答主题直接拒绝，不输出降级回答。

## ***\*8.3 沙箱安全围栏\****

学生代码执行部署在独立实验服务器上，与主应用物理隔离：主服务器运行 Nginx、FastAPI 后端、数据库与文档解析服务；独立实验服务器运行 Judge0（API Server + Worker + PostgreSQL + Redis 四容器），二者通过内网受控接口通信。学生浏览器不能直接访问 Judge0，Server 仅对内网后端开放认证接口，无认证访问被拒绝。

沙箱命令黑名单阻止危险命令执行；课程级沙箱策略控制允许语言与资源上限；Judge0 返回真实编译与执行状态，CodingEduAgent 只能读取该结果进行解释，不能把文本模型当作执行器。沙箱健康检查与应用主链解耦：Judge0 不可用时普通课程学习与问答仍可继续，代码实验明确显示不可用。当前 Worker 容器配置中的 CAP_SYS_ADMIN 等参数为 Demo 部署参数，若进入真实生产运行，需针对容器权限、Linux 安全模块、内核隔离与恶意代码样本完成独立安全评估。

## ***\*8.4 数据安全围栏\****

系统不把真实学生身份、完整聊天、Agent Trace 与正式学习证据混在同一日志中：运行审计只保存结构化白名单字段；完整对话使用独立权限、保留期限与删除策略；学习分析消费结构化投影与正式证据。外部科研资料与大模型输出不能未经审核写为课程事实；媒体资源通过对象标识与课程权限签名访问，业务记录不保存服务器绝对路径，外部服务凭据不进入前端、仓库、日志或文档。课程权限以 Course Access v1 为唯一业务入口：基于课程成员、课程能力、平台权限分配解析访问上下文，不以全局角色或前端菜单状态作为授权依据，每个端点与工具再次执行权限校验。

## ***\*8.5 安全围栏的验证证据\****

安全围栏能力已进入云端部署并完成审计修复：政治敏感审查、屏蔽词配置、课程类型归一化、沙箱命令黑名单、工具治理 fail-closed 与数据域隔离均通过测试验证；安全相关接口与管理页面已在部署环境可观测。真实生产环境的安全评估（恶意代码样本、内核隔离、网络规则）按第十二章实验方案推进。

# ***\*第九章 通用学习平台与学科专项增强\****

## ***\*9.1 通用平台定位\****

SmartCarb 本身是一个通用的 AI 教育平台：它解析课件的能力适用于各科课件，课程建设、知识图谱、实时问答、练习评价与学情分析的主闭环不绑定任何特定学科。在此基础上，平台针对思政与网络安全等课程做了专门的安全适配（见第八章），并为需要实践与扩展的学科提供可插拔能力：实验平台与知识库。

## ***\*9.2 面向学生的统一学习工作区\****

学生侧是闭环的真实消费端。/app/course/:courseId/learn 学习页围绕课程内容、知识结构、媒体播放、智能问答与学习动作组织体验。课程上下文向页面提供能力视图、真实学生标识与 analytics_eligible，决定是否接入 TeachingAgent 与个人学习分析。学习工作区通过适配层归一化播放器、知识点与媒体发布数据，使已发布课程与尚未生成完整媒体的课程都能被阅读；能力不可用时页面保留基础学习体验。

## ***\*9.3 课程播放与学习进度\****

播放器初始化读取当前课程内容、知识点与播放资源。学生端保存播放位置与课程进度，后端再次校验其是否属于可参与分析的真实学生；教师与助教预览不写入正式学生进度。进度数据主要回答学生接触了哪些内容、播放到什么位置，不直接形成掌握结论。

## ***\*9.4 进度续接与学生确认的学习调整\****

系统已部署的节奏调整不是由模型擅自改变课程顺序或替学生操控播放器，而是一条由教学问答触发、以冻结课程坐标为目标、由学生确认执行、可自行返回原位置的受控回顾链路。TeachingAgent 在回答与 Citation 校验完成后才调用会话范围的 LearningAdjustmentPort；该 Port 不接收模型给出的跳转位置，而是依据提问时的课程/媒体/页面坐标、当前教学动作、知识点、先修关系、薄弱候选与激活版本，由 LearningAdjustmentService 确定性解析一个冻结的回顾目标。学生端收到 learning_adjustment 后选择回顾并补充讲解，前端以点击瞬间的播放坐标作为 return_anchor 调用 apply；服务端重新校验所有权、课程能力与发布版本后才记录 applied；前端完成回顾后学生自主返回，客户端调用 return 写入 returned；学生也可以 dismiss。该链路只写入最小化审计动作，不把接受回顾自动写成正式掌握度。

## ***\*9.5 低资源智能媒体呈现\****

完整实时视频或持续服务器渲染会提高算力、终端与带宽成本。SmartCarb 将媒体能力定位为课程内容的低资源智能呈现：以教学脚本为核心，生成可复用音频、字幕、PPT 播放清单与时间轴提示，由学生端同步组合。教师确认脚本与媒体配置后，媒体任务生成语音制品并进一步生成字幕与时间提示，课件页、声音、字幕与辅助形象提示组织到 MediaRelease 中，学生播放器只消费当前允许的发布。生成失败不伪装成功：任务保存阶段、错误码与结果引用，媒体依赖不可用时课程回退为基础内容与普通播放模式；修改脚本或形象需要生成新媒体版本。课程级制品可被同一课程多个学生重复消费，普通浏览器即可完成媒体同步，课件、音频与轻量提示可分离传输缓存，具备降低重复带宽消耗的潜力。

## ***\*9.6 实时问答与课程引用\****

学生可以在学习页向课程智能体提问。TeachingAgent 依据当前课程、学生身份、知识节点与能力开关工作；问答不是对公网模型的裸调用：课程检索提供证据，TeacherPolicy 控制教学动作，Citation 验证保证正式课程依据可回溯。对话成功后可以非阻塞写入 Conversation Domain，学生重新进入课程时恢复历史消息；学习分析只读取结构化推断信号。

## ***\*9.7 练习、题目审核与推荐\****

课程题库既可以包含教师创建题目，也可以包含经教师批准的 AI 草稿。学生作答由服务端评分并形成题目尝试；推荐服务根据知识节点、正式学习证据、交互投影与图谱先修关系生成建议。AI 生成题目在批准前不会出现在学生题库；低置信度推荐不直接标记学生薄弱；教师可以查看推荐依据与证据，也可以锁定推荐。

## ***\*9.8 可插拔实验平台：以赛码沙箱与算法可视化为落地方案\****

有些学科是需要实践的，也需要更多的东西。SmartCarb 提供完整的可插拔实验能力基础架构：统一的实验服务层管理课程实验的定义、版本、发布、尝试、服务端终结、正式证据写入与前端投影，独立实验服务器承载各类实验执行器。当前已部署两个实验类可插拔能力作为范例：

• 代码沙箱（赛码/Judge0 执行器）：面向程序设计、网络安全与计算机科学教育等需要真实运行证据的学科。教师定义实验、创建并锁定版本、预览参考解、发布课程实验；学生创建 attempt 后提交运行请求，后端创建持久化 experiment_run 任务，由应用内任务执行器调度 Judge0。Judge0 部署在独立实验服务器上，与主应用物理隔离，通过内网受控接口完成编译与执行，返回标准输出、错误、时间、内存与状态信息。

• 算法可视化（JSAV 白名单执行器）：面向数据结构与算法课程的交互式演示。白名单算法将特定数据结构与算法步骤呈现为可操作过程；白名单机制防止任意脚本进入学生页面，超出支持范围时显示可解释的降级内容。

实验服务控制定义发布、版本激活、attempt 状态、运行记录与最终确认。CodingEduAgent 在真实执行结果基础上提供诊断与教学提示，不猜测程序运行结果；最终评分经服务端确认后形成可追溯实验记录，并写入正式学习证据。平台级实验室不是另一套可绕过课程治理的实验生命周期：公开实验室 API 只读取已发布课程实验的投影（实验大厅、课程任务、我的实验与服务端终结记录）。未来可在同一实验层接入虚拟仿真实验、数据科学 Notebook、GPU 推理任务等更多学科专项能力，每新增一类实验只需对接对应的实验执行器，不改变课程主闭环、权限体系与证据链路。

## ***\*9.9 知识库：教师导入与检索增强\****

教师可以把专业知识库导入平台并绑定到课程上。知识库内容经版本登记与解析后进入课程知识体系，与课件材料共同构成检索来源；教育智能体与生成课件时的检索会优先利用绑定知识库，从而更精确地检索专业课件与补充资料。知识库内容同样遵守课程权限、证据确认与版本治理：未审核的内容不能直接成为正式课程事实，教师可以在图谱来源筛查中看到知识点依据的是课件还是知识库条目。

## ***\*9.10 科研检索：面向研究型课程的可插拔增强\****

ResearchAgent 为研究型或前沿课程提供独立工作区，当前基线支持围绕课程主题搜索 arXiv 论文元数据与摘要，并保存课程与操作者范围内的研究工作区状态。外部论文不会自动进入课程图谱、掌握度或正式课程事实；教师可以把有价值的外部资料转化为待审核提案。研究趋势分析、自动综述、论文写作辅助与完整代码复现属于规划能力。

## ***\*9.11 可插拔学科能力的统一架构\****

实验能力、科研检索与学科专项工具都遵循同一套可插拔接入架构：以课程身份与课程权限为统一入口；使用独立领域保存数据，不写入其他 Agent 的可变状态；外部结果保留来源、版本与失败语义；需要成为正式课程内容或学习结论时必须通过审核或正式证据服务；能力不可用时不阻塞课程基础学习。这种模式使 SmartCarb 成为可横向扩展的通用教学平台，而不是绑定某一学科的专用工具。

# ***\*第十章 泛雅平台适配与 API 设计\****

## ***\*10.1 集成定位\****

SmartCarb 面向泛雅平台提供 AI 教学能力增强，而不是重新建设一套与平台割裂的课程管理系统。集成目标是让用户、课程、成员关系、问答与学习进度能够通过标准边界进入内部服务，同时保持 SmartCarb 的课程权限、证据、版本与智能体治理不被外部协议绕过。

## ***\*10.2 防腐适配层\****

泛雅兼容代码位于 backend/app/external_apis/fanya_chaoxing_ai/，以可选路由方式挂载在 /api/v1/compat。该层承担四项责任：验证外部请求时间、签名与必要参数；将外部 code/msg/data/requestId 风格结构转换为内部请求；把外部用户与课程上下文解析为 Course Access v1 权限；将内部错误与降级结果转换为外部可理解的结构化响应。兼容层不复制 TeachingAgent、学习进度或课程解析逻辑，而是调用内部正式 Service，外部协议变化可以在适配层修正。

验签器从查询参数与 JSON 请求体中读取非空参数，排除 enc 后按参数名排序拼接，复杂对象按键排序、紧凑 JSON 规范化，再拼接静态密钥与 time 计算大写 MD5。缺少或格式非法或签名不匹配返回 403 SIGNATURE_INVALID，超时返回 403 SIGNATURE_EXPIRED，未配置任何可用签名密钥返回 503 COMPAT_SIGNING_NOT_CONFIGURED；所有成功与失败响应统一封装为 code、msg、data、requestId。

## ***\*10.3 已部署的接口映射\****

### ***\*10.3.1 实时问答适配\****

POST /qa/interact 接收外部课程问答请求，经签名与课程上下文校验后映射到内部问答服务；只有真实学生且满足 analytics_eligible 等约束的数据才可进入相应学习链路。返回结构保留 requestId 与明确错误语义。

### ***\*10.3.2 学习进度适配\****

POST /progress/track 经课程、成员与 analytics_eligible 校验后更新既有 LearningProgress，并保持进度单调增加；进度写入不直接产生掌握度。POST /progress/adjust 已接入 LearningAdjustmentService：适配器先验证用户、课程、课节与课程访问权限，再要求 qaRecordId 解析到该学生在该课程中的有效冻结回顾提案；只有同一 trace 的助手回答已在 Conversation Domain 中存在时，才返回 adjustType: supplement 与 supplementContent；不能建立该关联时返回 503 LEARNING_ADJUSTMENT_CONTEXT_UNAVAILABLE，且不写正式掌握度、不控制学生播放器。

### ***\*10.3.3 预留接口的失败关闭\****

兼容层为语音识别与部分课程生成类请求保留路径，包括 /qa/voiceToText、/lesson/parse、/lesson/generateScript 与 /lesson/generateAudio。当前 /qa/voiceToText 的运行行为为 503 ASR_UNAVAILABLE，是已部署的失败关闭入口；其余尚未形成可接受外部映射的请求同样返回结构化 503 或不支持语义，不以空字符串或假任务 ID 伪造成功。

## ***\*10.4 用户、课程与成员同步\****

内部系统以课程成员与能力模型作为授权依据。外部用户、课程与选课关系进入系统时，先完成身份映射，再由课程访问服务生成成员关系与能力；同步流程采用本地预览、确认与状态记录，避免外部返回异常数据时直接覆盖内部课程。外部平台不可用时，已有本地课程与发布内容仍可继续服务。

## ***\*10.5 无缝嵌入方式\****

## ***\*10.6 内部 API 设计原则\****

# ***\*第十一章 部署架构与可靠性设计\****

## ***\*11.1 当前部署定位\****

SmartCarb 已在云服务器形成正式展示与功能验收环境，用于系统集成、比赛演示与授权样例验收。该环境不代表已获准处理真实生产学生数据，也不代表已达到互联网规模生产系统的全部运维要求。系统采用版本化发布部署：服务通过版本化 release 目录与 current 指针选择运行版本，发布目录保持干净可回溯。

## ***\*11.2 部署拓扑\****

***\*图 11-1 正式部署架构图\****

### ***\*11.2.1 主服务器：主服务集群\****

主服务器运行统一入口与主应用服务。Nginx 作为统一入口提供前端静态资源并将 API 请求转发至 FastAPI 后端；浏览器只访问统一入口，不直接连接数据库、PaddleOCR 或 Judge0。FastAPI 后端承载用户与课程访问、课程建设、解析任务编排、知识包、教学智能体、学习进度、练习、媒体与分析接口，由 systemd 管理，使用 Uvicorn 2 个 Worker 监听 127.0.0.1:8000。数据库使用 PostgreSQL 16.14 + pgvector 0.7.4，容器只绑定服务器回环地址；对象存储保存原始课件、DocumentIR、音频与媒体制品，业务表只保存对象标识；LanceDB 为课程知识包提供课程隔离的向量索引。PaddleOCR 以独立 HTTP 服务运行于主服务器，仅绑定 127.0.0.1:8090，作为扫描内容与复杂版面的增强来源。

### ***\*11.2.2 副服务器：代码沙箱服务\****

Judge0 独立部署于专用实验服务器，与主应用服务器物理隔离，二者通过内网受控接口通信。实验服务器内部包含 API Server、单个 Worker、PostgreSQL 与 Redis 四个容器，构成独立的运行时边界：Server 仅对内网后端开放认证接口，数据库与 Redis 不发布到公网，学生浏览器不能直接访问 Judge0。主应用只通过沙箱 Port 提交代码与读取结果，学生代码不进入 FastAPI 进程。这种主服务与沙箱分机部署的拓扑，使代码执行的风险面被限制在独立服务器内：即使沙箱被攻破，也不影响主应用数据与课程服务。

### ***\*11.2.3 模型与媒体能力\****

大语言模型、嵌入模型、TTS、ASR 与其他媒体 Provider 通过配置与 Provider 层接入，密钥只存在于服务器配置，不进入前端、仓库、日志或文档。系统以数据库中的 PlatformIntegrationConfig.enabled 作为 LLM/TTS/PPT/ASR 的管理员开关，关闭外部接入时不进行探测，消费端按能力返回显式 Demo 语义或失败关闭。

## ***\*11.3 课程权限安全\****

Course Access v1 是课程授权的唯一业务入口：基于课程成员、课程能力、平台权限分配解析访问上下文，不以全局角色或前端菜单状态作为授权依据。前端使用能力视图决定显示哪些操作，后端在每个端点再次执行权限校验；Agent 工具在执行前校验 course/role。课程检索需要知识查看与 Citation 读取能力，教师配置与版本管理需要更高权限；课程之间的数据查询始终包含 course_id 范围。

## ***\*11.4 发布一致性与回滚\****

课程、图谱、知识包与媒体分别具有版本与激活语义。系统通过发布关联确保学生使用的课程内容能够找到相应知识与媒体制品：知识包使用 Active Head 原子切换，图谱快照不可变，媒体发布不可变，课程回滚保留历史 release。这种设计将故障恢复从重新生成同样内容转化为切换到已知历史版本；回滚行为与操作者被记录，旧索引与旧制品不被立即删除。

## ***\*11.5 任务与故障语义\****

文档解析、知识包构建与媒体生成等长流程使用任务记录保存等待、运行、成功、失败、中断与部分成功状态。业务 API 区分任务已经提交、制品已经生成与版本已经激活，避免把异步接受请求写成最终成功。当前任务执行器为进程内 LocalTaskWorker：任务状态能够持久化，服务重启后可识别遗留运行任务并标记中断，但并非独立的分布式队列服务；多实例竞争、统一重试、死信队列与跨节点恢复属于后续工程化方向。

## ***\*11.6 可观测性与故障定位\****

系统在多个层面保留结构化状态：FastAPI 返回业务错误码，任务记录保存阶段与失败原因，Agent Trace 保存节点与工具结果，知识包保存索引错误，沙箱保存执行状态，课程发布保存质量门结果。检索链路记录知识包、向量索引、返回 Citation 与降级原因；推荐记录保存 retrieval trace 与 evidence refs。教师与开发人员可以从用户可见问题逐层定位到课程版本、Agent 节点、工具、外部 Provider 或任务。

## ***\*11.7 当前可靠性边界\****

系统已具备版本发布、回滚、结构化错误、依赖降级与核心任务状态；大规模并发、跨地域容灾、全链路分布式追踪与长期生产 SLO 验证仍在推进。部署环境中的运行健康证明服务进入实际拓扑，完整可靠性结论需结合压力测试与故障演练。

## ***\*12.6 三项核心机制实验设计\****

### ***\*12.6.1 机制一实验：课件解析与受控生成\****

数据集从不同课程选取包含文本型 PPT、图文混排 PPT、可复制 PDF、扫描 PDF 与 Word 讲义的材料，所有样本使用授权或合成数据，由教师标注标题层级、主要内容块、知识点与可接受证据位置。对比方案：基线 A 仅原生文本抽取；基线 B 仅 OCR；SmartCarb 为原生解析 + OCR 增强 + DocumentIR + 证据审核。当前 60 份混合格式课件的离线实验已给出初步结果，决赛阶段将扩展到百份样本规模，补充不同学科、不同格式的细分数据与教师审核人信度；除准确率外，还记录部分成功、人工复核与完全失败样本。

### ***\*12.6.2 机制二实验：检索演进与可追溯知识包\****

问题集为每门课程构建四类问题：精确术语问题、同义表达问题、需要知识关系的问题、材料更新后的版本问题，每个问题由教师标注支持答案的材料页、知识节点与允许引用。对比组：BM25；本地 BGE 向量检索；BM25 + BGE + RRF 混合检索；当前可追溯课程知识包（GraphSnapshot + 课程独立 LanceDB + 三类检索结果 RRF + Citation 闭包）。对比不把 CrossEncoder 作为当前系统组。四阶段离线实验初步结果见第五章表 5-1：S4 阶段 Recall 略有下降属于主动取舍，引用闭合率与隔离安全性以可量化的相关性下降为代价换取可追溯性。

### ***\*12.6.3 机制三实验：双源证据与学情反馈\****

实验重点验证系统是否避免无证据结论，而不是只比较仪表盘数值是否丰富。设计包含以下场景：只有观看无答题、频繁提问但答题正确、少量答题样本、连续错误、代码实验通过、教师预览混入课程等，教师为每个场景标注允许得出的结论。6 门课程、312 名学生、约 4200 条交互记录与 1800 条正式评分记录的离线对比实验初步结果显示：六维模型的核心设计目标是在证据不足时宁可 unknown 也不下结论，薄弱判定误报率从 31.7% 降至 4.6%。决赛阶段将扩展真实教学场景数据，补充推荐采纳率、学习成绩提升量与长期留存等教学效果指标。

## ***\*12.7 媒体资源与性能可靠性实验\****

媒体实验用于验证低服务器开销、低终端要求与较低带宽消耗的架构目标，需在同一课程内容下比较课程级分离制品与传统完整视频方案；未取得数据前正文只陈述设计原理，不使用降低 X% 等数字。性能与可靠性实验需要分别测试：课程读取、播放器初始化、问答与检索的 P50/P95/P99 响应时间；不同课程并发下的权限隔离与检索隔离；OCR、LLM、嵌入、对象存储与 Judge0 不可用时的错误语义；服务重启后运行中任务的中断标记与恢复操作；课程、知识包与媒体回滚的一致性；数据库迁移升级与回滚演练。当前任务测试需区分云端应用由两个 Uvicorn Worker 提供请求服务与业务任务仍由进程内 LocalTaskWorker 执行两种事实。

## ***\*12.8 实验结果呈现原则\****

最终文档中的每项数字必须同时注明数据集、版本、硬件、样本量、对比方案与测试日期。来自历史比赛材料的指标不能直接作为当前结果；来自 Mock、单元测试或合成数据的结果必须标明证据类型；未达到预期的结果同样保留并解释原因。



# ***\*第十三章 结论与商业化展望\****

## ***\*13.1 结论\****

SmartCarb 从泛雅平台资源丰富但难以被 AI 可靠利用这一现实问题出发，系统重建了教学材料、生成式人工智能、知识检索与学习分析之间的关系。让课程回应学习是贯穿始终的核心思想：课件像证据追踪一样被带来源地解析，知识图谱作为技术基座支撑认知路径推荐、查漏补缺与精确检索，教育智能体依据六维认知数据理解学生怎么学、学到什么程度、学习意愿如何，并据此促学、导学、督学与办学，让智能体跟着学生一起进步。

项目形成三项可落地的核心机制：以证据锚定与教师双门控构建可审核的智课生成机制，以知识图谱驱动的融合检索与课程隔离知识包实现可追溯的精确检索，以交互—测评双源分层与六维认知状态驱动可解释的学情反馈。智能体协作架构将三项核心机制统一为可运行的工程系统；AI 安全围栏贯穿生成、代码执行与数据边界，证明系统在提供智能能力的同时具备完整的安全约束。在认知机制上，系统不满足于可解释的规则投影，正通过证据驱动的细粒度知识追踪研究（RE-KT）向可学习的证据驱动学生模型演进，使学情判断随多源证据长期更新、可追溯到具体事件，并在证据不足或相互冲突时明确表达不确定性——这使让课程回应学习从一次交互的反馈，深化为对每个学生认知过程的持续理解。

目前系统已完成云端部署：主服务器运行主服务集群，独立实验服务器运行代码沙箱，十类核心场景通过端到端验证。系统价值不在于用 AI 替代教师生成一次课程，而在于建立一种可持续演进、来源可追溯的课程生产方式：教学材料能被机器理解但不失去来源，智能体可以协作但不能越过责任边界，学生学习能被分析但不被弱信号武断定义，AI 生成、知识引用与教学判断都能回到明确的课程、版本、证据与审核责任。

## ***\*13.2 商业化展望\****

SmartCarb 具备清晰的商业化承接方向，商业模式定位为平台订阅 + 机构授权 + 增值计费三轨并行的 B2B2C 结构：面向高校院系、职教集团与教育培训机构按机构授权采购（按开通课程数、并发学生数与智能体调用量分层计费，支持私有化部署与公有云 SaaS 托管）；面向教师个人提供会员订阅；TTS/数字人媒体、代码沙箱算力、语音转写额度与深度科研检索等重资源能力按用量计费。学生端基础学习能力对已授权课程免费开放，平台收入来自机构与教师侧而非学生侧。

商业化优先从高等教育与职业教育切入：高校院系与职教集团对课程数字化与 AI 教学增强有明确付费预算，且与泛雅既有部署环境天然衔接；成熟后再向 K12 培训机构、企业培训部门与出版机构扩展内容授权。平台运营以多租户管理后台支撑机构、教师、学生分层管理，内容审核与风控沿用课程访问控制的权限语义，数据合规遵循最小化采集与四域分离边界。上述计费、账号、市场与运营能力均处于规划阶段，当前已实现并验证的是课程建设、实时问答、学情分析等核心教学闭环。
