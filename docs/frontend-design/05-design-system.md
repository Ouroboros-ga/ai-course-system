# 前端视觉语言与设计系统

## 1. 设计命题

新视觉语言命名为 **“学术工作台 Academic Workspace”**。它服务于两类高频、长时任务：学生持续理解课程，教师持续生产和校验课程。视觉不依赖“AI 紫色渐变”制造智能感，而通过清楚的上下文、证据链、任务状态与可恢复操作建立可信感。

本轮不全局覆盖现有 `tokens.css`，避免造成已有页面行为和视觉大面积回归。新 Token 先作用于 `.fd-workspace` 原型作用域；通过验证后再按页面渐进迁移。

## 2. 核心原则

1. **内容是主角**：课件/讲解和编辑画布获得最大面积；AI 固定为协作轨而不是整页产品。
2. **证据比装饰重要**：引用、来源、页码和审核状态具有稳定位置。
3. **轨道而非卡片墙**：顶栏、目录/流程轨、主画布、检查轨用边界和层级组织；卡片只承载独立对象。
4. **状态必须可行动**：处理中、待检查、失败后均显示下一步。
5. **AI 与人工有界**：AI 生成用小型紫色语义标记；教师确认使用绿色并带确认信息，两者不混用。
6. **中文长时阅读优先**：紧凑但不拥挤，正文和讲解内容行高高于控制区。
7. **一次只支持一个学习意图**：学生主舞台以 `跟随讲解` / `课件研习` 双模式组织媒介；禁止把数字人、PPT、全文讲解和笔记同时平铺。

对比与使用规则：

- 主按钮仅使用 `primary`；同一视区最多一个主按钮。
- `progress` 只表示学习/任务推进，不同时承担链接色。
- 紫色仅用于 `AI 生成`、`AI 建议` 等来源标识，面积不超过当前视区强调色的约 10%。
- 红色只用于阻断失败或不可逆风险；低置信度用琥珀色而非红色。
- 禁止以颜色作为唯一状态信号，必须配合文本和图标。

## 4. 字体与排版 Token

```css
--fd-font-sans: "Noto Sans SC", "PingFang SC", "Microsoft YaHei", system-ui, sans-serif;
--fd-font-mono: "JetBrains Mono", "SFMono-Regular", Consolas, monospace;
--fd-text-11: 11px; /* 辅助元数据，非正文 */
--fd-text-12: 12px; /* 状态、时间 */
--fd-text-13: 13px; /* 密集控制区 */
--fd-text-14: 14px; /* 默认界面正文 */
--fd-text-16: 16px; /* 区域标题/学习正文最小值 */
--fd-text-18: 18px; /* 页面上下文标题 */
--fd-text-22: 22px; /* 课程/编辑主标题 */
--fd-text-28: 28px; /* 教学内容一级标题 */
```

- 控制区行高 1.45；学习讲解和引用行高 1.7；代码/公式区域允许横向滚动。
- 标题字重 600，正文 400，状态 500；不使用 800 以上超粗字重。
- 教学内容宽度大于 760px 时限制正文每行约 42–60 个汉字。

## 5. 空间、圆角、边框与阴影

| Token | 值 | 用途 |
|---|---:|---|
| `space-1/2/3/4/5/6/8` | 4/8/12/16/20/24/32px | 4px 基线，常用 8/12/16 |
| `radius-1/2/3` | 4/8/10px | 字段、面板、独立对象 |
| `radius-round` | 999px | 仅头像、圆形状态点，不做大量胶囊 |
| `border` | 1px solid `#dbe2ea` | 轨道和区域分隔 |
| `border-strong` | 1px solid `#bcc8d6` | 聚合面板/拖拽边界 |
| `shadow-float` | 0 12px 32px rgba(15,23,42,.14) | 仅抽屉、弹出层 |
| `shadow-focus` | 0 0 0 3px rgba(37,99,235,.18) | 焦点反馈 |

固定轨道不使用阴影；抽屉、菜单和拖拽悬浮项才使用浮层阴影。禁止多层阴影、发光边缘和玻璃拟态。

## 7. 层级、遮罩与动效

| 层级 | z-index | 组件 |
|---|---:|---|
| 基础内容 | 0 | 主画布 |
| 固定顶栏/停靠条 | 20 | 顶栏、长任务条 |
| 抽屉 | 40 | 目录、智能体、检查面板 |
| 遮罩 | 35 | 抽屉背景 |
| 菜单/提示 | 50 | menu、tooltip |
| 对话框 | 60 | 仅高风险确认 |
| Toast | 70 | 非阻断反馈 |

- 快速反馈 120ms，面板 180ms，抽屉 220ms；使用标准 ease-out，不使用弹跳动画。
- 回答流式状态只使用轻微光标/点动画；不让整段文字闪烁。
- `prefers-reduced-motion: reduce` 下关闭平滑移动和循环动画。

## 8. 状态系统

| 状态 | 视觉 | 文案/行为 |
|---|---|---|
| 默认 | 中性边框、正文色 | 可操作 |
| 悬停 | 浅蓝/浅灰背景 | 不改变布局 |
| 聚焦 | 2px 蓝色轮廓 + 3px 柔和外环 | 键盘始终可见 |
| 选中 | 浅蓝背景 + 左侧 3px 蓝线 | 配合 `aria-current`/`aria-selected` |
| 禁用 | 45% 文本、不透明浅底 | 保留原因提示，禁止假可点 |
| 加载 | 局部骨架/进度 | 不清空已有内容 |
| 成功 | 绿色图标+文本 | 表示已完成/已确认 |
| 警告 | 琥珀图标+文本 | 可继续但需注意 |
| 失败 | 红色边框局部使用 | 必须给重试/日志 |
| 待人工检查 | 琥珀 `待教师确认` | 不等同于生成完成 |
| AI 生成中 | 紫色小标 + 进度 | 可停止/离开 |
| AI 低置信度 | 琥珀提示 + 紫色来源标 | 提供核验与反馈 |

## 9. 图标规则

- 沿用 `lucide-vue-next`，默认 18px、线宽 1.75；密集列表 16px，主要操作 20px。
- 图标与文字并用；只有业界通用动作（播放、关闭、更多）可以仅图标，但必须有 `aria-label` 和 tooltip。
- 状态图标固定语义：圆点=未开始，旋转/进度环=处理中，时钟/眼睛=待检查，对勾=确认，三角=警告，圆形叉=失败。
- 不使用 emoji 充当产品图标，不使用机器人头像表达 AI。

## 10. 深色模式策略

现有项目已有 `dark.css`，但本轮原型优先完成浅色高可信工作区。深色模式不是简单反色，正式迁移前需补充：课件图像与代码对比、视频黑边、引用高亮、状态色对比、系统主题切换和截图回归。未完成这些验证前，原型不宣称完整支持深色模式。

## 11. 响应式断点

| 断点 | 页面策略 |
|---|---|
| `>= 1360px` | 完整三轨；学生 AI 与教师检查轨可见 |
| `1100–1359px` | 一侧辅助轨默认折叠；主工作区优先 |
| `768–1099px` | 双抽屉 + 单主舞台；控制分两行 |
| `< 768px` | 手机学习/审核模式；复杂映射提示使用桌面端 |

断点以空间是否足以完成任务为依据，不以设备名称硬编码。所有布局验证 1440×900、1280×720、1024×768、390×844，并确保无全局横向溢出。

## 13. 角色化页面模板

设计系统统一 Token，但不要求所有页面使用同一种卡片模板。

| 模板 | 适用页面 | 布局规则 |
|---|---|---|

| LearningWorkspace | 课程学习、补学、复习 | 100dvh 沉浸空间；顶部上下文 + 主舞台 + 可收起辅助轨 |

## 14. 页面级视觉语义

- 学习内容比控制区更安静：更大字号、更宽行高、较少边框；控制区使用紧凑 13–14px 排版。
- 教师治理页面使用“表格、树、分栏编辑器、检查队列”构成学术工具感，不用知识图谱大屏替代审核工作。
- 引用采用中性蓝灰定位标记；verified/partial/stale/no_evidence 同时使用文本、图标和说明，禁止只给分数。
- AI 候选使用小面积紫色来源标；教师确认使用绿色并显示 reviewer/time/version；两者不能共享同一个“已完成”样式。
- 学情结论不得以仪表盘百分比分数作为唯一内容。默认展示“观察到什么、依据是什么、建议做什么、不确定在哪里”。
- ui-ux-pro-max 检索得到的 Claymorphism、儿童化字体、大圆角和紫色暗色主题与高校专业工具定位冲突，明确不采用；仅采用其可访问性、语义 HTML、动态 ARIA、响应式和 reduced-motion 规则。
