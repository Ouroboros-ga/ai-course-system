# 开放问题与接口缺口

> 这些问题不会在本轮通过虚构接口解决。P0 表示阻断正式接入，P1 表示影响完整体验，P2 表示可后续验证。

## 1. 产品与角色

| 优先级 | 问题 | 当前证据 | 临时处理 | 建议责任方 |
|---|---|---|---|---|
| P0 | 教师能否编辑所有课程，还是仅自己创建的课程？ | 路由有角色门禁，课程级权限规则需继续确认 | 原型只显示拥有编辑权限的课程 | 产品+后端 |
| P0 | 学生未选课访问学习 URL 的正式行为是什么？ | 有 enroll/unenroll 与课程详情接口 | 页面规格定义无权限态，不猜重定向 | 产品+后端 |
| P1 | 管理员是否需要课程审核、Provider、队列、审计中心？ | 当前 AdminPanel 仅用户/角色；规划有零散提法 | 不建立万能后台 | 产品 |
| P1 | 教师生产步骤是否允许按课程类型裁剪？ | 不同素材链可能无需数字人/PPT | 原型显示完整候选链，正式需配置规则 | 产品+教学设计 |
| P2 | 课程助教、审核教师等协作角色是否存在？ | 当前 User 角色较粗 | 不设计协作权限 | 产品 |

## 6. 明确不开放的问题

以下不作为本阶段待实现项：BKT、HMM、LSTM 学习困难预测、GraphRAG、复杂多智能体竞争/协商/投票/反思。它们受阶段约束明确排除，不应通过 UI 占位制造“即将上线”的印象。

## 7. 建议的决策顺序

1. 先确认学生双模式、教师流程与角色权限。
2. 再冻结课程目录/播放/问答/前置返回的前端 adapter。
3. 冻结统一长任务和发布门禁契约。
4. DocumentIR/Evidence 通过独立验证后冻结 citation 契约。
5. 再决定笔记同步、版本/协作和管理员运维范围。
6. 最后讨论认知推荐和其他远期能力。
## 8. 本轮已冻结的产品决策

1. 教师端、学生端采用独立角色工作空间，不建立万能后台。
2. 学生学习使用“跟随讲解/课件研习”双模式；跟随讲解持续显示可折叠、可放大的当前PPT。
3. 课程知识与Evidence治理成为教师端第三个P0核心页面。
4. 先产品化现有V1 mapping，再按Evidence/图谱门禁逐层开放。
5. 新后端接口采用新增兼容方式；不删除或改变现有公开路径与字段语义。
6. Citation可以先于完整教育图谱上线；当前不实现GraphRAG。
7. 学情先展示事实和LearningEvidence；交互语义不直接修改MasteryState。
8. Recommendation和Memory必须经过Shadow/Canary、权限、删除和审计门禁。
9. Prototype路由必须从正式构建隔离。
10. 技术栈保持Vue 3、Vite、JavaScript、Pinia和现有UI体系，不迁移React/TypeScript或引入第二套组件库。

## 9. 新增接口与契约阻断项

| 优先级 | 阻断项 | 当前证据 | 关闭条件 |
|---|---|---|---|
| P0 | StudentMemory契约状态描述不一致 | registry为frozen-major，enums.py头部仍写draft | 契约Owner更新单一事实源并通过contract review |
| P0 | 学生Citation授权端点不存在 | internal Evidence API为admin/flag门禁 | 课程级授权、脱敏、真实页面/Evidence和权限测试 |
| P0 | Evidence G4可能只返回空响应/页面不可渲染 | internal-evidence-api说明G5/G6才是真实数据 | 真实DocumentIR/Evidence Canary门禁通过 |
| P0 | 课程发布阻断项没有统一真实规则 | 现有publish接口与检查清单分离 | publish-check契约、权限、版本和回滚测试 |
| P0 | 审核队列/快照产品接口缺失 | edu-graph领域契约存在，教师API缺失 | candidate/review/snapshot/pointer接口与持久化 |
| P1 | 统一任务只有领域状态，无完整列表接口 | TaskResult consumed，任务来源分散 | /tasks聚合、权限、重试关联和分页 |
| P1 | stale依赖没有统一计算服务 | 当前只可推导 | 后端影响服务输出稳定StaleDependency |
| P1 | 笔记持久化和冲突规则未定 | 原型仅本地草稿 | note CRUD、revision和导出/删除政策 |
| P1 | 教师问题/RAG质量聚合接口缺失 | 现有TeacherHistory主要是progress | analytics/questions和analytics/rag-quality |
| P1 | Memory同意、导出、删除和审计产品接口缺失 | 领域repository/enums存在 | API、权限、隐私评审和删除测试 |

## 10. 必须由产品/教学负责人确认

- 课程owner、editor、reviewer、publisher的最终权限矩阵。
- 未选课学生深链访问时返回403、404还是选课引导。
- 不同课程是否可裁剪PPT、TTS和数字人步骤。
- 发布检查中哪些是硬阻断，哪些可以带警告发布。
- 教师是否可查看单学生Memory全文；默认建议为不可查看。
- 学生退课、删除问答、删除Memory和删除全部数据的保留范围。
- 推荐和学情在比赛演示中可使用的真实数据范围及脱敏规则。
