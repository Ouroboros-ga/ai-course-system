## 2. 阶段 1：备份（写入操作，授权后执行）

```bash
# 数据库备份（以实际基线为准；PostgreSQL 示例）
pg_dump -Fc <dbname> -f /root/backups/xh202620_pre_$(date +%F_%H%M).dump
# 前端目录备份
cp -a <html根> <html根>.bak_$(date +%F_%H%M)
# 后端代码备份（若 git 管理则打 tag；否则 tar）
tar -czf /root/backups/backend_$(date +%F_%H%M).tar.gz -C <repo父目录> <repo名>
# .env 备份（含敏感信息，备份文件权限 600，不进入任何文档/提交物）
cp -a <repo>/.env /root/backups/env_$(date +%F_%H%M).bak && chmod 600 /root/backups/env_*.bak
```

## 4. 阶段 3：数据库迁移

```bash

uv run alembic current            # 确认 0066 (head)
# 说明：本轮改造不含 schema 变更；数据库字段审计（35 个死字段）未执行删列，
```

## 9. 阶段 8：回滚方案

| 故障 | 回滚动作 |
|---|---|
| 后端起不来 | `git checkout <原分支>` + `uv sync --frozen` + 重启；或恢复 tar 备份 |
| 迁移出错 | `alembic downgrade <原版本>`（0066 之前无不可逆变更；0070 前如有需先确认） |
| 前端异常 | 恢复 `<html根>.bak_*`；或重放旧 dist |
| 数据异常 | `pg_restore` 阶段 1 的 dump |
| .env 被改坏 | 恢复 `env_*.bak`（权限 600） |

## 10. 风险与注意（AGENTS.md 硬边界）

4. **GraphRAG 保持关闭**（数据外发授权未批）；Judge0 保持现状灰度。

6. **回滚优先**：每阶段完成后记录状态（版本号/迁移号/asset hash），便于快速回退。
7. **压测纪律**：4C8G 级资源，Docling/OCR/GraphRAG 类任务串行执行，避免 OOM。
