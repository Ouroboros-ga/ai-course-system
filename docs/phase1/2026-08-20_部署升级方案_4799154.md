## 12. 2026-08-31 线上 LLM 401 故障记录与 env 修复（已执行，用户授权部署）

**现象**：`/api/v1/teaching-agent/respond` 返回 503 `TEACHING_LLM_UNAVAILABLE`；
后端日志出现 `POST https://api.deepseek.com/chat/completions → 401`。

**根因（三层叠加）**：
1. `shared/env/backend.env` 中存在一行**带前导空格的旧密钥**
   `␣LLM_API_KEY=sk-6a5e***`（systemd EnvironmentFile 解析后 `settings.LLM_API_KEY`
   被旧密钥污染）；
2. `bootstrap.py` 在**模块导入期**构造 TeachingAgent/CodingAgent LLM（早于
   startup 的 `restore_from_db` 回填 settings），直接读 `LLM_API_*`，把旧密钥
   **冻结**进 Agent；
3. `read_env_config("llm")` 只读 `LLM_*`，DeepSeek 垂类配置
   （`DEEPSEEK_API_KEY` 等）已就绪时误判为"未配置"。

**修复**（代码 e4d6a54 + 796d4e1，均已推送 Gitee 并部署）：
- `platform_provider_manager.read_env_config("llm")` 按 DeepSeek 专属变量优先取值；
  `get_runtime_health("llm")` 改为检查进程内实际 client 配置；
- `bootstrap.py` 新增 `_effective_llm_settings()`：按与运行时 client
   （`llm_client.py` 的 `DeepSeekClient`）相同的优先级解析
  （deepseek/spark 专属变量优先），替换全部 5 处直接读取；
- 服务器 `backend.env`：旧行替换为与 `DEEPSEEK_API_KEY` 一致的新密钥
  （就地取值，密钥不出现在命令/输出中）；`LLM_API_BASE` 对齐
  `https://api.deepseek.com/v1`；`LLM_MODEL_NAME` 对齐 `deepseek-chat`。
  修改前自动备份 `backend.env.bak.*`。

**验证**（2026-08-31，发布 796d4e1d）：
- 发布脚本健康检查通过（openapi + 首页）；
- 启动日志：`TeachingAgent registry injected; AgentPlatform registered EDU agent`
  （两 worker 均注入）；
- 端到端：登录 → 课程列表（200）→ `POST /teaching-agent/respond` 返回 200
  与真实教学回答（含 `discipline_references` 学科知识库引用）；
- 会话域：`GET /teaching-agent/conversations/{course_id}` 返回 200，
  问答消息已持久化。

**注意**：`deepseek-chat` 与 `deepseek-v4-flash` 为同一模型（API 返回的
`model` 字段显示 alias 映射），两者均可作为 model 名。DB
`platform_integration_configs.llm` 行已确认与新密钥一致（enabled/healthy）。

## 13. 2026-08-31 重解析后语料快照外键失败修复与课程 14 重建（已执行）

**现象**：课程 14 触发材料重解析（`dpr_a933415`，发布 3260f0c 后执行）成功
生成新 DocumentIR `dirv_216fad`（噪声过滤生效：证据锚点 649 → 492），但语料
快照仍是旧的 `ccs_6fa7caea`（16:14 基于旧 IR），目录/讲稿未重建。

**根因**：`document_parse.py` 的 reparse 端点创建任务时 `input_payload`
未携带 `initiated_by`；`handlers.py` 的 document_parse handler 完成后以
`owner_user_id=0` 调用 `create_ready_snapshot`，`course_corpus_snapshots.created_by`
是 `users.id` 外键，插入违反约束后异常被外层 try 吞掉（仅日志
"Could not update material parse projection"），课程停留在旧语料。

**修复**（fb61ad4，已推送并部署 releases/fb61ad47）：
- reparse 端点 `input_payload` 补充 `initiated_by`；
- handler 以 `parse_run.initiated_by` 兜底（parse run 是发起人权威记录），
  快照与构建任务共用同一教师 id。

**课程 14 重建操作**（教师 id=1，旧草稿 0 锁定 0 人工编辑，满足
initial-draft/rebuild 的安全前提）：
1. 服务器脚本调用 `create_ready_snapshot`（owner=1）→ 新快照
   `ccs_daea233`（含新 IR `dirv_216fad`）；
2. `POST /api/v1/course-build/course/14/initial-draft/rebuild`
   （`force_initial=True`）→ 构建任务 `cdbt_f8b1b1`（generation_mode=initial）；
3. 构建约 1 分钟 SUCCEEDED。

**验证结果**：

  多文件工程等真实教学内容，0 页眉噪声；
