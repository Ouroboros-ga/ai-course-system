# 第一阶段实施方案：CS 学科知识库构建

> **状态：规划方案（2026-08-25）**
> 本文为 CodeNexus 阶段第一阶段的实施规划，基于已核实的代码事实编写；任何"内容已填充""导入已验证"的表述必须以实际导入日志、检索结果为准，规划本身不构成实现证据。

---

## 1. 目标与范围

### 1.1 目标

建立**计算机学科（`SubjectType.COMPUTER`）结构化知识库**，为以下三条下游链路提供可检索、可追溯、可导出的知识底座：

1. **TeachingAgent / CodingEduAgent 学科问答与诊断**：概念讲解、算法分析、错误模式解释的知识来源；
2. **垂类模型微调（阶段二）**：SFT 训练数据的结构化来源（从知识点自动生成 Q&A 对）；
3. **GraphRAG 学科图谱（可选）**：知识节点与教育关系的种子数据（当前 `GRAPHRAG_ENABLED=false`，需授权后启用）。

### 1.2 范围分层

| 优先级 | 覆盖内容 | 规模目标 | 说明 |
|---|---|---|---|
| **P0（本阶段必做）** | 数据结构、算法设计、复杂度理论 | 知识点 ≥350、关系 ≥300 | 与产品二首期学科范围一致（Python/C++、数据结构、排序查找、BFS/DFS/最短路、复杂度） |
| P1（视进度） | 操作系统、计算机网络、数据库 | 知识点 ≥150 | 知识库 JSON 骨架先建，内容可后补 |
| P2（暂缓） | 编译原理、AI/ML、大模型 | 知识点 ≥80 | 只建骨架与标题，不展开内容 |

### 1.3 非目标

- 本阶段不做模型微调（阶段二）、不做代码诊断错误模式库（阶段二）、不做算法可视化（阶段三）；
- 本阶段不改造 `KnowledgePoint` 表结构；`point_type` 沿用现有枚举（concept/formula/theorem/example/exercise/summary/extension），算法/数据结构维度通过 `tags` 表达；
- 本阶段不启用 GraphRAG 构图（数据外发授权未获批前维持 `GRAPHRAG_ENABLED=false`），仅保证知识数据可被现有检索链路消费。

| 树形结构 | 二叉树、BST、AVL、红黑树、B 树、B+ 树、二叉堆、Trie、线段树、树状数组、并查集、哈夫曼树、伸展树 | ~45 |

| 操作与复杂度 | 每种结构的插入/删除/查找/遍历复杂度（并入各知识点内容，不单列） | — |

#### 3.1.2 算法（P0，目标 ≥200 条）

| 主题 | 必含知识点 | 条数 |
|---|---|---|
| 排序 | 冒泡、选择、插入、希尔、归并、快排、堆排、计数、基数、桶、外部排序、排序稳定性、比较排序下界 | ~15 |
| 查找 | 线性、二分、三分、插值、哈希查找、分块查找 | ~12 |
| 图算法 | BFS、DFS、Dijkstra、Bellman-Ford、Floyd、Prim、Kruskal、拓扑排序、强连通分量、最近公共祖先、网络流、二分图匹配 | ~30 |
| 动态规划 | LIS、LCS、0-1 背包、完全背包、多重背包、区间 DP、树形 DP、状态机 DP、数位 DP、记忆化搜索 | ~35 |
| 贪心 | 活动选择、区间调度、哈夫曼编码、最小生成树贪心、跳跃游戏 | ~15 |
| 分治 | 归并排序分治、快排分治、最近点对、大整数乘法、主定理 | ~10 |
| 回溯 | N 皇后、全排列、子集、组合、数独、图着色、排列树/子集树 | ~12 |
| 字符串 | KMP、Rabin-Karp、Trie、AC 自动机、后缀数组、Manacher、编辑距离 | ~15 |
| 复杂度理论 | 大 O 记号、时间复杂度、空间复杂度、摊还分析、递归复杂度、P/NP/NPC 概述 | ~20 |
| 算法设计范式 | 分治/贪心/DP/回溯/分支限界 各自适用条件与对比 | ~10 |

#### 3.1.3 关系（P0，目标 ≥300 条）

仅限四种 `relation_type`：

| 关系类型 | 语义 | 示例 | 占比目标 |
|---|---|---|---|
| `prerequisite` | 前置知识 | 二叉树 → BST；递归 → 分治；图结构 → Dijkstra | ~45% |
| `related` | 相关并列 | 快排 ↔ 归并；栈 ↔ 递归 | ~25% |
| `extends` | 扩展演进 | BST → AVL → 红黑树 → B 树；数组 → 动态数组 | ~20% |
| `applies_to` | 应用落地 | 哈希表 → LRU 缓存；栈 → 括号匹配；堆 → 优先队列 | ~10% |

### 3.2 内容质量规范

每条知识点必须满足：

1. **必填字段**：`title`、`content`、`point_type`、`difficulty`、`importance`、`keywords`、`tags`；
2. **content 结构**（Markdown，300-800 字）：定义/本质 → 关键性质或公式 → 典型场景 → 常见误区（可选）；禁止只写一句话；
3. **可追溯**：`source`（教材名+章节，如"《算法导论》第 6 章 堆排序"）与 `source_url`（如 MIT OCW 链接）尽量填写；
4. **复杂度信息**：算法类知识点在 content 内用表格给出时间/空间复杂度，并在 `related_formulas` 中结构化记录（如 `{"name": "时间复杂度", "formula": "O(n log n)"}`）；
5. **示例**：排序/搜索/图算法等 ≥60% 的知识点应带 `examples`（含代码片段或输入输出样例）；
6. **tags 双维度**：课程维度（`数据结构`/`算法`/`复杂度`）+ 主题维度（`排序`/`图`/`动态规划`），逗号分隔，用于后续检索过滤与微调数据分组。

### 3.3 内容生产方式

| 方式 | 适用对象 | 说明 |
|---|---|---|
| 人工编写（团队 CS 背景） | 核心 100 条（数据结构/排序/图算法/DP 主干） | 质量最高，作为骨架与校验基准 |
| LLM 辅助生成 + 人工复核 | 其余 250 条 | 给定模板与教材目录生成，人工逐条复核，禁止未经复核入库 |
| 批量导入 | 全部 | 见 §4 导入方案 |

> 任何 LLM 生成内容必须经人工复核并补充 `source`，否则视为未完成。不允许"生成即入库"。

## 4. 数据格式与 schema 设计

### 4.1 `knowledge_data/data_structures.json` 与 `algorithms.json`

两者 schema 一致（每条为 `KnowledgePoint` 字段的合法子集）：

```json
[
  {
    "point_id": "KP_CS_ALG_001",
    "title": "快速排序",
    "content": "## 定义\n快速排序采用分治策略：选择一个基准（pivot），将序列划分为小于/大于基准两部分，递归排序。\n\n## 关键性质\n- 平均时间复杂度 O(n log n)，最坏 O(n^2)（基准选择不当）\n- 空间复杂度 O(log n)（递归栈）\n- 不稳定排序\n\n## 典型场景\n大规模数据原地排序；C 标准库 qsort、Java Arrays.sort 的底层实现。\n\n## 常见误区\n最坏情况出现在已有序序列 + 固定取首元素为基准时。",
    "point_type": "concept",
    "difficulty": 3,
    "importance": 5,
    "keywords": "快速排序,分治,基准,不稳定排序",
    "tags": "算法,排序,分治",
    "examples": [
      {
        "input": "[3,1,4,1,5,9,2,6]",
        "output": "[1,1,2,3,4,5,6,9]",
        "description": "一趟划分演示（基准=3）"
      }
    ],
    "related_formulas": [
      { "name": "平均时间复杂度", "formula": "O(n log n)" },
      { "name": "最坏时间复杂度", "formula": "O(n^2)" },
      { "name": "空间复杂度", "formula": "O(log n)" }
    ],
    "prerequisites": "KP_CS_ALG_002",
    "source": "《算法导论》第 7 章 快速排序",
    "source_url": "https://ocw.mit.edu/courses/6-006-introduction-to-algorithms/",
    "difficulty_level": 3
  }
]
```

> 注意：JSON 中的 `difficulty_level` 等自定义字段**不允许**出现——`batch_create_knowledge_points` 会因未知关键字抛异常。schema 校验脚本（§4.4）会在导入前拦截。

### 4.2 `knowledge_data/relations.json`

```json
[
  {
    "source_point_id": "KP_CS_ALG_001",
    "target_point_id": "KP_CS_ALG_002",
    "relation_type": "prerequisite",
    "weight": 1.0,
    "description": "理解分治思想是掌握快排的前提"
  }
]
```

约束：
- `source_point_id` / `target_point_id` 必须能解析到已导入的 `KnowledgePoint.point_id`；
- `relation_type` 仅限 `prerequisite/related/extends/applies_to`；
- 不允许自环（source == target）；
- 双向关系（如 related）需显式写两条或约定只写一条（本方案约定：`related` 只写一条，检索端按无向处理）。

### 4.3 `point_id` 命名规范

```
KP_CS_{模块}_{三位序号}
模块: DS（数据结构）/ ALG（算法）/ OS / NET / DB / ML / TH（复杂度理论）
示例: KP_CS_DS_001（数组）、KP_CS_ALG_012（二分查找）、KP_CS_TH_003（大O记号）
```

`prerequisites` 字段引用 `point_id`（字符串），导入脚本需在**两阶段导入**后做引用完整性校验（见 §5.2）。

### 4.4 schema 校验脚本（新增）

新增 `backend/app/tools/validate_cs_knowledge.py`（纯校验，不入库），执行：
1. 字段白名单校验（仅允许 `create_knowledge_point` 签名字段）；
2. `point_type` / `difficulty(1-5)` / `importance(1-5)` 取值校验；
3. `point_id` 唯一性与命名规范校验；
4. `relations.json` 引用完整性校验（target/source 必须存在、无自环、类型合法）；
5. 输出统计：各 tags 分布、各 `point_type` 分布、缺 `source` 的条目清单。

> 校验不通过 → 阻断导入。这是"内容质量"的硬门，不允许带病入库。

## 5. 导入与集成方案

### 5.1 新增导入脚本 `backend/app/tools/import_cs_knowledge.py`

复用现有服务，不重复造轮子：

```
流程:
  1. 解析 CLI: --data-dir(默认 knowledge_data/) --kb-name(默认"计算机学科知识库") --dry-run
  2. 定位或创建 KnowledgeBase(subject=COMPUTER, level=COLLEGE, is_public=True)
  3. 读取 data_structures.json + algorithms.json → KnowledgeImportService.import_from_json()
     （dry-run 模式下只打印将导入条数，不写库）
  4. 按 point_id 建立 映射表: point_id -> KnowledgePoint.id
  5. 读取 relations.json → 对每条调用 KnowledgeRelationService.create_relation()
  6. 引用完整性复核: 未被任何关系引用的孤立节点、缺少前置但内容声明前置的条目，输出告警
  7. 汇总输出: 导入知识点数/成功/失败、关系数、耗时
```

幂等策略：
- `point_id` 唯一约束天然防重；重复导入同一 `point_id` 会失败并计入 `fail_count`；
- 提供 `--update` 开关：对已存在 `point_id` 执行更新（先按 `point_id` 查再改字段），默认关闭；
- `KnowledgeImportLog` 自动记录每次导入，作为审计证据。

### 5.2 向量嵌入（可选，接入检索增强）

`KnowledgePoint.embedding` 字段已存在。接入路径：
- 复用 `backend/app/platform/knowledge/embedding.py`（本地 BGE）；
- 在导入脚本末尾（或独立脚本 `embed_cs_knowledge.py`）对全量知识点生成向量并写回 `embedding` 字段；
- 嵌入服务不可用时降级：跳过嵌入，不阻塞结构化导入；检索链路已有降级语义。

## 7. 风险与回退

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| 内容工作量超预期 | 高 | 中 | 裁剪 P1/P2 范围；LLM 辅助生成 + 双人复核加速 |
| LLM 生成内容质量参差 | 中 | 高 | 校验脚本硬门 + 抽样人工复核；`source` 缺失即拦截 |
| 未知字段导致导入失败 | 低 | 中 | 校验脚本先行拦截；`batch_create` 异常计入 `fail_count` 可定位 |
| GraphRAG 授权未获批 | 中 | 低 | 本阶段不依赖 GraphRAG；知识数据先入库，授权后一键构图 |
| 嵌入算力/服务不可用 | 低 | 低 | 嵌入降级跳过，检索走关键词链路 |

回退原则：所有变更仅涉及新增 JSON 数据与新增工具脚本，不修改现有表结构与主链路；导入失败不影响既有功能，`--dry-run` 可完整预演；`KnowledgeImportLog` 保证导入可审计、可重放。
