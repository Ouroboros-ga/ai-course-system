## 0. 2026-08-31 XH 分支改进状态（本地实现，未部署）

本轮已完成证据获取链的四道一致性门禁，不改变 canonical 原文的可审计性：

1. `block_noise.py` 提供原因编码分类，新增 Roman 页码、私用区图标残片、

## 1. 审计结论（一句话版）

**证据生成的"闸门"设计整体是严谨的，但漏斗在真实数据上几乎空转**：
全库 24,934 条候选证据中只有 386 条（1.5%）被教师确认为正式证据；6 门
课里 4 门的确认数为 0，学生可读 Citation 因此也只存在于 2 门课。同时
审计快照中的旧部署只让新解析受益，历史课程与图谱候选仍带噪声；§0 的 XH
本地改进已补齐新投影、图谱、列表与确认门，但远端存量数据尚未治理或部署。

## 3. 各链路效果评估（实测）

### 3.1 解析投影链路——噪声过滤方向正确，覆盖面 \~17%

设计上确定性、可审计、无 LLM（`block_noise.py:1-12` 的模块注释即此
意图），过滤发生在投影层（`projector.py:135-137`），模板块保留在
canonical 存储中。这一层是健康的。

实测覆盖情况：

| 课程      | blocks | spans  | 残留 furniture | 残留 cover | 短无标点  | 重复组(≥3)          | 解析日期         |
| ------- | ------ | ------ | ------------ | -------- | ----- | ---------------- | ------------ |
| 1 算法    | 21,620 | 21,620 | 1,149        | 22       | 9,920 | 713 组（x287 单组最大） | 08-14        |
| 2 汽车工程  | 407    | 293    | 9            | 0        | 263   | 19 组             | 08-10        |
| 5 控制数学  | 1,805  | 743    | 92           | 0        | 638   | 55 组             | 08-15        |
| 7 控制原理  | 1,805  | 743    | 92           | 0        | 638   | 55 组             | 08-18        |
| 12 数据结构 | 802    | 393    | 6            | 0        | 313   | 12 组             | 08-30        |
| 14 cpp  | 1,298  | 1,141  | 1            | 49       | 547   | 41 组             | 08-31（唯一新链路） |

问题清单：

1. **只有课程 14 走了带噪声过滤的新解析**（`dirv_216fad` 的
   `quality.noise_filtered_blocks=157`）。其余 5 门全部在 08-30 之前
   解析，`noise_filtered_blocks` 字段缺失（旧 IR 无此标记），候选证据
   带着页眉/封面/重复噪声留在库里。
2. **规则盲区**：roman 数字页码（"IV / V / VI"，c1 有 25 个）、Wingdings
   私有区字符（"\uf0fc …"，c14 图谱节点标题大量出现）、书封营销行
   （"┃算法训练营：海量图解+竞赛刷题" x287 重复）都不在
   `_FURNITURE_LINE` / `_INSTITUTION_NAME_TAIL` 匹配范围
   （`block_noise.py:31-42, 28-30`）。
3. **读路径过滤只覆盖一个端点**：`course_build_editor.py` 的
   prep-agent evidence 读取有 `detect_noise_block_ids` 过滤，但
   `list_evidence_spans`（`document_parse_service.py:782-799`）与
   图谱候选均无过滤，教师审核列表仍全量暴露噪声。
4. **span 粒度 = 块粒度**：每个非空文本块一条 EvidenceSpan，无语义
   聚合。c1 一本书 21,620 条候选，任何人工漏斗都无法消化。
5. c14 残留的 49 条 cover 行与 41 组重复**全部来自旧 IR**
   （`dirv_8efe` 的 649 条 span，见 §3.4），新 IR（492 条）只漏了 1
   条 furniture。

### 3.2 教师确认链路——漏斗空转（最严重问题）

实测确认漏斗（候选 → 正式证据 → 学生 Citation）：

| 课程 | 候选     | 确认  | 转化率   | 学生 Citation |
| -- | ------ | --- | ----- | ----------- |
| 1  | 21,620 | 0   | 0%    | 0           |
| 2  | 293    | 147 | 50.2% | 147         |
| 5  | 743    | 237 | 31.9% | 238         |
| 7  | 743    | 2   | 0.3%  | 2           |
| 12 | 393    | 0   | 0%    | 0           |
| 14 | 1,141  | 0   | 0%    | 0           |
| 合计 | 24,934 | 386 | 1.5%  | 387         |

设计上状态机完整（candidate→confirmed/rejected/stale/orphaned，
`confirm_evidence_span` 的幂等与状态守卫在 `document_parse_service.py:587-593`）。
问题不在闸门，在**输入量**：逐条 confirm（一次一个 span\_id），无批量
操作、无优先级排序、无预分级。教师面对 1.1 万条候选，唯一理性选择就是
不审。结果是全链路最末端（学生看到的引用）在 4 门课里为空。

对照：初始备课链路里其实**已经存在一个句级 LLM 证据审查器**
（`course_initial_prep_service.py:517 _review_evidence`，Stage 0，
可删近重复/无意义/乱码句，失败回退保留原文），但它只在备课构建时
运行一次，产物不回写候选库，也不给审核漏斗分级。能力是现成的，
没有接到漏斗上。

### 3.3 图谱候选链路——无噪声门 + 节点不退役

实测：c14 有 **1,305 个 candidate 知识节点（0 发布）**，前 30 个标题
里混着"C++ 程序设计 第五章 C++ 程序结构"（页眉，出现 3 次）、
"\uf0fc 使程序得以运行的框架组织…"（项目符号行）、"本章内容"、
"1. 作用域与可见性"（目录条目，与真实章节标题重复）。

根因（`document_parse_pipeline.py:603-675`）：

1. `_build_graph_candidates` 直接读全量 `DocumentBlock`（**含噪声块**
   ——canonical 存储按设计保留模板块），没有任何 `filter_noise_blocks`；
2. 每个 title 型块一个概念节点：目录页每个条目、每页小标题、PPT
   textbox 都成为独立概念，与目录树重复；
3. 批次有 superseded 机制（`document_parse_service.py:853-870`，实测
   18 个批次 12 个已 superseded），但**节点不随批次退役**——c14 的
   1,305 节点 = 新旧两代 run 的节点全部存活。

全库 review 行 3,547 条，基本无人处理（c2/c5 的 published 节点来自
早期人工演示）。

### 3.4 重解析退役——spans 与节点跨代累积

c14 两个 run 的实测：

```
dpr_6c735c90e6 (08-31 08:14)  → dirv_8efe…  649 spans  reparse_applied=False
dpr_a933415dfc (08-31 08:51)  → dirv_216fa…  492 spans  reparse_applied=False
```

两次 run 的 `affected_evidence_count=0`、`reparse_applied=False`，
即 `_mark_old_evidence_stale`（`document_parse_service.py:251-362`）
从未执行——旧 IR 的 649 条 candidate span（含全部页眉噪声）与新的
492 条并存，`list_evidence_spans` 又不按 IR 版本过滤
（`document_parse_service.py:791-797` 只按 course/status/node 过滤）。
教师看到的是新旧两代混排的 1,141 条候选，其中约 12% 是已被新解析
判定为噪声的文本。

### 3.5 学习分析证据链路——闸门最严，数据为零

全库仅 2 条（c5：quiz\_accuracy×1、quiz\_pattern×1）。链路本身的边界
是全项目最严谨的：仅服务端评分写入（`cognitive_service.py:580-583`
未评判/非 scored 角色直接拒绝）、节点白名单（`experiment_service.py:1132-1140`）、
幂等键、教师判分 confidence=1.0 / 自动判分 0.8。**这是"量"的问题而非
"质"的问题**：demo 中没有学生真实做 Quiz/实验，链路无输入。

### 3.6 其余链路（健康，仅数据量说明）

* Agent 审计：752 events / 71 tool invocations，脱敏白名单
  （`_sanitize_event/_sanitize_trace`）按规范运行；

* WebResearch：0 条（默认禁用 fail-closed，符合预期）；

* ResearchAgent：`is_supplementary=True` 边界在 `research_agent.py:164/267`
  等 3 处硬编码，`evidence_synthesis` 工具标记 `research_preview`；

* 知识库：0 bases / 0 points / 0 relations——代码活跃但从未灌数据。

## 6. 外部研究（业界与学界做法）

* **三层降噪 + 坐标级过滤**：生产级 RAG 预处理把"坐标级（按 bbox 剔除
  固定位置页眉/页脚）— 规则级（正则匹配页码/版权）— 格式归一"作为
  标准流水线 [$TRAE\_REF](https://blog.csdn.net/weixin_42917352/article/details/163314626)。
  我们已有 `bbox` 字段（`projector.py:150` 持久化）但未用于噪声判定。

* **引用可信度**：ALCE 开创的 citation 评估给出"正确引用率"指标
  [$TRAE\_REF](https://arxiv.org/pdf/2305.14627)；G-Cite（生成时内联）
  与 P-Cite（事后校验）的系统对比表明两者在覆盖与正确性上存在权衡
  [$TRAE\_REF](https://arxiv.org/html/2509.21557v2/)；RECLAIM 的交错
  "引用-断言"生成把正确归因率提到 90.7%、引用长度缩到 ALCE 的 22%
  [$TRAE\_REF](https://www.alphaxiv.org/overview/2407.01796v2)；CiteGuard
  用检索增强校验补齐生成时漏掉的引用 [$TRAE\_REF](https://arxiv.org/pdf/2510.17853v1)。

* **语义去重**：MinHash/LSH 粗筛 + 小模型 embedding 精筛的两级去重是
  通用模式 [$TRAE\_REF](https://github.com/informatique-cdc/SCORE/blob/main/docs/INGESTION_AND_ANALYSIS.md)；
  我们目前只有精确 hash 去重。

* **人工漏斗效率**：LLM 初筛 + 人工只复核低置信行，可用 6-7% 的人力
  达到全人工标注质量（RLTHF）[$TRAE\_REF](https://jatinbansal.com/ai-engineering/human-feedback-loops/)；
  循证医学文献筛选的 GREP-Agent 同样是人校准 + LLM 分级队列的形态
  [$TRAE\_REF](https://onlinelibrary.wiley.com/doi/full/10.1002/cesm.70042)。

## 7. 改进方案（按优先级；完成度以各项标注为准）

### P0 直接修 Demo 体验（1-2 天量级）

**A. 重解析退役旧候选**

状态：**部分实施**。默认列表 active IR 边界、显式历史入口和 STALE 确认拒绝已完成；
采用动作继续保持教师显式 `/apply`，不采用“handler 成功即自动替换”的旧提案。

* **不采用原“handler 成功即自动退役”提案**：该做法会绕过教师采用安全阀。
  现行路径由 `/reparse/{run_id}/apply` 显式调用 `_mark_old_evidence_stale`，
  将 prev run 的 candidate/confirmed span 按策略退役；

* **已完成**：`list_evidence_spans` 默认仅返回 active snapshot 对应 IR 的 span；
  `include_history=true` 或显式 `run_id` 给教师查看历史/预览；

* 图谱侧：批次 superseded 时把该批次 bridge 出的未发布 candidate
  节点置 `rejected`（或删除），与批次语义对齐。

**B. 噪声过滤补齐存量与规则**

状态：**规则、投影、图谱与审核/确认门已实施；远端存量治理脚本未实施**。

* **已完成**：规则补充 roman 数字页码、私有区字符（`\uf000-\uf8ff`）开头的短行、
  书封营销行（纯符号+冒号结构，如"┃…"）；判定继续走
  `block_noise.py`，保持确定性可测试；

* **未完成**：存量治理脚本——对 5 门旧课程跑一次"投影重放"，读取 canonical
  DocumentBlock，用现 `detect_noise_block_ids` 计算 noise 集合，把命中
  的 candidate span 标记 `REJECTED`（`reject_reason="boilerplate"`）。
  不需要重解析、不需要 LLM，幂等可重入；跑前后各出统计。

* **已完成**：`_build_graph_candidates` 输入块先过 `filter_noise_blocks`，旧批次
  的教师读取投影同步剔除碎片节点与相关关系；
  **未完成**：目录型候选的进一步语义去重。

**C. 批量确认交互**

* confirm 端点支持 `span_ids: list[str]`（服务端循环复用现有单条逻辑
  与守卫）；前端证据页加"按节点全选/批量确认"。

### P1 审核漏斗效率（核心价值，3-5 天量级）

**D. LLM 预审分级队列**（对齐 RLTHF / GREP-Agent 形态）

## 8. 布局解析改进（已实施，2026-08-31）

针对"最新解析方法仍有语义不通截断与无意义英文公式残片"的实测问题，
在 PDF 解析层落地了**框感知布局分析**。

### 8.1 根因（修复前 pdf-plumber 提取行为）

1. **按视觉行提取**：`_resolve_lines` 逐行产出块，换行句被切成行级
   片段（u1 教材正文 p90 长度仅 23 字符）；
2. **无区域聚类**：同一文本框内的行与相邻框的行按 top 混排，
   双栏代码、旁注与正文互相穿插；
3. **绝对字号判 heading**（`avg_size >= 16`）：PPT 转码页字号普遍
   偏大，course14 曾出现 647/649 块全为 heading 的误判；
4. **行内 gap 阈值单一**（0.8×字号）："第一章 绪 论"这类字空格标题
   （gap≈1.0×字号）被拆成"第一章绪"+"论"两段——这是标题截断的
   直接根因；
5. **数学字形无治理**：Unicode 数学斜体字形（𝑘/𝑄/𝜀，U+1D400 区）
   的图注标签与分式碎片（"="、"0 ="、"= 12.29"）成为独立候选块，
   即"无意义英文公式残片"。

### 8.2 实现（`providers/pdf_layout.py`，约 460 行）

| 机制        | 做法                                                                                         |
| --------- | ------------------------------------------------------------------------------------------ |
| 文本框重建     | 词→紧致行→gap 分段→Union-Find 聚类（垂直邻接 + 边缘对齐 + 字体/字号/类别兼容），一个框=一个阅读单元                            |
| 相对标题判定    | `body_mode = 页内众数字号`，标题提升需 ≥1.05×body\_mode 且位于页首 25% 区域                                   |
| 代码区聚合     | 代码/注释类行聚为单块并保留换行；窄符号（`}`）跨距合并；短中文尾巴（≤10 字、CJK≥0.6）粘回代码行                                    |
| 段落合并      | 连续行按行距 pitch 与句终标点合并为完整段落                                                                  |
| CJK 字空格容差 | CJK-CJK 词间 gap 阈值放宽至 1.8×字号（真栏间隔仍按 0.8×字号切分），修复字空格标题拆分                                     |
| 公式残片吸收    | 孤立公式块按水平投影重叠 + 垂直距离并入前段或后置代码块                                                              |
| 符号残片过滤    | 无 CJK 且有效符号 ≤1（如 𝑘、"="）或纯数值操作符（"= 12.29"）的微块直接丢弃；≥2 个有效符号的真公式（𝑄 = 𝑄 + 𝑊(𝑄)、COP=Q/W）保留 |
| 家具过滤      | 页首短框、页码行、封面署名行（大学/学院+人名尾）                                                                  |

集成路径：`pdf_plumber._extract_page` → `extract_page_blocks(page)` →
`map_pdf_plumber_output_to_ir` 消费 `block_type`（heading/paragraph/code）
→ `projector.py` 把 code 映射为 DocumentBlock `block_type=code`、
`semantic_role=code_example`（完整教学示例，非截断正文）。
同步删除了 `document_parse_pipeline.py` 中无调用方的
`_map_block_type/_infer_semantic_role` 死代码（语义与 projector 冲突）。

### 8.3 验证（本地真实课程 PDF，行级旧行为 vs 新布局）

| 指标       | course3 PPT转PDF 旧→新 | u1 教材PDF 旧→新   |
| -------- | ------------------- | -------------- |
| 块数       | 413 → 297           | 1176 → 711     |
| 文本长度中位   | 8 → 9               | 10 → 14        |
| 文本长度 p90 | 19 → 28             | 23 → 33        |
| 数学残片微块   | 12 → 2              | 157 → 13（-92%） |
| 字空格标题    | '第一章 绪 论'（空格串）      | 无此问题           |

抽样确认：course3 p3 标题完整输出 '第一章绪论'（heading）；u1 p20/21
目录页 7 条目逐条独立且完整；u1 '𝑄 = 𝑄 + 𝑊(𝑄)'、'COP=Q/W' 等真
公式保留为独立块，'𝑘'、'= 12.29' 等残片被过滤。

测试：`tests/document_intelligence/providers/test_pdf_layout.py` 15 用例
（双栏隔离、代码完整性、段落合并、标题提升、残片过滤、字空格标题）
全绿；document\_intelligence 全套 240 通过；`test_step3_combo_parse.py`
16 通过。

### 8.4 覆盖范围与限制

* 仅影响 **PDF 解析链路**（含 PPT 经 LibreOffice 转码的 PDF）；
  PPTX 原生链路（`native_pptx.py`）不受影响；

* 服务器已解析课程的旧 IR 不变，**需重新解析才生效**（P0-A 的
  退役机制仍是前置依赖，避免新旧混排）；

* 分式结构的完整重建（分子/分母垂直堆叠拼合）未做：分式各部分
  仍可能成为独立公式块，但作为"真公式"保留而非混入正文；

* 双栏识别依赖 gap 与对齐特征，极端排版（栏间距 <1.8×字号的
  窄栏 CJK 文本）理论上有误合并风险，现有测试与真实样本未复现。
