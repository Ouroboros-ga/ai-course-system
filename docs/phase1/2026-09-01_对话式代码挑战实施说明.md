# 对话式代码挑战实施说明

> 状态：2026-09-01 本地实现并完成定向自动化与浏览器组件级验收；尚未部署，
> 尚未在真实课程账号上执行“TeachingAgent → 真实 Judge0 → 数据库证据”的完整冒烟。
> 本文覆盖旧《CodingEduAgent 与 EduAgent 集成说明》中面向学生产品入口、代码会话恢复和
> 证据终结的描述；旧文仅用于独立实验 API 的兼容链路追溯。

## 1. 产品结论

学生在课程对话里只看到 TeachingAgent。正常回答先完成，随后可原地出现代码挑战卡；
AI 补题以异步准备卡更新，不阻塞回答。进入代码空间后只有一个主操作“运行并获得反馈”，
每次运行都由 Judge0 产生服务器所有的原始 `ExperimentRun`，但同一 guided session 只在
关闭时聚合为一个 `CodingEvidenceEpisode`，并只向 offer 固定发布身份对应的单一知识节点写一条正式证据。

教师不逐题审批。课程必须同时具备 `experiment`、`coding_sandbox` 能力和
`experiment.run` 权限，且课程级 `coding_challenge` 工具策略启用。该工具是 medium 风险、
默认启用、`supports_confirmation=false`；持久题库的 `question_generation` 审批链保持独立。

## 2. 真实调用链

```text
POST /teaching-agent/respond
  → TeachingAgent 完成课程回答
  → CodingChallengeDecisionPolicy 输出结构化时机建议
  → CodingChallengeService 执行权限/发布身份/频率/活动会话/Judge0 缓存健康门
  → 已验证课程实验立即 ready；否则 coding_challenge_prepare 异步任务
  → 学生 start，固定 experiment/version 并创建 guided_practice attempt + open episode
  → 每次 runs 创建 ExperimentRun + experiment_run task
  → Judge0 终态 → 确定性诊断 + TeachingAgent 安全反馈
  → accepted、返回课程或 45 分钟不活动关闭 episode
  → 服务器聚合最佳有效评分并写入一条低噪声 LearningEvidenceRecord
```

决策模型只建议 `code_practice_fit`、`pedagogical_timing`、目标概念、难度和原因码。
服务端拒绝非代码概念、无活动发布/课程节点、另有活动挑战、沙箱不可用或策略关闭的提议。
同一浏览器会话的 30 分钟学习窗口最多创建 3 个原始 offer（换题不重复计数），同概念主动建议
跨会话冷却 10 分钟；学生明确要求练习可跳过冷却，但不能绕过窗口上限与其他安全门。
`why_now` 由原因码模板生成，不下掌握度结论。

## 3. AI 补题质量门

`CodingChallengeGenerationService` 复用 `StructuredLLMPort` 和严格 Pydantic schema。
任务负载只有 course/student/offer 标识；完整会话、源码、Prompt、原始模型输出和参考解都不
进入任务记录。结构输出允许一次 schema repair；质量门失败后允许重新生成一次。

草稿依次校验：非空与字段约束、公开/隐藏测试去重、语言和资源限制、参考解跑过全部
Judge0 测试、起始代码不得误通过。两次均失败或 Judge0 不可用时 offer 进入 `failed`，不创建
占位题、不写证据。参考解仅存在于任务局部内存和当次 Judge0 请求中；数据库只保存
prompt version/hash、模型和结构化校验原因码。AI 题是学生私有、24 小时有效，不进入公共题库。

## 4. API 与数据模型

学生门面统一位于 `/api/v1/teaching-agent/coding-challenges`：

- `GET /active`、`GET /offers/{offer_id}`：恢复当前会话或轮询准备状态；
- `POST /offers/{offer_id}/start|dismiss|replace`：开始、稍后再说或限额换题；
- `POST /sessions/{session_id}/runs`：要求 `Idempotency-Key`，返回 `202` 的 run/task 标识；
- `GET /runs/{run_id}`：只返回受限结果、诊断、教学反馈和 episode 摘要；
- `POST /runs/{run_id}/hint`：按需揭示可选提示，并由服务端记录提示使用；
- `POST /sessions/{session_id}/close`：聚合并幂等关闭 episode。

迁移 `0067`（`0066 → 0067`）新增 `coding_challenge_offers`、
`coding_evidence_episodes`，并扩展 ExperimentDefinition/Version/Attempt/Run 与
ConversationMessage。状态使用字符串，不新增 PostgreSQL enum。`ExperimentVersion` 固定题目，
`ExperimentAttempt.interaction_mode=guided_practice` 跨多次运行保持 `IN_PROGRESS`；
`ExperimentRun.normalized_source_hash` 消除换行和尾随空格噪声。

公开响应不含内部 experiment/version ID、参考解、隐藏用例 I/O、完整沙箱日志或源码。
刷新恢复时服务端返回固定题面、公开样例、starter code、最近受限运行结果和 return anchor；
浏览器仅用 sessionStorage 保存当前 session 的编辑草稿，不把 run_id 桥接到下一次对话。

## 5. 证据与认知边界

基础设施失败可审计但不计有效运行；相同规范化源码与相同错误不会增加有效修订数。
关闭 episode 时：通过计 `1.0`，否则取最佳有效服务器测试得分；保留最终 outcome、有效修订数、
提示依赖和运行总数的结构化摘要。提示文本默认不下发，学生按需展开后才由服务端把
`hint_used` 写入 run，关闭时再聚合到 episode；正式 `event_refs` 只引用 episode/attempt，详细运行链按
attempt 反查，不把 run 字段碎片复制进证据。

证据写入必须使用 offer 固定的 `source_release_id + outline_node_id`，并核对该 outline 在固定
release 中映射的唯一知识节点也属于题目配置；身份冲突或节点不一致时 fail-closed，不把多节点题的
同一次表现复制到其他节点。AI 题和教师题都沿用代码证据权重 `1.5`；认知投影至少需要 `3.0` 有效评分权重，
所以一个 episode 不能单独得出“已掌握”。诊断文本只用于教学反馈，不直接修改认知。

## 6. TeachingAgent 内部代码能力与兼容层

新代码位于 `platform/agents/edu/coding/`，主 TeachingAgent 只接收白名单诊断和 episode 摘要；
源码只在运行记录的课程/学生/run 范围内由内部反馈能力临时读取。Conversation 的
`coding_feedback` 消息只保存安全教学文本与 run 引用。LLM 调试捕获只允许 PrepAgent 明确保存
原始请求/响应；代码挑战始终只记录 hash、模型、耗时和结构校验结果。

`platform/agents/coding/`、`AgentType.CODING` 和旧 `/experiments` 说明接口暂保留为兼容层。
Swagger 不再把它作为学生可见的独立 CodingAgent 产品；旧解释响应以
`teaching-agent-coding-compat` 标识委托关系。正式实验、题库审批和历史 finalize 证据仍可读。
学生私有 AI 挑战不进入旧实验目录/详情/版本接口；guided attempt 也拒绝从旧正式运行端点提交，
避免私有题泄露或旁路破坏多次运行 episode。

## 7. 前端体验

`learnMachine` 增加 `CODING` 分支，进入时暂停媒体并保留 return anchor，退出回到精确位置。
`CodingChallengeCard` 支持 preparing/ready/failed/dismissed，异步状态在原消息卡片更新；换题会
用新 offer 替换旧卡片，刷新会恢复准备卡或活动 workspace。

`CodingChallengeStage` 使用现有 CodeMirror 编辑器和 `SfxButton`。桌面为题目、编辑器、结果
三栏，移动端为自然高度纵向布局；只有“运行并获得反馈”一个主按钮，Ctrl/Cmd+Enter 走同一路径。
反馈固定为结果概览、已做对的部分、当前问题、下一步建议、按需展开的可选提示；未展开的提示
不进入 Conversation 或 episode，不回显源码或隐藏测试。

## 8. 开源复用审计

实施前复核了计划中指定的两个固定提交。OpenTutor `60e68569` 实际是网站 weekly/营销内容变更，
futurecoder `def491c2` 实际是依赖版本更新；它们不包含计划所描述的质量门或结果归一化实现。
因此本实现没有复制或实质改写这两个提交的代码，也没有据此新增虚假的第三方代码声明。
质量门与反馈分区为项目内独立实现。继续复用仓库已有 CodeMirror 和既有 Judge0 API 客户端，
未新增编辑器、沙箱或 GPL/AGPL 依赖。
