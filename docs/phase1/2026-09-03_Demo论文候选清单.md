# Demo 论文候选清单（Nexus Quick Reproduction 演示论文选择）

> **状态**：现行决策文档（2026-09-03 建立）
> **用途**：为 Nexus AI 的 Quick Reproduction 能力选定演示论文（比赛现场演示 +
> 材料 06 效果验证的复现案例）
> **依据**：《CodeNexus 技术决策补丁 v1.1》§15/§27 论文选择 P0 Gate 筛选标准
> **核实方法**：仓库 License/stars 经 GitHub API 核实（2026-09-03）；nanoGPT CPU
> 可行性经官方 README 核实（<https://github.com/karpathy/nanoGPT>）

## 1. 筛选标准

1. 官方或高信誉开源实现（作者本人/官方组织仓库优先）；
2. License 明确允许演示与复现用途（MIT / Apache-2.0 优先，规避 CC-BY-NC 等限制灰区）；
3. Repro Worker 无 GPU——CPU 可在演示时长内完成训练或推理；
4. 复现步骤清晰，README 命令可直接执行，无需大幅改代码；
5. 产物直观可展示（生成的文本/图像/指标，适合现场演示与录屏）；
6. AI/ML/CS 主题、评委认知度高，与"学科垂类大模型"赛题叙事契合（LLM/NLP 优先）；
7. 资源占用可控（内存 < 2GB，磁盘 < 5GB）；
8. 仓库经典稳定（fork 断裂风险低）。

## 3. 推荐决策

**主选：#1 nanoGPT（GPT-2 论文的最小复现）**

理由：

1. **叙事最契合**：赛题是"学科垂类大模型与创新应用开发"，复现一篇 LLM 奠基论文
   直接呼应"大模型"主线；复现过程本身（克隆 → 分词 → 训练 → 生成）恰好是
   Nexus"拆解论文 → 给出复现计划 → Repro Worker 执行 → 产出证据"完整链路的
   最佳展示脚本；
2. **训练闭环完整**：不只是推理，包含完整训练循环（loss 下降曲线可截图作为
   产物），比纯推理类复现更能展示 Repro Worker 的真实执行能力；
3. **CPU 三分钟训练**：README 官方提供 `--device=cpu` 缩小配置命令（4 层/4 头/
   128 维/2000 iters，实测口径约 3 分钟），产物为生成的莎士比亚风文本，直观易懂；
4. **MIT License** 无演示风险；62.7k stars，评委认知度极高。

**备选：#2 CLIP**——若现场更重视视觉直观（图文匹配演示），CLIP 零样本推理
可作为第二案例；与 nanoGPT 不冲突，可一并作为 Nexus 论文研究模式的展示广度。

**其余 4 项作为候选池**保留，用于演示 Nexus 论文研究模式的多论文对比能力。

## 4. 复现演示脚本（nanoGPT 主线，供 Nexus Quick Reproduction 编排参考）

```bash
git clone https://github.com/karpathy/nanoGPT && cd nanoGPT
pip install torch numpy transformers datasets tiktoken wandb tqdm
python data/shakespeare_char/prepare.py
python train.py config/train_shakespeare_char.py \
  --device=cpu --compile=False --eval_iters=20 --log_interval=1 \
  --block_size=64 --batch_size=12 --n_layer=4 --n_head=4 --n_embd=128 \
  --max_iters=2000 --lr_decay_iters=2000 --dropout=0.0
python sample.py --out_dir=out-shakespeare-char --device=cpu
```

预期产物：训练 loss 曲线（约 1.88 收敛）+ 生成文本样本。
环境要求：Python 3.9+，约 2GB 磁盘。
