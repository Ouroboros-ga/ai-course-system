一、评审结论（便捷性 × 功能相关性）

先量后说：P0 两条均有代码与截图双重证据。总评——诚实性设计（能力三态、待接入 popover、fail-closed 状态条）是这个页面的骨架优势，全部保留；问题集中在「空间分配失衡」与「状态语言不统一」两件事上。

P0-1

右栏桌面端常驻 340px 且不可收起

证据：NexusPage.vue:1527 右栏 v-if="!isTablet && !isMobileOrSmall"，无折叠状态；tokens.css --nexus-detail-width: 340px。截图里主对话区被压到约 590px。纯问答轮次（占大多数）右栏没有任何新增信息，340px 是纯房租。

修法：默认收起为 48px 图标轨（上下文 / 轨迹 / 信息源，带计数徽标），点击以 320px overlay 抽屉展开——主区宽度不再被挤占；展开状态按 page-design §3.4 持久化到设备。
P0-2

左栏底部三个语义层混排

证据：截图左栏底部依次是「本机资料（聊天记录 1 个会话 / 产物 1 个会话）」「真实数据源」「收起侧栏」。系统状态（数据源）、内容库（资料）、视图控制（收起）三类信息平铺，且「产物」并无真实数据源（SSE 无结构化产物事件），裸计数易被误读。

修法：底部收敛为设备状态区两行卡片——「数据源：真实｜切换」+「本机资料：聊天记录 · 产物｜展开」。去掉裸计数，点开才列清单；收起侧栏并入栏头。
P1-3

评价按钮无数据通道仍渲染

证据：NexusPage.vue:1455-1474，点赞/点踩 onClick 是 feedbackSoon（title 标注「评价服务未接入」）。4 个操作图标里 2 个是死的——tooltip 诚实救不了按钮本体的存在感。

修法：砍掉或收进「更多」，操作条只留复制 / 重新生成；评价通道接通后随 nexusCapabilities 恢复。
P1-4

课程绑定双入口、右栏重心错位

证据：chips 行「选择课程」（:1181）与右栏「未绑定课程 → 更换课程」（:1567-1574）双入口；右栏未绑定时最大的一块视觉面积给了零信息的状态卡。

修法：右栏课程卡紧凑化为一行（图标 + 课程名 + 更换）；「未绑定」的引导动作前置到启动页引导条（见 Board C），chips 行保持唯一常驻入口。
P1-5

空态有示例、无模式感知

证据：空态已有 quick cards（:1254-1274），但通用 / Research 两种模式的差异（工具白名单）只藏在 Mode 下拉里；新用户第一眼无法理解「两种模式差别是什么」。

修法：空态升级为启动页：两张模式预设卡（含工具白名单差异 pills，选中即切模式）+ 示例问题 + 课程绑定引导条。
P1-6 撤回

会话操作不可发现 —— 原判断错误

代码事实：.nx-session-more { display: none } + .nx-session-item:hover .nx-session-more { display: block } 早就在，hover 操作组（置顶 / ⋯ → 重命名·删除）本来就有。

真问题：只靠 :hover，键盘 Tab 用户进不去。修法：补 :focus-within（已落地）。
教训：这条来自对截图的推断，不是实测。
P2-7 撤回

Composer 下方两个浮动圆钮 —— 不存在

排查结论：main.js 只挂载 App；App.vue 仅 <router-view />；NexusPage.vue 内无任何 fixed/absolute 浮动圆钮；全仓唯一全局 position: fixed 是 PrimaryNav.vue:454 的移动端导航抽屉。代码中不存在这两个按钮。

错误成因：本会话模型图片输入被过滤，我实际看不到图，却按"图里有两个圆钮"写了结论。以后凡是"我在截图里看到 X"，先确认能不能真的看到图。
P2-8

能力状态文案三套词混用

证据：右栏列表同时出现「已连通 / 数据就绪 · 未注入回答 / 未建立」三种表述；chips 行又用「待接入」。同一个事实（wired）有两种说法，普通用户无法建立映射。

修法：统一三态命名——已生效 / 已连接 · 未生效 / 未建立（见 Board B 文案规范），单一来源仍为 nexusCapabilities.js。
P2-9

失败轮次的过程折叠行无告警色

证据：截图「执行过程 · 1 次工具调用 · 6.8s」呈中性灰，但其后答案明说 arXiv 检索不可用（ARXIV_UNAVAILABLE）。过程真实发生，展示是对的；但失败结果用完成观感呈现，状态色缺位。

修法：turn 内含失败工具事件时，折叠行图标与边框转 amber 告警色，一行摘要补「1 次失败」。

attention是什么
执行过程 · 1 次工具调用 · 6.8s

在传统 Standard Attention 中，计算 Softmax 矩阵需要将 N×N 的注意力得分矩阵显式写入 HBM（高带宽显存），其显存复杂度为 O(N²)。FlashAttention（Dao et al., 2022）通过 Tiling（分块计算）与 Recomputation（前向重计算）避免了向 HBM 写入完整的注意力矩阵，仅在 GPU SRAM（高速片上缓存）中完成增量计算 Softmax，将显存复杂度降至 O(N)。

# 标准注意力 vs FlashAttention 计算链差异 # Standard: Q, K → S = Q·K^T (HBM) ⇒ P = softmax(S) (HBM) ⇒ O = P·V (HBM) # Flash:   Q, K → 分块载入 SRAM → 局部 Softmax 归一化 → 增量输出 O
核心文献

Attention Is All You Need — Vaswani et al., 2017 · arXiv:1706.03762

FlashAttention: Fast and Memory-Efficient Exact Attention with IO-Awareness — Dao et al., 2022 · arXiv:2205.14135

六、值得保住的设计（改版时别拆）

能力三态单一真相源

nexusCapabilities.js 的 ready / wired / unwired 语义与 integration 契约字段是整个页面的骨架。本次改版只动展示层映射，数据结构零改动——后端接线时把 state 改成 ready 即生效的机制必须完整保留。

「N 项待接入」popover

把未接入能力收进一个聚合入口而非常驻占位，既诚实又不污染首屏。这是对「绿色 ✓ 打在没接线的 Chip 上比不放更糟」这条原则的正确实现。

Mode 即工具白名单

Mode 下拉里直接列出每个模式的可用工具，让模式切换可验证。Board C 的模式卡是同一机制的启动页前置，不是第二套机制。

过程折叠摘要 + 右栏轨迹

消息流一行摘要、完整时间线在详情面板的分工，同时满足了「工具状态必须可见」与「答案可读性」。图标轨化后此分工不变，只是右栏从挤占改为按需。

fail-closed 演示数据状态条

「演示数据：由浏览器本地模拟……」常驻状态条 + 真实模式健康错误的互斥呈现，是结果诚实性的门面，改版中位置不动。

只读引擎标识

Composer 的「DeepSeek-V3 · Nexus Agent 编排」把价值主张讲在编排层而非模型层。保留；模型切换器继续不做，除非运行时提供 /models 驱动。
