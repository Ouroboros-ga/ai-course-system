# NX-H1 + NX-R1 夜间执行任务书

> 面向编码智能体：按下列任务顺序自主实施，每项自行验证后进入下一项；不在任务间等待用户确认。遵守仓库 AGENTS.md；不要求安装额外执行技能，不因技能不可用而停工。本任务书授权本地开发，不授权提交、推送、部署或安装依赖。

**Goal：**交付“可见、可恢复的计划 + 基于已上传论文全文的证据研究闭环”，保护现有附件、审批、Console 和 Cancel 链。

**Architecture：**复用已安装 TodoListMiddleware 和 LangGraph checkpoint；Todo 作为计划状态，工具/实验事件作为执行事实。Research 使用现有搜索、附件解析和 Artifact，经薄编排完成证据定位与综合；本批不另造通用 Scientific RAG 框架。

**Tech Stack：**现有 Nexus 独立 Python 环境、Deep Agents/LangGraph、FastAPI、Vue、现有 Backend 附件与对象存储接口；不增加依赖与常驻服务。

**计划基线：**2026-09-07 本地 HEAD `342d6825`；已包含 `5f989495` F1–F6 修复及 `c89ee487` 前端 TDZ 修复。执行时重新记录实际 HEAD 和工作区，不能假定部署 SHA 与之相同。本任务书未重新验收上述修复。

## 1. 今晚交付边界

必交付：

1. H1：Research 多步骤任务的 Todo 卡、修改、状态快照、刷新恢复；简单 General 不强制建计划。
2. R1a：用户上传 1–3 篇 PDF，提出研究问题 → 读取全文块 → 证据清单 → 方法比较/综合 → 带可核对定位的 Markdown Artifact。只有一篇时不伪造跨论文比较。
3. 搜索候选与全文证据明确区分：只有摘要时标记 abstract_only；全文不可得时提示上传，不冒充读过全文。
4. 边界回归、前端构建、本地验收记录、文档真实状态同步。

这是 NX-R1 的限定薄链，不将完整 Paper Research 全部标成 CURRENT。自动全文获取、PaperQA 集成、系统性大规模综述保留为后续缺口。PaperQA/同类组件的最终选型不由本次“无新增依赖”约束永久否决。

本批不做：Subagent/文件 Workspace、任意 shell/仓库执行、SandboxProvider/A-B、Worker 重启对账、完整服务端 Session 重构、新向量库、全站 UI 重构、DOCX/PPTX 输出、新模型网关。

## 2. 自主执行与停止规则

- 不在 T0–T6 之间询问“是否继续”；完成后自动进入下一项。
- 先检查现有实现，已完成且验证通过的部分直接复用，不能重写以凑交付。
- 普通命名、组件拆分和本批接口细节由智能体按既有模式决定，并写入同一回执。
- 依赖不足：不得安装/升级，先复用现有能力；确实不能完成的子项记录 BLOCKED，继续其他独立任务。不得删减目标后改称完成。
- 无真实 LLM/登录/测试 PG：用明确标注的合成输入和 fake transport 完成实现及本地验证，在线验收列为待办；不得寻找真实密钥或冒用生产库。
- 同一环境阻塞最多进行两种有依据的排查方案；之后保留证据转做独立任务，不反复重跑同一失败命令。
- 模型/网络不可用不能触发假证据、空实现或返回假成功。
- 遇到必须跨越硬边界的操作，不执行该操作；记录需要用户处理的具体动作，继续不依赖它的工作。
- 全部必交付项完成或仅剩外部阻塞时结束并交接；不要空转、额外扩建、靠 sleep 等用户醒来。
- 本地修复本批引入的问题已授权；不提交、推送、部署、修改服务器、安装依赖、重建环境、清理 stash 或用户文件。

计划产品快照最低语义：

```json
{"session_id":"synthetic-session","plan_id":"p1","revision":2,
 "items":[{"id":"t1","content":"读取论文证据","status":"in_progress"}],
 "source":"agent_plan"}
```

middleware 原生 Todo 状态保持 pending/in_progress/completed；稳定 id、plan_id、revision 属产品投影。暂停、取消、失败属于运行状态，不能硬塞进上游不支持的 Todo 枚举。计划修改可替换项，revision 单调；不同用户/会话绝不共享快照。计划 completed 是模型的计划标记，不能作为工具成功或实验 PASS 证据。

## 7. T3：R1a 全文证据薄链

范围：1–3 篇已上传、ready、属于当前用户且绑定当前会话的 PDF。现有八格式通用附件仍保持原能力；本研究薄链先验收 PDF。

- [ ] 编写 Research-only 证据工具，消费 `question` 与 `attachment_ids`，身份只来自请求作用域。必须经现有 Backend 附件内容接口校验 owner/session/删除/过期；禁止直读磁盘或从模型参数信任 user_id。
- [ ] 证据对象至少包含 evidence_id、attachment_id、source_title、locator、excerpt、coverage（fulltext_excerpt/abstract_only）、is_supplementary。内容来自实际返回块；source_title 是用户上传文件标签时明确标注，不能伪装已验证书目信息。
- [ ] 模型只能引用服务端已建立的 evidence_id；服务端解析 ID 并渲染来源/locator，不能接受模型编造页码和引文。页面映射不可用时明确缺失，不编造 page 1。
- [ ] 单次默认最多 3 篇、12 条证据、每条 1200 字符、总计 12000 字符；截断明确记录 truncated/coverage。不得宣称已完整读完超出实际处理范围的全文。
- [ ] 搜索候选复用现有 arXiv/Web 工具，元数据与已读证据分开；本批不新增任意 URL 下载器、不扩展 SSRF 面、不自动抓付费全文。候选没有全文时请求用户上传，继续综合已有证据。
- [ ] 薄工具负责读取、筛选、规范化和校验；综合分析使用现有 Agent 模型循环，不新增隐藏收费 LLM 服务或自研检索框架。
- [ ] 完成问题→证据→比较→综合→Citation→Markdown Artifact 的实际调用链；Artifact 沿用既有存储、归属、下载和生命周期。
- [ ] 引用校验失败时明确返回可修复错误；最多 1 次修正尝试，仍失败则输出证据缺口，不写带伪引用的“成功报告”。引用定位存在不等于论点正确，报告保留推断、限制与冲突。
- [ ] 无全文、单篇、证据冲突、解析失败、越权、删除/过期、配额触发均有明确结果，不用空报告当成功。

报告固定内容：研究问题、实际资料与覆盖范围、证据列表、方法比较（适用时）、综合结论、限制/待补证据、引用。不得写入 Course KB、Course Graph、LearningEvidence；不自动执行复现。
