v3NexusLab · 实验工作台（主舞台形态）

v2 的视觉语言一笔不动；这一版动的是布局与定位 —— 实验台从右侧窄卡升级为主舞台， 会话里的实验卡降为一行「引用条」。依据 = 真实论文复现工作流调研 + 你的反馈。

2026-09-07 · 家良拍板「工作台不能挤在右栏」 · 规划文档已同步 v1.2 · NX-E2/E3 已上线（stage/日志/取消有真数据，v2 板上的 TODO 标注作废）
v2 的问题 · 布局层
  • 主次颠倒 —— 「复现论文的工作台」里，对话占了 60%，实验台挤在右栏 340–400px
  • 信息被截断 —— COMMAND / EXIT / DURATION 三列在窄栏里放不下，只剩半截
  • 塞不下真实日志 —— 2000 字符日志尾 + 步骤展开 + 指标判定，窄栏一条都展不开
  • 实验卡在会话流里占一大块 —— 刷日志时把对话顶得看不见
v3 · 方案
  • 实验台 = 主舞台（≥55% 宽），日志/命令/指标完整可见；对话收为左列
  • 会话流里的实验卡降为 44px 一行「引用条」（状态点 + 名称 + 时长 + 打开工作台）
  • 工作台内按真实复现循环分区：阶段条 / 步骤列 / 日志（最大面积）/ 指标 / 参数 / 产物
  • 窄屏（<1100px）主区二选一 tab：对话 | 实验台，互不挤压

调研 · 真实论文复现工作流 → 设计映射

参照对象：W&B run 页 / MLflow run 对比 / Hydra+TensorBoard 复现实践 / ML 复现清单（McGill）
F1
复现是多 run 循环 「配置 → 跑 → 盯日志/loss → 改 → 再跑 → 对比」。工作台服务整个循环，不是单次进度条。
F2
参数在 run 之间改 真实实践是「复制上一 run 的 config → 改 → 新 run」，从不在 run 中途改。UI 不做运行中改参的假交互。
F3
按面积盯：日志最大 实时日志 > loss 走向 > 终态指标判定。日志区必须是工作台里最大的元素。
F4
run 带着自己的参数 seed / repo / license / 配置要常驻 run 头——两周后还要能对上「这个结果是谁跑出来的」。
F5
失败也是记录 exit=-9（取消）、超时、失败的 run 如实保留，对比和排查都要看。不洗成「已结束」。
来源：W&B Projects/Workspace 文档（runs 侧栏 + config/metrics/logs/artifacts 面板）· MLflow Run Detail（Parameters/Metrics/Artifacts 分区 + 多 run 并排对比）· McGill《ML Reproducibility 12 practices》（config 管理 / checkpoint / logging / seed）· Hydra 多 run 目录实践（每 run 一份完整 resolved config）

规格 · 布局断点 / 滚动 / 契约约束

布局与断点
  • ≥1100px：会话轨 264px 固定 + 对话列 24–32% + 工作台 ≥55%（min-width 620px）
  • <1100px：主区二选一 tab（对话 | 实验台）；图标轨入口带运行徽标（小圆点，非闪烁）
  • 引用条 44px 一行：状态点（运行中=spinner）/ 名称 / 当前步骤·时长 / 判定摘要（终态）/ 打开
  • 工作台 = 头部 46px + 身份行 + 阶段条 + 主体（步骤列 212px | 内容 tab 区）+ 底部状态条 32px
  • 滚动：工作台内日志区是唯一滚动子区（design.md §5.1 三层滚动模型）
交互与契约
  • 日志「跟随中」开关：暂停时右上角累计「+N 行」，点击回底恢复跟随（tail -f 心智模型）
  • 失败 run 打开工作台 → 自动定位失败步骤并展开其 log_tail
  • 「基于此 run 调整」= 生成新提案走既有审批硬门，绝不就地改运行中的作业（F2）
  • 组件落点：ExperimentWorkspace.vue（主舞台）+ ReproReferenceBar.vue（引用条）；既有就地展开 Console 改造为引用条
  • 契约：一律 SfxButton，禁原生 <button>（apiContracts.test.cjs:816/:1003）
  • 待后端注释前缀统一为 // GAP-1/2/3/4（v2 的 TODO(NX-E2/E3) 作废）
