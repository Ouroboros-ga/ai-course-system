**Goal:** 将服务器现有五类 CS 语料构建为可增量、可回退的段落检索库，让学科页面、TeachingAgent 与 Nexus AI 检索相同版本的原文、保留出处，并完成真实部署与使用验收。

**Tech Stack:** 复用 Python 3.12、SQLModel/Alembic、PostgreSQL 16 + pgvector、SQLite FTS5、现有 torch/transformers、FastAPI 与 Vue。优先评测小型多语言 embedding；不引入抽取 LLM、Neo4j、KAG、GraphRAG 批量构图或新的任务平台。

### 2.2 复用必须解决的代码问题

1. **DK1 只有原文指针形状，没有原文存储闭环。** `ingest.py` 接受内联 text，却没有写规范化正文；text_object_key 的 `#chunk-N` 不是一个已实现的对象读取器。新流程先真实存正文，再登记偏移；读回核验通过才算 ingest 完成。
2. **DK1 重分块遗漏。** `ingest_document` 命中文档版本即返回旧 chunks，未按 chunker_version 区分；新版本必须支持同文档多分块方案，不能拿新版本名套旧切法。title 也需进入持久元数据。
3. **DK1 的 NFKC 和按字符切块不宜直接用于全部技术文本。** 旧 norm/1 不修改语义；新 `corpus-norm/2` 用换行统一与 NFC，保留代码/公式/大小写。按 embedding tokenizer 控制块长度，超长明确拆块，禁止静默截断。
4. **DK4 每个工作项会重读整个 manifest 并重建全部文本映射。** 改为流式导入和按文档/分片读取；严禁几 GB 一次载入内存，亦不能每算一个向量重扫全库。
5. **DK4 短任务租约不等于长任务安全。** 当前 process_one 无持续心跳，run_item 的业务写入早于 complete_item。向量任务需独立连接续租，实际产物写入与 owner/取消检查一并事务提交，避免旧 worker 落库后仅状态提交失败。
6. **DK4 预算/依赖需换口径。** max_chunks 当前按 succeeded 工作项数计，不是唯一片段数；认领也不表达索引阶段前置依赖。改为 embedding token/片段/时间/磁盘限额和阶段依赖，不保留 A/B/C/D 的调用预算。
7. **DK4 跨批次幂等需修正。** 当前工作项 fingerprint 全局唯一且从属单 build，新批次可能不拥有工作项。改为每批次工作身份唯一，跨批次复用从 embedding 缓存读取；成功批次计数以实际成员/产物计算。
8. **DK3 规则不能作为准确性门。** 本会话合成反例中，“栈移除最新元素；队列移除最早元素”的原文，会使“栈移除最早元素”被逐字出现规则判 supported。旧挑战测试通过不证明语义蕴含成立；本路线不消费这一判定。

### 3.2 存储结构（拟修改/新增）

所有规范化正文及 FTS 文件复用既有文件/对象存储，以 object_key 寻址；不新增每片段一个小文件。文档一份规范化正文，chunk 记录起止偏移；FTS 可保存段落展示投影。绝对目录仅在部署配置中。

| 数据 | 处理方式与必须字段 |
|---|---|
| discipline_document_versions（DK1） | 复用；补 title、metadata_hash；保留 external_id/source_kind/source_url/license/language/source_family_id、真实 object_key 与文本哈希 |
| discipline_chunks（DK1） | 复用；稳定 chunk_id、version_id、chunker_version、chunk_no、start/end、content_hash、token_count；需要时补 section_path，不编造页码 |
| discipline_builds/work_items（DK4） | 补 pipeline_kind=`corpus_rag`；工作项支持 shard/batch 单元与 payload_ref，旧 chunk_id 对新分片可空；唯一(build_id, stage, fingerprint)，旧任务标 legacy_extraction |
| discipline_releases/heads（DK1） | 复用通用 manifest/head 能力，scope=`corpus:cs`；此 scope 的发布是索引版本，不是知识卡/课程 GraphSnapshot；旧 release_items 不承担文本复制 |
| discipline_corpus_vectors（拟新增） | embedding_id、model_fingerprint、input_hash、dimension、embedding；唯一(model_fingerprint,input_hash)；模型与预处理均相同才能复用 |
| discipline_corpus_index_members（拟新增） | release_id、chunk_id、embedding_id(nullable)、display_metadata；唯一(release_id,chunk_id)，外键可验证；保存冻结展示元数据，构建中不被查询 |
| FTS 新版本文件 | meta(release_id,schema_version,tokenizer_hash,input_manifest_hash)，paragraph(rowid,chunk_id,title,body,source) 与 FTS5；rowid 只在本文件内部使用 |

schema 由 Backend Alembic 管理，SQLite 单测不创建 pgvector 扩展。新向量表与旧 discipline_corpus_embedding 分离；绝不执行旧 embedding 脚本的清表逻辑来“升级模型”。

数据库扩量约束（CR1/CR2/CR3共同验收）：

- 成员表的唯一 `(release_id,chunk_id)` 支持版本内回读；补查按 embedding_id/chunk_id 反向关联的执行计划，必要索引采用 `(embedding_id,release_id)`、`(chunk_id,release_id)`，不假定外键自动建索引，也不重复创建已被唯一索引覆盖的索引。
- 向量和成员按工作批次执行批量 INSERT/冲突复用，不逐片段 commit；推理、对象存储IO和索引文件生成均在数据库事务外，最后在短事务中校验租约并提交该批成员及状态。
- staging 导入后显式更新统计信息，再用专用测试库的 `EXPLAIN (ANALYZE, BUFFERS)` 检查版本成员过滤、ANN召回和原文回读；同时记录真实延迟，不以“建了HNSW”代替性能验证。
- Worker/查询连接数有上限；心跳连接计入连接预算。不得为提升离线吞吐直接扩大线上连接池、全局 work_mem 或取消超时。

文档去重只复用计算，不丢失各份来源。没有明确 external_id 的原始记录由来源类型和来源内稳定定位生成，不用全库行号。文本变化与元数据变化都进入新索引 manifest；撤回资格在查询/引用读取时实时检查，回退不能恢复撤回来源。

### 3.3 切块和模型冻结

- CR0 默认评测 `intfloat/multilingual-e5-small`（384 维）作为资源优先方案；当前中文 BGE 作历史基线。若中英检索达不到验收门，再评测 BGE-M3，不先全库重算两个模型。
- E5 使用 attention-mask mean pooling、`query: ` / `passage: ` 前缀及 L2 归一化；现有 LocalBgeEmbeddingProvider 的 CLS pooling 不可原样用于 E5。模型仓库版本、文件哈希、tokenizer、池化、前缀、维度、最大长度和代码版本共同生成 model_fingerprint。
- 新块目标正文约 320 tokens，相邻重叠 32 tokens；连同标题（最多 64 tokens）、章节、前缀和特殊 token 的总输入不超过 512。保留段落/代码块边界，超长块显式继续拆分；块的正文始终是规范化原文连续切片。
- E5 参数由[官方模型说明](https://huggingface.co/intfloat/multilingual-e5-small/raw/main/README.md)确认；采用前锁定实际 revision 并与参考实现比对。BGE-M3 的 CLS/长度/指令规则依其[官方说明](https://huggingface.co/BAAI/bge-m3)单独适配。
- 旧 130,351 条向量可继续服务 legacy 模式；即使新模型也为 384 维，模型不同仍不得混算距离。

### 3.4 本地推理与费用控制

一个本地 embedding 服务进程承载模型，构建 Worker 和 Backend 查询经 loopback 调用，Nexus 不加载模型。服务拟监听 `127.0.0.1:8310`，端口冲突由 CR0 预检明确报出；不对公网暴露。

- 服务接口：GET /health 返回 model_fingerprint/dimension/ready；POST /embed 接收 kind=query|passage、texts、expected_model_fingerprint，返回 vectors/token_counts。查询批最多 8，文档批初始 16；队列有上限，查询优先于批构建，超限返回 429。
- 小型进程复用已获准的 Backend torch/transformers 环境，不共享 Nexus venv。启动离线加载固定模型，不在请求时下载。新增依赖/模型下载在实施阶段按 AGENTS.md 获取明确授权。
- CR0 按机器余量冻结 CPU/内存/并发；构建初始 1 worker，限制 CPU/IO，在线服务受影响则暂停构建。租约初始 180 秒；**订正（2026-09-08 全量审核 P2-14）**：实现为"每批推理结束后用独立短连接续租一次"，不是周期心跳——推理超租约只会让他 worker 重认领重算，提交时 lease_token 校验保证不双写；周期心跳列为 V2 候选（触发条件：实测单批推理时长接近租约）。长任务不靠无限增大超时维持。
- 不调用生成模型改写/翻译每个 chunk，也不做 LLM 自动摘要或 LLM rerank。V1 使用关键词 + dense + RRF；只有检索评测证明需要才单列本地重排增强。
- 估时 T = 实际待算输入 tokens / 实测持续 tokens/s + IO/索引时间。记录缓存命中率和请求排队；不从旧约 635 万段推算确定工期。
- 向量本体大小约 N×(4d+8) bytes，尚不含表、HNSW、WAL、备份和 FTS。100 万×384 维约 1.54GB；空间预算必须实测这些附加项，不能只预留向量本体大小。[pgvector 存储说明](https://github.com/pgvector/pgvector#vector-type)

## 4. 索引构建、增量与发布契约

### 4.1 阶段

`扫描登记 → 保存正文/分块 → 分批向量化 → FTS/ANN 构建 → 完整性与检索验收 → READY → 激活`

- 扫描/正文导入按 JSONL 流式执行，记录文件哈希、字节断点和已完成文档；已有全文件 hash 可复用并按源变更重算，不能每批重算文件 hash。
- embed 是分片/批次任务；文档登记成功才创建任务。FTS/index 验证是 build 级任务，有显式依赖；不是每个 chunk 都创建一次索引。
- 新任务的 unit_kind/unit_key/payload_ref 描述稳定成员清单。逐次认领只加载本批文本；重试以模型输入 hash 命中缓存，不重算已完成向量。
- 文本模型输入相同可跨构建复用向量；来源不同仍有各自 chunk 与引用记录。metadata/标题进入向量输入时，其变化必须改变 input_hash。
- 取消/租约丢失后停止提交该批索引成员；在提交向量/工作项完成状态的同一短事务内检查 lease_token、lease_until 和 build 状态。心跳不持有推理期间的长数据库事务。
- 持续增量通过同一个 CLI 或已启用的服务调度触发，V1 不新增爬虫。重跑同一输入自动复用；不要求人工逐条处理。

### 4.2 发布

manifest 至少包括 release_id、source_manifest_hash、scope、chunker/normalizer/model_fingerprint、FTS object_key/hash、成员数量、向量覆盖数、排除原因计数、构建起止时间、检索配置和测试报告引用。

FTS 的 input_manifest_hash 只覆盖构建前冻结的输入/配置/成员清单，不包含最终FTS文件hash；最终发布manifest再记录FTS文件hash，避免文件与manifest相互包含hash形成循环依赖。

1. 先完成 staging FTS 与向量写入，检查同一 release 的 membership、引用定位、维度、模型身份、ANN 可用性。
2. 全部指定范围通过后标 ready；服务不可读取 building 数据。限定范围的小批发布是合法版本，但页面必须展示范围与覆盖数。
3. 通过事务比较并交换 discipline_heads(scope=`corpus:cs`,revision) 激活。查询在开始时固定 release_id，此次所有召回/回源/引用沿用该版本。
4. FTS 文件按 release 打开只读连接，校验 meta；不能覆盖仍被查询进程使用的同名文件。旧版本保留，便于回退和在途请求完成。
5. 回退重新检查旧版本文件、模型服务兼容、成员和来源可见性，然后 CAS 切回。不同模型的回退需恢复该模型进程并通过健康检查；过渡时明确降级 lexical。

pgvector ANN 在过滤后可能不足 top-k；查询必须带 model_fingerprint 与已发布 membership 过滤。CR3 检查扩展版本：支持时用有上限的 iterative scan，否则有界扩大召回并报告不足；不能取全库 top-k 后过滤一遍就假装完整。新模型以独立物理分区或固定维度表隔离，索引DDL只使用可信内部标识。[pgvector 过滤说明](https://github.com/pgvector/pgvector#filtering)
