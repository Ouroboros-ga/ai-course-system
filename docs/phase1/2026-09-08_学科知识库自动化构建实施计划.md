以下为已替代的原方案与历史实现回执。

**Goal:** 把已有 CS 语料持续处理为带证据、可去重、可更新和回退的学科参考知识库，并让页面、TeachingAgent、Nexus 查询同一发布版本。

**Architecture:** 现有 Backend 管理学科知识数据、权限、检索和发布；独立构建进程读取持久任务，以“高召回抽取 → 概念消歧 → 盲证据核验 → 分歧裁决”四个隔离模型角色生成候选，再经确定性硬门自动发布或隔离。学科库自有版本与事实来源，不写课程 GraphSnapshot 或 LearningEvidence；课程采用仍是另一条课程治理链。

**Tech Stack:** 优先复用 Python 3.12、SQLModel / Alembic、PostgreSQL 16 / pgvector、现有 GraphRAG 3.1.1 worker、Vue 3。LangExtract 为同样本对照候选，仅在独立评测环境按获批依赖安装；V1 不以引入 KAG / LightRAG / CocoIndex / Neo4j 为前置条件。

## 0. 全局约束与估算边界

- 当前基线分支 dev-liu；本次代码读取基线为本地 5ba8f0c7 + 工作区，不把本地与线上视为同一版本。实施前重查 HEAD、工作区和 Alembic heads。

- 工时为单个熟悉仓库的编码智能体有效工作时间，含阅读、编码、针对性测试、调试和文档；不等于 token 生成时间或确定承诺。

## 2. V1 交付范围

### 2.1 必交付

1. 文档登记、版本、稳定片段身份、按学科和来源选择处理范围。
2. 概念 / 陈述 / 关系候选抽取，证据原文定位和语义支持检查。
3. 中英文别名、概念消歧、重复合并和可撤销合并审计。
4. 分片队列、断点恢复、失败重试、取消、预算和构建状态。
5. 机器抽取 / 模型核验 / 自动接纳 / 自动隔离的独立状态；生成可回退的学科发布版本。
6. 页面 + TeachingAgent + Nexus 同源读取，逐条来源和 supplementary 边界。
7. 新增、修改、撤回文档时，仅重算受影响知识；批次发布和回退验证。

### 2.2 不纳入 57–85 小时

- 全网自动抓取、无限开放领域知识发现、多模态 OCR 能力重建。
- 多套开源框架同时上线、图数据库迁移、分布式计算集群、多模型自动调参。
- 直接生成并发布正式课程先修图、认知评分或课程事实；这些需另一个课程采用任务。
- 全量数百万片段付费处理完成。V1 验收使用有限的公开语料批次。
- 专家双标金标准集或强制人工抽查；如后续要对外声明真实 precision/recall，再单独建立人工真值集，不能把模型互评冒充人工准确率。

### 2.3 第一批数据与扩大顺序

- 自动校准批：1,000 个片段，textbook / zhwiki / enwiki / RFC / arXiv 各 200；按文档分组，评估集不能与示例/调参集共享文档或近重复内容。
- 自动挑战集：以现有 112 个 seed 概念、ontology 规则和合成模板生成至少 200 个可判定用例，覆盖无应抽知识、同名异义、否定句、条件限定、方向反转、版本冲突、提示注入和伪造引文；每个期望由确定性规则或显式 fixture 给出，不由被测抽取模型自己出题并自己判定。
- 第一产品批：操作系统与数据结构/算法，优先教材和相关维基，先登记最多 10,000 个去重后片段；实际不足时如实报告，不扩充无关内容凑数。
- 下一批：依校准过的预算扩至更多基础学科；RFC 按协议范围/版本扩展；arXiv 按研究主题纳入研究层。
- 不把 arXiv 实验性结论写成无条件教材定义；同来源转载不计为多个独立证据。

所有新关系型表均加 discipline_ 前缀，由 Backend Alembic 显式迁移管理；同一 PostgreSQL 实例允许共存，但不写 nexus_checkpoints、课程图表或学习证据表。V1 采用关系表和 JSON 发布投影，不引入图库依赖。

身份约定：chunk_id = hash(version_id + chunker_version + locator + content_hash)；concept_id 首次登记生成，legacy ID 通过映射保留；支持关系绑定文档版本，不以 corpus_paragraph.rowid 作永久引用。现有 FTS / pgvector 继续保持旧索引契约，新增桥接索引时必须一起记录 corpus_index_version。

原文定位约定：start/end 是指定 normalized_text 的 Python Unicode code-point 半开区间，quote 必须等于该区间。V1 不对定位文本做复杂重写；normalize 版本或分块方式变化必须生成新 ID。前端使用后端返回的 before/quote/after 展示，不直接将 Python offset 用于 JS UTF-16 切片。PDF/网页只能展示原来实际保存的页/章节信息，缺失坐标显示文本来源。

V1 predicate 白名单：defines、has_property、uses、part_of、contrasts_with、applies_to、example_of、related_to、prerequisite_candidate。复杂度等为 has_property + qualifiers，不无条件合并平均/最坏复杂度。prerequisite_candidate 不进入正式教学图；RELATED_TO 无需 DAG，只有明确启用的教学先修子图校验无环。

## 4. 处理与发布契约

### 4.1 顺序

登记输入版本 → 分块与去重 → 抽取模型生成候选 → 原文对齐 → 消歧模型归一 → 核验模型盲审 → 分歧模型裁决 → 确定性硬门 → 自动接纳或隔离 → 构建知识卡 → 冻结候选版本 → 校验索引与质量 → 自动发布。

每阶段单独提交可重用的中间产物，失败后从最近完成阶段续跑。同内容、配置未变时不再次调用模型；Prompt、模型标识、ontology、normalizer/chunker 版本改变均影响缓存指纹。抽取输入中的指令被当作语料，抽取器无 shell、网络浏览、课程写入等工具。

### 4.2 零人工模型流水线

“词抽取”只产生字符串，不能直接形成知识库。V1 的最小输出链是 `mention（原词）→ concept（规范概念）→ assertion（可核验陈述）→ relation（有方向关系）→ support（原文证据）`。四个模型角色使用不同指令和上下文，任何角色均不能直接写 active release：

1. **Extractor A（高召回）**：按 ontology 抽取 mention、定义、性质、关系、限定条件及原文 quote 候选；允许多报，不负责最终合并。
2. **Resolver B（身份消歧）**：仅接收 mention 上下文、候选概念及必要定义，输出 resolved / new / ambiguous；不得仅按向量第一名合并。
3. **Verifier C（盲证据核验）**：不读取 A 的 confidence，只读取原文、结构化陈述和 predicate 规范，判断 supported / contradicted / insufficient，并检查否定、条件、方向和时间版本。
4. **Adjudicator D（按需裁决）**：仅处理 B/C 分歧、跨来源冲突和高风险关系；输出 accept / keep_separate / quarantine / reject。它不能绕过原文 span、schema、来源资格等硬门。

角色可由同一供应商的不同模型或同一模型的隔离调用承担；默认使用较低成本模型处理 A/B/C，仅把预计 5%–15% 的争议项升级给更强模型 D。上线前以真实小批次测出升级率，而不是把该比例写成既有结果。模型自报 confidence 不作为放行依据，放行依据是可验证证据、角色间一致性和确定性规则。

确定性 Gate 至少检查：schema 合法、quote 与 normalized_text 精确一致、关系端点存在、predicate 在白名单、限定条件未丢失、来源未撤回且许可允许、无未决身份/冲突、构建预算及版本指纹一致。任一硬门失败即 quarantine/reject；不会创建“等人工”的阻塞任务。

### 4.3 全局参考自动接纳规则

- 定义和性质：存在可定位来源，校验其语义支持与限定条件；一份高质量原始来源可成立，不机械要求两篇。
- 别名：大小写/Unicode 等规范化不等于语义同义；跨语言或有歧义的别名用上下文决策，保存依据。
- 关系：来源必须支持类型和方向；只共现的实体只能记录共现信息，不直接当作实质性关系。
- 身份：有两个合理候选时保留 unresolved 并自动隔离，不能挑相似度第一名静默合并。
- 冲突：先由规则比较时间、版本和条件，再由 D 裁决；仍冲突时双方可作为带版本/限定的并存陈述，无法表达时自动隔离，新陈述不覆盖旧描述。
- legacy：保持 legacy_unverified 标记；没有实际原句的书目来源不伪装 span 证据。
- 自动发布只接纳 `grounded + model_verified + policy_passed` 的限定批次。模型、Prompt、schema、ontology 或阈值变化时，先自动重跑固定挑战集和 shadow 小批；不通过则保持旧 release，失败配置不得切 head。

### 4.4 状态

- 工作项：pending → running → succeeded / failed / cancelled；lease 过期只回收该任务，已完成结果保留。
- 构建：queued → running → validating → ready / partial_success / failed / cancelled；预算耗尽使用原有 failed/partial_success + BUDGET_EXCEEDED，不扩散未知状态到通用任务中心。
- 候选：extracted → grounded → resolved → model_verified → auto_accepted，或进入 quarantined / rejected；quarantined 不阻塞其他项目，也不进入发布。
- 发布：building → ready → active（由 head 表示）；以前 active 的版本仍然 ready，可回切。
- 缺源或变更：来源撤回即时影响可查询资格；相关候选标 stale，增量重建受影响卡片和后继版本。

### 4.5 租约、预算与异常

- Worker 初始并发 2，可配置；SQL 事务内认领 pending 工作项，PG 可用 SELECT FOR UPDATE SKIP LOCKED，续租与完成均比较 lease_token。
- 租约建议 180 秒、每 30 秒续租，模型请求超时独立配置；过期旧 worker 的结果不能覆盖新 owner。
- 429 / 5xx / 短暂网络错误最多重试 2 次，退避遵守 Retry-After；预算不足、权限失败、结构不合法不无限重试。
- 模型调用前预留输入与最大输出 token 预算；结束按实际 usage 结算，重试也计入。并发预留必须原子，不能仅在批次结束后统计超支。
- 费用按选定供应商实际定价配置估算，本文不写未核实价格。网络超时可能已计费但未返回结果；保持 usage_unknown，记录预留额，不能承诺外部调用 exactly-once。
- 取消停止新认领，已完成产物保留；迟到的模型响应可进入缓存但不能让 cancelled build 自动发布。
- 错误码至少包括 SOURCE_UNAVAILABLE、GROUNDING_FAILED、SCHEMA_INVALID、IDENTITY_AMBIGUOUS、RELATION_UNSUPPORTED、BUDGET_EXCEEDED、PROVIDER_UNAVAILABLE、LEASE_LOST、RELEASE_CONFLICT。

### 4.7 API 与权限

| 路由（基于 /api/v1/discipline-knowledge） | 行为 |
|---|---|
| GET /overview | 保留 node_count / relation_count / courses；新增 release_id、registered_docs、eligible_chunks、processed_chunks、quarantined_count、source_counts、更新时间 |
| GET /search；GET /nodes/{node_id} | 读取已发布知识；旧 seed ID 可解析；节点详情固定搜索时 release_id |
| GET /references/{support_id} | 返回授权可见的来源段落/定位；受文档可见性与撤回状态约束 |
| GET /sources | 管理员分页浏览已登记文档版本及来源/学科统计，供构建范围选择；不展示实际服务器路径 |
| POST /builds；GET /builds；GET /builds/{build_id} | 平台管理员创建有限范围构建、看进度；scope 使用登记对象 ID，不能提交任意服务器路径 |
| POST /builds/{build_id}/cancel；POST /builds/{build_id}/retry | 只处理目标批次，重试复用完成产物 |
| GET /quarantine；POST /decisions/{target_id}/override | 可选管理员诊断/纠错，不是发布前置；expected_revision 冲突返回 409 |
| POST /releases；POST /releases/{release_id}/activate | 系统从通过策略的 ready build 自动生成并 CAS 激活冻结发布；管理员接口用于主动重建/恢复，仍校验 expected_head_revision |
| POST /releases/{release_id}/rollback | 复验可见性后切回旧 head，写审计；不能恢复撤回来源的对外展示 |
| POST /reload（既有） | 仅清理读取缓存，禁止隐式启动构建或发布 |

### 6.2 V1 零人工质量门（建议值，不是已有结果）

没有人工真值时，系统能自动证明的是“有证据、规则一致、模型分歧被隔离、版本可回退”，不能诚实证明真实世界 precision/recall。下表因此把自动放行指标与可选的人类效果测量分开；前者是运行硬门，后者不阻塞 V1。

| 指标 | 建议目标 / 解释 |
|---|---|
| 发布内容引用可解析 | 100%；legacy_unverified 单列，不能计为已定位 |
| 固定挑战集 | 规则可判定用例 100% 通过；任一回归阻止新 config_hash 自动切 head |
| 模型核验 | auto_accepted 均有 C=supported；B/C 分歧必须经过 D，D 仍不确定则隔离 |
| 身份合并 | 歧义挑战集不得误合并；无法唯一归一时宁可新建候选或隔离，不追求零未决率 |
| 关系方向/条件 | Gate 检查端点/谓词，C 检查原文语义，反向/否定/缺限定挑战用例不得发布；先修候选不计作已确认教学边 |
| 自动隔离 | 所有 schema、grounding、identity、conflict 失败有 reason_code；隔离项为 0 不自动视为高质量，异常骤降触发 shadow 告警 |
| 增量幂等 | 同配置同输入重跑无新概念/重复关系，无新的成功片段模型调用 |
| 中断恢复 | 杀掉测试 worker 再启动，已完成工作保留，旧 lease 不能落库 |
| 发布隔离 | 三入口读取同 release；active 切换与失败回退不混入半成品 |
| 费用完整性 | 有 usage 的全部计入，无 usage 的超时保留未知额和预留额，不能当作免费 |
| 可选真实效果测量 | 若将来需要公开“准确率/召回率”，另做独立专家盲标；不把 LLM-as-judge 一致率包装成专家准确率 |

### 7.1 里程碑

- M1 零人工样本链：DK0–DK3，21–32h 基础，预留后 **约 27–40h**。交付来源可回看的样本知识点/关系、模型分歧与隔离报告；真实报告依赖试跑条件，不承诺此时已有生产页面。
- M2 完整 V1：DK0–DK8，累计 **57–85h**。三入口、构建/取消/重试、模型裁决、自动发布、版本、来源、增量/回退均可验收。
- M3 扩量：系统验收后按批次预算推进；源码完成不表示 18 万篇/数百万片段已抽完。质量或吞吐不足则重新估计，不强行降低校验。
- 默认按单智能体排期；以上不依赖多 Agent 并行，也未启动自动化或后台任务。

### 7.2 机器处理时间（单独估算）

首先在选定抽取器与真实限额下测 end-to-end 稳定吞吐 r（片段/小时，包含 A 抽取、B 归一、C 核验、D 按需裁决和重试）。剩余时间 = 待处理有效片段数 / r + 发布索引时间。同时记录各角色 RPM/TPM、缓存命中、争议升级率和资源占用，不能只用请求并发数推断吞吐。相较单次抽取，多角色方案预计增加约 2–4 倍 token 消耗；这是容量预估，实际以 DK0 小批实测为准。

仅作算术示例，**假设 r=2,500 片段/小时，未实测**：

| 有效处理范围 | 机器处理时间 |
|---|---:|
| 1,000 片段 | 0.4 小时，另有模型/索引启动时间 |
| 10,000 片段 | 4 小时 |
| 100,000 片段 | 40 小时，约 1.7 天连续运行 |
| 1,000,000 片段 | 400 小时，约 16.7 天连续运行 |

若 r 只有 500，表中时间乘 5；若 5,000 则除以 2。不能拿该假设承诺上线日期，也不能把历史 635 万段直接当作全部必处理范围。

**知识处理人工工时目标：0。** 系统不需要人工标注、逐条复核、冲突清队列或逐批点发布。项目层面仍有两个一次性外部动作：负责人授权真实模型预算/供应商，管理员授权部署并启用某个 scope/config_hash；这属于系统变更授权，不是语料加工劳动。若连一次启用也希望自动化，可把启用策略写入部署配置，由获授权的部署流程一次带入。

可选专家抽查只用于获得可对外声明的真实准确率，或调查隔离率/知识覆盖异常；不做抽查不会阻塞系统持续处理，但此时文档只能报告 grounding、规则通过率、模型一致率和隔离率，不能声称“专家验证准确率 95%”。

### 7.3 主要变动因素

- LangExtract 和现用模型端点无法保持相同输出能力时，可维持 GraphRAG 基线推进；额外适配超出 DK2 9h 上限另记变更，不把无限调试计入固定工期。
- 现有知识源大部分为英文；如果要求完整跨语种语义召回和统一英文定义质量，新增多语言 embedding 选型、重建与评测，单列 **8–16h 编码 + 向量重建机器时间**。
- 要上线完整 KAG / LightRAG 产品及双套存储迁移，需要重新拆任务；本估算仅覆盖自有模型 + 抽取组件。
- 远程写权限、模型调用预算、获批依赖/本地测试 PG 影响日历时间，不妨碍先完成合成样本、接口、前端和部署包。

## 8. 开源采用证据

- [KAG](https://github.com/OpenSPG/KAG)：本体约束与概念对齐的参考；V1 不整体部署。
- [LightRAG](https://github.com/HKUDS/LightRAG)：完整图检索和文档级维护的备选；V1 不同时引入另一套知识权威来源。
- [CocoIndex](https://github.com/cocoindex-io/cocoindex)：增量计算参考；V1 先在当前任务设施上实现持久工作项，后续依据维护收益选用。

上述项目检索在本会话进行；未安装、未运行新框架，没有本项目效果对比实测。具体第三方依赖版本在获准采用时核对、锁定并记录。
