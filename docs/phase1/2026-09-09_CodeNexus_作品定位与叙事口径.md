## 0. 两句话交代作品

**定位句**（**已定稿 2026-09-09**；首页 hero、README 首屏、PPT 封面、全部对外材料统一使用）：

> # 面向计算机学科的垂类大模型与可执行智能体平台

不是"功能很多的 AI 教学平台"。三个词概括：**懂学科、能执行、可核查。**

**白话阐释**（副标、口播、需要一句话讲清的场合）：

> 让知识有出处，让代码跑得通，让学习有回响

- **知识有出处** → 可核查：专业回答必须回到权威语料与课程证据，带 `reference_id` / Citation，检索不可用时不强行作答。
- **代码跑得通** → 能执行：代码与算法结论不只"看起来对"，要在 Judge0 / 实验沙箱里真的编译运行，以执行结果为证据。
- **学习有回响** → 懂学科：学习证据而非聊天印象驱动认知状态与下一步路径。

**已落地位置**：`README.md` 首屏、`design.md` 文件头、`frontend/public/static/docs/about/产品介绍.md` 首句、`frontend/src/app/pages/home/AppHomePage.vue` hero 大标题（两行排版 + `--position` 修饰类降字号）。

## 1. 主句定稿记录（2026-09-09）

**定稿结论**：首页与全部对外材料统一使用定位句本身，不再另起口号式主张：

> **面向计算机学科的垂类大模型与可执行智能体平台**

**白话副标**（保留，用于口播与副标位置）：**让知识有出处，让代码跑得通，让学习有回响。**

### 定稿过程与留档

两轮口号式候选均被否决：

- 第一轮（可验证 / 查得到 / 经得起检验）——**否决理由：不好听**。四句都是在陈述"我们要做什么"，是功能罗列。
- 第二轮（让智能回应学科 / 让知识经得起运行 / 让结论可复现）——**否决理由：不好听**。

**教训（写进口径，避免重犯）**：对标 SmartCarb「让课程回应学习」不等于必须再造一句同构口号。那句成立的前提是**教学场景里主客关系可被倒置且有温度**；一旦为了同构而生造动词（回应/经得起/可复现），就会牺牲音韵、变得拗口。**定位句本身足够清晰时就直接用它**，口号只做副标补充。

**留档候选**（如后续做品牌 Slogan 需要，可重启评估）：

| # | 候选 | 点评 |
|---|---|---|
| A | 让知识有出处，让代码跑得通 | 七字对仗，零技术名词，一句管可核查、一句管可执行。**已采用为白话副标。** |
| B | 让 AI 说到做到 | 最短、最有传播力（说=解释，做=执行）。风险：偏口语，评委或嫌不学术。 |
| C | 让答案经得起追问 | 有"学生追问到底"的画面，覆盖可追溯；弱在没体现执行。 |
| D | 让知识经得起运行 | 计算机学科独占（法学医学的知识没法"运行"）；覆盖不到教学侧。 |
| E | 让智能回应学科 | 与 SmartCarb 结构同构，但"智能"作名词生硬。 |

**与 SmartCarb 的关系**：SmartCarb「让课程回应学习」倒置的是"学生适应课程"；CodeNexus 倒置的是"人去迁就通用模型的输出"。**教学侧仍沿用「让课程回应学习」**（见 `design.md` 文件头），不因对外定位变更而废弃。

## 3. 核心思路：一条闭环，不是一堆功能

评委记住的是一条链，不是十几个模块。全系统只讲这一条：

```text
学生/教师提出一个计算机专业问题
        ↓
  学科模型理解（可插拔基座 + CS LoRA）    ← 懂学科：术语、算法、教学表达
        ↓
  权威知识约束（CS 语料 RAG + 课程图谱）  ← 查得到依据：原文、出处、版本身份
        ↓
  生成带出处的回答（Citation / reference_id）
        ↓
  进入工具层实际执行（Judge0 / 实验沙箱）  ← 跑得出结果：编译、运行、比对退出码
        ↓
  结果形成学习证据（代码执行结果可入正式证据）
        ↓
  更新认知状态 → 决定下一步学什么        ← 留得下证据
```

这条链一次性穿过**垂类模型 + RAG + Citation + 代码工具 + Agent + 沙箱 + 个性化**，且所有技术都在回答一个专业问题，不会像技术栈阅兵。

**一句话主叙事**：

> 通用大模型只能"说计算机"，CodeNexus 要做到**懂计算机、查得到依据、跑得出结果、知道学生下一步该学什么**。

## 4. 四层学科能力栈（PPT 核心架构图）

| 层 | 组成 | 负责什么 | 代码锚点 |
|---|---|---|---|
| **L1 学科模型层** | **可插拔基座**（现行 DeepSeek `deepseek-chat`，已 10 用例实测 9/9；讯飞星火 `SparkClient` 已就绪待 Key 验收）+ CS **LoRA/SFT 微调管线** | 术语理解、算法解释、代码分析、专业教学表达、复杂任务规划 | 默认 `LLM_PROVIDER=deepseek`（`config.py:59`）；星火 `llm_client.py:332` `SparkClient` / `config.py:66-74` / `bootstrap.py:96`；微调管线 `backend/finetune/` |
| **L2 权威知识层** | CS 语料库 + 混合 RAG + 课程知识图谱 | 教材原文、专业资料、课程材料、Citation、知识结构 | `platform/knowledge/discipline_corpus.py`；`platform/agents/providers/retrieval/discipline_kb.py`；图谱 `GraphSnapshot` / `CourseKnowledgeBundle` |
| **L3 可执行工具层** | Judge0 + 实验沙箱 + 检索 + 文档解析 | 代码执行、算法验证、实验复现、多格式材料解析 | Judge0 沙箱端口；`nexus/` Repro Worker；`document_parse_pipeline.py` |
| **L4 教育智能层** | TeachingAgent + Nexus + 学习证据 | 教学问答、代码实践、科研实验、认知状态、学习路径 | `platform/agents/edu/`；`platform/agents/research/`；`rule_baseline.py` |

**讲法要点**：LoRA 不是"另外训练了一个模型 + 另外做了一个网站"，而是**垂类模型是整个智能体体系的认知核心**（L1），知识、工具、教学各自承担不同责任：

> **模型能力 ≠ 知识库 ≠ 验证工具。**
> LoRA 解决"推理与表达的学科适配"，RAG 解决"事实与最新知识的外部约束"，代码工具解决"答案是否真的可运行"。
>
> **基座口径（实测，勿超前）**：当前运行与评测基座是 DeepSeek `deepseek-chat`（`config.py:59` 默认，2026-08-20 实测 10 用例 9/9）；
> 讯飞星火 Provider 已完成接入（单测 6 项通过），真实 Key 手工验收待进行。**不得在材料中写「已使用星火 8B」**。

## 5. 双层知识体系（必须讲清，否则逻辑混乱）

| 知识层 | 管什么 | 技术 |
|---|---|---|
| **计算机学科语料库** | 管"知道什么"：教材原文、专业资料的事实知识与出处 | 原文切块 + 本地 embedding + FTS/BM25 与向量混合检索 + pgvector |
| **课程知识图谱** | 管"怎么学"：课程知识点、前置关系、学习路径、课程结构 | `CourseKnowledgeNode` / `GraphSnapshotRecord` / `CourseKnowledgeBundle` |

一句话：**RAG 管"知道什么"，课程图谱管"怎么学"。**
（不再把整个体系讲成 GraphRAG 知识图谱检索系统——与 9/8 路线冲突。）

## 6. 可信 AI：五层防线（不靠准确率数字）

| 风险 | 机制 |
|---|---|
| LLM 知识幻觉 | 学科 RAG（语料原文约束 + 检索不可用时拒绝作答） |
| 来源不明 | Citation / `reference_id` / source 三件套 |
| 课程串库 | course + release 双重隔离，Citation 闭包校验 |
| 代码"看起来正确" | Judge0 / 沙箱**实际执行**，以执行结果为证据 |
| AI 擅自形成教学事实 | Evidence + 证据门 + 教师审核门，发布版本不可变可回滚 |
| 对学生下结论 | **证据不足时保持 `unknown`**，交互信号与正式测评证据分域（见 `README.md` 三项核心机制 · 双源证据分层） |

宣传句：

> 从"AI 猜测学生状态"，升级为"**基于可验证学习证据更新认知状态**"。

## 7. 四个创新点（不再堆技术名词）

2026 年 LoRA / RAG / Agent / 知识图谱**都不新**。只讲机制创新，且只讲这四个：

1. **模型—知识—工具协同的计算机垂类智能体系**
   学科 LoRA 负责专业推理，RAG 负责事实约束，沙箱/Judge0 负责客观执行验证。三者职责分离、互相制衡。

2. **面向代码学习的"回答 → 执行 → 证据 → 反馈"闭环**
   不只解释代码，而是让真实执行结果进入正式学习证据——计算机学科独占，其他学科复制不了。

3. **双层知识体系下的可追溯可信生成**
   学科语料给权威事实，课程图谱给教学结构，所有内容保留来源与版本身份。

4. **从问答型 Agent 到受控执行型 Agent**
   Nexus 通过隔离环境、审批门、持久执行、租约/fencing 与恢复认领处理复杂计算机实验任务。

## 9. 三个英雄案例（内容质量度 20 分要求 ≥3 个）

赛题要求"至少 3 个典型问题案例 + 正确性论证"，且明确接受引用权威来源佐证。三例分别覆盖**助教 / 助学 / 助研**：

### 案例一（助学 · 专业知识问答）——"为什么 Dijkstra 不能处理负权边？"

| 环节 | 系统做什么 | 正确性论证方式 |
|---|---|---|
| 理解 | 学科模型识别这是算法性质辨析问题 | — |
| 检索 | CS 语料 RAG 取回教材/权威资料原文 | 展示原文出处与 `reference_id` |
| 生成 | 带 Citation 的分步解释 | 每条结论可点回原文锚点 |
| 验证 | 构造负权反例 → Judge0 实跑 → Dijkstra 输出错误结果 | **执行结果截图即证据**（赛题明示接受"代码/公式可执行验证"） |
| 巩固 | 学生改算法 → 再跑 → 通过 | 前后两次执行结果对比 |

### 案例二（助教 · 学情诊断）——一次作业后的薄弱点归因

只消费**正式测评与代码执行证据**，不靠聊天印象；证据不足时输出 `unknown` 而非"掌握了"。
论证方式：展示证据类型分离表 + 一次 `unknown` 的实际输出（证明系统不强行下结论）。

### 案例三（助研 · 实验任务）——准备 → 执行 → 修复 → 报告

Nexus 在隔离环境准备实验、持久运行、失败后调整、产出带指标与判定的报告。
论证方式：展示 stage_events 六段轨迹 + 终态指标 + 可下载产物；**如实说明"验证中"步骤当前为不适用**。

## 10. 商业化：学科能力包（10 分不能白丢）

赛题看的是**高校 / 专业研究 / 学科领域的规模化复制**，不是学生会员。

| 学校教学平台 | API / 插件接入 |
| 科研团队 | Nexus 实验智能体 |

CS → 人工智能 → 软件工程 → 数据科学。复制的不是 UI，而是替换**四件套**：

> LoRA Adapter + Corpus + Tool Policy + Workflow Template
