## 2. 开发哲学与硬约束

1. **成熟核心 + 薄适配 + 必要领域逻辑。**能通过现成配置、公开 API、原生中间件完成的能力，不另起一套实现。
2. 不重写图调度器、Todo 引擎、Shell/PTY、文件编辑器、依赖解析器、通用容器管理平台、向量库、对象存储或文档转换器。
3. “胶水少”不能以删除功能或削弱权限为代价。用户授权、结果可信性、冻结身份和外部副作用对账是本项目必须负责的业务逻辑。
4. 使用一个 Nexus 主管。Open Deep Research 可提供流程参考或受控研究子图，不另行部署一个主管接管同一任务。
5. Backend、Nexus、执行控制服务依赖隔离；新增构建/渲染依赖进入对应独立环境，不升级旧 Backend 的 LangGraph/LangChain。
6. Ask/Auto 仅 Research 可选；两者均支持规划、检索、阅读全文、研究子任务和多格式文档。Ask 禁止新实验执行，但可查询已有实验、下载成果和由用户取消任务。固定文档渲染不属于实验执行授权。
7. 实验一次确认的是目标、代码/数据/网络范围和资源预算；范围内修依赖、修代码、换启动方式、重建与重试不逐命令审批。改变研究问题、数据集、指标门槛或新增付费资源时才请求新决定。
8. 不可信代码不进入 Backend/Nexus 主进程；任务容器不含生产凭据、宿主业务目录或 Docker socket。联网安装必须可用，但不能访问宿主业务网及其他任务。
9. LangGraph checkpoint 保存继续任务所需的最小状态；原始完整 Prompt、模型输出和隐含思维不进入通用审计。大段资料/日志使用受权限控制的引用；checkpoint 同样有权限、保留和删除策略。
10. 未知不是失败，也不是成功。不能用不重复提交代替恢复，不能用记录降级代替资源约束，更不能用有文件代替正式成果交付。
11. 新依赖在实施前单独批准、核验许可证、锁版本/镜像摘要并记录回退方法。官方文档描述或“生产级”标签不等于已经满足本系统的故障恢复和安全要求。

依据与限制：

- [LangGraph 持久化说明](https://docs.langchain.com/oss/python/langgraph/persistence) 区分内存和持久 checkpoint；本项目仍须处理图外副作用，不能把 checkpoint 等同容器任务账本。
- [Deep Agents 子任务文档](https://docs.langchain.com/oss/python/deepagents/subagents) 提供显式子任务和编译子图；在线文档可能对应新版本，实施先以当前锁版本公开接口为准。
- [SWE-ReX 数据接口](https://swe-rex.com/latest/api/runtimes/data/) 和 [RemoteRuntime](https://swe-rex.com/latest/api/runtimes/remote/) 提供会话动作与远程连接。本地 1.4.0 源码已读到 `BashInterruptAction`、`run_in_session` 和 `RemoteRuntime.from_config`；这只证明有可复用原语，不证明中断并发、日志流或重启完整恢复已经接好。
- [repo2docker 配置说明](https://repo2docker.readthedocs.io/en/latest/configuration/) 是识别配置的权威；平台只声明支持子集，不复制其解析规则。基础镜像路线和构建路线分别交付。
- [Pandoc 手册](https://pandoc.org/MANUAL.html) 明确 DOCX 数学可输出为 OMML；并非所有复杂公式和版式都能无损转换，需公开支持范围。不把 Pandoc 的选项当成 OS 级隔离。
- [latexmk 官方包说明](https://ctan.org/pkg/latexmk) 提供自动编译编排；[LibreOffice 命令行说明](https://help.libreoffice.org/latest/en-US/text/shared/guide/start_parameters.html) 提供无界面转换入口。二者只承担固定渲染任务，参数和配置由平台控制；不接受来源文件自带的可执行编译配置。LibreOffice 预览不能替代声明支持的 Word 编辑行为确认。
- [Docker Rootless 说明](https://docs.docker.com/engine/security/rootless/) 可作为独立受限构建 daemon 的实施参考，但不是已经部署的事实；资源限制、网络和构建器兼容性仍须按所选环境落实。
- [PaperQA](https://github.com/Future-House/paper-qa) 有可配置模型/embedding/证据接口，也有默认外部服务和成本，接入时必须显式覆盖。先限定为论文证据 Provider；不能为选型而重新启动 8 GB 全语料的 LLM 抽取。
- [Open Deep Research](https://github.com/langchain-ai/open_deep_research) 作为开源研究流程参考；引用/移植代码保留许可证与来源，按接入的固定提交复核依赖，不照搬演示服务设置。

### 4.1 成熟项目缺接口时怎么办

实施先完成一个明确的能力判定：公开接口能否保留会话、找回在途操作、取得终态、中断命令及输出增量。能满足则写薄适配；需要升级则先提出版本和兼容影响；确实缺失则给出等价 Provider 替换方案及迁移范围。

禁止把“上游没有接口”变成以下任一结论：删除原产品能力、拼一套新的 PTY/调度器、制造已恢复状态、把终态日志包装成实时流。允许少量特定操作的元数据/结果引用封装，不允许其演化为第二个通用执行内核。

## 5. 共享接线契约

以下是待实施的领域契约，不表示当前字段全部存在。优先扩展现有模块/表；只在一对多实体需要独立生命周期时增加窄表，迁移走 `nexus/migrations/`。不建立新业务数据库、通用事件总线或平行对象存储。

| 对象 | 最小信息 | 责任边界 |
| --- | --- | --- |
| ExperimentGoal | `mode=setup/smoke/reproduce`、目标描述、目标命令/产物要求、环境检查、指标政策引用 | 由原始目标和批准 scope 推导；模型可以建议，不可放宽完成标准 |
| OperationIntent | run、stable operation_id、tool_call_id、请求哈希、操作类型、session/执行句柄、状态、deadline、结果引用 | 执行前原子登记；Nexus 和控制服务各持有自己的持久状态；不直接写对方表 |
| ExecutionLease | run、持有者、到期时间、单调 fencing token | 防止两个恢复者同时接管；控制端拒绝旧 token 的新提交 |
| FrozenRecipe | recipe ID/hash、源码 SHA、patch/新增文件引用、镜像身份、依赖清单、数据清单/hash、命令、参数、种子、指标政策 | 不可变；与探索过程的 attempts 分离 |
| ResearchTask | task/parent/session、Brief、子问题、证据引用、计划、预算、状态、产物引用 | 大内容进既有来源/Artifact 域，任务只保存恢复所需数据 |
| FrozenDocument | source ID/version/hash、模板、受控内容、引用/图表/数值清单 | 同一版本供三个格式消费，转换不能重新创造事实 |
| DocumentJob | owner/session、幂等键、content hash、renderer/template version、分格式状态、诊断、Artifact | 复用已有任务能力；只补文档作业状态，不另起三套队列 |

状态原则：

- 操作：`prepared → submitted/running → succeeded/failed/cancelled/timed_out`；无法判断进入 `reconciling`，不是自动重交。
- run 保留现有公开状态及兼容映射，增加独立 `recovery_status`/完成原因，不强行让每个 UI 消费新枚举。
- 科学验证：`not_run / incomplete / passed / failed`，必须同时带验证类型、规则版本、recipe hash 与证据引用；历史 `passed` 没有同等证明时标 `legacy_unverified`，不重写历史事实。
- 文档：`queued/rendering/validating/succeeded/partial/failed/cancelled`；成功只表示所列格式真实完成，不提高研究结论可信度。

## 6. F1：按目标判定结果，统一产品口径

**目标：**不再把目录探测、最后一次诊断成功或重复失败当成实验完成。

**复用：**现有 proposal/scope、`repro_report.compare_metrics`、报告和工作台；不引入 LLM 裁判平台。

**修改文件：**`nexus/src/nexus/experiment_contracts.py`、`experiment_agent.py`、`experiment_report.py`、`experiment_clean.py`；`frontend/src/app/pages/nexus/components/NexusExperimentWorkspace.vue`。

**接线契约：**ExperimentGoal + 实际操作结果 → 四分量结论与判定证据。操作类型至少区分 `probe / environment / diagnostic / target / verification / file_tool`，分类本身不是完成证据。

- [x] 保留 setup/smoke/reproduce 的目标差异；setup 不要求论文指标，smoke 要求目标程序/最小产物，reproduce 要求可比较指标政策。（2026-09-10 落地：`derive_goal`，setup 强制 not_evaluated，reproduce 需 metric_policy 一致；6 项回归测试。）

- [ ] 用 Pandoc 替换标准库手拼 OOXML/通用 TeX 转换核心；保留必要的安全输入规范化和来源映射。数学表达保留数学节点，Word 输出原生 OMML；遇到不支持表达明确报错，不能默默变成普通文本或截图。
- [ ] 先交付技术说明、研究综述、实验报告三模板；使用可信 `reference.docx` 与 TeX 模板、受控 bibliography/图片。支持范围包含中英混排、表格、公式、图题、引用；任意期刊模板不纳入本批。
- [ ] 独立渲染任务无外网、无生产密钥/宿主业务挂载，只可读取本次授权资源和可信模板；禁 shell escape、任意用户 filter/宏和路径逃逸。Pandoc/TeX 参数不能替代容器文件/网络边界。
- [ ] 固定编译器、字体、模板和镜像版本，使用 latexmk 等现成工具处理必要编译轮次与引用；保存 LaTeX 工程、所需资源、编译说明、PDF 预览，不把临时目录中的 PDF 删除后仍声称已交付预览。
- [ ] 每格式独立状态和诊断；一个失败返回 partial，保留成功格式；重试只处理失败格式。同幂等键但不同内容报冲突；渲染中断可凭作业身份恢复/重试。
- [ ] 复用二进制 Artifact 路径；生成、重试、下载均核对 owner/session/源权限。撤销材料不能再生成新版本；旧产物按现有保留/删除规则处理。
- [ ] 将“结构文件有效”“公式可编辑”“编译成功”“排版可用”分开记录；页面仅展示实际交付状态。本轮不执行格式检查，实施交付时按这些用户可见结果确认。

**用户可见交付：**Ask 也能直接得到可编辑 Word、LaTeX 源工程与 PDF，而不是“请复制到 Word”或只得到 `.tex` 文本。

## 12. F7：完整研究、受限子任务与持续推进

**目标：**恢复完整研究原意：候选发现→全文/相关内容阅读→比较与冲突追查→综合→可追溯成果；实验是研究分支，不是必经路径。

**复用：**Deep Agents 原生 Todo/子任务、LangGraph checkpoint/store、已有 SearXNG/arXiv/附件/论文证据；参考 Open Deep Research。PaperQA 仅在证据 Provider 层引入。

**修改文件：**`nexus/src/nexus/agent.py`、`main.py`、`request_scope.py`、`paper_evidence.py`、`tools/paper_research.py`、`tools/paper_search.py`；按原 SR 文档新增/复用窄模块 `research_state.py`、`research_reading.py`、`research_loop.py`。不创建另一个研究产品入口或复制用户域。

**接线契约：**ResearchTask/Brief → 子问题与完成标准 → 受限 researcher → 结构化证据/缺口 → 原主管继续 → FrozenDocument；需要实验时引用同一研究任务启动既有提案流。

- [ ] Brief 保留用户要求的分析维度、数据/时间范围与交付格式；解析、读过与理解到什么分别表达，不把上传完成等同已经读懂全文。
- [ ] 自动获取允许访问的全文或导入已有附件，按问题补读后续页、长块后半段、表格和图；不可得如实显示 abstract_only/partial，并继续可独立完成部分，不直接伪称全文综述。
- [ ] 证据持久化来源版本、内容 hash、locator、覆盖范围、权限与引用；复用既有解析块。引用 ID 合法不等于支持结论，综合阶段仍须核对主张与原文。
- [ ] PaperQA 接口若采用，输入仅为授权论文，输出映射回本系统证据引用；显式使用已批准模型/embedding 和预算，不沿用默认付费服务。依赖冲突时隔离 Provider；收益不足可保留现有检索 Provider，但不能因此删掉全文研究流程。
- [ ] 在现有 Deep Agents 内显式装配只读 researcher，优先一个受限角色，不全面解除 `excluded_tools`。子任务不能审批、执行实验、读取宿主或改写他人材料；身份由服务端注入。
- [ ] 父任务分配预算/取消信号/授权范围，子任务返回 findings、evidence_ids、gaps、conflicts 和状态；只回传摘要及引用。子任务恢复使用明确 namespace，不只靠内存列表。
- [ ] 观察新证据后由模型重规划；平台执行预算和停止条件。找不到证据、来源冲突或部分工具失败时调整路径，不要求用户逐步指挥，不无限循环。
- [ ] 持续状态涵盖研究、实验和文档作业；复用 F2 的领域对账原则，不把实验 operation 表当成所有任务的万能状态机。已有 preset Worker 的恢复单独接其真实 job 标识，不能因自主实验恢复完成就声称旧 Worker 全部完成。
- [ ] Ask/Auto 保留相同研究工具和正式输出；实验结果回到同一证据/研究任务。完成时逐项检查原交付要求，而不是看 Todo 是否全勾。

**用户可见交付：**不运行代码也能完成多论文比较与正式研究报告；证据不足会自动补查；中断后保留研究进度及来源，不让用户手工搬运。

## 13. F8：受控 A/B，复用实验机制而不再建平台

**目标：**在同一实验问题下比较两个明确配置；与 F5 的“探索 A → 干净 B”区分，也与历史开发批次 A/B 区分。

**复用：**FrozenRecipe、既有 proposal/run/Artifact、指标比较和工作台。A/B 只是关联两份冻结配置和结果，不引入 MLflow 或通用实验追踪服务。

**修改文件：**`nexus/src/nexus/proposals.py`、`experiment_contracts.py`、`experiment_runs.py`、`repro_report.py`、`tools/reproduction.py`、`main.py`；实际 Backend 代理与工作台消费者同步。

- [ ] 对照说明保存共同数据/指标政策/预算与允许变化的参数；自动排错不能改变控制变量。
- [ ] 两组各引用冻结配方，各在独立环境执行；共享只读数据按许可与权限复用，不共享可变安装目录。
- [ ] 预算内按一次批准的对照 scope 执行；超出原目标/资源范围才重新确认，不逐组要求重复审批。
- [ ] 报告并列实际指标、运行条件、失败与缺失；没有足够重复次数与统计依据，不自动声称显著提升。

**用户可见交付：**知道哪一个变量不同、两边实际跑了什么、结果是否可比；不是两张无共同条件的成功卡。

**目标：**上述能力真正被用户入口调用，而不是停在内部 Provider；功能状态与交付事实一致。

**修改文件：**`frontend/src/app/pages/nexus/NexusPage.vue`、`components/NexusExperimentWorkspace.vue`、成果卡、`frontend/src/api/nexus.js`；`backend/app/api/v1/endpoints/nexus_proxy.py`；相关部署脚本、README、P2 计划、文档索引、审计记录。界面改动先读 `design.md`，不重做已接受的 v6 布局。

- [ ] 实际前端消费恢复状态、操作引用/取消、日志游标、分量结论、配方身份与文档分格式状态；缺配置时解释能力不可用，不显示假完成。
- [ ] 原 run/Console/报告接口保持兼容薄适配；新增字段按协议版本引入，同步所有真实消费者，不能只改 Runtime。
- [ ] 新表/列走可重入显式迁移；旧记录缺意图、补丁或配方时标不可完整恢复/历史未验证，不从文本报告反推已执行事实。
- [ ] 发布按 schema→独立服务与依赖→Runtime/Backend→前端的兼容顺序推进；先保持新增能力关闭，确认接线后再逐项开启。所有远程写入另需授权。

- [ ] 实施交付时分别记录代码实现、真实核心运行、真实模型行为、用户入口与未完成项。付费模型凭据不可用只阻塞相应实证，不能掩盖功能代码缺口；不复用未经重新确认的旧 Key 健康结论。

**用户可见完成标准：**

| 用户任务 | 最终必须看到的结果 |
| --- | --- |
| 给一个新公开仓库要求跑起来 | 自动读配置/准备数据，一次确认，真实安装、排错、运行和可下载配方 |
| 给一个带不同环境声明的项目 | 确实进入 repo2docker 路线并返回实际执行镜像，而不是退回基础镜像冒名 |
| 长命令卡住 | 模型可停止该命令继续修复；用户能取消整个实验 |
| 任务中断/刷新/服务重启 | 同一任务对账后继续；不重复命令；不能恢复时明确说出缺失证据 |
| 对最终方案做干净验证 | 从冻结源码/补丁/依赖/数据恢复，目标执行与指标分别说明 |
| Ask 模式要求多论文综述和 Word | 自动研究、补查、正式输出；零实验启动；不要求先有实验 run |
| 要求技术说明/综述/实验报告 | 同一冻结内容的 Markdown、可编辑 DOCX、LaTeX 工程及实际 PDF 预览 |
| 要求受控对照 | 控制变量清楚、预算一致、真实结果可比较，失败不隐藏 |

本轮仅定义这些功能交付标准，不执行相关代码或测试。未来不能用测试数量代替上述用户任务完成情况，也不把自动化覆盖率设成继续开发的前置条件。

## 15. 交付顺序与工程量参考

先修正结果口径与持久执行基础，再完善准备/构建和干净 B；正式输出和完整研究按各自接口交付，不要求一次合并所有改动。

| 批次 | 主要依赖 | 交付物 | 有效工程时间参考 |
| --- | --- | --- | --- |
| F1 判定与口径 | 无 | 不误导的运行/报告/验证状态 | 4–8 小时 |
| F2 持久执行与恢复 | F1 状态契约 | 操作意图、图恢复、租约/对账、显式迁移 | 16–28 小时 |
| F3 操作控制与资源/Console | F2 操作身份 | 中断、在途限额、真实增量输出 | 12–20 小时 |
| F4 自动准备与构建 | F2/F3 执行能力 | 论文/仓库准备、公开数据、repo2docker 路线 | 12–20 小时 |
| F5 冻结与干净 B | F1/F2/F4 | 完整配方、补丁、确定性恢复及验证结论 | 12–20 小时 |
| F6 正式成果 | F1 结论、已有证据/Artifact；实验格式另接 F5 | 三模板三格式、隔离渲染和 PDF | 12–20 小时 |
| F7 完整研究 | 持久任务/证据契约；最终输出接 F6 | 全文研究、受限子任务、观察/重规划 | 20–32 小时 |
| F8 受控 A/B | F5 | 共同条件下的配置比较 | 6–10 小时 |
| F9 产品贯通 | 各批完成后逐段接入，最后统一交付 | 前后端、迁移/回退与真实状态说明 | 8–12 小时 |

以上是单编码智能体实施、接口整合与必要交付检查的粗估，不是已测得速度或日历承诺。合计约 **102–170 有效小时**；按每天 8 个有效小时约 13–22 个工作日，仅作规划。实验核心 F1–F5 约 56–96 小时；不能把完成该部分称为完整研究产品完成。

外部等待、依赖批准、镜像下载、大规模真实实验、模型质量调优不包含在估算内。F2/F3 的上游恢复/中断能力是最大不确定项，先核清；如果需要升级或更换执行 Provider，应重新估算，不通过自研执行内核强行维持工期。
