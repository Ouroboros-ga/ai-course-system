## 2. P0-A：`reasoning_content` 不回传导致多轮工具链断裂（核心根因）

### 2.1 官方要求（原文）

> 请注意，携带了 `tools` 参数的请求，在后续所有请求中，必须完整回传 `reasoning_content` 给 API
> ——即使该轮模型未实际进行工具调用。**若您的代码中未正确回传 `reasoning_content`，API 会返回 400 报错。**

官方 Agent 集成页以 compat 字段形式再次强调：

> `requiresReasoningContentForToolCalls: true` — DeepSeek requires `reasoning_content` to be preserved
> across tool-call turns in conversation history. **Skipping this causes 400.**
> （同页并列的 `supportsToolChoice: false`、`requiresAssistantContentForToolCalls: true` 三者被标注为
> "Without them, DeepSeek V4 will return 400 errors when using tools in thinking mode"）

### 2.2 本项目侧的实现事实

`langchain_openai/chat_models/base.py` **模块 docstring 第 3-11 行**：

```
!!! warning "API scope"
        `ChatOpenAI` targets official OpenAI API specifications only.
        Non-standard response fields added by third-party providers (e.g.,
        `reasoning_content`, `reasoning_details`) are **not** extracted or
        preserved. If you are pointing `base_url` at a provider such as
        OpenRouter, vLLM, or DeepSeek, use the corresponding provider-specific
        LangChain package instead (e.g., `ChatDeepSeek`, `ChatOpenRouter`).
```

`nexus/src/nexus/agent.py` 用 `ChatOpenAI` 指向 `https://api.deepseek.com/v1`，
而 V4 **默认开启思考模式**（`build_llm` 未设 `thinking`）→ 命中上述冲突。

### 2.3 本地实测复现（零真实调用）

`tmp/ll_reasoning_probe.py`：本地假端点扮演 DeepSeek，第一轮返回带 `reasoning_content` 的 tool_calls，
捕获第二轮 langchain 实际发出的请求体：

```
=== 第一轮模型响应（langchain 解析后） ===
content          : '好的，我先查一下日期。'
tool_calls       : ['get_date']
additional_kwargs: {'refusal': None}
  -> reasoning_content 是否被保留: False      ← 字段被丢弃

=== langchain 实际发出的第二轮请求 ===
  messages[0] role=user       keys=['content', 'role']
  messages[1] role=assistant  keys=['content', 'role', 'tool_calls']   ← 无 reasoning_content
  messages[2] role=tool       keys=['content', 'role', 'tool_call_id']

!! 结论：第二轮 assistant 是否回传 reasoning_content = False
```

**据此，研究模式（检索 → 读证据 → 写报告，多轮工具）在第二轮即应 400 中断。**
用户反馈的"只回了一小段就停"与此一致。

### 2.4 修复（已实施）

`nexus/src/nexus/config.py` 新增：

```python
llm_thinking: str = "disabled"        # enabled / disabled
llm_reasoning_effort: str = "high"    # 仅 enabled 时发送
```

`nexus/src/nexus/agent.py build_llm()` 显式下发：

```python
extra_body = {"thinking": {"type": "enabled" if thinking_enabled else "disabled"}}
if enabled: kwargs["reasoning_effort"] = settings.llm_reasoning_effort
```

**为什么默认 `disabled` 是"修复"而非能力降级**：在当前 `ChatOpenAI` 路径下 `enabled` **必然 400，不可用**。
附带收益：关闭思考后 `temperature=0.2` 恢复生效（官方明示思考模式下不生效）。

**若要启用思考模式**（保留 `high`/`max` 推理能力），前置条件已写入 `config.py` 注释：

1. 依赖换成 `langchain-deepseek`，用 `ChatDeepSeek`（官方推荐，原生保留 `reasoning_content`）；
2. **同步把 `agent._register_tool_surface_profile()` 的 provider 键由 `"openai"` 改为 `"deepseek"`** ——
   `HarnessProfile` 按 `ls_provider` 匹配，键不改则 `NEXUS_EXCLUDED_TOOLS` 收敛失效，
   `execute`(shell) / `write_file` 等工具会被重新挂载（**安全边界破裂**）；
3. 处理 `tool_choice` 被拒（thinking mode 不接受该参数）。

### 2.5 v4：真正修复并启用思考模式（2026-09-11 下午）

**v3 的 §2.4 是规避**：把 `thinking` 关掉，就绕过了 `reasoning_content` 回传要求，
代价是**放弃模型的推理能力**，且 `temperature` 才会生效。

**v4 改走官方推荐路径**，三条前置条件全部落地。

#### 2.5.1 依赖迁移：`ChatOpenAI` → `ChatDeepSeek`

| 事实 | 依据 |
|---|---|
| `langchain-deepseek==1.1.0` 的 `ChatDeepSeek` 继承 **`BaseChatOpenAI`，不是 `ChatOpenAI`** | 实测 MRO |
| 因此**不会**把构造器 `max_tokens=` 改写成 `max_completion_tokens` | 实测 payload |
| 接收侧**会**把 `reasoning_content` 存进 `message.additional_kwargs` | 实测 |
| 但发送侧**不**把它写回请求体（`BaseChatOpenAI._convert_message_to_dict` 丢弃非标准字段，模块 docstring 明写 "not extracted or preserved"） | 实测假端点抓 body |

**结论**：`ChatDeepSeek` 解决了"收"，**没解决"发"** —— 必须自己补。

#### 2.5.2 关键实现：在 `_get_request_payload` 回传

`_get_request_payload` 是**唯一插入点**（`_convert_message_to_dict` 是纯函数、
`BaseChatOpenAI.chat()` 内部链路不暴露 message 对象）。实测确认 `ChatDeepSeek` 有覆写该方法。

```python
class _NexusChatDeepSeek(ChatDeepSeek):
    def _get_request_payload(self, input_, *, stop=None, **kwargs):
        payload = super()._get_request_payload(input_, stop=stop, **kwargs)
        try:
            origin = self._convert_input(input_).to_messages()
        except Exception:
            return payload
        wire = payload.get("messages") or []
        # 长度不一致说明 SDK 做了增删（如 system 注入），放弃改写而不是错位配对
        if len(origin) != len(wire):
            return payload
        for src, dst in zip(origin, wire):
            if not isinstance(dst, dict) or dst.get("role") != "assistant":
                continue
            reasoning = (getattr(src, "additional_kwargs", None) or {}).get("reasoning_content")
            if reasoning and not dst.get("reasoning_content"):
                dst["reasoning_content"] = reasoning
        return payload
```

**为什么不用 `_convert_message_to_dict`**：它是 `staticmethod`，无实例上下文；
且 `ChatDeepSeek` 未覆写它，改它要 monkey-patch 基类，影响面超出本模块。

#### 2.5.3 安全边界：`HarnessProfile` provider 键

`HarnessProfile` 按 `_get_ls_params()["ls_provider"]` 匹配。
`ChatDeepSeek.ls_provider` **硬编码返回 `"deepseek"`**，而原实现的双注册键是 `"openai"`
→ **不处理则 `NEXUS_EXCLUDED_TOOLS` 收敛静默失效，`execute`(shell) 被重新挂载**。

修法：`_register_tool_surface_profile()` **同时注册 `"deepseek"` 与 `"openai"` 两个键**
（后者供测试桩 `_SpyChatOpenAI` / `_Scripted` 继承 `ChatOpenAI` 用），
`_NexusChatDeepSeek` 另用 `PrivateAttr` 持有可变的 `_provider_key`，
Research 模式改指向 `"nexus-research"` 以放开 `task` 工具。

```python
class _NexusChatDeepSeek(ChatDeepSeek):
    _provider_key: str = PrivateAttr(default=PROVIDER_DEEPSEEK)

    def _get_ls_params(self, stop=None, **kwargs):
        params = super()._get_ls_params(stop=stop, **kwargs)
        params["ls_provider"] = self._provider_key
        return params
```

#### 2.5.4 请求级开关（不再靠重启改配置）

`config.py` 的 `llm_thinking` 语义由"**唯一真相**"改为"**默认值**"：

```python
llm_thinking: str = "enabled"      # 默认值；请求可覆盖
llm_reasoning_effort: str = "high"
```

```python
def apply_thinking_mode(llm, thinking: bool | None):
    if thinking is None or not isinstance(llm, ChatDeepSeek):
        return llm
    extra_body = dict(getattr(llm, "extra_body", None) or {})
    extra_body["thinking"] = {"type": "enabled" if thinking else "disabled"}
    return llm.model_copy(update={
        "extra_body": extra_body,
        "reasoning_effort": settings.llm_reasoning_effort if thinking else None,
    })
```

`build_llm(model_name)` **签名保持不变**（测试桩用 `lambda model=None: spy` 依赖它），
思考模式改由 `build_agent(thinking=...)` 注入。

#### 2.5.5 顺带修掉一个潜伏 400

`experiment_agent.build_experiment_llm` 原先建 LLM 时**不下发 `thinking`** →
V4 **默认开启**思考 → 实验图同样带 tools → **同样在第二轮 400**。
该路径此前从未被真正跑到，属潜伏缺陷。已改为显式下发 `disabled` 并复用 `_NexusChatDeepSeek`。

#### 2.5.6 P1-4 落地：推理过程对用户可见

`main.py` 的 `AIMessageChunk` 转发分支重写：

```python
if isinstance(chunk, AIMessageChunk):
    reasoning = (chunk.additional_kwargs or {}).get("reasoning_content")
    if isinstance(reasoning, str) and reasoning:
        yield _sse("reasoning", await _tag({"content": reasoning}))
    content = chunk.content
    if isinstance(content, str) and content:
        token_count += len(content)
        yield _sse("token", await _tag({"content": content}))
    elif isinstance(content, list):
        for block in content:
            text = (block.get("text") if isinstance(block, dict) else None)
            if isinstance(text, str) and text:
                token_count += len(text)
                yield _sse("token", await _tag({"content": text}))
```

**三个要点**：
1. `reasoning` 与 `token` **严格分流** —— 推理内容**绝不写入 `answer`**
   （混入会污染 Markdown 渲染、引用锚点与历史重放）；
2. 兼容 **content blocks（list 形）** —— 原实现只处理 `str`，list 分支直接丢弃，
   这会在多模态/工具场景静默丢字；
3. 空推理**不发事件**（避免前端出现 0 字折叠块）。

前端折叠块见 §5.4（本节原为"未实施"，v4 已实施）。

## 5. P1 建议项（已实施）

### 5.1 篇幅要求：提示词 + 写入点门禁（✅ 已实施）

**改前**：`agent.py` 的 `SYSTEM_PROMPT` 与 `MODE_PROMPT_APPENDIX["research"]` 零篇幅约束；
`research_state.py:606-647` `delivery_checklist()` 的 `synthesis_report` 只判断
`bool(task.get("report_artifact_id"))` —— 检查存在性，不检查长度。

**已实施两处**：

1. **提示词**（`agent.py` `MODE_PROMPT_APPENDIX["research"]`）新增规则 7「NX-Report」：
   正文 ≥6 节（研究问题 / 资料覆盖与来源 / 关键证据 / 方法比较 / 综合结论 / 限制与待补证据）；
   禁止"暂无相关内容""详见上文"占位；**证据不足时缺口写进末节，不得因此压缩其余各节**；
   禁止"由于篇幅限制""为简洁起见"式省略；对话回复亦须分点而非单段收尾。

2. **写入点门禁**（`tools/paper_research.py` `write_research_report`）：
   `body` 少于 `report_min_chars`（默认 1500，新配置项）即返回可修复错误
   `REPORT_TOO_SHORT`，指引模型按 NX-Report 结构补足后重试，并提示先用
   `read_paper_more` 补读而非写短。

> **为什么放写入点而不是 `delivery_checklist`**：task 记录里只有 `report_artifact_id`，
> **没有正文长度**；为它加列需改 `nexus_research_tasks` 表结构 + 迁移 + 三处行映射
> （`_update_row` / `_create_row` / `_row_to_task`）。写入点能直接拿到 `body`，
> 且**拦得更早**（模型还有机会修正，而不是交付核对时才失败）。
> 语义与既有 `CITATIONS_REQUIRED`、`EVIDENCE_ID_INVALID` 等 rejected 完全一致——
> 模型对这类"可修复错误 + 明确指引"已有成熟应对模式。
>
> **实测**：4 字符 → `REPORT_TOO_SHORT`；1650 字符 → 落到 `CITATIONS_REQUIRED`
> （说明门禁通过且**早于**引用校验生效）。阈值 0 可关闭（`NEXUS_REPORT_MIN_CHARS`）。

### 5.2 证据预算放宽（✅ 已实施）

`paper_evidence.py`：`EVIDENCE_EXCERPT_MAX` **1200 → 2400**、`EVIDENCE_TOTAL_CHARS_MAX` **12000 → 40000**。

理由：原预算下一次取证最多给模型 1.2 万字符原文（≈6000–8000 汉字），而报告只能引用已登记证据
→ 素材量直接封住报告深度（写长就触发伪引用风险）。V4 为 1M 上下文，4 万字符注入仅占 2–3%，
容量不是约束。`MAX_ATTACHMENTS_PER_CALL` / `MAX_EVIDENCES_PER_CALL` 保持不变。

### 5.3 SSE 心跳（✅ 已实施）

`main.py` `_agent_stream` 改为**生产者任务 + 队列 + 带超时消费**：

```
pump_task ──agent.astream()──▶ asyncio.Queue ──wait_for(15s)──▶ 消费者
                                      └─超时→ yield ": keep-alive\n\n"
```

- **不采用 `wait_for` 直接取消 `__anext__()`**：取消会关闭异步生成器、破坏 agent 循环状态；
  队列 + 独立 task 让 `astream` 不受心跳干扰。
- 心跳为 SSE **注释帧**，前端 `parseSseFrames` 无 `data:` 行即跳过（`nexus.js:590`）
  → **零前端改动**。
- `finally` 里 `pump_task.cancel()`，正常/异常/取消路径都不留悬挂 task。

#### 7.3.3 `_tool_surface()` 容错缺口（本轮发现并修复）

`/health` 的 `tool_surface` 是**外部确认「`execute`(shell) 是否被收敛掉」的唯一观察点**，

  **逐项容错**而非整体失败。

### 操作规程（下次遇到同类先看这里）

1. **多 worktree 仓库（`worktreeConfig=true`）上禁止在未确认并发情况时执行 `git stash`**——

3. **判定"仓库坏了"的最小检查集**：`.git/refs`、`.git/HEAD`、`.git/objects/pack/*.pack`、
   `git rev-parse --git-dir`。git 的仓库门禁要求 `HEAD` + `objects` + `refs` 三者同时存在。
4. **`git diff --cached` 在 HEAD 未出生时不代表"有人暂存了东西"**——unborn HEAD 会把整个索引
   列为新增，条目数没有诊断价值。
5. **首选恢复源是远端**：`git ls-remote origin <branch>` 先确认远端有完整 commit，
   再考虑本地修 ref。**切忌 `reset --hard`**（会毁掉未提交的工作树）。
