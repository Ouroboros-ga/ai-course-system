## 0. 结论

两个反馈都成立，且第一个是**真 bug，不是体验问题**。

1. **内容显示不全 = 滚动容器缺失**。页面根节点 `overflow: hidden` 掐掉了滚动，而它唯一的子面板没有任何滚动容器，超出视口的部分直接不可达。不是"没显示好"，是**永久看不到、也点不到**。
2. **题目设置繁琐 = 六步线性向导 + 三个本该是控件的字段被做成了自由文本 + 权重靠手凑**。

按"直接重置"的要求，教师侧设定界面整体重写为**左侧任务列表 + 右侧四段式编辑器**，两列各自滚动。改动文件 5 个（前端 4 + 后端 1），后端只加了两个序列化字段。

## 1. 诊断

### P0 —— 编辑区内容被永久裁掉

**现象**：截图 1 中「版本与测试」的「测试 1」卡片在视口底部被切断，没有滚动条；「现有实验」表格在更下方，同样不可达。

**根因**（两个因素叠加，缺一不可）：

| 位置 | 代码 | 后果 |
|---|---|---|
| `CourseExperimentsPage.vue:284-293`（改动前） | `.experiments-page { height: 100%; overflow: hidden; display: flex; flex-direction: column }` | L3 页面根禁止滚动 |
| `TeacherExperimentPanel.vue:493`（改动前） | `.sfx-teacher-experiments { display: flex; flex-direction: column; gap: var(--space-4); min-width: 0 }` | 面板既无 `flex: 1` 也无 `overflow-y: auto`，被内容撑高后溢出，父级 `overflow: hidden` 把它裁掉 |

命中 `design.md` §5.1 强制规则 3：「L3 内部滚动容器必须显式设置 `min-height: 0`，否则 flex/grid 子元素会被内容撑爆」。

**对比**：学生侧的 `.workbench-container { flex: 1; min-height: 0 }` 之所以没坏，是因为 `CodeWorkbench` 自己 `height: 100%; overflow: hidden`，内部面板各自滚动。教师侧完全没有这一层。

**修法**：教师面板改为 `flex: 1; min-height: 0`，内部用 `grid-template-columns: 300px minmax(0,1fr)` + `grid-template-rows: minmax(0,1fr)`（§5.2 的 `1fr` 陷阱），左列 `.task-list` 与右列 `.editor-column` 各自 `overflow-y: auto`。列表多长、用例多少条都不再影响可达性。

---

### P1 —— 六步线性向导，每步一屏

**根因**：`TeacherExperimentPanel.vue:22` `stageOrder = ['definition','limits','version','preview','lock','publish']`；每个 stage 是 `v-if / v-else-if` 的独立表单（`:345/:370/:383/:429/:444/:453`），前进靠提交按钮，后退靠「返回」。段与段之间不可跳转。

三个具体代价：
- `max_attempts` / `cooldown_minutes` 在「任务定义」与「语言与资源」两段各出现一次（`:349-350` 与 `:374-375`），同一份数据两个入口，教师不知道哪个生效。
- `stage === 'preview'` 段（`:429-442`）里要粘参考解源码，`stage === 'lock'`（`:444-451`）只放一句说明和一个按钮 —— 一整屏换一个 4 字动作。
- 刷新页面后必须重跑参考解预览：`canLock` 依赖内存里的 `preview.value`（`:84`），而服务端其实已经把 `reference_preview_verified_at` 存下来了，只是没回传。

**修法**：四段可任意跳转（`EXPERIMENT_SECTIONS = ['basics','tests','limits','publish']`），预览 / 锁定 / 发布合并为「发布检查」段的一张清单 —— 对教师来说它们是同一件事的三道门槛，不是三次创作动作。

---

### P1 —— 权重靠手凑，凑不齐只给一个红标

**根因**：`TeacherExperimentPanel.vue:222` `if (Math.abs(testWeight.value - 1) > 0.000001) return`，按钮 `:disabled`（`:425`），反馈仅为一个 `SfxBadge`（`:412`）显示「权重 0.85 / 1.00」——**不告诉教师差多少，也不提供任何一键补齐**。`addTestCase`（`:206-214`）新增用例权重固定为 0，所以每加一条就必然先把按钮弄灰。

服务端 `experiment_service.py:280-282` 用 `1e-9` 容差硬校验权重和，所以这个字段不能不管。

**修法**：默认「权重自动均分」。`distributeWeights()` 把 1.00 按"分"整除再落回小数，保证求和精确等于 1.00 且极差 ≤ 0.01（3 条 → 0.34/0.33/0.33；15 条 → 10×0.07 + 5×0.06）。关掉开关即转手动，实时显示「还差 0.15」。

**顺带发现的静默漏洞**（服务端只校验总和，不校验单条 > 0）：`weight: 0` 的用例能通过校验，但在全量通过规则下即使失败也不影响判定 —— **等于一条静默失效的用例**。v2 不拦截（不比服务端更严），但会明确提示「N 条权重为 0，等于静默失效」。补测试清单见 §5。

### P2 —— 三个字段本该是控件，被做成自由文本/平铺

| 字段 | 改动前 | 问题 |
|---|---|---|
| 允许语言 | `definitionForm.languages: 'python3'`（`:45`），`.split(',')` 解析（`:70-73`） | 纯文本逗号分隔。页面**已经取到了** `/sandbox/languages`（`CourseExperimentsPage.vue:44`），教师面板却完全没用它 —— 教师只能靠记忆猜合法取值，填错要等创建接口 400 才知道 |
| 关联知识点 | `knowledgeNodes` 全量 checkbox 平铺（`:354-363`），容器 `max-height: 180px`（`:508`） | 精编图谱 112 个节点，无搜索、无过滤、已选不置顶 |
| 测试用例结构 | 每条用例一张卡片（`:398-408`），每个字段一个带 label 的大控件 | 3 条用例 = 12 个纵向堆叠控件，把编辑器撑到 4 屏 —— 与 P0 叠加后就是"看不到" |
| 发布状态 | `{{ item.publish_status }}`（`:481`） | 界面直出英文 `draft` / `published` |

### P2 —— 继续配置会静默清空已填内容

**根因**：`TeacherExperimentPanel.vue:295-315` `continueDraft(item)` 把 `versionForm` 整体重置为两条空默认用例（`:97-104`）。而 `resolveExperimentWizardStage`（`experimentPublishWorkflow.js:1-4`）在草稿已有 `default_version_id` 时返回 `'preview'`，无版本时返回 `'version'` —— 两种情况都要求教师从空表重填。

更麻烦的是：版本不可变（`experiments.py:572-604` 的 `PUT /versions/{id}` 只改 `label` / `passing_score` / `writes_formal_evidence`），所以重填 + 点「创建不可变版本」= 静默产出 v2、v3…… 而 `default_version_id` 只有 `lock_version` 才会更新（`experiment_service.py:443-453`）。教师会得到一串谁也没在用的版本。

**修法**：`GET /versions/{id}` 回读既有测试集与起始代码，编辑区语义明确为"下一个待创建的版本"，并用脏检查（`isDirty`）阻止重复创建同内容版本。

### P2 —— 三个已存在的后端端点前端从未调用

`GET /{experiment_id}/versions`（`experiments.py:480`）、`GET /versions/{version_id}`（`:546`）、`POST .../archive`（`:453`）此前无任何前端消费者。

- 前两个正是"恢复现场"所需；
- 第三个是唯一能清理草稿的途径 —— 此前草稿只能越堆越多，没有归档入口。

v2 全部接上（`frontend/src/api/experiments.js` 新增三个函数）。

## 2. 新设计

### 结构

```text
.sfx-teacher-experiments          grid: 300px | minmax(0,1fr)     rows: minmax(0,1fr)
├── .task-column                  左列，面板自身不滚动
│   ├── 头部：实验任务 + [新建任务]
│   ├── 搜索框
│   └── .task-list                overflow-y: auto ← 长列表在这里滚
│       └── 分组：草稿 / 已发布 / 已归档
└── .editor-column                overflow-y: auto ← 长表单在这里滚
    ├── 编辑器头：任务名 + 状态/版本/锁定徽标 + 归档
    ├── 段导航：① 基本信息 ② 测试用例 ③ 运行限制 ④ 发布检查（任意跳转）
    └── 当前段
```

### 四段职责

| 段 | 内容 | 对应服务端 |
|---|---|---|
| ① 基本信息 | 名称、说明、**语言多选 chip**、尝试次数、冷却、**可搜索知识点（已选置顶）** | `POST/PUT /definitions` |
| ② 测试用例 | 紧凑行 + 点击展开编辑、**权重自动均分**、**JSON 批量导入**、复制/删除行、版本历史 | `POST /{id}/versions` |
| ③ 运行限制 | 三档预设、五个数值字段（含范围提示）、按语言 Tab 的开始代码、证据开关 | 同上（同一 payload） |
| ④ 发布检查 | 8 项清单 + 内联参考解预览 + 锁定 + 发布 | `reference-preview` / `lock` / `publish` |

### 关键交互决定

- **发布检查清单 = `ExperimentPublishValidator` 的客户端镜像**。清单逐项对应服务端 `experiment_service.py:1996-2023` 的校验顺序：课程编码沙箱能力 → 语言白名单 → 默认版本存在且活动 → 已锁定 → 预览已验证 → 阈值 1.0 → 资源边界 → 用例非空 → 权重和 1 → Judge0 健康。三态：已闭合 / 可执行 / 被前置阻塞。
- **`weight: 0` 提示不拦截**：客户端规则不严于服务端。
- **知识点创建后只读**：`DefinitionUpdateRequest`（`experiments.py:66-71`）本就不接收 `knowledge_node_ids`，所以只能在创建前选 —— UI 明确说出这一点，而不是让教师后面才发现改了没用。
- **语言至少保留一种**：`toggleLanguage` 拒绝取消最后一项，避免进入"白名单为空"的版本创建死路。
- **版本不可变显性化**：版本历史列表标出「学生使用中 / 已锁定 / 可继续配置」；内容未改动时「创建版本」按钮禁用并说明原因。
- **用例身份用自增 id**：旧版 `:key="`${index}-${testCase.is_hidden}`"`（`:398`）以数组下标作 key，删一行会让后续所有行重建，中文输入法的候选状态会断。

## 6. 值得保住的设计

重写时明确保留、不要顺手删掉的东西：

- **服务端才是唯一权威**。`ExperimentPublishValidator` 把发布前置条件集中在一处，前端这次只是镜像它，没有自己另立一套规则。这个结构要守住。
- **参考解源码不落库**（`experiment_service.py:461-466` 注释）：源码只在请求内存里，不产生 run/artifact/agent 记录。UI 里也明确写了这一点，别改成"保存参考解"。
- **权重不参与判定**：注释「权重用于完整性校验，正式结果仍是全量通过或未通过」在 UI 里保留了。这是 ACM/ICPC 语义的诚实表达，不要因为界面上有权重输入框就让用户以为它影响得分。
- **`passing_score` 恒为 1.0**：`VersionCreateRequest` 用 `ge=1.0, le=1.0` 把它钉死。UI 不提供这个字段是对的。
- **知识点只在创建时写入**：`DefinitionUpdateRequest` 不接受该字段。这是有意的（避免改绑后历史证据归错节点），不是漏实现。
- **Nexus 的 SWE-ReX / Judge0 双沙箱边界** 与本次无关，未触碰。
