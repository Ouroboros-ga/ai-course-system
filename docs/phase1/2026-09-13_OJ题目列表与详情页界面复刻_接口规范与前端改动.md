# OJ 「题目列表页 / 题目详情页」界面复刻 — 接口规范与前端改动清单

> 2026-09-13 · 触发：家良提供两张参考截图（洛谷题库列表页 / 题目详情页），
> 要求把 `/app/oj/problems/` 两页复刻为截图所示的布局、组件结构与视觉风格。
>
> **已确认的三条边界**（2026-09-13 拍板，实现以此为准）：
> 1. **结构复刻 + 彩色标签，底色沿用系统**：布局 / 组件 / 信息层级严格照截图；
>    页面底色、顶栏、按钮沿用 `design.md` 的 Academic Ink 令牌；只有承接语义的
>    彩色元素（难度标签、算法标签、通过率条）改用洛谷色板。**不改 `design.md`，不动全局令牌。**
> 2. **题号取「课程内序号」**，由前端派生（`#001` 形式），零后端改动。
> 3. **难度保持三档**（`easy` / `medium` / `hard`），用洛谷色板着色，标签文案显示洛谷区间名。
>    不引入七档 —— PR-09 已有测试钉住「本域拒收 1–5」，改七档会击穿该断言并使已上线题目全部需重标。

## 二、接口规范表

统一约定：`baseURL = /api/v1`，OJ 全部挂在既有前缀 **`/experiments`**（ADR-0001 决定 ⑥：**不引入 `/oj` 前缀**）；
统一信封 `{ code, message, data }`；学生侧权限 `experiment.view`，教师侧 `experiment.configure`。

### 2.1 已有接口（无需改动，本次直接消费）

| # | 接口名称 | 请求方式 | 路径 | 请求参数 | 返回字段（`data`） | 说明 |
|---|---|---|---|---|---|---|
| A1 | 学生题库列表 | `GET` | `/experiments/course/{course_id}/problems` | `search`、`difficulty`、`tags`（逗号分隔）、`status`、`page`、`page_size` | `items[]`：`experiment_id` / `title` / `description` / `difficulty` / `tags` / `pass_rate` / `attempt_total` / `my_status` / `my_best_score`；`total` / `page` / `page_size` | 只列 `PUBLISHED` + `visibility=course_catalog` |
| A2 | 学生题目详情 | `GET` | `/experiments/course/{course_id}/problems/{experiment_id}` | 路径参数 | `experiment_id` / `title` / `description` / `difficulty` / `tags` / `language_whitelist` / `limits{cpu_time_limit,memory_limit,wall_time_limit}` / `starter_code` / `samples[{name,input,output}]` / `stats{attempt_total,passed_total,pass_rate}` / `my_status` / `my_best_score` | **不含任何 hidden testcase**；`samples` 只含 `is_hidden=false` |
| A3 | 我的提交 | `GET` | `/experiments/course/{course_id}/submissions` | `experiment_id` / `outcome` / `language` / `date_from` / `date_to` / `limit` / `offset` | `items[]`（`run_id`/`outcome`/`passed_count`/`total_count`/`cpu_time_ms`/`submitted_at`…）、`total` | 只认本人 |
| A4 | 判题语言列表 | `GET` | `/sandbox/languages` | — | `languages: string[]` | 语言下拉数据源 |
| A5 | 自由运行（样例「运行」用） | `POST` | `/sandbox/course/{course_id}/execute` | `language`、`source_code`、`stdin` | `status` / `stdout` / `stderr` / `exit_code` / `time_ms` / `memory_kb` | 样例「运行」= 把样例 `input` 填进 `stdin` 后调此接口 |
| A6 | 课程列表 | `GET` | `/experiments/courses`（经 `listExperimentCourses`） | — | `[{course_id, title, …}]` | 「所属题库」tab 行数据源 |

> 结论：**列表页与详情页的骨架，用 A1–A6 已能完整渲染。** 下图是「像不像」与
> 「好不好用」的增量缺口 —— 属于 P1/P2，不阻塞本次复刻。

### 2.2 需新增 / 扩展的接口（P1，建议下一批）

#### B1 扩展：`GET /experiments/course/{course_id}/problems`

| 类型 | 参数名 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|---|
| 新增 | `search_in` | string | 否 | `title` | 关键词匹配范围：`title`（现行）/ `statement`（题面正文）/ `both`。对应截图「搜索题面」勾选框 |
| 新增 | `difficulty_min` | string | 否 | — | 难度区间下界（`easy`/`medium`/`hard`）。对应截图「题目难度范围」区间选择 |
| 新增 | `difficulty_max` | string | 否 | — | 难度区间上界。与 `difficulty_min` 同时给出时用区间语义，`difficulty` 单值参数保留兼容 |
| 新增 | `tag_mode` | string | 否 | `and` | `and`（现行，全部命中）/ `or`（任一命中）。多维筛选场景需要 `or` |
| 新增 | `source` | string | 否 | — | 题目来源 / 所属题库（`codeforces` / `uva` / `atcoder` / `custom`…） |
| 新增 | `year` | int | 否 | — | 题目年份 |
| 新增 | `sort_by` | string | 否 | `default` | 排序列：`no` / `title` / `difficulty` / `pass_rate` / `attempt_total` |
| 新增 | `sort_order` | string | 否 | `asc` | 排序方向：`asc` / `desc` |

**返回字段增量**（`data.items[]` 每项新增）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `problem_no` | string | 课程内题号，如 `#015`。**服务端给出则为权威**；缺省时前端按目录顺序派生（本次实现走缺省分支） |
| `source` | string \| null | 题目来源 / 所属题库，用于「所属题库」tab 与标签着色 |
| `year` | int \| null | 题目年份 |
| `algorithm_tags` | string[] | 与 `tags`（自由标签）分离的**算法标签**，对应截图「显示算法标签」列 |
| `sort_index` | int | 课程目录内的稳定序号，供 `sort_by=no` 使用 |

> ⚠️ **为什么排序必须服务端化**：现行列表是**先分页、再返回**，前端排序只能排「当前页」，
> 跨页排序会给出错误的第 1 名。截图四列都可排序 → 必须由服务端在全量集合上排序后再分页。

#### B2 扩展：`GET /experiments/course/{course_id}/problems/{experiment_id}`

| 字段 | 类型 | 说明 |
|---|---|---|
| `problem_no` | string | 同 B1 |
| `source` / `year` | string/int | 同 B1 |
| `statement_locales` | string[] | 已提供的题面语言，如 `["zh"]`；驱动详情页「中文」切换器 |
| `statement_default_locale` | string | 默认语言，缺省 `zh` |
| `samples[].sample_id` | string | 样例稳定 id（样例「运行」的幂等键 / 埋点用） |

#### B3 新增（可选）：样例单跑

| 项 | 内容 |
|---|---|
| 接口名称 | 样例单跑（judge 侧比对期望输出） |
| 请求方式 | `POST` |
| 路径 | `/experiments/course/{course_id}/problems/{experiment_id}/samples/{sample_id}/run` |
| 请求参数 | body：`language`（string）、`source_code`（string）、`idempotency_key`（string，≤128） |
| 返回字段 | `run_id`、`status`、`stdout`、`stderr`、`expected_stdout`、`matched`（bool）、`time_ms`、`memory_kb` |
| 说明 | **P2 可选**。截图样例区「运行」需要「跑完告诉我过没过」；本次已用既有 A5（自由运行 + 前端比对）实现同效果，故**不阻塞**。B3 的价值是把比对放回服务端，避免前端拿到 `expected_stdout` 做判定的语义错位 |

### 2.3 明确不做的接口（诚实清单）

| 截图元素 | 为什么不建接口 |
|---|---|
| 「O2」编译优化级别 | 判题环境无该维度；**不造一个改不动的假开关**。界面渲染为只读状态位 |
| 题目「收藏 / 题解 / 讨论」 | 本系统无对应域，属**方案外新功能**，需单独立项（不在 OJ 整改 v3 范围内） |
| 批量多选的批量动作（批量加入作业 / 批量导出） | 无对应后端能力；本次只实现**选择状态 + 顺序练习**（前端可完成） |

### 5.3 顺手修掉的一个既有 bug（不在本次范围内，但挡住了复刻）

**KaTeX 样式从未被引入**：`utils/markdownRenderer.js` 产出 KaTeX 的 HTML，但
`katex/dist/katex.min.css` 只在 `ChatPanel/MessageBubble.vue` 与 `PptPlayer/PptContent.vue`
里 import 过。结果是**任何非聊天页面**渲染带公式的 markdown 时，本该被 CSS 视觉隐藏的
无障碍回退层 `.katex-mathml` 会直接显示 —— 公式变成「渲染结果 + 原始 TeX」两遍叠在一起。
修法：把 CSS 引用移到**产出方** `markdownRenderer.js`，所有消费方自动正确。

### 5.6 环境备注

`npx vite dev` 在本机**起不来**：本仓沙箱的 safe-delete 对 `node_modules/.vite/deps`
（67 文件 > 50 阈值）做 fail-closed 拦截，dev server 在依赖预构建阶段直接退出。
**绕过方式 = 先 `vite build` 再 `npx vite preview`** —— 服务静态产物，不做依赖预构建、不删文件。
这与既有的「`npm run build` 会被沙箱删保护拦」是同一类问题，均**不是代码缺陷**。
