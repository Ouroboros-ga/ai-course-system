# M5 前端冒烟报告

更新时间：2026-07-08

## 范围

M5 只确认前端构建、路由入口、页面组件存在性、前后端 API 契约和 8 月决赛演示风险。本阶段未重构 UI，未修改前端业务逻辑，未修改后端 endpoint/service/model，未调用真实外部服务。

## 命令结果

### build

第一次在受限沙箱执行：

```text
cd frontend
npm.cmd run build
```

结果：失败于 `Error: spawn EPERM`，发生在 Vite 加载配置时启动 esbuild 子进程。该结果属于当前执行沙箱限制。

提升权限后重跑同一命令：

```text
cd frontend
npm.cmd run build
```

结果：通过。

```text
vite v7.3.1 building client environment for production...
2153 modules transformed.
✓ built in 4.52s
```

build 警告：

```text
(!) Some chunks are larger than 1000 kB after minification.
markdown chunk: 1,271.47 kB, gzip 401.37 kB
```

结论：前端当前可以生产构建；存在体积风险，但不是构建阻塞。

### lint

第一次在受限沙箱执行：

```text
cd frontend
npm.cmd run lint
```

结果：失败于 `ERROR: spawn EPERM`，属于当前执行沙箱限制。

提升权限后重跑：

```text
cd frontend
npm.cmd run lint
```

结果：失败，停在 `lint:oxlint`。

主要错误分类：

- 空占位文件：`src/composables/useD3.js`、`src/composables/useCognitiveTracking.js`、`src/composables/useWebSocket.js`、`src/stores/cognitive.js`、`src/stores/agent.js`。
- 未使用变量/未使用 catch 参数：`src/utils/markdownRenderer.js`、`src/utils/request.js`、`src/composables/useStudentLearning.js` 等。

单独执行：

```text
cd frontend
npm.cmd run lint:eslint
```

结果：失败，`105 problems (105 errors, 0 warnings)`。主要包括未使用变量、空 catch 块、单词组件名、`vue/no-dupe-keys`、`vite.config.js` 中 `process` 未定义等。

注意：lint 脚本带 `--fix`，M5 执行后已确认没有遗留前端代码 diff；本阶段未为了 lint 通过修改业务/UI 代码。

## API 不一致与运行时风险清单

| 优先级 | 前端证据 | 后端证据 | 风险 | 8 月影响 | 建议 |
|---|---|---|---|---|---|
| P0 | `frontend/src/components/chat/player/SplitVideoPlayer.vue` 调 `getPlayerInitData()` 后判断 `response.data` | `backend/app/api/v1/endpoints/player.py` 的 `GET /api/v1/player/init/{course_id}` 返回 `PlayerInitData` 扁平响应，M4B 也按扁平响应锁定 | 统一 request 拦截器要求 `res.code === 200`，扁平响应会被当作错误；播放器页可能无法初始化 | 高，直接影响分屏播放器演示 | M5C 最小修复候选：统一前端播放器 API 适配扁平响应，或后端返回统一外壳；需先确认兼容策略 |
| P1 | `frontend/src/api/user.js` 定义 `POST /user/logout` | 当前后端路由清单无 `/api/v1/user/logout` | 若页面调用 logout API 会 404 | 中，取决于演示是否使用接口登出 | M5C 或 M6 明确登出策略：纯前端清 token，或补后端路由 |

## 影响 8 月决赛的前端风险

1. 分屏播放器 `/player/course/:courseId` 的初始化响应契约不一致是最高风险。后端接口存在，后端测试通过，但前端统一 request 可能拒绝扁平响应。
2. 如果演示 AI PPT 生成，`PPTGenerationDialog.vue` 的响应读取方式可能与统一 request 解包不匹配。
3. `npm run lint` 当前失败，说明前端质量基线未达成；但 `npm run build` 已通过，短期不阻塞构建演示。
4. `Knowledge.vue` / `KnowledgeProgressPage.vue` 未注册路由且内部 API 方法缺失，不能作为已接入演示页面。
5. SSO/泛雅路径前端和后端均存在，但依赖外部平台，不应在自动化或无准备演示中假定可用。

## 不影响当前演示但后续需要修复的问题

- 空占位 composable/store 文件导致 oxlint 失败，与禁止实现未来能力的范围冻结有关，建议 M6/M7 通过 lint 配置或删除未接入占位文件前先确认策略。
- `chat.js` 的删除聊天记录接口与后端不一致。
- `user.js` 的 logout 接口与后端不一致。
- 未注册占位页面和已注册主流程页面混在 `views/` 下，后续需要文档化区分。
- 前端 `request.js` 只支持统一响应，但后端仍有少量扁平响应，需统一契约或局部适配。

## 是否修改代码

M5 本轮未修改前端或后端业务代码。执行 `lint` 脚本时工具曾尝试自动修复一个正则转义，已立即回滚。当前无已跟踪业务代码 diff；`git status --short` 显示既有未跟踪 `.agents/` 和三份新增 M5 文档。
