日期：2026-09-07。审查基线：dev-liu / `45c31a22`。性质：只读代码审查与本地合成边界验证；未部署、未重跑线上实验、未读取生产凭据。本记录不替代原浏览器验收记录。

## 结论

产品方向符合：会话内 Experiment Console、阶段/步骤/退出码/日志/报告、独立 Cancel、非交互式终端，均沿着已冻结的 NexusLab 设计实现。Building/Verifying 的 skipped/not_applicable 口径也保留了 preset runner 与完整 A/B 平台的区别。

主流程验收有价值，但当前不宜表述为“边界完备、测试全绿”。本轮确认 6 项问题，其中取消失败被当作成功、日志缺少真正脱敏、长行输出破坏执行结果，应先于 NX-H1/NX-R1 扩展处理。Worker 重启对账仍属明确延期的 NX-E4，不计为本批缺陷。

## 审查发现

### F1 / P1：取消代理把 Worker HTTP 错误转换为已接受取消

位置：`backend/app/api/v1/endpoints/nexus_proxy.py:580–591`。

只对 404 特判，其他 JSON 响应无论 HTTP 状态都返回 200；缺少 status 时默认 cancelling。以实际函数和 HTTP MockTransport 验证，Worker 401、500 均被转换成 `200 / cancelling`。这会让用户看到取消已接受，而实验可能仍在运行。

修复验收：映射所有非成功响应；成功响应必须校验作业身份和合法状态；401、500、畸形 JSON、超时均不能展示已接受取消。

### F2 / P1：日志清洗没有实现凭据脱敏

位置：`backend/app/api/v1/endpoints/nexus_proxy.py:446–448`；Worker 原样采集日志。

当前只删除控制字符并截断长度。用合成 Bearer 和含口令 URL 调用实际函数，两者均完整保留。删除 ESC 也不等于完整去除 ANSI 转义序列。前端纯文本渲染可避免 HTML 执行，但不能代替脱敏；日志还可能随前端会话存储保留。

本次没有观察到真实密钥泄漏。风险条件是子进程/依赖输出凭据；当前子进程默认继承环境，因此不能以“预设执行”代替输出防护。

修复验收：在日志进入持久化及外发路径前完成脱敏；审计子进程环境白名单；用合成令牌、Authorization、URL 用户信息及 ANSI 序列验证，且不损坏普通训练指标。

### F3 / P1：长行日志可能使成功命令被记录为失败

位置：`deploy/repro-worker/worker.py:311–316,340`。

采集使用默认限制的 `StreamReader.readline()`，环形缓冲按整行移除。实际本地子进程输出 9000 字符单行，退出成功但日志变空；输出 70000 字符单行时，采集出现行长度 ValueError，步骤返回 exit_code=None，而非真实成功退出结果。

修复验收：按有界块持续读取并保留尾部；支持无换行/超长行；采集异常不能伪造执行退出码，并保证管道排空及进程回收。覆盖 9KB、70KB、持续无换行输出。

### F4 / P2：冷恢复遗漏取消中轮询和终态 Console 详情

位置：`frontend/src/app/pages/nexus/NexusPage.vue:425–450`；代理 `_merge_run_live`。

没有本地 turn 时，恢复代码初始化空步骤和日志，只对 queued/running 启动详情轮询。服务端清单没有提供完整 steps_result/live log。因此 cancelling 可一直停在取消中；succeeded/cancelled/failed 作业即使 Worker 仍存活，也没有补齐步骤日志。真实函数的 Node 隔离验证显示：cancelling、succeeded、cancelled 均为 0 次轮询，步骤为空；running 会轮询。

这与已经验收的“同浏览器运行中刷新恢复”是不同边界，也不是 Worker 重启丢内存问题。另有首次恢复网络失败后 Set 标记不清除、同页不能重试的相邻问题。

修复验收：恢复时为所有已知作业拉取一次详情；queued/running/cancelling 持续跟进；终态补齐历史；失败可重试；整个恢复过程不重新提交实验。

### F5 / P2：创建子进程期间的取消存在竞态

位置：`deploy/repro-worker/worker.py:325–335,671–676`。

cancel 在 await 创建进程期间到达时，记录尚无活动句柄，只写入取消标志。创建完成后注册句柄却不再检查该标志，导致命令仍可执行。用 Event 控制实际进程创建窗口，本地合成命令在取消之后仍输出并 exit 0，未记录 cancel_landed。

修复验收：获取进程句柄后立即重查取消请求，或通过锁/事件统一交接；确认回收后再置 cancelled。覆盖排队、spawn 窗口、运行中、终态重复取消。

### F6 / P2：Metric 完成事件目前代表产物扫描，不代表指标计算

位置：`deploy/repro-worker/worker.py:534–542`。

metric started/done 包围的是 `_collect_artifacts`；确定性指标判定在后续 Nexus 报告链。合成作业仅打印 hello、没有指标及产物，仍得到 metric done。

这不否认已验收 nanoGPT 报告的确定性 PASS，但阶段语义不满足“真实边界事件”的产品约定。

修复验收：明确区分执行成功、产物收集、指标提取/判定；无指标应待判定或缺失，不能仅因扫描完成就标记 Metric 完成；真实比较完成后再更新该阶段。
