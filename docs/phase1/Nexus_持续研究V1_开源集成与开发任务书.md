# Nexus 持续研究 V1：开源集成与开发任务书

> **重要设计参照／下一批排期依据，2026-09-07。** 根据本轮用户确认的“输入理解—证据驱动拆解—自主研究—按需实验—正式成果”要求编写。当前本地基线 a60d4e87；本文为规划，未实现能力不能翻为CURRENT。沿用项目AGENTS.md；只在批准范围内执行，本文不授权安装依赖、提交推送或部署。

**Goal：**优先交付用户一次确认后自主配置环境、准备数据、运行与排错的实验闭环；同时建设能够主动补查和调整计划的持续研究能力，并接入Markdown/LaTeX/Word成果交付。

**Architecture：**一个Nexus主智能体，Research配置接入受限研究子任务；沿用Deep Agents与LangGraph状态和执行机制。自主语义决策来自模型，权限、预算、状态转换、引用有效性和执行判定由服务端强制。实验是获取证据的一条分支，不是所有研究任务的必经路径。

**Tech Stack：**优先现有Deep Agents/LangGraph/Postgres、Backend附件与对象存储、SearXNG/arXiv；新增科研RAG、执行、构建、文档转换组件按版本核验和实测选择，保持Nexus/Backend独立依赖树。

## 1. 用户结论的正式冻结

### 1.1 本轮纠正：一次确认，沙箱内自主完成

产品的首要价值是替教师和学生完成配置环境、准备数据、运行与排错。用户给论文/仓库并说“帮我跑起来”，系统自动读取资料、识别需求，展示简短的实验目标、使用资源和外部访问说明；用户点击一次“开始实验”，智能体即可在本任务的可销毁沙箱内持续下载公开且允许使用的数据/代码、安装依赖、修改环境与启动脚本、运行、诊断、重试并整理成果。已有的有效实验授权继续生效。

**不要求先完成完整文献综述、填满研究字段、证明某结论、或得到“证据充分”评分才允许做实验。** 缺少信息时先自主查找或试验；实验本身就是查明问题的方式。只在确实缺少用户才能提供的数据/凭据、需要改变用户实验目标或超出已确认资源/访问范围时请求用户决定。

四个词只对应具体记录，不建四套审批系统：

| 内部词 | 具体含义 | 用户是否要处理 |
| --- | --- | --- |
| 证据 | 论文第几页/哪张表怎么写；本次运行用了什么数据、输出什么日志和指标 | 自动记录，报告可查看；不要求上传“证据包”或逐条确认 |
| 主张 | 要验证的一句话，例如“按论文设置能否得到表2的准确率”；配置环境任务可以没有此字段 | 从请求/论文提取；缺失不阻止配置或试跑，不单建主张审批 |
| 权限 | 此任务可在自己的沙箱内读写/安装/运行，可用哪些已授权数据和网络；不能操作别人文件和宿主业务服务 | 用户一次启动确认；日常工具调用继承，不逐命令询问 |
| 预算 | CPU/GPU、内存、磁盘、最长运行时间，以及已配置付费服务的金额上限 | 平台给可用默认值，确认卡简要展示；不是每一步做预算表 |

**确认的是实验目标、可用数据/访问范围、资源上限和允许自主配置排错，不是提前写死所有shell命令。** 修改依赖版本、安装缺包、修路径、调整启动命令、重建沙箱、在相同目标下重试属于默认授权内行为，自动记录即可。替换目标数据集、降低验证标准、改实验问题不能悄悄改变；所需额外付费/GPU/私有访问不在原授权内时才重新确认。用户可随时取消。

开发上保留不可变的授权记录，同时另存实际尝试的配置与命令。授权范围没有改变，尝试版本变化不使授权失效；最终验证B前再冻结成功配方。现有preset精确计划指纹仍保留，新增自主实验用不同的提案类型接同一审批服务，不能直接删掉旧指纹校验。

这是产品用户的实验授权，和开发人员安装平台依赖/部署服务的仓库授权不同；后者继续遵守AGENTS.md。

### 1.2 Research专属Ask / Auto（NEXT）

只在Research输入区显示Ask/Auto。两者都支持自主多步骤规划、资料搜寻/补查、读论文、研究子任务与各种格式文档输出；唯一差别是Ask不能调用实验代码沙箱，Auto可在一次确认后自主配置、运行、排错。Ask不是每次搜索都征求确认的模式。默认Ask，切Auto不等于批准实验，格式是否已经实现对两者采用同一口径。

Ask可阅读已有实验日志并输出分析、配置脚本或报告，但不执行脚本；固定文档转换服务仍可使用。切Ask不自动终止已批准的run，后续新请求不能借旧run执行新命令；用户可随时取消。界面、请求字段与服务端校验详见[前端规格§2.1](Nexus_AI_前端开发规格与UX落地说明.md)。

### 1.3 研究行为参照

以下作为实现评审的重要参照，不能在任务拆分时再次降为“上传+Todo+更多工具”：

1. 能上传文件不等于理解输入；需要理解文档、表格、公式、图表与用户问题的关系，并说明实际读取范围。
2. Todo只投影当前任务清单；研究状态还要表达目标、证据、矛盾、缺口、预算和停止原因。
3. 首轮结果不足时主动补读/补查；发现条件不可比或证据冲突时调整计划，而非机械勾完原清单。
4. 子任务用于独立研究和上下文隔离；首版一种受限researcher足够，不堆砌角色名称。
5. 实验首次启动确认后，在任务沙箱内自主配置、安装、运行、排错和重试；按§1.1判断是否真的越出授权范围，不能因命令或依赖变化重复审批。
6. 实验结果必须回到研究问题：它支持/削弱哪个假设，仍缺什么，是否要继续研究。不能生成报告后流程就失去原始目标。
7. 最终成果区分原文支持、综合推断、摘要级支持、未解决问题；同一冻结内容交付Markdown、LaTeX和可编辑Word。
8. 持续执行有边界：证据足够、预算耗尽、连续无新信息、缺少必要用户决定、等待审批时结束或暂停，并保存可恢复的部分成果。

## 2. 开源复用决策：不把参考示例当成生产认证

本轮查阅的官方资料如下。候选的功能说明不等于某个版本已满足Nexus生产要求；实施前记录具体版本/commit、许可证、依赖、故障恢复和隔离测试结果。

| 项目/资料 | 复用层 | Nexus决策 |
| --- | --- | --- |
| [Deep Agents研究教程](https://docs.langchain.com/oss/python/deepagents/deep-research) | Todo、研究委派、读取与综合的示例骨架 | 首选改造起点；保留已有模型与搜索适配。示例中的Tavily/模型/本地文件写入不直接搬入产品 |
| [Deep Agents子任务](https://docs.langchain.com/oss/python/deepagents/subagents) | 隔离上下文的子智能体；可接编译图 | 显式配置一个只读researcher，核实本地版本的工具过滤和middleware装配，不默认继承全部权限 |
| [Open Deep Research](https://github.com/langchain-ai/open_deep_research) | 研究流程参考实现 | 参考简报、主管反馈与综合逻辑；不再部署第二个顶层主管。只有明确证明需要时才接受控子图 |
| [LangGraph模式](https://docs.langchain.com/oss/python/langgraph/workflows-agents)、[持久化](https://docs.langchain.com/oss/python/langgraph/persistence) | 图路由、子图、checkpoint/store | 复用框架执行机制；Nexus实现自己的领域状态和外部副作用对账，不自研调度引擎 |
| [PaperQA](https://github.com/Future-House/paper-qa) | 科学文献RAG与引用 | 作为论文证据Provider评估，必要时独立sidecar；不同时打开其不受预算控制的第二套研究主管 |
| [SWE-ReX](https://github.com/SWE-agent/SWE-ReX) | Agent执行运行层 | 作为SandboxProvider候选；只采用满足测试的部署后端，不因其支持本地运行就允许在主应用执行不可信代码 |
| [repo2docker](https://repo2docker.readthedocs.io/en/latest/) | 仓库到可运行环境的构建 | 作为EnvironmentBuilder候选；构建不等于论文指标验证，构建本身也在隔离和预算内 |
| [Pandoc](https://pandoc.org/MANUAL.html) | 文档转换与模板/引用输出 | NX-O1首选验证候选之一；复杂公式、Word编辑性、LaTeX编译需用实际样例验证，不能只因格式受支持就算产品完成 |

**Nexus必须自行负责的一等业务逻辑：**TaskBrief/Evidence/Claim、证据权限与撤销、读取覆盖范围、预算及动作授权、Reproduction Orchestrator、冻结配置/判定依据、产品事件、外部任务对账、成果版本与Artifact生命周期。这些不是应当删掉的“多余胶水”。

**不得重复建设：**第二套图调度器、Todo引擎、通用向量库/对象存储、通用容器shell执行器、通用文档格式转换器。已有能力可适配时先适配；不为“代码行数少”省掉必要业务校验。

生产采用门：兼容锁定版本、明确许可、可运行小样例、隔离与并发测试、升级/回滚方案、日志与资源上限、可恢复失败语义。没有通过门的组件只标候选。官方示例代码涉及文件写入与联网时必须改接现有Artifact和受控读取工具。

## 3. 总体循环与状态契约

```text
输入材料 + 用户目标
  → TaskBrief（目标/交付/约束/完成条件）
  → 子问题与初始计划
  → 检索/阅读/研究子任务
  → 更新证据、主张、矛盾与缺口
  → 选择下一动作
      ├ 补查 / 精读 / 修改计划 / 委派
      ├ 形成实验准备 → 等待批准 → Sandbox执行 → 结果回流
      └ 收尾 / 请求必要输入 / 预算停止
  → 冻结成果 → Markdown / LaTeX / Word
```

最小研究状态（存Nexus域；完整原始模型思考不保存）：research_id、owner/session、revision、brief、questions、evidence_refs、claims、contradictions、gaps、selected_action、decision_summary、budget_used/remaining、stop_reason、linked_preparation/proposal/run/output_ids。

brief必须含objective、scope、constraints、deliverables、success_criteria、unresolved_inputs。模型对用户含糊指令作假设时记录assumptions；只对决定下一步且无法自行查明的信息提问。General简单问题保留轻路径，不强制研究工作流。

Claim包含statement、evidence_ids、support_type（direct/inference/abstract_only/unsupported）、limitations。模型的support_type是待审评估，不是形式化事实证明；服务端校验引用存在/归属/有效性，独立质量评估检查证据是否真正支持主张。

模型下一动作限制为 search/read/delegate/replan/propose_experiment/synthesize/ask_user/stop，使用结构化输出；代码检查条件和预算后执行。格式无效最多一次结构修正，仍无效返回可恢复错误，不无限重新调用模型。

运行上限由平台根据可用资源提供默认值，并在启动时简要展示；任务及子任务共享计量。撤回此前未经实测的“3轮/24次/180秒”产品硬限建议，这些不能直接成为长任务的停止标准。工具超时与重复失败保护保留，但读取没有新发现时可换路径或试验，不机械要求用户再次审批。达到真实时间/资源上限时保存工作区或可恢复配方和部分成果，明确说明停止原因。

停止条件不是“引用达到三条”或“模型自评高分”。关键子问题有证据覆盖且无未声明的关键矛盾才能正常收尾，否则交付部分结果并说明不足。

- [ ] 事件含session/request/research/parent_task与revision；按发起会话归属，旧事件不能覆盖新状态。v6只增加必要状态消费，不重新设计工作台。
- [ ] 服务端研究快照为事实源，刷新/换设备可恢复证据和任务；读失败保留缓存并标stale，不清空成成功空态。
- [ ] 实验/文档副作用登记与对账，恢复不再创建同一proposal/run/output。需要用户输入/审批时保存可继续状态，而非不断重新问相同问题。

V1验收：可以独立完成不需要实验的研究任务并保存有引用的研究成果；真实研究质量与离线协议测试分开记录。

## 9. SR5：自主实验执行（接N1–N4，最小闭环优先）

输入可以是用户直接提出的论文/仓库配置与运行请求，也可以是研究过程中产生的实验问题；hypothesis/claim_refs可选。无preset进入N1准备链，独立SandboxProvider经N2验收后才进入N3执行；不要求先完成SR2/SR3的完整综述才能配置环境。

- [ ] 实验前写明“这次测量将回答哪个子问题”、数据/对照/指标及可接受的证据边界；模型不能为了让实验通过自填宽松容差。
- [ ] 下载、静态检查和安装依赖权限分开；安装即可能执行代码，必须进入隔离构建。基于SWE-ReX/同类适配执行，基于repo2docker/同类适配构建，Nexus掌握业务审批与Verification。
- [ ] 按§1.1的一次授权自主完成构建、Smoke、排错、修改依赖/脚本、运行和重试；保存尝试记录而不逐命令审批。只有超出目标、数据/访问或资源授权才暂停；最终实际配方另行冻结。
- [ ] 报告/verifier输出作为新的实验Evidence接回研究状态，标识run/config/指标/范围；主智能体据此更新Claim和下一动作，不能由LLM改PASS/FAIL。
- [ ] Freeze/B结果明确验证范围。B未跑/失败/缺指标，不可说“论文已成功复现”。

验收：一个问题通过阅读即可收尾，Worker零调用；另一个问题先发现证据缺口，经过批准实验后调整原结论，验证结果确实影响后续计划。

## 10. SR6：冻结成果与三格式交付（与SR4起并行）

复用NX-O1，不重复建立输出服务。先固化经过引用和数值校验的成果版本，再渲染Markdown/LaTeX/Word；优先验证Pandoc及已有文档域适配，公式/表格/中文/引用/模板不合格则改适配而非让模型重写事实。

- [ ] LaTeX工程含所需资源并编译成功；DOCX为原生可编辑正文、公式和表格；Markdown引用可用。
- [ ] 编译/转换隔离、禁shell escape/宏/任意外联；部分格式失败返回partial，不影响已验证版本的其他产物。
- [ ] 三格式的结论、数值、引用与实验状态一致；不得为了版式删掉失败记录或未解决问题。

## 11. 任务顺序、边界与完整验收

下一批按[自主实验V1执行任务书T0–T7](Nexus_自主实验V1_执行任务书.md)具体实施：它细化本文件§1.1的一次授权语义、开源核心接入、文件范围、测试与真实验收；本文件保留持续研究的产品设计参照，不要求先建完全部研究模块才能开始实验。

下一批优先交付“一次确认后自主把实验跑起来”的纵向闭环：SR0必要修复→SR1最小输入理解与N1准备→N2独立任务沙箱→N3/SR5自主配置、运行与排错→实际结果和报告。SR2/SR3/SR4的完整研究循环并行或随后补齐，其完整验收不作为配置实验的前置门；最小运行记录、权限与恢复随实验链交付。SR6正式输出可并行，N4再用冻结配方完成干净B验证，最后进入NX-FINAL。

不要求一夜完成整个产品，不以token/时间预算耗尽冒充完成。代码任务按真实调用方小步完成；每任务先运行相关失败样例，再完成接线并验证，记录实测结果。缺依赖/权限时不擅自安装或降级目标，完成独立工作并记录具体阻塞。

限定修改：上述Nexus模块、Backend对应nexus代理/服务/显式迁移、最小前端协议消费和相关测试。保护用户未提交NexusPage修改；不得把整个项目重构、Teaching、课程权限、生产配置或新架构框架纳入本批。

自主实验首个必过样例：无硬编码preset的可运行公开仓库，合成缺包/路径故障，用户只确认启动一次，智能体完成安装、修复、重试、真实结果回收。断言授权范围内修复不弹第二次审批；额外付费/越界数据访问才请求决定；报告引用实际尝试与指标。

持续研究V1必过任务集：需求与输出约束保留；正文补查；矛盾导致重规划；独立子任务权限与预算；无新信息停止；中断恢复。后续SR5/SR6另验：无preset准备；有批准才执行；实验结果回流；三格式一致。每类明确离线与真实环境证据，不能只用一个合成nanoGPT或测试数宣称完整能力。真实模型质量评估使用经授权的人工验收或批准的评测环境，不将付费服务接入自动化测试。
