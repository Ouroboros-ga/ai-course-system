## 2. 新的产品契约

1. 有 preset：沿用已验收方案/审批/执行，不破坏 nanoGPT 基线。
2. 没有 preset：进入实验准备，不把“没有模板”当成整项任务无法协助。
3. 用户已明确论文/目标时直接推进；存在多篇歧义时只问最关键目标，不把可检索的环境信息全部交给用户填写。
4. 无执行能力也要返回真实准备成果：实验主张、来源、代码候选与版本、依赖/数据/资源清单、最小实验范围、未决问题与执行阻塞。
5. 许可证、可安装、可运行、指标达标、干净环境可复现是五种不同状态，不能互相替代。
6. 不承诺任意论文成功；遇到无代码、许可不清、数据不可得、需付费 API/GPU 等事实时如实保留证据和可继续路径。

## 4. N1 / NX-P1a：没有 preset 也能完成实验准备（持续研究后的实验分支）

### 4.1 输入与持久化成果

新增 Nexus 域 preparation 记录（使用显式迁移）：preparation_id、owner/session、version、paper_refs、objective、claim_refs、repo_candidates、selected_repo/revision、environment_requirements、data_requirements、resource_requirements、metric_spec、source_refs、missing_items、execution_blockers、status、created_at/updated_at。

论文输入支持已绑定 PDF 或明确论文标识；来源标题/标识不等于全文已读。初批在线候选发现复用 arXiv/Web；未提供或无法合法取得全文时，明确请求上传。仓库 revision 未取得不能填默认分支名冒充 commit SHA。日志/模型原始 Trace 不写准备记录。

status 最少区分 preparing、needs_input、draft_ready、blocked、failed；另设 execution_readiness（unsupported/needs_review/ready）。draft_ready 只表示准备报告可审阅，不表示可运行。草案允许缺失项，禁止强填环境、命令或指标。重试以 client_request_id 幂等，revision 乐观锁，刷新恢复不重新研究/执行。

### 4.3 工具/API/模块落点（规划接口，非现有能力）

- 工具：`prepare_reproduction`、`inspect_reproduction_repository`、`get_reproduction_preparation`；Research-only，消费服务端 owner/session，复用现有 Todo/事件，不创建 Subagent 引擎。
- API：`POST /api/v1/nexus/repro/preparations`（创建草案，不执行）、`GET /.../preparations?session_id=...`、`GET /.../preparations/{id}`、`PATCH /.../preparations/{id}`（expected_version，选择目标/仓库或补充事实，校验来源）。耗时准备沿用现有 graph/chat 入口和事件；不把 HTTP 创建记录等同于已完成研究。
- preparation 与现有执行 proposal 分开：现有 proposal 要求可执行 preset，不能为绕过限制制造虚拟 preset。后续 N3 校验通过才创建引用 preparation_id/version 的执行提案。

- 前端只为实际 preparation 数据增加摘要/缺口/报告引用，沿用 v6 会话与方案位置；不新增科研工作台页面，不在本批重做布局。

## 5. N2 / NX-S1：独立 SandboxProvider（选型验证可与 N1 并行）

- [ ] 对候选执行/构建组件逐版本核验许可、维护情况、Python依赖树、隔离/取消/日志接口；输出可运行小验证与 go/no-go，不仅写选型报告。新增依赖/服务安装前遵守授权。
- [ ] 统一 Provider 的 create/build/execute/status/cancel/collect/cleanup 语义；PresetWorkerAdapter 保留既有调用，新的不可信代码 Provider 必须有独立隔离边界。
- [ ] 执行实例按用户/run 隔离：非特权、无生产密钥/宿主业务挂载、磁盘/CPU/RAM/pids/时间限额、默认限制网络、禁止访问主服务与 metadata；容器管理能力仅在受控运行服务，不向模型/仓库暴露 Docker socket。
- [ ] 安装依赖和构建本身也视为不可信执行，不能先在 Backend/Runtime 中构建再放进沙箱。构建联网与运行联网分别设策略。
- [ ] 先用现有 nanoGPT 验证 Provider 的输出/取消/回收/报告一致性；随后使用经审核的合成仓库验证越界、超时、失败构建和无孤儿资源。
- [ ] 持久化 sandbox/run 外部标识与关键状态，重启只能查询/对账，不能重放未知执行；这部分与 NX-E4 共用一次实现。

完成标准不是“装上一个开源包”，而是应用确实经 Provider 创建隔离实例、受控执行、收集结果并清理，失败路径也可核验。

- [ ] Preparation→自主实验授权：固定实验目标、初始repo SHA、允许的数据/网络范围、资源上限和自主配置排错范围；依赖与命令允许沙箱内迭代，未知项通过实际构建查明，不以全部细节事先冻结阻止启动。保存每次尝试实际配方，最终B验证前再完整冻结。现有preset的精确指纹校验不变，新增自主实验提案类型。
- [ ] 经同一 LB2 提案/审批核销服务提交；未知仓库不经过旧 preset Worker。预算需覆盖 build、smoke、repair、execute 全程。

## 9. 完整版本的另外三条必需主线

以下不是等到 N4 结束再讨论的可选能力，应分别开发、最后汇合；N0–N4 本身不能作为整个转型完成的证明。

### 9.1 NX-H：复杂问题持续执行

- [ ] 保留简单 General 不强制计划；复杂任务能从目标、交付物、约束出发建立可执行子任务与完成标准。
- [ ] Observe/Re-plan：读取真实工具结果，发现证据不足、失败或矛盾后更新计划；保留已完成事实，不能只修改 Todo 文案模拟推进。
- [ ] 设置任务/工具/子任务预算和停止条件，超时/费用或资源条件不满足时返回部分成果及剩余项，不能无限循环。
- [ ] NX-H2 先交付受限只读子任务：独立上下文、工具白名单、父子结果引用；共享同一用户/会话授权，预算向下分配，取消向下传播。按需使用子任务，不要求每个问题强行并行。
- [ ] Workspace 的读写限定会话工作区；执行只走已验收 SandboxProvider。不得为启用 Subagent 顺便解除宿主文件/execute 限制。
- [ ] 任务结束需要检查原始交付要求，输出结论、证据、文件、未完成项；工具调用成功或 Todo 全勾不等于用户任务完成。

验收：一个需要多来源分析但不运行实验的复杂任务，一个工具失败后重规划任务，一个证据冲突任务，一个任务取消/部分交付任务；有真实行为与最终成果，不仅验证 write_todos 注册。

### 9.2 NX-R1 完整 Paper Research

- [ ] Research Question→候选→全文获取/导入→问题相关证据→跨论文比较→矛盾/证据缺口追查→综合→引用。不能只为实验准备查一段 README 就称深度研究完成。
- [ ] 对 PaperQA/同类成熟组件做限定样例选型验证，复用基础设施；保留 Nexus 的权限、证据生命周期、引用与 Artifact 业务边界。
- [ ] 区分已检索、只读摘要、读过哪些正文范围；论文标题匹配、全文覆盖、引用正确性、结论支持程度分别验收。
- [ ] 输出能独立作为研究报告使用，也能作为 N1 输入；同一证据重复使用不要求用户手工搬运，撤销/过期仍在消费时校验。

验收：多篇真实论文中的方法/数据/指标比较，包含至少一处证据不足或相互冲突；综合结论逐项能回到来源，不能用伪引用补齐报告。

### 9.3 NX-E4 长任务与会话恢复

- [ ] 服务端保存必要产品状态和有界事件/游标；计划、研究任务、preparation、proposal、run、输出作业关联同一会话与用户。
- [ ] 请求去重与关键执行状态跨进程重启可对账；不确定状态不得自动重放。检查父任务/子任务/文档生成作业的恢复，而不只检查聊天文字是否还在。
- [ ] 刷新/换设备恢复来源、计划、阶段和产物引用；正在执行、暂停、失败、取消、部分完成分别如实投影。
- [ ] 不持久化完整原始模型 Trace/隐含思维；产品需要的消息、结构化证据和运行事实沿独立域及生命周期保存。

验收：研究中刷新、Worker失联后对账、Runtime重启后恢复、文档渲染中断后重试、两设备并发、撤销及跨用户隔离；均不能出现重复提交实验或错误宣称完成。

## 10. NX-O1：正式成果输出（NEXT，首个完整版本必交付）

### 10.1 当前事实与新的验收定义

本次代码核查：`nexus/src/nexus/tools/artifact.py` 和 `backend/app/services/nexus_artifact_service.py` 支持 markdown/latex 纯文本，后者映射 `.md`/`.tex`。现有研究报告工具写 Markdown。没有 DOCX 生成和 LaTeX 编译验证，所以“保存了.tex文件”不能计为正式LaTeX交付完成。旧 P0 的 DOCX no-go 只属于历史冻结范围，本阶段用户明确要求 Word，现提升为必做。

| 输出 | 必交付内容 | 验收 |
| --- | --- | --- |
| Markdown | 完整正文、来源引用、图表链接与资源引用 | 可下载，链接/引用有效；作为已有基础能力保留 |
| LaTeX | main.tex、所需bibliography、图表资源、编译说明/模板版本；多文件时打包 | 在声明的固定工具链下编译成功，附PDF预览；正文/公式/引用可核对，不能只交代码块或改后缀 |
| Word | 真正的.docx二进制文件，标题层级、段落、列表、表格、图题、引用和原生可编辑公式 | 可在声明支持的Word版本打开/编辑；渲染检查无溢出、缺字、公式损坏；不能整页截图贴进Word |

PDF 是 LaTeX/Word 渲染校验与预览产物，不替代用户要求的源文件和可编辑DOCX。PPTX、期刊投稿系统集成、任意模板全兼容仍为后续增强。

### 10.2 一份内容，多格式交付

- [ ] 使用结构化成果快照表示 sections/paragraphs/equations/tables/figures/citations 与来源证据、run/config/metric引用。先核查现有文档域中间表示，能扩展就复用，不平行新建通用文档平台。
- [ ] 内容组织可以由模型协助，但输出前冻结 content_version/hash。三种格式由同一内容版本渲染，不让模型分别重写三遍产生数值、结论或引用差异。
- [ ] 证据引用用受校验的稳定ID，服务端生成编号/书目/定位；缺失引用不得生成“验证成功”的文档。格式转换不能提高原结论可信度。
- [ ] 实验实测值、配置、PASS/FAIL/EXPLORATORY/INCOMPLETE来自冻结运行与verifier，模型不改数值和阈值；B未运行时文档不得自动增加“已复现”的措辞。
- [ ] 学术/实验报告具备问题、资料与范围、方法、结果、讨论、限制、参考资料；普通General任务使用合适结构，不强制科研章节。
- [ ] 表格、公式、中文/英文、图题/交叉引用使用明确支持子集；不支持的公式/对象返回诊断，不静默截图或丢弃。

### 10.3 工具、服务与数据契约

- 规划入口：`create_document_output`，参数包括当前成果引用或内容、formats（markdown/latex/docx）、template_id；用户明确要求Word/LaTeX时进入实际生成链，不能回答“请自行复制到Word”。权限跟随源会话/材料/运行。
- 规划API：`POST /api/v1/nexus/document-jobs`、`GET /document-jobs/{id}`、`POST /document-jobs/{id}/cancel`；复用已有任务基础设施实现有限异步渲染，不为三个格式建立三套队列。
- 作业字段：owner/session、client_request_id、source/content_version/hash、template/renderer版本、formats、每格式status/diagnostics/artifact_refs、整体状态及时间。单格式失败不冒充整体成功，重试只处理失败格式；同键内容不同返回冲突。
- 状态：queued/rendering/validating/succeeded/partial/failed/cancelled。只有文件生成并通过该格式校验才返回可用Artifact链接；用户可看见partial，明确下载哪些格式、哪些失败。
- 文件复用既有对象存储，元数据仍在Nexus域；扩展Artifact类型/MIME/下载/大小限制与关联，DOCX走真正二进制内容路径，不能沿用纯文本content接口伪造文件。
- owner/session及原始材料访问校验覆盖生成与重试；失效源不能用于新作业。源材料撤销后既有文档按明确产品保留/删除政策处理，不擅自扩大或无限保存原文。
- Runtime工具只编排，Backend沿现有身份/Artifact服务承接；渲染组件按现有部署/依赖核查后选择，Nexus与Backend不共享venv。新增工具依赖和服务需批准后安装。

### 10.4 渲染安全、模板及校验

- [ ] 模板先支持“研究综述、实验验证报告、通用技术文档”三类，统一标题、字体、引用、图表样式；自定义期刊模板不作为首批验收要求。
- [ ] LaTeX及文档转换在受限渲染执行环境完成，不在主应用进程执行不可信命令；禁shell escape、宏执行、任意网络/宿主文件读取，仅允许本次已授权资源，限制时间/内存/文件数/输出大小。
- [ ] 渲染环境与实验环境职责分开，不能因文档生成需要编译器就开放研究实验任意执行。
- [ ] LaTeX验收无未解析引用、缺失图表和编译错误；中文字体/数学公式覆盖支持清单。编译失败允许有限修正，但修改数学/事实内容需要保留版本，不能为通过编译删掉实质段落。
- [ ] Word检查文件结构、样式、表格/公式可编辑性；逐页渲染复核断页、宽表、长链接、图题/脚注/目录。PDF预览成功不等于Word可编辑性通过，两者分开检验。
- [ ] 三格式对照同一事实清单、引用清单和数值，图表取真实输入；未取得时序数据不画虚构实验曲线。

### 10.5 输出验收样例与排期

必测三份成果：中英混排技术说明（公式/表格/列表）、多论文综述（编号引用/定位/图题）、实验报告（冻结配置/指标/失败与探索性结果）。每份同时生成三格式，验证内容一致、可下载及可编辑/编译。

失败样例：无效citation、被撤销图片、恶意TeX指令、无法支持的公式、渲染超时、单格式失败、并发重试、断流/重启、他人下载。在线效果验收前先使用合成数据和固定内容测试渲染，避免为了测试格式调用付费模型。

排期：NX-O1对应持续研究任务书SR6；在N0引用/生命周期修复且SR2证据与冻结成果结构稳定后，可与SR4恢复及后续N1准备链并行开发；不必等N4全部完成，先让真实研究/准备报告能交付Word/LaTeX，再接实验验证报告。只有研究/实验逻辑与渲染均验收通过才宣称完整成果输出。
