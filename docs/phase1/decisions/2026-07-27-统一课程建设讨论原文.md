## 1. 统一上传入口

正式保留：

```text
POST /api/v1/document/course-imports
```

旧 `/document/upload` 改成兼容转发，最终删除其同步解析、直接写 `CourseScript`、自动 TTS 等旧逻辑。

上传成功后立即返回：

```json
{
  "course_id": 85,
  "task_id": "task_xxx",
  "run_id": "dpr_xxx",
  "status": "processing"
}
```

浏览器离开不影响当前解析任务。Demo 阶段可以接受后端重启导致任务中断，但重启后至少要把残留的 `running` 标记成：

```text
interrupted
解析因服务重启中断，请重新解析
```

不用自动恢复，但不能永远显示“解析中”。

## 2. 正式解析矩阵

按你确认的策略执行：

| 输入 | 处理方式 |
|---|---|
| PPTX | NativePptx 提取结构；图片型页面用 PaddleOCR |
| PDF | PdfPlumber 提取原生文本；每页渲染并执行 PaddleOCR，再进行结果融合 |
| 图片 | PaddleOCR 主解析 |
| DOCX | PythonDocx 提取语义结构，同时转 PDF 获取页码、坐标及 OCR |
| DOC | LibreOffice 转 PDF，再执行 PdfPlumber + PaddleOCR |

PaddleOCR 使用独立解析服务，避免污染主后端 Python 3.12 环境：

```text
Backend
→ DocumentOcrPort
→ 独立 PaddleOCR 服务
```

主后端只消费稳定 JSON，不依赖 Paddle 运行时。

```text
课程
├─ 章
│  ├─ 节
│  │  ├─ 知识点
│  │  ├─ 示例
│  │  └─ 练习建议
```

输出必须包含：

```text

```

对应建设页：

```text
/app/course/{course_id}/build/structure
```

页面需要从现在的“只读旧 ScriptNode”改成真正编辑器，至少支持：

- 新增、删除、重命名；
- 拖动排序；
- 修改父级；
- 保存草稿；
- 查看来源；
- 接受或拒绝 AI 修改；
- 教师锁定节点。

## 6. 讲授脚本

结构形成后，由 AI 自动生成第一版讲解稿：

```text
审核中的课程结构
+ 对应 Evidence
+ 教师课程风格配置
→ TeachingScriptCandidate
```

对应：

```text
/app/course/{course_id}/build/scripts
```

每个节点的讲稿应支持：

- 直接编辑并保存；
- AI 重写、缩短、扩展；
- 选择解释风格；
- 查看引用来源；
- 接受、拒绝 AI 建议；
- 锁定教师版本；
- 保留简单版本历史。

自动生成后仍是草稿，但不要求每一段都单独点击“通过”才能保存。更实用的交互是：

```text
AI 初稿默认进入编辑器
教师可直接修改
最终点击“确认本步骤”
```

后续 Agent 提出的改动才使用绿色/红色差异框。

## 7. 备课 Agent

小悬浮窗的设计合理。它应通过受控 Tools 修改草稿，而不是直接写数据库：

```text
DraftRagSearchTool
WebSearchTool
GraphDraftTool
StructureDraftTool
ScriptDraftTool
PptGenerationTool
MediaGenerationTool
```

工作流：

```text
教师：“把第三章改得更适合零基础学生”
→ Agent 读取草稿结构和可信 Evidence
→ 生成 Patch Proposal
→ 页面显示修改差异
→ 教师逐项或批量接受/拒绝
→ 接受后写入新草稿版本
```

Patch 应是结构化数据：

```json
{
  "proposal_id": "proposal_x",
  "operations": [
    {
      "operation": "replace",
      "target": "script_node_12.content",
      "before": "原内容",
      "after": "建议内容",
      "reason": "降低术语密度",
      "evidence_refs": ["ev_01"]
    }
  ]
}
```

前端表现：

- 新增内容：绿色边框；
- 删除内容：红色边框和删除线；
- 修改内容：左右或行内 Diff；
- 每项提供接受、拒绝；
- 页面顶部提供全部接受、全部拒绝；
- 教师手动编辑后，以教师内容为准。

WebSearch 的内容必须标记为“外部补充资料”，不能伪装成课程原文。

## 8. 页面映射和 AI PPT

你的规则可以冻结为：

- PPTX：自动生成知识点—幻灯片映射，允许教师调整。
- PDF、DOCX、DOC：保留 Citation 页码，但建设页面不显示“教学 PPT 映射”步骤。
- 没有 PPT 时提示教师：

```text
上传现有 PPT
或
根据已确认的课程结构和讲授脚本生成 PPT
```

科大讯飞 AI PPT 输入应只使用教师已确认的数据：

```text
确认后的课程结构
+ 确认后的讲稿
+ 课程主题/风格
→ AI PPT 任务
→ PPT 草稿
→ 教师预览与确认
→ 新 SourceMaterialVersion
→ 再次解析并建立页映射
```

生成出来的 PPT 不能绕过解析链直接成为正式课件。

## 1. PaddleOCR 随主后端启动和关闭

建议用“统一启动脚本管理两个独立服务”，不要让 FastAPI 生命周期直接启动 PaddleOCR。否则 Uvicorn 多 Worker、热重载时可能重复启动多个 OCR 进程。

目录规划：

```

├─ Dockerfile
├─ compose.yml
├─ requirements.lock

└─ service/
   ├─ app.py

├─ dev-stack.ps1

```

Windows 本地执行：

```

```

脚本流程：

```
检查 Docker

→ 轮询 /health
→ 启动主后端 uvicorn
→ 捕获 Ctrl+C / 后端退出
→ 停止 PaddleOCR 容器
```

Linux 部署执行：

```

```

未来云服务器则直接用一个 Compose：

```
backend
paddleocr
judge0
postgres
redis
frontend/nginx
```

并通过：

```
depends_on:
  paddleocr:
    condition: service_healthy
```

控制启动顺序。

PaddleOCR 服务只开放内部接口：

```
GET  /health
POST /v1/ocr
POST /v1/ocr/pdf
```

```

```

- OCR 未启动：文件任务明确失败为 `OCR_SERVICE_UNAVAILABLE`；
- 主后端普通问答仍可运行；
- PDF/PPT 图片补充解析可以重试；
- 不回退到伪造 OCR 结果；
- 本地脚本退出时停止 PaddleOCR；
- 云端 Compose 统一 `down` 或由服务编排管理。

- CPU 推理配置；

## 2. Markdown 保存到资源库

同意。解析后的 Markdown 应成为课程资源，而不是只塞在解析任务返回值里。

正式关系：

```
SourceMaterialVersion
→ DocumentIR
→ Course Markdown
→ ResourceItem
→ ResourceVersion
```

现有资源模型已经有：

- `ResourceItem`；
- `ResourceVersion`；
- `course_id`；
- `ResourceScope.COURSE`；
- `object_key`；
- 内容哈希和版本。

因此可以直接使用：

```
resource_type = document
mime_type = text/markdown
scope = course
course_id = 当前课程
```

建议增加两个明确字段：

```
lifecycle_status = draft | published | archived
visibility = teachers | course_members
```

权限语义：

- 草稿 Markdown：仅课程 owner、teacher、assistant 可看；
- 发布 Markdown：所有有效课程成员可浏览；
- 非课程成员拒绝；
- 课程 A 成员不能读课程 B Markdown；
- Agent 修改 Markdown 时新增 `ResourceVersion`，不覆盖旧版本；
- 每个版本记录生成它的 `material_version_id`、`parse_run_id` 和 `source_block_refs`。

前端资源库显示：

```
课程资料
├─ 原始课件
├─ 解析版 Markdown
├─ 教学讲稿
└─ AI 生成 PPT
```

课程成员可以阅读和下载发布版 Markdown，不能编辑。教师在建设页编辑后保存新版本。

## 3. 当前系统是否真的支持“课程—章—节—知识点”

结论：**还不完整支持。**

当前有三套接近但不等价的数据：

| 当前模型                  | 能力                                | 缺口                                                    |
| ------------------------- | ----------------------------------- | ------------------------------------------------------- |
| `CourseScript/ScriptNode` | 有节点顺序、标题、内容、页码        | 节点是平铺的；`chapter_id` 只是字符串，没有 `parent_id` |
| `KnowledgePoint`          | 有 `parent_id` 和 `level`，能形成树 | 属于通用 `KnowledgeBase`，没有可靠的课程作用域          |
| `GraphSnapshotRecord`     | 按课程存储节点和关系                | 是图结构 JSON，不是受约束的有序课程目录树               |

所以当前 `/build/structure` 展示的是平铺 `ScriptNode`，不是真正的：

```
课程
→ 章
→ 节
→ 知识点
→ 示例/练习
```

应新增正式课程结构模型：

```
CourseOutlineVersion
- outline_version_id
- course_id
- version
- status
- created_by
- source_parse_run_id

CourseOutlineNode
- outline_node_id
- course_id
- outline_version_id
- parent_node_id
- node_type
- title
- order_index
- knowledge_graph_node_id
- source_block_refs
- generation_reason
- confidence
- locked_by
- content_hash
```

`node_type` 冻结为：

```
chapter
section
knowledge_point
example
practice_suggestion
```

课程本身不必再存为根节点，`course_id` 就是根作用域。

关系应这样理解：

```
CourseOutlineNode
├─ 决定教学顺序和目录层级
├─ 可关联 GraphNode
├─ 可关联多条 Evidence
└─ 可关联 TeachingScript
```

知识图谱仍负责：

```
先修
```

## 4. Agent 通过 Tools 修改

同意冻结为：

```
Agent
→ 读取草稿
→ 调用 StructureDraftTool / ScriptDraftTool
→ 创建 PatchProposal
→ 前端显示 Diff
→ 教师接受或拒绝
→ 写入新版本
```

Agent 不直接执行数据库 `UPDATE`。

建议 Tools：

```
CourseDraftReadTool
CourseRagSearchTool
WebSearchTool
OutlineProposalTool
ScriptProposalTool
MarkdownProposalTool
GraphProposalTool
PptGenerationTool
MediaGenerationTool
```

所有写操作统一返回 Proposal，包含：

```
before
after
operation
reason
evidence_refs
policy_version
```

教师手动编辑内容优先级最高；锁定后 Agent 不可覆盖。

## 5. 所有课程都显示“教学 PPT 映射”

同意。左侧七步导航始终保留“教学 PPT 映射”，但页面根据 PPT 状态切换。

### 有 PPT/PPTX

正常显示：

- 教学节点；
- PPT 页面预览；
- 自动映射；
- AI 语义匹配；
- 教师手动修改；
- 映射置信度；
- 保存和锁定。

### 没有 PPT

页面整体为灰色冻结态：

```
教学 PPT 映射

当前课程尚无可映射的 PPT 课件。

[ 上传现有 PPT ]

[ AI 智慧生成 PPT ]
  根据已经确认的课程结构和讲授脚本生成
```

其中：

- “上传现有 PPT”是主按钮；
- “AI 智慧生成 PPT”是次按钮；
- 下面的小字显示“根据课程结构和讲授脚本生成”；
- 课程结构或讲稿尚未确认时，AI 按钮继续禁用，并说明缺少什么；
- PDF/DOCX 的页码继续用于 Citation，但不激活教学 PPT 映射；
- AI PPT 生成完成后自动注册为新的 `SourceMaterialVersion`；
- 新 PPT 重新解析后，映射页面解冻；
- 生成服务失败不影响课程结构、Markdown 和普通教学功能。

当前 [BuildMappingPage.vue (line 1)](E:/smartcarb/ai-course-system/frontend/src/app/pages/course/build/BuildMappingPage.vue:1) 已经有真实映射操作，但没有“无 PPT 时的统一冻结态”，而且目前仍绑定旧的平铺 `ScriptNode`。后续需要把它切换到新的 `CourseOutlineNode`。
