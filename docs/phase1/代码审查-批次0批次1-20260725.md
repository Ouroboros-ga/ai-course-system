## 二、阻塞性 Bug（建议优先修复）

### Bug-1：PracticePanel 选择题分支永不进入（阻塞 B1-3 主流程）

- 文件：[frontend/src/app/components/learn/PracticePanel.vue](file:///e:/smartcarb/ai-course-system/frontend/src/app/components/learn/PracticePanel.vue#L133)
- 现象：模板使用 `currentQuestion.options && currentQuestion.options.length` 判断是否渲染选择题选项
- 后端实际：[backend/app/models/question_bank_model.py](file:///e:/smartcarb/ai-course-system/backend/app/models/question_bank_model.py#L94) `options: dict = Field(default_factory=dict, sa_column=Column(JSON))` —— `options` 是 **dict**，没有 `.length` 属性
- 后果：所有题型（含 single_choice / multi_choice / true_false）都走「填空/简答」分支，学生看到的是 textarea 而不是选项按钮
- 后端判分逻辑仍能正常工作（按 `question_type` 走 `_normalize_objective_answer`），但 UX 严重退化
- 修复建议：
  - 改为 `currentQuestion.options && Object.keys(currentQuestion.options).length > 0`，并迭代 `Object.values(currentQuestion.options)`；或
  - 后端 `_serialize_question` 将 dict 转 list 后再返回；或
  - 统一约定 options 为 list（需迁移）

### Bug-2：多选题 v-model 类型不匹配

- 文件：[frontend/src/app/components/learn/PracticePanel.vue](file:///e:/smartcarb/ai-course-system/frontend/src/app/components/learn/PracticePanel.vue#L24-L144)
- 现象：`selectedAnswer = ref(null)`，但 multi_choice 用 `<input type="checkbox" v-model="selectedAnswer">`
- 后果：即使 Bug-1 修复，多选题也只能单选（checkbox 绑定到非数组会失效）
- 修复建议：根据 `question_type` 初始化 `selectedAnswer` 为数组（multi_choice）或单值（其他）

### Bug-3：record_scored_evidence 教师改分不更新旧证据

- 文件：[backend/app/services/cognitive_service.py](file:///e:/smartcarb/ai-course-system/backend/app/services/cognitive_service.py#L398-L404)
- 现象：通过稳定 `evidence_id` 找到 existing 后直接 `return existing`，不更新 `value / confidence / label / description`
- 后果：教师在 `grade_attempt` 改分后，`LearningEvidenceRecord.value` 仍是改分前的旧值；后续 `compute_cognitive_state` 读到的 `observed_performance_score` 基于过时数据
- 修复建议：existing 存在时更新可变字段，再返回
  ```python
  if existing is not None:
      existing.value = score
      existing.confidence = confidence
      existing.label = ...
      existing.description = ...
      existing.source = f"question_attempt:{attempt.judged_by}"
      session.add(existing)
      return existing
  ```

## 三、与 page-design.md 的差距

### 1. B1-3 练习闭环与 §12.6 PRACTICE 试一试的差距

page-design §12.6 要求 PRACTICE 首屏必须包含：

- 为什么进入这个实践
- 学习目标
- 任务说明
- 完成条件
- 返回课程位置
- 当前沙箱权限摘要

当前 PracticePanel 仅显示「试一试」标题、题目、进度、返回课程按钮，缺少上述上下文信息。属于 P0 最小闭环范围内的妥协，但未达到设计文档的完整验收标准。

§12.10 VERIFY 验证完成状态要求：练习完成后进入 VERIFY，展示「本次做了什么 / 获得了什么结果 / 哪些证据被记录 / 仍需关注什么 / 下一步」。当前 PracticePanel 只有「下一题」按钮，无 VERIFY 流程。

### 2. B1-2 笔记持久化与 §12.8 NOTE 的差距

page-design §12.8 要求：
- 自动保存草稿（✅ 已实现，800ms 防抖）
- 手动「完成笔记」后返回课程（❌ 未实现，无「完成笔记」动作）
- 关闭前若保存失败必须提示（❌ 未实现，`syncNoteToBackend` catch 块静默吞错）
- 保存成功后显示笔记入口（❌ 未实现）

当前实现是纯自动同步，未提供「完成笔记」语义动作，失败时仅回退到 localStorage 不提示用户。

### 3. B1-5 课程概览与 §11.1 的差距

page-design §11.1 学生概览要求 5 个区块：A 继续学习、B 课程进度、C 当前待办、D 最近课程回应、E 课程结构摘要。

当前 CourseOverviewPage 实现了 A/B/C/D，缺少 E「课程结构摘要」（设计要求「展示当前章前后位置，不在概览中加载完整知识图谱」）。

### 4. B1-4 LearningEvidence 与 §22.8 Experimental 标记

LearningEvidence 模型本身是正式评分证据（非实验能力），符合 §22.8 不需要标记为 experimental。但 `record_scored_evidence` 在教师未批改时不创建证据（`is_correct is None` 直接 return None），符合「禁止时长伪装掌握度」原则。
