## M4-M7 最可能阻塞

1. `app.main` 导入副作用会阻塞干净的 TestClient 基线。
2. `pytest.ini` 与 `backend/tests` 目录冲突会阻塞统一命令。
3. 外部服务单例对象分散在 endpoint/service，Mock 边界需要先统一。
4. 生产 SQLite 路径和启动建表逻辑需要避免被测试污染。
5. 前端没有现成测试框架，短期只能先做构建/路由/API mock 冒烟。
6. 旧测试中存在路由命名和 fixture 缺口，不能直接把“现有测试全绿”当基线目标。

## 建议：调整测试范围

建议保留原计划的 M4-M7 方向，但调整第一轮测试范围：

1. 第一轮只锁定 8 月决赛主流程：登录、教师上传/建课、脚本编辑、发布、学生选课、播放、问答、进度、前置知识跳转、PPT/TTS/数字人接口的 Mock 流程。
2. 不把计算机垂类、BKT、HMM、LSTM、GraphRAG、多智能体纳入测试实现范围。
3. 不追求真实外部服务质量指标，只验证调用关系、状态流转、错误处理和响应结构。
4. 先补“可发现、可重复、无外部付费调用”的最小基线，再考虑拆分大文件。
