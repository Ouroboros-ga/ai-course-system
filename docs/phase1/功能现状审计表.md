  未被修改。

## 批次0 API契约缺口决策记录（2026-07-25）

### logout 接口缺口

- **现状**：后端 `user.py` 无 `POST /api/v1/user/logout` 端点；认证为无状态 JWT（`security.py` 无 token 黑名单/会话存储）。
- **前端**：`api/user.js` 曾声明 `logout()` 指向 `/user/logout`，但全前端无任何组件调用（死导出）。
- **决策**：**移除前端死调用**。前端退出时仅清除本地 token 与登录状态（`PrimaryNav.vue`、`UserInfoCard.vue` 等已如此实现）。不补后端假端点——无状态 JWT 下 logout 端点无法提供真实撤销语义，补端点会造成"看起来完成"的假象（违反 AGENTS.md §3.2.4）。
- **证据**：`frontend/src/api/user.js` 已移除 `logout()` 并保留决策注释；全前端 grep `api.user.logout` 返回零匹配。

### 聊天记录删除接口缺口

- **现状**：后端 `chat.py` 仅有 5 个端点（history/messages/ask/create/quiz），无 DELETE 端点。
- **前端**：`api/chat.js` 曾声明 `deleteChatRecord(chatId, userId)` 指向 `DELETE /chat/{chatId}`，但全前端无任何组件调用（死导出）。
- **决策**：**移除前端死调用**。若后续需聊天删除能力，应先在后端补端点再恢复前端调用。
- **证据**：`frontend/src/api/chat.js` 已移除 `deleteChatRecord()` 并保留决策注释；全前端 grep `deleteChatRecord` 返回零匹配。
### 2026-07-28 受控备课 Agent 补充审计

- **现状**：新增 `POST /api/v1/course-editor/course/{course_id}/controlled-prep/run`，依次执行 `EvidenceSegmenter -> OutlinePlanner -> ScriptWriter -> EvidenceVerifier -> PatchCompiler`。
- **结构化约束**：`backend/app/schemas/controlled_prep.py` 使用 Pydantic `extra="forbid"`、字段约束、`model_json_schema()` 和严格 JSON 校验；LLM 失败只做有限次局部重试。
- **证据边界**：API 只接受当前课程的 ACTIVE `CourseEvidenceRecord` 或 CONFIRMED `EvidenceSpan`；未知、跨课程、失效 Evidence 直接拒绝，LLM 输出中的 Evidence ID 也会再次校验。
- **审核边界**：PatchCompiler 只创建 `PatchProposal`/`PatchProposalOperation`，不直接写课程树或讲稿；教师接受提案时才进入草稿版本，锁定节点仍拒绝覆盖。
- **局部性**：`candidate_id` 可只重跑单个 knowledge point；每个知识点生成独立 `TeachingScriptNodeDraft`，拥有自己的 Evidence、课程定位、前置知识和风格配置。
- **验证**：`backend/tests/test_controlled_prep_workflow.py` 使用 Fake LLM 验证 schema、Evidence 拒绝和局部 Proposal；这不代表真实 LLM 质量或线上效果。

### 2026-07-31 助教智能体交互与运行时补充审计

- **全量一键动作**：`一键整理结构` 与 `一键优化讲解` 已使用

### 2026-07-31 助教智能体课程级优化与响应审计

- **批量编辑上下文**：`一键整理结构` 与 `一键优化讲解` 不再把课程拆成独立的
  20 节点 LLM 分块。每次动作向模型提供当前草稿中全部未锁定的目录层级
  （`id/parent_id/type/order/title`）和完整原始讲稿（`content/style`），并要求每个
  允许目标恰好返回一项修改；任何漏项、重复、无效项或超过 500 项硬上限都会在写库前
  失败，不会部分应用。锁定目录和讲稿不会发送给模型。
- **课程结构语义**：结构整理 Prompt 明确要求将图号、表号、页码、OCR 碎片和
  `a）/b）/c）` 图注改为真正的教学概念；可根据可见层级判断命名是否合适，但仍不能
  新增、删除、移动或重设父子关系。错误层级只能通过教师手动结构编辑纠正。
- **TTS 讲解语义**：讲稿优化 Prompt 把全套未锁定讲稿视作连续课程讲解，要求自然
  短句、清晰停顿、段间承接、术语先解释后列举，并避免朗读图号和 OCR 片段；它不改变
  课程事实。
- **前端反馈与互斥**：建设工作台共享 `batchRun` 与 `agentMessages`。一键动作开始时
  自动打开助教智能体面板并立即显示处理气泡，完成或失败后原地更新该气泡；运行期间禁用
  结构、讲稿、PPT 映射和面板单点智能优化。
- **服务端互斥**：`course_build_editor.py` 以课程 ID 维护本地进程锁；同一课程已有
  一键动作时，第二个一键动作或自然语言智能修改返回 `409 PREP_AGENT_BUSY`。这是本地
  Demo 的单进程保护，不是多 worker 分布式锁。
- **检索现状**：Prep 单点修改实际使用课程范围内的 SQL 文本包含查询和词项计分，最多
  返回 8 个候选原文块及其 CONFIRMED EvidenceSpan；它**没有**接入 BM25、BERT/
  cross-encoder 重排或 LanceDB 向量检索。项目内的 BM25/BGE/RRF 研究演示和已发布
  课程的 LanceDB 检索不能直接复用于不断变化的草稿，否则会读取过期 release 边界。
- **响应判断**：单点慢的主要来源是同步 LLM 调用、严格 JSON 校验后可能的一次修复重试，
  以及当前 Incremental Runtime 的 120 秒总超时；不是上述不存在的三段检索。批量操作
  改为一次课程级调用后，减少了多请求调度开销，但长课程的完整上下文和输出仍会随课程
  规模增长。自动化验证仅使用 Fake LLM，未测量真实付费模型延迟。

## 可视化 PPT 映射工作台（2026-08-01）

- **教师工作区**：`GET /api/v1/course-editor/course/{course_id}/ppt-mapping/workspace` 按 `material_version_id` 分页返回已解析页的 OCR 摘要和受课程权限保护的页图内容路由；浏览器不接收对象存储键或 PPT 原文件。页图采用当前材料版本，不能把课程级发布 `ppt-manifest/v1` 误认作多份上传 PPT 的共同页码空间。
- **保存语义**：建设页在客户端暂存多条教师选页，`PUT /ppt-mapping` 一次性校验并写入不连续 `page_refs`。手工保存默认设置 `teacher_locked=true`，之后的智能匹配不得覆盖；旧的单节点 PATCH 仅保留兼容。
- **智能匹配与兜底**：`POST /ppt-mapping/match` 提供全部未锁定、当前知识点、所选页面三种受限范围。OCR 是服务端确定性 `DocumentOcrPort` 依赖，不是 LLM-facing Tool；模型只接收指定页的 OCR 文本、知识点和已有映射。当没有可信候选时返回可操作的 `no_reliable_match`，提示教师直接选页或缩小范围重新匹配，而不是伪装为系统失败。

### 原始课件视觉源与学习播放器（2026-08-01）

- **视觉真源**：`ppt_slide_render_service.py` 将教师上传的每个 `SourceMaterialVersion` 的 PPT/PPTX 经 LibreOffice 渲染为 `EvidenceRenderAsset(asset_type=ppt_slide_image)`。对象键带内容哈希，OCR 或证据页图不能覆盖、替换或伪装为教师课件。

### 发布前检查与教师确认（2026-08-02）

- 面向教师的流程使用“草稿 / 发布前检查 / 正式发布”称呼；旧 API 路径与数据库字段保留兼容，不作为界面文案。

- **证据现状**：单节点与脚本动作优先读取课程内确认 `EvidenceSpan`，有 Active Bundle 时还会通过 `ActiveBundleCourseRetrievalPort` 获取课程范围内的向量证据。向量检索不可用会降级为课程内词法检索，不伪造引用。
