## 批次0 API契约缺口决策记录（2026-07-25）

### logout 接口缺口

- **现状**：后端 `user.py` 无 `POST /api/v1/user/logout` 端点；认证为无状态 JWT（`security.py` 无 token 黑名单/会话存储）。
- **前端**：`api/user.js` 曾声明 `logout()` 指向 `/user/logout`，但全前端无任何组件调用（死导出）。
- **决策**：**移除前端死调用**。前端退出时仅清除本地 token 与登录状态（`PrimaryNav.vue`、`UserInfoCard.vue` 等已如此实现）。不补后端假端点——无状态 JWT 下 logout 端点无法提供真实撤销语义，补端点会造成"看起来完成"的假象（违反 AGENTS.md §3.2.4）。
- **证据**：`frontend/src/api/user.js` 已移除 `logout()` 并保留决策注释；全前端 grep `api.user.logout` 返回零匹配。

### 聊天记录删除接口缺口

- **现状**：后端 `chat.py` 仅有 5 个端点（history/messages/ask/create/quiz），无 DELETE 端点。
- **前端**：`api/chat.js` 曾声明 `deleteChatRecord(chatId, userId)` 指向 `DELETE /chat/{chatId}`，但全前端无任何组件调用（死导出）。
- **决策**：**移除前端死调用**。若后续需聊天删除能力，应先在后端补端点再恢复前端调用。
- **证据**：`frontend/src/api/chat.js` 已移除 `deleteChatRecord()` 并保留决策注释；全前端 grep `deleteChatRecord` 返回零匹配。
### 2026-07-28 受控备课 Agent 补充审计

- **现状**：新增 `POST /api/v1/course-editor/course/{course_id}/controlled-prep/run`，依次执行 `EvidenceSegmenter -> OutlinePlanner -> ScriptWriter -> EvidenceVerifier -> PatchCompiler`。
- **结构化约束**：`backend/app/schemas/controlled_prep.py` 使用 Pydantic `extra="forbid"`、字段约束、`model_json_schema()` 和严格 JSON 校验；LLM 失败只做有限次局部重试。
- **证据边界**：API 只接受当前课程的 ACTIVE `CourseEvidenceRecord` 或 CONFIRMED `EvidenceSpan`；未知、跨课程、失效 Evidence 直接拒绝，LLM 输出中的 Evidence ID 也会再次校验。
- **审核边界**：PatchCompiler 只创建 `PatchProposal`/`PatchProposalOperation`，不直接写课程树或讲稿；教师接受提案时才进入草稿版本，锁定节点仍拒绝覆盖。
- **局部性**：`candidate_id` 可只重跑单个 knowledge point；每个知识点生成独立 `TeachingScriptNodeDraft`，拥有自己的 Evidence、课程定位、前置知识和风格配置。
- **验证**：`backend/tests/test_controlled_prep_workflow.py` 使用 Fake LLM 验证 schema、Evidence 拒绝和局部 Proposal；这不代表真实 LLM 质量或线上效果。
