# 实验室-代码沙箱可信评测契约

## 2026-08-13 现行实现补充：分层 Agent 边界与代码认知证据

本节覆盖下文任何“CodingAgent 不得接收源码”的旧表述。学生已提交的单次源码可由
CodingAgent 经 `SessionScopedCodeSubmissionPort(student_id, course_id, run_id)` 读取，
仅用于定位、解释和教学。端口自校验三元范围，且不返回 Judge0 token、隐藏用例、完整
artifact 或无关提交；只有服务端验证终态可读。源码不进入 Agent state、诊断记录、
trace/audit、响应或 EduAgent；若模型回答回显任意非空完整源码或有效源码行，自动丢弃并
改用规则诊断。EduAgent 在消费端再以字段白名单丢弃任何源码、artifact、输出、自由摘要和
未知嵌套字段，防止上游 Port 回归绕过边界。

EduAgent 只接收无源码 `coding-learning-signal/1`，包括错误类型、显式知识点映射、
有界重复模式、建议动作和引用。正式评测仍是唯一成绩来源：已验证的通过与已验证的
编译/运行/超时/内存/错误答案失败都会按映射知识点写入 `coding_execution`，得分为
ACM/ICPC 的 `1.0` 或 `0.0`；pending、沙箱不可用和基础设施失败不写。无有效课程知识点
映射时不能改变认知。

迁移 `0058` 将学习投影 outbox 泛化为 source identity。代码证据在 finalization 事务提交后
以 `experiment_attempt` 事件触发既有异步认知刷新；题库旧 `attempt_id` 调用保持兼容。
认知融合权重为题库 `1.0`、代码 `1.5`，有效权重至少 `3.0` 才形成掌握度结论。部署仍须
显式 `alembic upgrade head`，没有引入应用启动时建表。

> 现行契约，2026-08-13。以已注册路由、`ExperimentRun`/`TaskRecord` 模型、Alembic `0057` 和契约测试为准。本文替代任何将实验成绩交由学生提交、或将正式 Judge0 运行描述为同步请求的旧说明。

## 开放边界

- 课程必须同时启用 `experiment` 和 `coding_sandbox`；既有课程默认保持关闭。首轮 Beta 只允许新建的编程演示课程。
- `POST /sandbox/course/{course_id}/execute` 是自由运行 Port。它只接收语言、源码和 stdin，服务端套用资源限制；不写 `ExperimentRun`、`LabRecord`、LearningEvidence 或源码日志。每学生每课程限制为 10 次/10 分钟，超额返回 `429` 和 `retry_after`。
- `POST /experiments/attempts/{attempt_id}/runs` 是正式评测 Port。必须带 `Idempotency-Key`，总是返回 `202 { task_id, run_id, status }`；前端轮询任务并读取运行结果，永不在请求中等待 Judge0。

## 正式评测

- 创建正式运行时，服务端将尝试置为 `submitted`。只有 worker 在真实运行终结后才可评分、终结尝试并投影可信记录。
- 评分规则为 ACM/ICPC：全部测试 Accepted 才得到 `final_score=1.0` 和 `passed=true`；任何非全 AC 结果均为 `0.0` 和 `false`。测试权重只用于发布完整性校验，`passing_score` 必须为 `1.0`。
- 正式运行以 `TaskRecord` 持久化。`sandbox_execution` 本地并发组和数据库 `SandboxExecutionLease` 双层限制 Judge0；槽位忙时任务等待，取消可退出等待，租约在每个测试用例前续期，并在所有成功、取消和失败路径释放。
- Judge0 基础设施不可用时写入 `SANDBOX_UNAVAILABLE`，允许重试；编译错误、运行错误、超时、内存限制和错误答案均为已完成评测，不是基础设施失败。
- `POST /experiments/attempts/{attempt_id}/submit`、`POST /experiments/attempts/{attempt_id}/finalize` 已下线。学生不能提交 final score、passed、evidence id 或其他终结字段。

## 实验室投影与智能体

- 实验室只读页面从已发布课程实验、推荐、尝试和可信终结 `LabRecord` 投影读取。`POST /lab/{lab_id}/records` 已下线；独立平台实验室的创建、发布和加入流程不在本轮保留。
- `legacy_unverified` 历史记录只作留存，不进入正式成绩、可信记录视图或 LearningEvidence。
- `ExperimentLabProjection` 以课程和实验唯一映射。终结服务逐项验证课程、实验、尝试所有权和服务端 evidence id 后，才创建唯一的可信 `LabRecord`。
- CodingAgent 可在本次授权提交的 `CodeSubmissionPort` 内短暂读取源码，用于定位和教学；其持久化/跨 Agent 输入仍只消费或传递 `CodingDiagnosisRecord` 与 `coding-learning-signal/1` 的脱敏事实。它不得接收隐藏测试、输入输出、Judge0 凭据或完整 artifact；LLM 不可用时仍返回规则反馈。
- TeachingAgent 只能为当前课程内已发布且已锁定的实验提出 `trigger_experiment` Proposal。教师批准后服务端再次校验课程成员、能力、版本和目录节点，并幂等创建学生可见推荐；不会创建尝试或运行。

## 发布与验收

- 教师锁定/发布前必须通过语言白名单、资源边界、至少一个测试、权重和为 1、默认活动锁定版本、参考解全 AC 预览及认证后的 Judge0 健康检查。
- 迁移 `20260813_0900_0057_experiment_sandbox_reliability.py` 有显式 `experiment_sandbox_reliability_v1` 批次账本和 downgrade 标记；部署通过 `alembic upgrade head`，不在应用启动时建表。
- 自动化测试禁止调用真实 Judge0、付费 LLM、学生数据或生产数据库。真实鉴权合成 smoke 与 24-48 小时灰度观察仍是部署前人工验收项，未由本地测试替代。
