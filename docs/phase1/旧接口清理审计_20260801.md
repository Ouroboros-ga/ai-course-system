# 旧接口与死代码清理审计（2026-08-01）

## 结论

本次以实际 FastAPI 路由、前端 import/调用、路由注册和测试为证据，不以历史文档
或目录名称判断功能是否仍在使用。

### 已删除的死代码

- `frontend/src/views/Knowledge.vue`
- `frontend/src/components/chat/player/PptPlayer/KnowledgeProgressPage.vue`
- 前端 `chat.js` 的 `createChatRecord` 与 `getChatMessages` 导出

前两项没有任何已注册路由或其他运行时代码引用；`KnowledgeProgressPage.vue` 还调用了
不存在的 `api.chat.getDocumentHierarchy` 与 `api.chat.updateNodeContent`，因此不应作为
新功能的可复用实现。删除它们不会删除后端 TTS 能力；该能力的有效入口仍由当前课程
工作流使用。

### 已收口、但暂保留的公开兼容接口

| 路径 | 当前处理 | 证据与迁移规则 |
| --- | --- | --- |
| `POST /api/v1/chat/create` | OpenAPI 标记 `deprecated: true` | 前端没有调用；会话由 `/chat/ask` 自动创建。新客户端不得使用。保留一个兼容窗口，避免无证据破坏仓库外调用方。 |
| `GET /api/v1/chat/messages/{chat_id}` | OpenAPI 标记 `deprecated: true` | 前端没有调用；新学习工作区不读取持久化原始聊天记录。新客户端不得使用。 |
| `GET /api/v1/chat/history` | 保留并在前端标明仅限旧 `/chat` 页面 | `/chat` 仍在路由表中并挂载 `ChatHistory`，不能当作无消费者删除。 |
| `POST /api/v1/chat/ask` | 保留并在前后端标明降级边界 | `useLearningWorkspace` 在 TeachingAgent 503/失败时必须回退到它；这是当前学习问答的可用性保障。 |
| `POST /api/v1/chat/quiz` | 保留 | 仍由学生学习组合式函数调用。 |

路由契约测试锁定前两条接口的 `deprecated` 标记，防止它们重新被当成正常 API 使用。
真正删除这两条后端公开路径前，应先确认没有仓库外调用方，或发布明确的版本化迁移
通知；它们的前端调用已在本次移除。

## 发现的瘸腿依赖（未擅自删除）

`POST /api/v1/chat/file/upload` 仍被 `TeacherDashboard.vue` 和旧 `/chat` 页的
`PptPlayer.vue` 调用。该路径只是 `document.router` 的二次挂载；它现在委托统一课程
导入流程并返回异步导入结果，而旧页面仍按历史的 `mindMapJson`、`fullContent`、`audioUrl`
等同步结果消费。因此它不是可安全删除的死接口，也不是适合新开发继续接入的成熟能力。

旧 `/chat` 页的 `ChatHistory.vue` 也按 `res.records` 读取数据，而当前 `GET /chat/history`
实际解包后提供的是 `list`。因此该页的历史列表同样是瘸腿依赖；不能把它作为保留
`/chat/create` 或 `/chat/messages/{id}` 的理由。

建议后续独立迁移这两个旧页面到课程导入任务和构建工作台的实际响应契约，再删除
`/chat/file/*` 二次挂载及相关旧 UI。该迁移会改变默认教师创建页，需单独进行页面级
验收，未在本次“无消费者/死代码”清理中冒然实施。

## 智能体兼容层核查

没有删除 `backend/app/platform/agents/` 的顶层兼容转发模块。实际运行入口
`bootstrap.py` 及 TeachingAgent endpoint 仍导入 `registry`、`kg_mest_report_store` 和
多个 `tools/*` 转发模块；相应测试也直接覆盖这些导入路径。它们属于正在被成熟功能
使用的迁移边界，按项目规则只保留转发、不新增逻辑。本次未将它们误判为死代码。
