# M4A 测试环境设计

更新时间：2026-07-08

## 目标

M4A 的目标是建立安全、离线、确定、可重复的测试启动与隔离基线，服务后续 M4B-M7。本阶段不补齐所有业务测试，不修复重复路由，不改变公开 API、生产数据库结构、启动命令或用户可见行为。

## pytest 入口

采用根目录 `pytest.ini`：

```ini
[pytest]
pythonpath = backend
testpaths = backend/tests
```

选择理由：

- 仓库已有根配置，原 `testpaths = tests` 指向不存在目录。
- 改为 `backend/tests` 是最小改动，并保留从仓库根目录执行 pytest 的统一入口。
- 不通过命令行参数隐藏既有测试。
- 不删除、不 skip、不 xfail 既有测试。

实际可用运行时为 `backend\.venv\Scripts\python.exe`。根目录 `.venv` 与 `uv run --frozen --no-sync pytest` 当前不能启动 pytest，详见 `docs/phase1/M4A执行报告.md`。

## 测试数据库隔离

`backend/tests/conftest.py` 在测试收集前设置：

```text
AI_COURSE_TESTING=1
AI_COURSE_SKIP_STARTUP_SIDE_EFFECTS=1
AI_COURSE_DATABASE_URL=sqlite:///E:/smartcarb/ai-course-system/.pytest_tmp/ai_course_m4a/test_smart_class.db
```

`backend/app/models/database.py` 增加测试 URL 覆盖能力：

```python
PRODUCTION_DATABASE_PATH = os.path.join(DATABASE_DIR, "smart_class.db")
DEFAULT_DATABASE_URL = f"sqlite:///{PRODUCTION_DATABASE_PATH}"
DATABASE_URL = os.environ.get("AI_COURSE_DATABASE_URL", DEFAULT_DATABASE_URL)
```

生产环境不设置 `AI_COURSE_DATABASE_URL` 时仍使用原生产 SQLite 路径。

隔离策略：

1. 测试会话创建 `.pytest_tmp/ai_course_m4a/test_smart_class.db`。
2. `test_engine` 启动前删除残留测试 DB，避免重复运行受上次异常退出影响。
3. `test_engine` 调用 `SQLModel.metadata.create_all(engine)` 建表。
4. `fastapi_app` fixture 使用 `app.dependency_overrides[get_session]` 指向测试 engine。
5. 会话结束后 drop tables、dispose engine，并清理测试根目录。
6. 保护性测试断言当前 `DATABASE_URL` 不是 `DEFAULT_DATABASE_URL`，且不包含 `PRODUCTION_DATABASE_PATH`。

## app.main 导入副作用隔离

`backend/app/main.py` 增加最小行为保持型开关：

```text
AI_COURSE_SKIP_STARTUP_SIDE_EFFECTS=1
```

测试环境设置该变量时，导入 `app.main` 不执行：

1. `run_dependency_check(auto_install=True)`
2. `create_tables()`
3. `run_migrations()`

生产环境默认不设置该变量，仍由 `run_startup_side_effects()` 执行原有依赖检查、建表和迁移。

## 外部网络阻断

`block_external_network` autouse fixture patch：

1. `socket.socket.connect`
2. `socket.create_connection`

默认只允许 loopback：

```text
127.0.0.1
127.*
::1
localhost
```

对 `example.com` 等外部地址会抛出 `RuntimeError("External network calls are blocked in tests")`。FastAPI `TestClient` 使用进程内 ASGI 调用，不依赖真实外部 socket。

## Fake/Mock 设计

`backend/tests/fakes.py` 提供：

| Fake | 覆盖对象 | 支持模式 |
|---|---|---|
| `FakeLLMClient` | LLM `chat` / `simple_chat` | `success`、`timeout`、`service_unavailable`、`malformed` |
| `FakeTTSClient` | TTS `synthesize` | `success`、`timeout`、`service_unavailable`、`malformed` |
| `FakeVoiceCloneClient` | 声音复刻创建与状态 | `success`、`timeout`、`service_unavailable`、`malformed` |
| `FakePPTClient` | 讯飞 PPT 模板、任务、轮询、下载 | `success`、`timeout`、`service_unavailable`、`malformed` |
| `FakeDigitalHumanClient` | 数字人健康检查和生成 | `success`、`timeout`、`service_unavailable`、`malformed` |

`install_external_fakes` autouse fixture patch 已知调用点，包括 `app.common.llm_client.llm_client`、多个 service 中的 `llm_client`、TTS/voice clone/digital human 客户端引用，以及 `ppt_generation_service.xfyun_client`。
