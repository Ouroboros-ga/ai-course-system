# 统一学习进度、认知推荐与教师统计契约

> 2026-08-07 实现补充：当前 release 的断点续学、`node_opened` 事件、浏览器待发事件队列、教师认知/推荐聚合字段和 active release 校验已接入。详见 `backend/app/services/unified_learning_service.py`、`backend/app/api/v1/endpoints/facade.py`、`backend/app/api/v1/endpoints/player.py`、`frontend/src/features/student-learning/composables/useLearningWorkspace.js` 与 `frontend/src/app/pages/course/CourseAnalyticsPage.vue`。

> 状态：`implemented-v1`（统一学习事件、学生投影、课程统计和门面 API 已接入）；Agent 扩展 Port/Tool 为 `planned/unimplemented`，不代表当前已可调用。
> 更新日期：2026-08-07。

## 1. 当前事实链

学习页面只以当前 active `CourseRelease` 为内容来源。知识点身份是
`course_id + release_id + outline_node_id`；`CourseKnowledgeNode.node_key` 仅作为可选认知关联。
chapter、section、example、practice_suggestion 不进入学习完成率分母。

学习事实写入 `learning_events`，由 `unified_learning_service` 更新
`student_learning_projections`，并刷新 `course_learning_stats_projections`。播放和阅读形成 exposure，正式评分型答题形成认知证据；观看本身不能产生 mastery。

## 2. 已实现 API

| 接口 | 权限 | 语义 |
|---|---|---|
| `GET /api/v1/facade/course/{course_id}/learning-context` | `course.learn` | 返回 active release 的知识点、学习状态、认知/推荐摘要 |
| `POST /api/v1/facade/course/{course_id}/learning-events` | `course.learn` | 写入规范化事件，要求 `release_id`、`outline_node_id`、事件类型和幂等键 |
| `POST /api/v1/facade/course/{course_id}/learning-actions/complete` | `course.learn` | 显式完成知识点 |
| `GET /api/v1/facade/course/{course_id}/analytics` | `analytics.view_course` | 课程级知识点完成统计 |
| `GET /api/v1/facade/course/{course_id}/analytics/students/{student_id}` | `analytics.view_member` | 单学生学习/认知摘要，不返回原始聊天或完整答案 |

### 2.1 当前响应补充

- `learning-context` 额外返回 `recent_anchor`，包含最新 `outline_node_id`、播放时间、页码和访问时间；学习页初始化优先用该 release-scoped 投影恢复位置。
- `analytics` 的每个知识点返回 `mastery_distribution`、`unknown_mastery_count`、`low_confidence_count` 和 `pending_recommendation_count`，并返回可下钻的学生完成摘要。
- `learning-events` 支持 `node_opened`、`media_progress`、`read_progress`、`explicit_complete`、`recommendation_consumed`、`agent_learning_action`；事件按 `student_id + idempotency_key` 去重，未来时间戳被拒绝。
- 前端失败事件会保存在课程级本地待发队列，恢复页面后重试；队列不是事实来源，服务端投影仍是唯一事实来源。
- `learning-actions/complete` 只接受当前 active `release_id`，历史 release 不能写入当前学习链。

完成规则固定为进度比例 `>= 0.8` 或显式完成。无图谱映射的知识点仍可学习，但认知和推荐为 `not_available`。

## 3. Planned Agent 契约

以下接口只冻结输入输出，不修改 Agent 内部实现：

- `LearningContextPort`: 读取当前 release 的学习上下文；
- `LearningProjectionPort`: 读取 exposure/completion 投影；
- `LearningEvidenceContextPort`: 将 evidence 映射到 source release 和 outline node；
- `CognitionPort` 扩展 release/node identity 参数；
- `RecommendationPort` 接收 exposure status、completion ratio、evidence confidence；
- `LearningEventPort` 接收规范化事件和 idempotency key；
- `StudentStateTool` 返回 learning/cognition/recommendation 三段摘要；
- `CognitionTool` 只读认知投影；
- `LearningEventTool` 只记录经过治理的教学动作。

这些 Port/Tool 当前标记为 `planned/unimplemented`，前端不得请求不存在的接口。Prep Agent 不增加 LLM-facing learning tool，也不写学生学习数据。

## 4. 数据边界与失败语义

- 事件按 `student_id + idempotency_key` 去重；
- release 或节点不属于当前课程时 fail-closed；
- 当前学习链路不等待认知刷新，认知不可用时返回 `unknown/pending/not_available`；
- 新 release/回滚保留历史学习投影；相同 `knowledge_node_key` 的正式证据可跨 release 复用；
- 旧 `LearningProgress/NodeProgress/StudentEnrollment` 保留用于审计和迁移，不作为新页面统一数据源。

## 5. 历史回填

`unified_learning_backfill_service.backfill_learning_projection` 由部署流程显式传入 `batch_id` 执行，具备幂等键。旧数字节点 ID 无法安全映射到新 `outline_node_id` 时计入 `unknown` 并保留原数据，不伪造完成结论；应用启动不会隐式执行回填。

## 6. 当前未完成项

- Outbox、重试、死信和投影重放尚未替代当前同步刷新路径；当前事件写入成功后直接刷新课程统计投影。
- `LearningContextPort`、`LearningProjectionPort`、`LearningEvidenceContextPort`、扩展后的 `CognitionPort` / `RecommendationPort`、`LearningEventPort` 以及对应 Agent Tool 仍为 `planned/unimplemented`。认知、推荐和 Agent 内部实现未因本次接线而改变。
- 认知/推荐聚合读取现有 `CognitiveState`、`RecommendationRecord`；没有可映射知识图谱节点时继续返回 `not_available`，没有正式证据时返回 `unknown`，不可用时不得阻断学习。
