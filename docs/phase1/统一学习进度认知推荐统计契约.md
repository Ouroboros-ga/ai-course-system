## 2026-08-13 现行实现补充：代码作答作为并列评分输入

认知服务当前接受两种并列的服务端评分观测：已有已判分 `QuestionAttempt` 的题库作答
权重为 `1.0`；由 `ExperimentFinalizeService` 写入的
`LearningEvidenceRecord(evidence_type=coding_execution)` 权重为 `1.5`。服务在共享的
近期窗口内计算 `sum(score * weight) / sum(weight)`，有效权重至少 `3.0` 才设置表现分和
掌握度；`sample_size` 表示原始观测数而非有效权重。题库单独使用时保持原有行为。

代码评分只接受已验证的 Judge0 终态及显式、同课程知识点映射。诊断摘要、前端成绩、
访问频次、源码和错误文本都不能直接成为评分。`CodingAgent` 可在私有、按
`student_id + course_id + run_id` 校验的端口内短暂读取本次源码；`EduAgent` 仅得到
不含源码的 `coding-learning-signal/1` 和正式评分投影。

`LearningProjectionOutbox` 现以
`(source_type, source_ref, student_id, course_id, knowledge_node_id)` 去重；
题库保留 `attempt_id` 的兼容路径，代码证据使用
`source_type=experiment_attempt`、`source_ref=attempt_id`。证据与 outbox 在终结事务中
落库，提交后才触发既有异步认知/推荐刷新。无法安全确定的 release/outline 身份保持
unknown/null，绝不从 active release 猜测。

## 1. 当前事实链

学习页面只以当前 active `CourseRelease` 为内容来源。知识点身份是
`course_id + release_id + outline_node_id`；`CourseKnowledgeNode.node_key` 仅作为可选认知关联。
chapter、section、example、practice_suggestion 不进入学习完成率分母。

学习事实写入 `learning_events`，由 `unified_learning_service` 更新
`student_learning_projections`，并刷新 `course_learning_stats_projections`。播放和阅读形成 exposure，正式评分型答题形成认知证据；观看本身不能产生 mastery。

## 2. 已实现 API

| 接口 | 权限 | 语义 |
|---|---|---|
| `GET /api/v1/facade/course/{course_id}/learning-context` | `course.learn` | 返回 active release 的知识点、学习状态、认知/推荐摘要 |
| `POST /api/v1/facade/course/{course_id}/learning-events` | `course.learn` | 写入规范化事件，要求 `release_id`、`outline_node_id`、事件类型和幂等键 |
| `POST /api/v1/facade/course/{course_id}/learning-actions/complete` | `course.learn` | 显式完成知识点 |
| `GET /api/v1/facade/course/{course_id}/analytics` | `analytics.view_course` | 课程级知识点完成统计 |
| `GET /api/v1/facade/course/{course_id}/analytics/students/{student_id}` | `analytics.view_member` | 单学生学习/认知摘要，不返回原始聊天或完整答案 |

### 2.1 当前响应补充

- `learning-context` 额外返回 `recent_anchor`，包含最新 `outline_node_id`、播放时间、页码和访问时间；学习页初始化优先用该 release-scoped 投影恢复位置。
- `analytics` 的每个知识点返回 `mastery_distribution`、`unknown_mastery_count`、`low_confidence_count` 和 `pending_recommendation_count`，并返回可下钻的学生完成摘要。
- `learning-events` 支持 `node_opened`、`media_progress`、`read_progress`、`explicit_complete`、`recommendation_consumed`、`agent_learning_action`；事件按 `student_id + idempotency_key` 去重，未来时间戳被拒绝。
- 前端失败事件会保存在课程级本地待发队列，恢复页面后重试；队列不是事实来源，服务端投影仍是唯一事实来源。
- `learning-actions/complete` 只接受当前 active `release_id`，历史 release 不能写入当前学习链。

学生学习页的 `LearningTrack` 直接消费 `learning-context.items`，将学习曝光与认知掌握分层展示：`advanced/proficient` 显示“已掌握”，`developing/beginner` 显示“待掌握”，`unknown` 显示“需要更多证据”，未映射显示“暂不可分析”。学生点击“看状态”后才按需调用现有 `/cognitive/course/{course_id}/state?node_id=...`，详情失败只显示“认知详情暂时不可用”，不阻断学习。

`learning-context.items[].cognition` 现在包含认知服务查询用的数据库 `node_id` 与知识图谱公开键 `node_key`，以及 `evidence_count`、`sample_size`、`computed_at`；无映射返回 `reason_codes=["knowledge_node_unmapped"]`，有映射但无正式状态返回 `status="unknown"` 与 `reason_codes=["insufficient_evidence"]`。学习轨道的“查看知识依据”只使用 `node_key` 跳转 `/app/course/{course_id}/knowledge/graph/{node_key}`，禁止把数据库整数 ID 当作图谱公开身份。

完成规则固定为进度比例 `>= 0.8` 或显式完成。无图谱映射的知识点仍可学习，但认知和推荐为 `not_available`。

## 3. Planned Agent 契约

以下接口只冻结输入输出，不修改 Agent 内部实现：

- `LearningContextPort`: 读取当前 release 的学习上下文；
- `LearningProjectionPort`: 读取 exposure/completion 投影；
- `LearningEvidenceContextPort`: 将 evidence 映射到 source release 和 outline node；
- `CognitionPort` 扩展 release/node identity 参数；
- `RecommendationPort` 接收 exposure status、completion ratio、evidence confidence；
- `LearningEventPort` 接收规范化事件和 idempotency key；
- `StudentStateTool` 返回 learning/cognition/recommendation 三段摘要；
- `CognitionTool` 只读认知投影；
- `LearningEventTool` 只记录经过治理的教学动作。

这些 Port/Tool 当前标记为 `planned/unimplemented`，前端不得请求不存在的接口。Prep Agent 不增加 LLM-facing learning tool，也不写学生学习数据。

## 4. 数据边界与失败语义

- 事件按 `student_id + idempotency_key` 去重；
- release 或节点不属于当前课程时 fail-closed；
- 当前学习链路不等待认知刷新，认知不可用时返回 `unknown/pending/not_available`；
- 新 release/回滚保留历史学习投影；相同 `knowledge_node_key` 的正式证据可跨 release 复用；
- 旧 `LearningProgress/NodeProgress/StudentEnrollment` 保留用于审计和迁移，不作为新页面统一数据源。

## 5. 历史回填

`unified_learning_backfill_service.backfill_learning_projection` 由部署流程显式传入 `batch_id` 执行，具备幂等键。旧数字节点 ID 无法安全映射到新 `outline_node_id` 时计入 `unknown` 并保留原数据，不伪造完成结论；应用启动不会隐式执行回填。

## 6. 当前未完成项

- Outbox、重试、死信和投影重放尚未替代当前同步刷新路径；当前事件写入成功后直接刷新课程统计投影。教师 `/analytics` GET 仅读取投影，绝不在 GET 内刷新或提交业务数据。
- 正式评分写入 `LearningEvidenceRecord` 时，同步 upsert `LearningEvidenceContext`。它记录 `evidence_id`、课程、图谱节点与可安全确定的 release/outline 身份；多 release 映射不唯一时保留 `source_release_id/outline_node_id = null`，并以 unknown 表示，绝不猜测来源。曝光事件不会创建正式证据。
- Agent-facing 的 `LearningContextPort`、`LearningProjectionPort`、`LearningEvidenceContextPort`、扩展后的 `CognitionPort` / `RecommendationPort`、统一领域 `LearningEventPort` 以及对应 Agent Tool 仍为 `planned/unimplemented`。已有名称相近的 Agent 审计/动作事件 Port 不等同于统一学习事实 Port；认知、推荐和 Agent 内部实现未因本次接线而改变。
- 认知/推荐聚合读取现有 `CognitiveState`、`RecommendationRecord`；没有可映射知识图谱节点时继续返回 `not_available`，没有正式证据时返回 `unknown`，不可用时不得阻断学习。
# 学习页可见状态补充（2026-08-08）

学习页的节点状态统一从 `GET /facade/course/{course_id}/learning-context` 读取，
不再分别请求学习进度和认知摘要后在浏览器合并。该聚合接口以当前 active
`release_id` 为边界，一次返回正式知识点列表及每项 `learning/cognition/recommendation`
三层摘要，因此页面刷新、切换节点和完成动作不会出现两套状态短暂不一致。

节点行展示两层状态：

- 学习事实：`未学习`、`学习中`、`已完成`；完成率只使用知识点分母；
- 认知结论：完成后显示 `已掌握`、`待掌握`、`需要更多证据`、`暂不可分析` 或
  `认知暂不可用`。未完成节点不会把观看行为显示为掌握。

点击“看状态”可查看完成原因、掌握度、证据置信度和正式证据数量；点击“查看知识依据”
跳转知识图谱节点。可执行推荐显示“去练习/继续学习”，复用现有 `PracticePanel` 和
学习状态机。推荐消费优先走 `/cognitive/recommendation/{id}/consume`，服务端在能映射
当前 release/node 时写入 `recommendation_consumed` LearningEvent；网络失败才进入学习页
离线事件队列。认知或推荐不可用不阻断学习，页面保持降级文案。

上述状态映射和 14 个知识点完成率由
`frontend/src/features/student-learning/learningStatus.js` 统一实现并有专项测试。
