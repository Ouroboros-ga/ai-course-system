# 统一课程建设与解析基线

> 状态：现行实现目标与接口设计基线，创建于 2026-07-27。
>
> 本文记录已经确认的目标架构；不表示下列能力均已完成。功能事实仍以注册路由、调用链、数据库迁移和测试为准。
>
> 当前实现细节见 [课程生成核心逻辑与统一建设链](课程生成核心逻辑与统一建设链.md)。本文保留架构基线；实现状态、接口清单和 Demo 限制以该 companion 文档为准。

> **2026-08-10 实现更新：** 首轮备课的材料证据整理采用页内碎块合并与分层 Map/Reduce。证据单元目标 1,500 字、硬上限 2,400 字；默认总证据预算 600,000 字、最多 1,000 单元、25 个 Map 基础批次，单批正文不超过 24,000 字、完整模型载荷不超过 36,000 字，并发为 2。原始块 ID 不发送给模型，只在服务端用于引用展开；目录、讲稿、图谱与 PPT 映射仍持久化真实 `DocumentBlock.block_id`。Reduce 和大纲使用独立 16,384-token 上限，不提高共享 LLM 全局上限。截断会递归拆批，Map + Reduce 共享调用预算为 160；超限明确失败且不写入草稿。Map 与 Reduce 对描述性 `examples`/`exercises` 稳定去重、去空并各裁剪至 10 项；Map 分段内冗余 `stage` 被程序移除。该归一化不适用于 evidence ID、segment 数量或其他未知事实结构，后者继续 fail-closed。真实高密度材料的完整端到端验收仍待复跑。

## 1. 唯一的课程材料事实链

```text
统一上传入口
  → ObjectStorage object_key
  → SourceMaterial / SourceMaterialVersion
  → TaskRecord / DocumentParseRun
  → DocumentIR / DocumentBlock
  ├─ 课程隔离的可信 RAG 索引
  ├─ Evidence 与课程图谱候选
  ├─ TeachingStructureBuilder（课程目录候选）
  ├─ TeachingScriptBuilder（讲授脚本候选）
  └─ Markdown 课程资源版本
       → 教师审核、编辑、锁定
       → DRAFT / PUBLISHED 课程状态
```

旧 `/api/v1/document/upload` 仅能在迁移期间保留为兼容入口，最终必须转发到统一导入服务；不得再独立同步写入旧 Docling、脚本和 TTS 结果。

## 2. 输入格式策略

| 输入 | 正式策略 |
| --- | --- |
| PPTX | `NativePptxProvider` 读取标题、文本框、备注和页序；文字稀少或图片型页面使用 PaddleOCR 补充。 |
| PDF | `PdfPlumberProvider` 读取原生文本与页码；每页必须经过 PaddleOCR，并由 Reconciler 合并原生文本与 OCR 坐标、置信度。 |
| 图片 | `PaddleOCRProvider` 为主解析器。 |
| DOCX | `PythonDocxProvider` 读取段落、标题和表格；同步转换 PDF 后走 PDF + PaddleOCR 链获得页码和坐标。 |
| DOC | `LibreOfficeHeadlessConverter` 转为 PDF 后走 PDF + PaddleOCR；转换失败返回 `SOURCE_REUPLOAD_REQUIRED`。 |

PaddleOCR 必须运行在独立服务中，主后端仅通过 `DocumentOcrPort` 调用，不将 Paddle 依赖安装到主后端 Python 环境。

## 3. 课程树与知识图谱分离

课程目录是有序树，图谱是可多跳的关系网络；两者不得混用。

```text
CourseOutlineVersion
└─ CourseOutlineNode
   ├─ chapter
   ├─ section
   ├─ knowledge_point
   ├─ example
   └─ practice_suggestion
```

每个课程目录节点可关联多个 `GraphNode`、`EvidenceSpan`、`DocumentBlock`、讲稿和 PPT 映射。图谱负责 prerequisite/related/extends 等关系，课程树负责目录层级与教学顺序。

## 4. 教师审核与备课 Agent

备课 Agent 只能调用受控工具生成 `PatchProposal`，不得直接修改正式课程数据。

```text
CourseDraftReadTool / CourseRagSearchTool / WebSearchTool
→ OutlineProposalTool / ScriptProposalTool / MarkdownProposalTool
→ PatchProposal
→ 教师接受、拒绝或手动编辑
→ 生成新的草稿版本
```

前端 Diff 约定：新增使用绿色框，删除使用红色框和删除线，修改显示 before/after；教师锁定的内容不得被后续 AI 重跑覆盖。外网资料只能标记为补充参考，不能伪装为课程 Evidence。

## 5. Markdown 与课程资源库

解析版 Markdown、讲授稿 Markdown 和教师编辑版 Markdown 均作为课程资源保存：

```text
ResourceItem(scope=course, course_id)
→ ResourceVersion(object_key, content_hash, source refs)
```

草稿仅课程建设角色可读；发布版本由有效课程成员通过 Course Access v1 浏览。Markdown 必须保留 `source_block_refs`，不能脱离原始页码、坐标和内容哈希。

## 6. 教学 PPT 映射

七步建设导航始终显示“教学 PPT 映射”。

- 存在已解析 PPT/PPTX：显示节点—幻灯片自动映射、AI 匹配、教师调整与锁定。
- 没有 PPT：页面保持灰色冻结，显示“上传现有 PPT”和“AI 智慧生成 PPT（根据课程结构和讲授脚本生成）”。
- PDF/DOCX/DOC 的页码仍用于 Citation；它们不自动成为教学 PPT 映射。
- AI PPT 仅可使用教师确认的目录和讲稿生成；生成后的 PPT 必须重新进入统一上传/解析链。

## 7. Demo 状态和任务语义

课程仅使用 `DRAFT` 与 `PUBLISHED` 两个面向用户的状态，由教师或管理员手动变更。旧课程不做自动历史迁移；新链完成后通过重新上传创建新课程。

Demo 阶段允许后端重启中断本地解析任务，但任务中心必须将遗留 `running` 任务标为 `interrupted`，前端给出“重新解析”操作，不能永久显示处理中。
