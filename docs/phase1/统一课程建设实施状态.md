# 统一课程建设实施状态

更新时间：2026-07-28（本地 Demo）

## 已接通的正式链路

```text
教师上传文件
→ SourceMaterial / SourceMaterialVersion
→ TaskRecord / DocumentParseRun
→ DocumentBlock / Evidence / 图谱候选审核记录
→ CourseOutline 草稿
→ TeachingScript 草稿
→ PatchProposal（规则候选，教师确认前不修改节点）
→ 教师编辑、锁定、提案审核
→ 已发布 Outline + Script
→ 课程 Release 质量门禁
```

- 建设页不再提供对象路径、文件哈希或“已解析”状态的手工输入。
- 历史重建路由不再注册。旧课程不能走批量重建；需要通过统一上传入口重新生成。
- `CourseOutline`、`TeachingScript`、`PatchProposal` 使用独立版本和教师审核 API；旧 `CourseScript` 只作为历史兼容读取，不再作为建设页写入源。
- 课程发布门禁要求至少一个已发布的新版课程树节点，以及与该树版本对齐、且含节点的已发布讲稿。
- 教师提案先显示 before/after Diff；接受操作只能写入草稿，且不能覆盖教师锁定或已发布版本。
- 解析任务现在会为每个有效文本块生成可追溯的 `GraphNodeReview` 节点/相邻关系候选；规则标题清理仅在确有变化时生成 `PatchProposal`，操作带 `EvidenceSpan` 引用。
- 当前 B1 是**确定性规则基线**，不是 LLM 生成质量证明；接入 LLM 后必须增加独立 policy version，并保留本基线作为对照。
- 课程数字人使用教师个人中心已校验、已预处理的预设。课程媒体页只创建绑定/生成任务/媒体发布草稿；学生只读取激活媒体版本。

## 文件解析策略

| 输入 | 实现路径 |
| --- | --- |
| PPTX | `NativePptxProvider`；低文本/图片内容由 OCR enrichment 补充。 |
| PDF | `PdfPlumberProvider` 提取原生文本；解析计划要求对每一页调用独立 PaddleOCR。PaddleOCR 不健康时以 `OCR_SERVICE_UNAVAILABLE` 失败并可重试，不能把未 OCR 的 PDF 标为成功。 |
| 图片 | 走 `DocumentOcrPort` 的 PaddleOCR 服务；本地 provider 仅为受控降级。 |
| DOCX | `PythonDocxProvider` 提取标题、段落、表格；同时通过 LibreOffice 转 PDF，再走 PDF 全页 OCR 获取页坐标。 |
| DOC/PPT | 先通过 LibreOffice 无头转换成 PDF，再走 PDF 全页 OCR；转换失败返回“重新上传 DOCX/PDF”的结构化失败。 |

> PaddleOCR 在当前 Demo 中只保留 `OcrProvider`/`DocumentOcrPort` 接口，标记为 `fake/unavailable` 能力：接口可以被规划器和任务调用，但未部署独立服务时不得返回伪造文本，也不得把任务标成已完成。真实 OCR 由人工部署 `deploy/paddleocr` 后再启用。

## Canonical DocumentIR replacement boundary

- Each successful parse stores immutable Canonical DocumentIR JSON plus
  versioned `DocumentIRVersion`, `EvidenceAnchor`, and `RetrievalChunk`
  projections. Course-scoped APIs expose anchor review and teacher-confirmed
  deterministic retrieval without changing the shadow APIs.
- DOCX and PPTX OCR enrichment renders Office pages through LibreOffice before
  sending page images to OCR. Raw Office ZIP bytes are never treated as images.
- Reparse keeps existing evidence until the replacement succeeds and a teacher
  inspects `/reparse/{run_id}/diff` then calls `/reparse/{run_id}/apply`.
  Failed or unreviewed replacements do not break existing citations.
- `DocumentBlock.block_id`, `EvidenceSpan.block_id`, and
  `EvidenceAnchor.block_id` now keep the Canonical DocumentIR locator exactly.
  The relational uniqueness boundary is `(document_ir_version_id, block_id)`,
  which preserves identical source locators across immutable reparses.
- `POST /course/{course_id}/reparse/high-quality-ocr` accepts an audited
  teacher-agent action ID plus an explicit page/slide scope. It uses only the
  isolated OCR port, creates a distinct IR version, and still requires the
  normal diff plus explicit `/apply` adoption step.
- The Canonical JSON object key contains a generated IR version ID. Storage
  rejects a same-key content mismatch instead of overwriting an immutable IR.
- PDF OCR enrichment renders only the requested pages with `pypdfium2` at a
  bounded DPI before calling the isolated OCR port. It does not route a full
  PDF to a generic image endpoint. The persisted IR outcome distinguishes
  `native_complete`, `native_with_ocr`, `partial_success`,
  `manual_review_required`, and `unsupported_visual_structure`.
- `RetrievalGateway` first reads active, teacher-confirmed Canonical
  `RetrievalChunk` records for course-scoped QA. It retains `document_id`,
  `unit_id`, `block_id`, anchor IDs, and IR version metadata; the legacy tree
  retriever is only a compatibility fallback when canonical chunks are absent.
- Every Canonical IR projection also builds a versioned
  `RetrievalIndexSnapshot` candidate. The first successful parse activates its
  snapshot; a reparse remains isolated until the teacher applies the diff,
  when the previous snapshot is superseded atomically. Canonical retrieval is
  restricted to the one active snapshot and still excludes unconfirmed
  anchors.
- A persisted Canonical quality outcome requiring review maps the parse run and
  its task to `partial_success`, rather than reporting a binary success. The
  resulting candidate IR remains reviewable and cannot silently replace the
  active reparse snapshot.
- PPTX native parsing recursively reads group children and supplements picture
  alternative text from slide OOXML with an exact XML locator. Detected
  SmartArt, chart, or OMML formula structures are not guessed into semantics:
  they produce an explicit review warning and the persisted
  `unsupported_visual_structure` outcome.
- DOCX native blocks retain `word/document.xml` locators and no invented page
  number. Floating-image alternative text is supplemented from OOXML; floating
  drawings and OMML formulas are explicit review signals. When LibreOffice OCR
  text strongly matches a native block, its rendition page/bbox and alignment
  confidence are attached as metadata while the native locator remains the
  source identity. Matched OCR is deduplicated; visual-only OCR remains a
  separate rendition block.
- Office and selective PDF OCR rendering now persist each selected page as a
  course- and parse-run-scoped `EvidenceRenderAsset`. The Canonical anchor
  viewer links only to the Evidence-specific authorized content endpoint (or
  a short-lived remote-storage redirect after that check), and returns image
  dimensions when the page asset exists; an unrendered page deliberately
  returns `rendition_url: null` rather than a fabricated asset location.
- The mounted Evidence Viewer route is now course/run scoped and reads
  `/api/v1/graph/course/{course_id}/document-ir/{run_id}/anchors`; it does
  not consume the `evidence-v2` shadow API. Its geometry is adapted from the
  Canonical anchor bbox into the existing viewer contract.
- Every new-course parse task persists its `run_id` inside `TaskRecord` after
  `DocumentParseRun` creation, so task-center retry receives a complete,
  durable worker payload. Ingestion also verifies that an explicit material
  version belongs to the requested material, not merely to the same course.
- Legacy `.doc` and `.ppt` imports stay in the same worker chain: LibreOffice
  produces a temporary PDF parser input only. The original source bytes,
  `SourceMaterialVersion`, source SHA-256, and Canonical artifact identity are
  never overwritten by that conversion.

## Legacy chain freeze and operational gate

- `DocumentService` remains for historical document endpoints only. New course
  material builds must use `/document/course-imports` and the asynchronous
  `SourceMaterialVersion -> TaskRecord -> DocumentParseRun` chain; no new
  course-building writes may be added to the legacy service.
- The shadow and sidecar document paths remain test-only. They are not a
  production source for canonical IR, retrieval, evidence, or citations.
- Before removing legacy behavior, record a representative import equivalence
  result, run the Alembic preflight and upgrade on an isolated copy, verify a
  reparse diff/adoption rollback path, then publish the decommission decision.
  Application rollback must precede any database rollback; canonical object
  storage objects are never deleted by schema rollback.

## 真实验收状态

### 2026-08-11 正式解析、GraphRAG 与向量索引链路

新课程统一采用 `文件上传 → DocumentIR/Evidence → CourseCorpusSnapshot → GraphRAG 草稿 → 教师审核 → LanceDB+BGE → Active Bundle`。解析、构图和向量化是三个可重试的 durable task；GraphRAG 不阻塞解析且不自动发布，只有审核通过并完成向量完整性校验后才激活 Bundle。

管理员可在平台管理页的“后台任务并发”区域开启开发者模式并设置总并发、文件解析、课程备课、GraphRAG、LanceDB 索引上限。默认关闭开发者模式，每进程串行执行；多进程/重启场景仍由任务 lease 保证一致性。

解析/草稿模型、OCR Port 和前端契约的隔离测试已经通过。真实 PaddleOCR 容器验收**尚未完成**：

```text
docker compose -f deploy/paddleocr/compose.yml up -d --build
→ Docker Desktop Linux engine 的 npipe 不可访问
```
