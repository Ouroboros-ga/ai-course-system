# 统一课程建设实施状态

更新时间：2026-07-28（本地 Demo）

## 已接通的正式链路

```text
教师上传文件
→ SourceMaterial / SourceMaterialVersion
→ TaskRecord / DocumentParseRun
→ DocumentBlock / Evidence / 图谱候选审核记录
→ CourseOutline 草稿
→ TeachingScript 草稿
→ PatchProposal（规则候选，教师确认前不修改节点）
→ 教师编辑、锁定、提案审核
→ 已发布 Outline + Script
→ 课程 Release 质量门禁
```

- 建设页不再提供对象路径、文件哈希或“已解析”状态的手工输入。
- 历史重建路由不再注册。旧课程不能走批量重建；需要通过统一上传入口重新生成。
- `CourseOutline`、`TeachingScript`、`PatchProposal` 使用独立版本和教师审核 API；旧 `CourseScript` 只作为历史兼容读取，不再作为建设页写入源。
- 课程发布门禁要求至少一个已发布的新版课程树节点，以及与该树版本对齐、且含节点的已发布讲稿。
- 教师提案先显示 before/after Diff；接受操作只能写入草稿，且不能覆盖教师锁定或已发布版本。
- 解析任务现在会为每个有效文本块生成可追溯的 `GraphNodeReview` 节点/相邻关系候选；规则标题清理仅在确有变化时生成 `PatchProposal`，操作带 `EvidenceSpan` 引用。
- 当前 B1 是**确定性规则基线**，不是 LLM 生成质量证明；接入 LLM 后必须增加独立 policy version，并保留本基线作为对照。
- 课程数字人使用教师个人中心已校验、已预处理的预设。课程媒体页只创建绑定/生成任务/媒体发布草稿；学生只读取激活媒体版本。

## 文件解析策略

| 输入 | 实现路径 |
| --- | --- |
| PPTX | `NativePptxProvider`；低文本/图片内容由 OCR enrichment 补充。 |
| PDF | `PdfPlumberProvider` 提取原生文本；解析计划要求对每一页调用独立 PaddleOCR。PaddleOCR 不健康时以 `OCR_SERVICE_UNAVAILABLE` 失败并可重试，不能把未 OCR 的 PDF 标为成功。 |
| 图片 | 走 `DocumentOcrPort` 的 PaddleOCR 服务；本地 provider 仅为受控降级。 |
| DOCX | `PythonDocxProvider` 提取标题、段落、表格；同时通过 LibreOffice 转 PDF，再走 PDF 全页 OCR 获取页坐标。 |
| DOC/PPT | 先通过 LibreOffice 无头转换成 PDF，再走 PDF 全页 OCR；转换失败返回“重新上传 DOCX/PDF”的结构化失败。 |

> PaddleOCR 在当前 Demo 中只保留 `OcrProvider`/`DocumentOcrPort` 接口，标记为 `fake/unavailable` 能力：接口可以被规划器和任务调用，但未部署独立服务时不得返回伪造文本，也不得把任务标成已完成。真实 OCR 由人工部署 `deploy/paddleocr` 后再启用。

## 真实验收状态

解析/草稿模型、OCR Port 和前端契约的隔离测试已经通过。真实 PaddleOCR 容器验收**尚未完成**：

```text
docker compose -f deploy/paddleocr/compose.yml up -d --build
→ Docker Desktop Linux engine 的 npipe 不可访问
```

待 Docker Desktop 切到并启动 Linux containers 后，执行：

```powershell
docker compose -f deploy/paddleocr/compose.yml up -d --build
Invoke-RestMethod http://127.0.0.1:8090/health
```

随后用一份已授权的扫描 PDF 上传到“建设 → 资料”，确认 `DocumentParseRun` 记录每页 OCR 的 provider/model hash 与页码坐标。不得把该验收前的测试结果表述为真实 PaddleOCR 已验收。
