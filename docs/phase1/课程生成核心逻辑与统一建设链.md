# 课程生成核心逻辑与统一建设链

> 状态：当前本地 Demo 的实现说明（2026-07-28）。
>
> 本文描述实际代码已经接通的课程资料生成链，不把规划、占位 Provider 或未配置的外部服务写成“已上线”。详细事实以注册路由、服务调用链、数据库迁移和可运行验证为准。本文是 [统一课程建设与解析基线](统一课程建设与解析基线.md) 的实现 companion，九步计划仍保留决策背景和历史差异。

## 1. 产品目标与最终产物

课程首次上传资料后，系统生成一套可审阅的课程草稿，而不是直接把模型输出发布给学生。目标数据结构为：

```text
课程
└─ 节（section）
   └─ 知识点（knowledge_point）
      ├─ 讲解脚本（TeachingScriptNode）
      ├─ PPT 播放映射（CoursePptMapping，可选）
      ├─ 示例（example）
      └─ 练习建议（practice_suggestion）
```

一份解析任务还会产生：

- 可追溯的 `DocumentBlock` 和 `EvidenceSpan` 候选；
- 课程隔离的 RAG 草稿索引计数和图谱候选计数；
- Markdown 课程资源草稿；
- 首次导入时的一份备课 Agent `PatchProposal`；
- 后续教师编辑、锁定、发布所需的版本和任务记录。

核心原则是：

```text
文件事实
→ 统一解析
→ 确定性课程骨架
→ 讲稿/映射/资源草稿
→ Agent 结构化提案
→ 教师审核、编辑、锁定
→ 质量门禁
→ 不可变发布版本
→ 学生学习单元
```

LLM 或 Agent 只能生成候选和提案，不能绕过教师安全阀直接改写已发布内容。

## 2. 端到端调用链

### 2.1 上传与异步任务

正式入口是 `POST /api/v1/document/course-imports`，兼容入口 `POST /api/v1/document/upload` 委托同一个 `_create_course_import_core`，不会再走旧的同步 Docling → Script → TTS → 发布链。

入口执行以下动作：

1. 校验扩展名（PPT/PPTX/PDF/DOC/DOCX），并将源文件写入对象存储，得到 `object_key`、内容哈希和 `SourceMaterialVersion`。
2. 为草稿课程创建或复用课程资料记录、`TaskRecord` 和 `DocumentParseRun`。
3. 返回 `202`，把真正的解析交给 `document_parse` 任务处理器。
4. 任务中心记录阶段进度；页面可以离开，重新进入“我建设的”或任务中心查看状态。

解析服务重启时，启动扫尾会把遗留的 `pending/running` 任务和解析运行标为 `interrupted`，前端显示可重试，而不是永久停在“解析中”。Demo 阶段不承诺进程重启后自动恢复执行。

### 2.2 统一解析

`run_parse_pipeline` 消费 `ParsePlanner` 生成的完整 `ParsePlan`，执行 PRIMARY 与 ENRICHMENT 步骤，再由 `BlockReconciler` 合并结果。

| 输入 | PRIMARY | ENRICHMENT / 转换 | 失败语义 |
| --- | --- | --- | --- |
| PPTX | `NativePptxProvider`：标题、文本框、备注、页序 | 图片型/低文本页经 `DocumentOcrPort` 调 PaddleOCR | 解析失败返回结构化错误，不伪造文本 |
| PDF | `PdfPlumberProvider`：原生文本、页码、布局 | 每页优先 PaddleOCR，Reconciler 合并文本、bbox、置信度；本地 Demo 可按配置回退 Tesseract | PaddleOCR 与回退 OCR 均不可用时返回结构化不可用/可重试错误 |
| 图片 | `PaddleOCRProvider` | 无 | OCR 不可用时任务可重试 |
| DOCX | `PythonDocxProvider`：段落、标题、表格 | 转 PDF 后走 PDF + PaddleOCR | 转换/解析失败返回明确错误 |
| DOC / 旧 PPT | `LibreOfficeHeadlessConverter` 转 PDF | 再走 PDF + PaddleOCR | 转换失败返回 `SOURCE_REUPLOAD_REQUIRED` |

主后端只依赖 `DocumentOcrPort`。PaddleOCR 服务在 `deploy/paddleocr/` 独立部署，避免把模型运行时和主后端 Python 环境耦合。当前 Demo 在端口不可用时保留进程内 Tesseract 回退；正式部署仍应验证 PaddleOCR 健康和 PDF 必需策略。

每个 `DocumentBlock` 保存 `material_version_id`、`page_or_slide`、`source_kind`、`confidence`、`provider_version`、内容哈希和语义字段，确保后续目录、脚本、引用和映射可以回溯到原始材料。

## 3. 稳定课程骨架生成

### 3.1 语义输入

解析阶段根据标题级别、样式和文本提示写入：

- `heading_level`：原始标题级别；
- `semantic_role`：`section_title`、`knowledge_title`、`example`、`practice_suggestion` 或 `explanation`；
- `style_hints`：标题/列表/表格等样式提示；
- `parent_block_id`、`reading_order`：原始阅读顺序；
- `visual_description`：图片或视觉块的补充说明。

这些字段是结构推断提示，不是发布结论。

### 3.2 `TeachingStructureBuilder`

`build_outline_draft` 创建 `CourseOutlineVersion(lifecycle_status=draft)`，然后按文档阅读顺序生成有序树：

1. 文档中的节标题生成顶层 `section`；没有节标题时创建兼容性的“课程内容”节。
2. 知识点标题或连续解释块生成 `knowledge_point`。
3. `example` 和 `practice_suggestion` 挂到当前知识点下面。
4. 节点保留 `source_block_refs`、页码范围、置信度、生成原因和内容哈希。
5. 仅知识点创建默认的 `CoursePptMapping` 草稿；示例与练习建议不作为独立播放单元。

该规则是稳定骨架：同一组有序 `DocumentBlock` 在相同版本代码下会产生相同的节点类型和父子关系。复杂课程的章节语义优化交给 Agent `PatchProposal` 和教师审核，不让 LLM 直接发布。

### 3.3 `TeachingScriptBuilder`

`build_teaching_script_draft` 创建与目录版本绑定的 `TeachingScriptVersion`，并为每个知识点生成 `TeachingScriptNode`：

- 内容来自该节点的 `source_block_refs` 文本拼接；
- 保留 `evidence_refs`、`source_block_refs`、样式和哈希；
- 目录和讲稿共享 `outline_version_id`，发布时必须同版本、同状态；
- 示例和练习建议保留在课程树中，但不生成空的播放器讲稿。

## 4. PPT 映射与资源产物

### 4.1 独立 PPT 映射表

正式映射表是 `CoursePptMapping`，不是 `CourseOutlineNode.page_range`。后者只作为兼容摘要字段。映射记录包含：

- `course_id`、`outline_node_id`、`material_version_id`；
- `page_start`、`page_end`、不连续页 `page_refs`；
- `source_block_refs`、置信度、`draft/published/stale/rejected` 状态；
- 教师锁定和更新者。

因此，非 PPT 资料仍可提供 Citation 页码，但不会被错误当成教学 PPT 播放映射。

### 4.2 Markdown 课程资料

`MarkdownBuilder` 按页和块顺序生成解析 Markdown，`CourseResourceWriter` 将其写入：

```text
ResourceItem(scope=course, lifecycle_status=draft, visibility=teachers)
└─ ResourceVersion(object_key, content_hash, material_version_id,
                  parse_run_id, source_block_refs)
```

Markdown 正文存对象存储，数据库只保存对象键、哈希和溯源字段。课程发布时，资源版本从教师草稿可见性切换为课程成员可读。

### 4.3 AI PPT

`POST /api/v1/course-editor/course/{course_id}/ppt/generate` 只消费已确认的课程结构和讲稿。生成的 PPT 会先作为新的 `SourceMaterialVersion` 写入对象存储，再重新进入统一解析链；不能直接写旧 `ScriptNode` 或绕过解析建立映射。未配置科大讯飞 PPT 服务时返回 `PPT_GENERATION_UNAVAILABLE`。

## 5. 备课 Agent 与教师安全阀

首次课程导入完成草稿资产后，`build_draft_assets` 创建一份 `CourseBuildAgent` 的初始提案（幂等：同一课程已有提案时不重复创建）。提案包含：

- `PatchProposal`：工具名、策略版本、整体理由和状态；
- `PatchProposalOperation`：`add/remove/replace/move/reorder`、目标、before/after、理由、课程 Evidence 引用和外部参考。

Agent 可以提出结构、讲稿和资源文本优化，但只能写提案表。教师可以逐项或批量接受/拒绝；接受后才会写入新的草稿版本。教师锁定的目录节点、讲稿节点和 PPT 映射不会被 Agent 覆盖。

WebResearch 资料只能放在 `external_ref`，不能冒充课程 Evidence，也不能直接改变正式图谱、掌握度或认知状态。

当前建设编辑器 API：

| 能力 | API |
| --- | --- |
| 读取/编辑/新增/排序/锁定目录 | `GET/PATCH/POST /api/v1/course-editor/course/{id}/outline...` |
| 读取/编辑/锁定讲稿 | `GET/PATCH/POST /api/v1/course-editor/course/{id}/scripts...` |
| 提案列表、创建、接受/拒绝 | `GET/POST/POST /api/v1/course-editor/course/{id}/proposals...` |
| PPT 映射读取、编辑、上传 | `GET/PATCH/POST /api/v1/course-editor/course/{id}/ppt-mapping...` |
| AI PPT 生成 | `POST /api/v1/course-editor/course/{id}/ppt/generate` |

所有带 `course_id` 的请求先通过 Course Access v1 建立课程范围，再检查 `course.view`、`course.edit`、`course.mapping.edit` 或 `course.publish` 等权限。

## 6. 发布与学生消费

### 6.1 发布门禁

`POST /api/v1/course-editor/course/{course_id}/publish` 创建发布草稿并执行质量门禁。门禁至少检查：

- 存在可用且已解析的课程材料；
- 存在课程结构和讲稿版本；
- 课程至少有一个节；
- 每个知识点归属节并有讲稿；
- PPT 课程的知识点具备 PPT 映射；
- 无关键解析任务仍处于运行状态；
- 课程访问基线和发布权限有效。

门禁通过后，目录、讲稿、资源和 PPT 映射切换为 `published`，课程状态切换为 `PUBLISHED`，并写入 `CourseRelease` 快照。已发布版本不可直接编辑；后续修改从发布版本复制出新的草稿版本。

### 6.2 学生学习单元

学生端只读取已发布版本：

- `GET /api/v1/course-editor/course/{id}/published-content`：目录、脚本和映射快照；
- `GET /api/v1/course-editor/course/{id}/published-learning-units`：按知识点返回可播放学习单元。

学习单元响应包含 `section`、`knowledge_point`、`script`、可选 `ppt_mapping`、`examples`、`practice_suggestions` 和 `playable`。这正是学生播放器和学习工作区需要的扁平消费 View Model，同时保留课程树的父子关系。

## 7. 任务、权限与失败语义

### 7.1 任务可观测性

解析任务按以下阶段写进 `TaskRecord.result_data.draft_assets` 和进度回调：

```text
rag_index_draft
→ graph_draft
→ outline_draft
→ teaching_script_draft
→ markdown_resource_draft
```

任一草稿子阶段失败不会伪造成功资产，会在结果中记录 `warnings`；解析主链或 OCR/转换失败则返回结构化错误码并保留可重试状态。

### 7.2 权限边界

- 课程草稿和教师可见 Markdown 只能由课程建设成员读取；
- 学生只能读取已发布目录、脚本、资源、映射和 Evidence；
- 所有 ORM 查询必须同时带 `course_id` 和共享权限解析结果；
- 不使用全局 `User.role` 或 `Course.teacher_id` 推断当前课程教师。

### 7.3 当前已知限制

以下是有意保留的 Demo 语义，不应在产品文案中写成完整生产能力：

1. RAG 草稿目前统计可索引块数，真实向量索引需接入正式向量 Provider。
2. 图谱草稿当前是可追溯规则候选，正式 GraphSnapshot 仍需教师治理和发布流程。
3. PaddleOCR、LibreOffice、科大讯飞 PPT 生成等外部依赖必须在目标环境单独验收；服务不可用时不会伪造解析或生成结果。
4. 本地任务 worker 重启后只标记 `interrupted`，不承诺自动恢复；用户可从任务中心重试。
5. 数字人/TTS/媒体时间轴不在本次课程骨架生成同步请求中，遵循独立任务和发布模型。

## 8. 迁移、验证与维护

相关数据库迁移按 Alembic 顺序执行至当前 head，包含：

- `0010_outline_script_patch_v1`：课程树、讲稿、PatchProposal；
- `0011_document_block_parse_provenance`：解析溯源字段；
- `0012_resource_lifecycle_visibility`：资源生命周期和可见性；
- `0013_course_ppt_mappings`：独立 PPT 映射表；
- `0014_document_block_semantics`：标题、语义角色、父块和阅读顺序。

针对课程生成链的重点验证入口：

```text
backend/tests/test_step0_task_sweep.py
backend/tests/test_step1_outline_models.py
backend/tests/test_step2_ocr_port.py
backend/tests/test_step3_combo_parse.py
backend/tests/test_step4_draft_assets.py
backend/tests/test_course_build.py
```

验证时应优先使用隔离 SQLite/临时对象存储；真实 PaddleOCR、PPT 生成、TTS 和数字人服务只在人工 Demo 环境验收，不进入自动化测试。

## 9. 维护规则

新增解析器、课程节点类型或学生消费字段时，必须同时更新：

1. `ParsePlanner` 和统一 pipeline；
2. 对应 Alembic 迁移和模型；
3. 草稿构建器、发布质量门禁和学生 View Model；
4. 教师建设 API/前端页面；
5. 本文与 `docs/phase1/功能现状审计表.md` 的实现状态。

任何“已完成”结论都需要至少有注册路由、调用链、数据模型和一次可运行验证作为证据。
