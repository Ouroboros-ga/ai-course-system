# 阶段 8 P5.2：OSS 上传与旧链隔离

> 状态：现行实现基线（2026-08-07）。本文记录已接入代码与验收边界，不把兼容入口或 Fake 测试表述为正式媒体能力。

## 上传协议

`AvatarSourceMediaService.request_upload_intent()` 只由服务端生成 `object_key`、大小/MIME 约束和短期上传意图。前端按 `method` 分支：

- Local：`PUT` 二进制到应用受控路由，携带 `exp/sig`；上传后必须调用 `confirm`。
- S3/OSS：`POST` 使用 provider 返回的 `url + fields + file` 构造 `FormData`，浏览器自动设置 multipart boundary；上传后仍调用同一 `confirm`。

`confirm` 不信任客户端元数据，服务端重新 HEAD、读取对象计算 SHA-256、探测 MIME/时长并执行扫描；对象不存在、错误 object key、过期签名、大小/MIME 不符或 SHA 不一致均 fail-closed。`content_sha256` 仅为历史登记字段，`server_content_sha256` 是确认结果。

## 本地签名读取

Local `/api/v1/media/assets/{object_key:path}/content` 必须提供 `exp`、`sig`、`scope`。scope 使用稳定的 `k=v;k=v` 形式参与签名，至少包含 `course_id` 与 `purpose`。验证顺序为：签名/过期时间 → object key 安全路径 → 资产课程范围 → Course Access → 文件返回。S3/OSS 不经过该路由，直接使用 presigned URL。

## 旧 `/video-gen` 隔离

`/video-gen` 保留为历史兼容入口，响应带 `legacy=true`、弃用说明、`Deprecation: true` 和 `Sunset: Wed, 31 Dec 2026 23:59:59 GMT`。旧任务只能写 `VideoGenerationTask`，禁止写入 `MediaRelease`、`MediaReleaseItem` 或 `audio-playlist/v1`；教师建设页不再引导提交旧视频任务。正式课程发布只接受新的 `MediaRelease + audio-playlist/v1`。
