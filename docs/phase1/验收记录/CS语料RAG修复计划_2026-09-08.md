### A4 · 发布 CAS 原子化（P1-3）

**文件**：`backend/app/services/discipline_knowledge/corpus_index.py::activate_index`（`:714-751`）。

**改法**：改为条件更新 + rowcount 判定——
`UPDATE discipline_heads SET release_id=:r, revision=:expected+1, updated_at=:now WHERE scope=:s AND revision=:expected`；
- `rowcount == 1` → 提交，返回新 revision；
- `rowcount == 0` 且 `expected_revision == 0` → 走 INSERT（`revision=1`），捕获 `IntegrityError`（scope 唯一约束）→ 回滚并返回 `RELEASE_CONFLICT`（含 `read_head` 现值）；
- 其余 → `RELEASE_CONFLICT` + `read_head` 现值。
`ready` 门与非 ready 拒绝保持不变；旧版本仍保持 `ready` 可回切。

**验收**：`test_corpus_index.py` 新增双 Session 用例——两个 session 均以 `expected_revision=0` 激活，先到者成功、后到者必须 `RELEASE_CONFLICT` 且 head 不被覆盖；现有 `test_incomplete_index_does_not_replace_active`、回切用例保持绿。

### A5 · FTS 探针非空真（P1-4）

**文件**：`backend/app/services/discipline_knowledge/corpus_index.py::validate_index`（`:574-606`）。

**改法**：探针词取自该 release 自己的内容——`SELECT title, body FROM paragraph LIMIT 1`（存库值已是 `tokenize_for_fts` 结果），取 body 首个 token（空则 title），`MATCH '"<token>"'` 断言 `COUNT(*) > 0`；两者皆空时记 `fts:empty_probe_source` 判不 ready。`fts_detail` 记录实际命中数。

**验收**：新增用例——构造 meta/paragraph 合法但 `corpus_fts` 为空行的同 key FTS 文件（按 `build_fts` 的表结构直写 sqlite），`validate_index` 必须 `ready=False` 且 reason 含 `fts:`；正常 release 仍 `ready=True`。

### A6 · unavailable 与无命中分离（P1-5）

**文件**：`backend/app/services/discipline_knowledge/corpus_search.py:186-240`。

**改法**：显式区分"通道失败"与"通道无命中"——`lexical_failed`/`vector_failed` 两个标志；`status="unavailable"` 仅在 `lexical_failed and (vector_failed or 无向量成员)` 时返回；FTS 正常但零命中 + 向量不可用 → `status="degraded"`、`match="none"`、`degraded_reasons=["VECTOR_UNAVAILABLE"]`。`mode` 语义不变。

**验收**：新增 `test_fts_no_hit_with_vector_down_is_degraded_not_unavailable`（命中一个 release 里不存在的词 + 抛错的 embed client，断言 `degraded`/`none`）；`test_both_paths_fail_is_unavailable`、`test_no_answer_returns_empty`、冷却用例保持绿。

## 7. 修复完成后的产品形态

**一句话**：一套"版本化语料索引 + 三入口同源检索"，把五类公开 CS 语料变成可检索、可回源、可回退的补充参考，而不是课程事实。

**用户看到的三个界面**
1. **学科页 `/app/discipline-knowledge`**：顶部模式切换（精编概念 / 资料检索 / 全部）。概念模式出概念卡（名称、类型、定义、要点、示例、权威标签、来源书目）。资料检索模式出语料块卡片：标题、片段、`来源种类`、`章节`、`匹配方式`（fts/vector）、许可、`语料版本：<release_id>`、覆盖率行（`文档 N · 文本块 N · 已向量化 N/N`，部分覆盖显示"部分范围"，降级显示原因），点"查看原文"行内展开该块正文与定位区间；无版本库时显示"语料检索暂不可用"。
2. **学生页助教回答**：回答下方"学科参考"区，每条含来源标题、`来源种类 · 许可 · 匹配方式`，可"查看原文"；只有被模型真正引用的条目计入 `used_discipline_reference_ids`，其余标"检索参考"；撤回来源显示"该来源已撤回，不再展示原文"。
3. **Nexus 会话**：`search_cs_knowledge` 工具返回"CS 语料参考（补充，需核对原文）"，信息源面板出现语料条目并显示回源身份（`reference_id`/`chunk_id`/许可）；模型上下文含完整原文，界面展示可截断但回源入口不丢。

**运维看到的形态**
`import_discipline_corpus`（登记+持久原文）→ `manage_corpus_index.py create-build`（建构建与分片）→ `run_discipline_worker --pipeline corpus_rag`（向量化，预算到顶可恢复暂停）→ `manage_corpus_index.py build --from-build`（组装 release + FTS）→ `validate` → `verify_corpus_rag --retrieval-only`（统计/引用可解析/延迟/错误码）→ `activate --expected-revision`（CAS 原子切换）→ 出问题 `activate` 回切旧版本；发布前 `corpus-preflight.sh` 只读预检；发布 `smartcarb-release.sh <批准SHA>`（迁移 + Nexus 独立发布 + 回退清单）。

**边界（产品承诺）**：语料块是"补充参考"，不进课程证据闭包、不改掌握度/图谱；无合适证据返回空并说明不足，不编造引用；覆盖率、降级原因、版本号对用户可见，不用数量冒充"全库完成"。
