## 2. 发现（按严重度）

### P0 · 阻塞（必须先修，否则 Runbook 无法执行）

**P0-1 corpus_rag 构建没有操作入口。** `builds.create_corpus_build` 的非测试调用为 **0 处**；`DisciplineBuild(...)` 仅 `builds.py:322` 构造；`discipline_knowledge.py` 无建构建端点；`manage_corpus_index.py build` 只做"导入→`create_release`→建 FTS"，**不建 build、不产生 embed 分片**（`--from-build` 要求 build 已存在）。后果：§7.2.4「分批向量化」无命令可跑，Worker 的 `corpus_rag` 管线无生产者，release 将 `embedded=0`（FTS-only）。直接违背 §7.3「build 创建构建与候选release」。
修：`manage_corpus_index.py` 增加 `create-build`（或 `build --create-build`），输出 `CORPUS_BUILD_ID` 供 worker 消费。

### P1 · 正确性/契约（会产出错误行为或永久卡死）

**P1-1 预算"暂停（可恢复）"三次后终态 `failed`。** `claim_item` 每次 `attempts+1`（`work_items.py:134`）；`fail_item` 在 `attempts > max_retries` 翻 `failed`（`:237`）；`_pause` 忽略返回值仍报 `"paused"`（`run_discipline_worker.py:188-193`）。默认 `DISCIPLINE_BUILD_MAX_RETRIES=2`（`config.py:275`）→ 第 3 次暂停即 `failed`；`_deps_met` 视 `failed` 为阻塞（`work_items.py:185`）→ fts/validate 永久卡死，构建停在 `running`，`retry_build` 又拒绝非终态构建。配合 `Restart=always`/`RestartSec=60`，无人值守约 3 分钟触发。
修：`BUDGET_EXCEEDED` 不计 attempts 或不计入失败上限；`_pause` 以 `fail_item` 返回值为准，返回 `failed` 时不得报 `paused`。

**P1-2 精编概念卡永不渲染（用户可见回归）。** `DisciplineKnowledgePage.vue:226` 的 `<template v-if="hasSearched && !loading && !error">` 之后紧跟 `:233` `<ul v-else-if="conceptResults.length">`；检索成功走 template 分支，概念 `<ul>` 永不渲染。CR5 回执"概念 UI 原逻辑不动"**不实**；§9.1 第 1 条若执行必失败。
修：把概念 `<ul>` 移出该 `v-if` 链（或改回 `v-else` 并调整 template 位置）。

**P1-3 发布 CAS 非原子。** `activate_index`（`corpus_index.py:714-752`）为 `select` → 比较 → 写入，无 `with_for_update`、无条件 `UPDATE ... WHERE revision=?`。两个并发激活者可同时通过检查。§8.1「并发发布冲突不覆盖」仅在单写者下成立。
修：改为条件 UPDATE + 检查 rowcount（或 `with_for_update`），PG 上补并发用例。

**P1-4 `validate_index` 的 FTS 探针是空真。** `fts_ok = True` 无条件置位，`probe_ok={probe >= 0}` 而 `probe` 为 `COUNT(*)`（`corpus_index.py:594-601`）→ 零命中的 FTS 也能判 ready，"探测命中"未被强制执行。
修：断言探针命中数 > 0（用 release 内必含词），或删除该伪检查并如实声明。

**P1-5 `unavailable` 与"无命中"混淆。** `corpus_search.py:217-223`：只要 `degraded` 非空且两路 ID 均空即返回 `status:"unavailable"`——包括"FTS 正常但无命中 + 向量不可用"的情形，与计划"两路均失败 → unavailable，与无命中区分"矛盾，且无测试。
修：仅当两路都**失败**时置 unavailable；正常无命中保持 `match:"none"` + `status:"degraded"`。

**P1-6 CR0"生成器断言"不存在。** 计划 §6 CR0/§9 声称"生成器断言题目非整段复制（`len(题)*2 < len(段)`）"。全仓**无 `queries.jsonl` 生成器**、无该断言（仅读者：`test_corpus_inventory.py:79`、`verify_corpus_rag.py:41`）。数据属性恰好成立（0/100 违反），但属**未强制**声明。
修：补生成脚本与断言，或改写计划措辞为"人工核验属性成立"。
