## 一、变更内容

`build_agent()` 增加三层工具面收敛，将 deepagents 0.7.12 默认挂载的
`ls`/`read_file`/`write_file`/`edit_file`/`delete`/`glob`/`grep`/`execute`/`task`
收敛到产品定义的 `NEXUS_TOOLS` 四件套 + `read_file`：

1. `FilesystemMiddleware(tools=["read_file"])` 经同名替换默认全量实例——
   上述文件工具与 `execute` 在 middleware `__init__` 即不创建（结构性移除，
   参见 deepagents `middleware/filesystem.py` L1765-1768 注释）；
   `read_file` 保留：SummarizationMiddleware 将压缩历史 offload 到 StateBackend
   （LangGraph state），模型需能读回。
2. `HarnessProfile(excluded_tools=NEXUS_EXCLUDED_TOOLS)` 注册于 provider 键
   `"openai"`（覆盖任意 `NEXUS_LLM_MODEL` 更名）：模型请求侧过滤 +
   工具调用侧拒绝（`_ToolExclusionMiddleware` 双层机制）。
3. `GeneralPurposeSubagentProfile(enabled=False)`：结构性移除 GP 子代理与
   `task` 工具（子代理栈会重新挂载文件工具）。

`/health` 新增 `tool_surface` 字段（执行器工具注册表；LLM 已配置时尽力构建
agent 以便部署后直接巡检，构建失败不阻断健康检查）。

## 二、严重度勘误（诚实性记录）

修复前实测（内省脚本，2026-09-04）：

- 模型请求侧可见 12 工具（4 产品工具 + 8 个 deepagents 默认文件/子代理工具）；
- 执行器注册表 13 工具（多 `execute`）；
- **StateBackend 落点为 LangGraph state 的 `files` 通道（随 checkpoint 持久化），
  不落宿主文件系统**；`execute` 因 StateBackend 未实现 SandboxBackendProtocol，
  调用时返回错误消息、不执行 shell。

故前端规格 §8 D1 原"默认后端根落在进程 cwd / 模型可直接改运行时源码"的表述
对 deepagents 0.7.12 **不成立**，已在该文档标注勘误。工具面暴露与提示注入后
state 污染风险属实，修复照常实施。
