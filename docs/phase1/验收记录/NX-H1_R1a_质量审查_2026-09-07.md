## 必须修复的发现

### H1 / P1：计划流事件串到当前打开的其他会话

位置：`frontend/src/app/pages/nexus/NexusPage.vue:1681`，事件消费在 1456–1464。

onEvent 回调读取执行回调时的 currentSession，而非请求发起时捕获的 session；handleEvent 不核对快照 session_id。生成过程中列表允许切会话。

复现：执行原始回调、handleEvent 与真实 planState.js，A 发请求后切 B，再收到 A 的 plan。结果 A.plan=null，B.plan.session_id=A，错误状态被持久化。这里是同用户不同会话污染，不是已证明的跨用户泄漏。

验收要求：回调绑定请求会话、事件校验 session_id；A 生成时切 B，A/B 各自仅接收自己的计划，revision 不能互相干扰。

### R1 / P1：合法证据 ID 不能保证正文引用合法

位置：`nexus/src/nexus/tools/paper_research.py:239,264–268`。

代码只 resolve cited_evidence_ids，然后把 body_markdown 原样拼入文件，引用附录从 1 编号。没有验证正文编号与证据列表映射。

实际工具调用复现：正文为 `Unsupported conclusion [999].`，参数包含一条合法 evidence_id，Artifact 写入边界以合成 stub 捕获。返回 success，正文保留 [999]，附录只有 [1]。所以“拒绝伪造 ID”通过，不代表“引用对应关系验证”通过。

验收要求：使用结构化引用标记并由服务端映射，或明确解析/验证受支持的正文引用语法；不存在的编号、引用顺序/去重错位、只有附录而无正文引用必须按契约拒绝或纠正。不得宣称服务端因此自动保证论点语义正确。

### R2 / P1：已登记证据绕过附件后续删除/过期

位置：`nexus/src/nexus/tools/paper_research.py:239` 至 Artifact 写入路径；`paper_evidence.py` 的进程内 Registry。

采集时经过 Backend owner/session/状态校验；报告写入只检查缓存 owner/session，不检查附件当前可用性。因此附件撤销后，只要 Runtime 还持有旧 evidence_id，就能继续生成包含旧摘录的新报告。

合成验证：先登记证据，再让附件读取边界模拟 ATTACHMENT_NOT_FOUND；调用报告工具仍 success，来源检查次数为 0。没有在生产执行删除；该结论来自实际函数调用和缺失的重新校验路径。

验收要求：新报告写入前验证所有来源当前的 owner/session/可读状态，或引入有效的撤销传播机制；删除、过期、重新绑定后旧 ID 不能继续新写报告。已生成报告如何保留应单独按 Artifact 生命周期处理，本条不要求静默删除既有报告。

### R3 / P2：固定取前部内容，问题相关证据可能永远不可引用

位置：`nexus/src/nexus/tools/paper_research.py:153–173`、`nexus/src/nexus/paper_evidence.py:61`。

question 只校验和回显，不参与选择；每块固定取前 1200 字，逐篇用尽共享预算；没有定位选择/后续分页登记入口。

复现一：一页前部为介绍，后部有 METHOD_RESULT_Z=42。提问该结果和提问介绍得到完全相同证据，结果句不在证据中，响应仍 truncated=false。复现二：第一篇有 13 个约 1100 字块，两篇请求只收集第一篇，第二篇 EVIDENCE_BUDGET_REACHED。第二例有如实报错，但使正常比较链易退化为单篇。

验收要求：允许按问题或明确 locator/块片段补充证据、合理分配多篇预算；任何块级截断都如实传播；总预算仍有界。至少验证页后半段结果、后续页方法、两篇长文比较，而不只验证短文本 fixture。

### H2 / P2：checkpoint 读取失败被当作没有计划且不再重试

位置：`nexus/src/nexus/main.py:738–745`；`frontend/src/app/pages/nexus/NexusPage.vue:498–499`。

aget_state 抛错被捕获为 state=None，接口返回 200 plan:null。前端把会话标记已恢复并清空当前计划。

实际 ASGITransport 注入 checkpoint unavailable，接口返回 200/null；真实 applyRestoredPlan 将原 rev3 清为 null/rev0。随后切回会话受 Set 阻止，不会重试。

验收要求：区分无计划与读取失败；失败返回明确错误，保留缓存但标注恢复失败，可重试；真正无计划才清空。

## 其他已确认的产品缺口

- `paper_evidence.py:65` 以 500 字符阈值判定 abstract_only/fulltext_excerpt，字符量不能证明文本是摘要还是正文。超过 500 字的摘要会显示全文摘录，短正文会显示仅摘要级；应依据来源/解析元数据，未知则明确未知。
- `NexusPlanCard.vue:23,36` 仅凭 Todo in_progress 展示“执行中”，未消费独立运行状态；Stop 后仍可能显示执行中。保留 Todo 原生状态是正确的，但任务书要求另外显示中断/暂停语义。
- `NexusEvidenceCard.vue` 摘录仅前 160 字，报告引用仅前 200 字，没有完整证据展开或附件定位入口；这削弱“用户可核对”体验，与 T4 的现有附件查看入口要求尚有差距。
- “最多修正一次”目前是工具说明/错误文字，不是服务端重试计数约束。交付口径应区分提示词规则与强制预算。
