## LB1 运行元数据（A）

- `nexus_runs` 显式迁移 `migrate_nexus_runs`：新库全列建表；旧库（12 列）
  逐列 ADD（SQLite PRAGMA / PG information_schema 双径）、run_number=0 旧行
  按 (user,session,created_at) 回填、`nexus_run_counters` 按 MAX 播种；
  可重入（第二次零变更）。回退：旧代码 SELECT 显式列名忽略新列，直接部署
  旧版即可；清退字段可手动 DROP COLUMN（PG）/重建表（SQLite）。
- 会话内稳定序号：counters 表 `INSERT..ON CONFLICT DO UPDATE + RETURNING`
  原子递增；同 run_id 重登不烧号；10 线程并发序号 1..10 无重复。
  前端 sorted index 仍只作临时显示（本批未改前端）。
- 默认显示名服务端生成：`preset display_name + run_number`（paper_title
  单独投影）；`PATCH /runs/{id}` 仅改 title（null/空恢复默认），
  `expected_version` 乐观锁（冲突 409 + current_version；跨用户 404；
  未声明字段 422 extra=forbid）。
- `GET /repro/presets`：Backend 经内部 HTTP 查 Runtime，不跨环境 import；
  只返回 display/论文/仓库/License/环境摘要/参数schema/预算/指标与来源/
  能力限制（无凭据、内部路径、命令原文——命令由 LB2 编译器按参数生成，
  不在此暴露可复制的执行串？注：训练命令模板含在编译器内，投影仅暴露
  参数 schema，不暴露完整 steps）。
- 列表详情扩展：display_title/title/run_number/version/parent/proposal/
  config_snapshot/status_source/observed_at/stale；分页 cursor/limit/
  next_cursor/total（total 真实 COUNT，失败抛 503 不冒 0）；老 items 字段保留。
- 有界并发：信号量 4＋整体 10s 截止；终态行消费快照且免问 Worker；
  live 终态与快照不一致 best-effort 回写；部分失联不阻塞列表。

## LB2 提案与审批（B）

- 提案模型（Runtime 自有存储 `nexus_proposals`，PG＋内存双径）：
  proposal_id/owner+session/version/preset/parent_run/objective/parameters/
  environment/repo_revision(+status)/data+seed/steps/budget/metric_policy/
  plan_hash/history（近 10 版）/status/created_at。
- 参数边界（nanoGPT 首版审核集）：9 个 typed 参数（min/max/default/
  metric_sensitive），未知字段/非法类型（含 bool）/越界一律 422；
  data 仅接受默认数据集配置；环境为预置声明（declared 非探测）。
- 确定性编译：默认参数编译结果与预设固定命令逐字一致（测试锁定）；
  lr_decay_iters 跟随 max_iters；未知预设拒绝。
- 审批绑定：request-approval pin 版本+hash+冻结步骤入票据（同版本重复请求
  幂等复用）；执行重验版本+hash（修改后旧票 `APPROVAL_PROPOSAL_CHANGED`）；
  提交用冻结快照（杜绝核验后修改竞态）；成功后提案标记 executed，
  后续 PATCH 须走新提案（409 PROPOSAL_LOCKED）。
- 待办恢复：`GET /approvals?session_id&status` 本人待办＋提案摘要；
  status 非法 422。
- 指标基线：仅全默认参数＋默认数据/环境继承已验证基线；任何敏感参数偏离
  → exploratory（comparison 为空、metric_note 写明原因、verdict
  EXPLORATORY）；报告产物照常生成；Worker /metric 只收 PASS/FAIL/
  INCOMPLETE——探索性跳过回写（metric 停留 pending 属诚实降级）。
  报告链经内部 by-job 取 linkage；无 linkage 走 legacy preset 判定（行为不变）。
- Worker 未改代码：提交载荷仍是 {preset_id, repo_url, repo_license, steps}
 （pydantic 默认忽略额外字段，但本批根本不发额外字段）；可验证性由
  冻结步骤（审批票据）＋Worker steps_result 命令＋run config_snapshot
  三方对账保证，测试覆盖"Worker 实际收到冻结命令"。

## 实现决策（与 §9.7 计划的偏差说明）

1. 未新建独立"运行上下文服务"模块：LB3 级别的 run/step 引用与有界上下文
   属批次 C；本批的上下文需求（提案 diff 取父快照）由 Runtime 经内部
   run 详情端点按需拉取，无需常驻服务。
2. Worker 零改动：§9.7 允许"最小扩展"，经核查不需要——提交载荷仍是
   {preset_id, repo_url, repo_license, steps}（pydantic 默认忽略额外字段，
   且本批不发额外字段）；可验证性由冻结步骤（票据）＋steps_result 命令＋
   run config_snapshot 三方对账保证。
3. 提案 PATCH 为增量语义（与创建全量一致，缺省回填当前值），非全量替换；
   extra=forbid 保证白名单外字段 422。
4. 探索性报告 verdict 新增 EXPLORATORY（PASS/FAIL/INCOMPLETE 不变）；
   Worker /metric 只收三值，探索性跳过回写（pending 属诚实降级）。
