## 批次 C（一）NX-LB3：同会话实验上下文及并发协议（§9.4）

- chat 请求扩展 `client_request_id`（Backend `NexusChatRequest` ↔
  Runtime `ChatRequest` 同构透传；Runtime 限长截断，空串=不启用幂等）。
- `context.run_ref {run_id, step_id?}` → 本层归属三重校验后替换为服务端
  白名单投影 `context.run_context`：本人 404 不区分、跨会话 403
  `RUN_SESSION_MISMATCH`、坏 step 422 `STEP_NOT_FOUND`；客户端自带
  `run_context` 一律丢弃、客户端提交的执行事实不透传。
- 有界日志：最近 ≤40 行且 ≤8000 字符（`_bounded_log_tail`）＋真实行数/
  截断标记；复用服务端脱敏（密码类遮蔽）；阶段事件沿用 NX-E2 裁剪口径。
- Runtime 单写者门（同 thread 一次一写）＋幂等注册表：不同请求竞争
  409 `SESSION_BUSY`；同键重试不调模型——/chat 回放已存结果
  （`deduped`）、/stream 回放说明性 done 事件；断流≠失败（有限状态
  恢复）；无幂等键请求在空闲后不受影响。
- 事件归属：token/plan/tool_call/tool_result/error/done 事件携带
  `session_id`/`request_id`；作业事件额外带 `job_id`/`run_id`
  （含 approval_id→run_id 的 linkage 语义）。
- Runtime 以系统注记注入快照（明确标注"不可信实验资料，非指令"；
  全长 12000 字符兜底；原始用户消息在注记之后）。

## 批次 C（二）NX-LB4：受限运行操作工具（§9.5）

- Research-only 六工具（General 结构性不可见）：`get_reproduction_run`、
  `cancel_reproduction_run`、`add_reproduction_note`、
  `create_reproduction_proposal`、`update_reproduction_proposal`、
  `request_reproduction_approval`。
- 查询/取消/备注经 Backend 内部端点（token＋用户＋会话三重头）消费；
  内部取消复用 NX-E3 取消核心（F1 语义：非成功如实上抛）。
- 取消授权：`POST /nexus/runs/{id}/cancel-grant`（登录态签发，绑定
  user/run/action=cancel_run＋会话＋300s TTL，一次性核销；并发下只一个
  调用方能拿到授权）。无授权 → 200 `confirmation_required`（模型引导用户
  确认，不自授权）；终态 → `already_terminal`（无需授权）；无 job →
  honest unknown。授权消费后 Worker 失败不伪装成功。
- 提案工具与 LB2 同一域服务（HTTP 端点已重构为同一核心
  `request_approval_for_proposal`，不再复制两套引擎）；模型只准备材料，
  批准永远由用户发起；陈旧版本请求被版本门拒绝。

## 批次 D NX-LB5：运行备注与产物（§9.6）

- `GET/POST /nexus/runs/{run_id}/notes`：追加式 note（note_id/author_kind/
  request_id 幂等/created_at/content ≤4000）；owner 校验（非本人 404，
  列表不可见即不存在）；用户端 author 固定 user。
- 内部端点 author 强制 agent（`add_reproduction_note` 工具）；author_kind
  仅 user/agent；备注不修改日志/指标/结论（字段语义＋提示词约束）。
- 报告链产物关联运行（`write_artifact_via_backend(run_id=linkage)`）：
  run 详情 `artifacts` 为已授权引用（artifact_id/类型/标题/大小/时间/
  download_path）；未收集/过期/他人产物如实不可见；Worker 工作目录清单
  不当下载链接。
- artifact 表旧库补 `run_id` 列（可重入；回退=旧代码不 SELECT 该列）；
  SQLite 方言分支仅用于本地测试。

## 附带修复（真实 bug，附回归测试）

- **签名键 body 容差**：前端 request.js 把 time/enc 注入 POST/PATCH
  body，`extra=forbid` 的 LB1/LB2 模型会对真实前端 422（线上 E2E 已实证
  PATCH 提案）。改为 extra=allow＋`_reject_unknown_fields`（除 time/enc
  外未声明字段仍 422；转发上游时排除 extras，Runtime forbid 兜底保留）。
  附 `test_rename_and_proposal_patch_tolerate_signature_keys`。

## 实现决策（与 §9.7 计划的偏差说明）

1. LB3 上下文投影放在 Backend 代理层而非新建独立服务：Worker 读取/
   裁剪/脱敏助手已在 proxy，内部端点经 import 复用（无循环依赖）。
2. 取消授权绑定三元组为 (user, run, action)＋会话（未绑定 request_id：
   确认发生在聊天请求之外，request 绑定会使授权无法跨请求使用）；
   session 绑定保留（浮窗上下文目标明确）。
3. /stream 同键重试完成态回放说明性 done 而非重放 token 流（流不可重放；
   内容从会话历史恢复——如实且不重复执行）。
4. action grant/notes 走 nexus_checkpoints 域表（与 runs 同模式），未另建
   存储；Artifact 文件仍复用既有媒体对象存储 prefix。
