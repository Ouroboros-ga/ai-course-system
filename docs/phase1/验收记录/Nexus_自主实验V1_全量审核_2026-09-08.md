## 2. 发现

### P1 · 正确性/契约（会产出错误行为或明确契约违背）

**P1-1 末次退出码把文件工具计入 → run 与报告可被误判"执行成功"。**
`experiment_agent.py:467-468` 对原生文件工具同样写 `last_exit = file_tool_exit(msg)`（成功→0，`:202-209`），`:489-491` 据此把 run 置 `succeeded`；`experiment_report.py:66-71` 的 `execution_succeeded` 取"末个非 None 退出码"（同样含文件工具）。后果：模型在命令失败后按提示词"查错误"读一次文件收尾，run 状态与报告都宣称成功——与"exit 0 ≠ 论文复现成功"的诚实性要求方向相反，且无测试覆盖（`test_bound_run_records_file_tool_attempts` 只断言成功场景）。
修：终态判定只取 `execute` 的退出码；文件工具仅记 attempt 不参与 verdict。

**P1-2 控制面 §2 契约两处未实现。**
(a) `PUT /sandboxes/{run_id}`：客户端发空体（`experiment_sandbox.py:259,272`），服务端与客户端全仓无 `scope_hash` → "同 run 同 scope 幂等、hash 不同 409"只剩"同 run 幂等"，现有 409 仅针对重启后 unknown run（`service.py:291-295`）。
(b) 文件接口"path 限定任务工作区、遍历/symlink 逃逸拒绝"：`service.py:_check_path:88-94` 只校验绝对路径＋无 `..`＋无 NUL，不限定任何工作区根、无 symlink 解析；上游 swe-rex 用 `Path.write_text`/`shutil.move` 会跟随符号链接。README/客户端 docstring 均写"工作区限定"，声明强于实现。

**P1-3 "后端和工具各自校验"只落实一半。**
`grep EXPERIMENT_EXECUTION_DISABLED backend/` 零命中：后端只做 ask|auto 词形 400（`nexus_proxy.py:146-157`），Ask→403 完全由 Runtime 裁决（`tools/reproduction.py:192-216`）；`backend/tests/test_nexus_runs_provider.py:358-372` 自证"403 来自 mock 上游"。任务书 T2 要求两侧独立拦截，现只有一侧。

**P1-4 已确认的资源上限未闭环。**
`ExperimentScope.resources` 经提案落盘，但 `_ensure_sandbox` 发空体、控制面用硬编码 `--memory=2g --cpus=2 --pids-limit=512`（`service.py:57-65`）；**磁盘无任何上限**，`wall_time_s` 只进审批卡/报告文案（`proposals.py:279`），无强制点。任务书 T4"服务端实施已确认的时间/磁盘/算力上限"未实现；T3 回执"容量核对属 T4"在 T4 未关闭。

**P1-5 T5 恢复未接线：`adopt_running_operation` 无生产调用点。**
`experiment_store.py:89` 有完整实现与单测（`test_experiment_recovery.py:163-171` 驱动它），但全仓仅 tests 引用；生产入口 `main.py:1461-1497` 的 console 只调 `_aprobe_console_reachable` 探可达性，从不续查 operation。Nexus 重启后：不会重放（这一点成立），但"接管查询"未落地，在途 operation 的结果无人回写，run 停留在 running。回执"重启后只接管查询（adopt_running_operation，零 submit）"与生产接线不符。

**P1-6 T1 回执称 `pull=never`，代码实为 `missing`。**
`swerex_adapter.py:71` 默认 `pull="missing"`，`service.py:297-299` 构造时不传 pull；缺省镜像 `REPRO_TASK_IMAGE` 回退公网 `python:3.12-slim`（`service.py:53-54`）。本地已缓存时等价 never，但缓存被清/tag 变更会静默联网拉取。README:57-58 自认"missing≡never"，回执写成"生产沿用 pull=never"。

**P1-7 T6 配方声称的"镜像 digest"在生产路径恒为空。**
`experiment_report.py:302-303` 读 `scope["resources"]["image"]` 与 `scope["image_digest"]`，而 `ExperimentScope`/`Resources` 无这两个字段、`validate_autonomous_scope` 走 `model_dump()` 丢弃 extra（`proposals.py:273`）→ 永远空串。能证明它的测试直接给函数传参，绕过生产路径。回执"配方：…＋镜像 digest"不实。

**P1-8 新增列走启动时 DDL，违反任务书明文且回执未记录偏离。**
任务书 T2："新增字段的存储升级按显式迁移进行，迁移文件编号读取当前 head 后分配，**不写启动时DDL**"。实现为 lifespan/懒加载 DDL＋`ADD COLUMN IF NOT EXISTS`（`main.py:79-94`、`proposals.py:411-432`），`git show --stat f8379d3e` 无迁移文件。Nexus 侧确无 alembic 机制（`nexus/` 无 alembic 目录，`NEXUS_POSTGRES_DSN` 独立于 backend 主库），既有惯例即启动 DDL——但偏离是明文禁令，回执未记录理由与编号分配。

**P1-9 T7 要求的 CURRENT 更新未做。**
任务书 T7："更新CURRENT仅标已验收范围：CPU公开仓库的一次确认自主配置与运行V1"。`docs/phase1/CodeNexus_P2开发计划.md:259` 仍写"当前全部NEXT，未安装新依赖或实现新运行服务"、`:268-271` 仍写"用户论文→实验准备 未实现""独立 Sandbox 目标链未实现""NX-O1 未实现"；`docs/DOCUMENTATION_INDEX.md` 同类。方向上没有提前翻绿（反而停在过期状态），但要求的受限标注缺失。
