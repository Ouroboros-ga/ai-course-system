# R1 外部服务适配层设计

## 1. 为什么先重构外部服务适配层

第一阶段目标是现状审计与测试基线。8 月初决赛前，最高优先级是现有功能稳定、兼容和可回滚。

现有系统中 LLM、TTS、PPT 生成、数字人、声音复刻、外部 HTTP 调用分散在多个 service 和 endpoint 中。M4A/M4B 已通过 `backend/tests/conftest.py` 和 `backend/tests/fakes.py` 建立测试隔离，但隔离点仍依赖对多个模块变量逐一 monkeypatch。R1 先补统一 adapter 层，是为了：

- 把外部服务的 success、timeout、service_unavailable、malformed_response、business_failure 统一表达。
- 让生产默认 client 和测试 fake 都能走同一个结果模型。
- 在不删除旧 client、不改公开 API、不改数据库结构、不改启动方式的前提下，逐步迁移高风险外部调用。
- 为后续 9 月计算机垂类能力复用外部服务接入、Mock 和错误处理基础。

## 3. 统一结果结构

`backend/app/platform/adapters/base.py` 定义 `AdapterResult`：

- `success`
- `data`
- `error_code`
- `error_message`
- `provider`
- `raw`
- `duration_ms`

`backend/app/platform/adapters/errors.py` 定义 `AdapterErrorCode`：

- `timeout`
- `service_unavailable`
- `malformed_response`
- `business_failure`
- `unknown_error`

该结构只作为兼容封装，不强迫所有业务立即重写。已迁移调用点仍把 adapter 结果转换回原有业务返回或原有异常路径。

数字人：

- 文件：`backend/app/platform/adapters/digital_human.py`

## 5. fake 和生产 client 的关系

旧 client 没有删除，生产默认配置语义不变。adapter 构造时接收 client：

- 生产路径传入当前已有 client。
- 测试路径通过 monkeypatch 或直接构造传入 fake。
- `backend/app/platform/adapters/registry.py` 提供延迟创建 helper，避免在 import 时固定旧 client，保留现有测试替换能力。

`backend/tests/test_r1_adapters.py` 已验证各 fake 在五种模式下可被 adapter 稳定分类：

- `success`
- `timeout`
- `service_unavailable`
- `malformed_response`
- `business_failure`

## 6. 已迁移调用点

数字人视频生成 service：

- 文件：`backend/app/services/video_generation_service.py`
- 调用点：`VideoGenerationService.generate_node_video`
- 迁移内容：`digital_human_client.generate_video` 改由 `DigitalHumanAdapter(...).generate_video` 包装。
- 业务保持：business_failure 仍记录 `GenerationStatus.FAILED` 并返回失败任务；timeout/service_unavailable 不会误标成功。

视频生成中的 TTS 合成：

- 文件：`backend/app/services/video_generation_service.py`
- 调用点：`VideoGenerationService._synthesize_tts`
- 迁移内容：`tts_client.synthesize` 改由 `TTSAdapter(...).synthesize` 包装。
- 业务保持：失败仍转换为 `TTSError`，由原有调用方记录失败任务。

PPT 生成 service：

- 文件：`backend/app/services/ppt_generation_service.py`
- 调用点：`PPTGenerationService.generate_ppt`
- 迁移内容：讯飞 PPT 模板获取、任务创建、任务轮询、下载由 `PPTAdapter` 包装。
- 业务保持：success 仍返回 `PPTTaskResult(status="done")`；business_failure 仍返回 `PPTTaskResult(status="failed", error=...)`。

TTS 节点音频合成路径：

- 文件：`backend/app/api/v1/endpoints/document.py`
- 路由：`POST /api/v1/document/course/{course_id}/node/{node_id}/synthesize-audio`
- 迁移内容：节点音频分段合成由 `TTSAdapter` 包装。
- 业务保持：success 响应结构不变；business_failure 返回原统一响应 `code=500`，不写入成功音频。

AI 问答 service 的一条 LLM 调用路径：

- 文件：`backend/app/services/qa_service.py`
- 调用点：`QAService.ask_question_with_rag` 的非 strict 普通问答分支。
- 迁移内容：`llm_client.chat(..., temperature=0.7)` 改由 `LLMAdapter` 包装。
- 业务保持：success 仍返回 `response.content`；business_failure/timeout 不会误标成功。

## 7. 暂未迁移调用点及原因

以下调用点本轮暂不迁移，避免扩大重构范围：

- `backend/app/services/document_service.py` 中多处 LLM 调用：文件超大且牵涉课件解析、脚本生成、映射等多流程，R1 禁止拆分或重写。
- `backend/app/services/mapping_service.py`、`progress_service.py`、`prerequisite_service.py`、`smart_course_service.py` 的 LLM 调用：不属于本轮指定最小业务路径。
- `backend/app/api/v1/endpoints/document.py` 中其他 TTS 调用：只迁移节点音频合成路由，避免影响上传解析和测试 TTS 路由。
- `backend/app/api/v1/endpoints/asset.py` 的声音复刻调用：adapter 已建立并测试，业务迁移留到后续有专门回归测试时处理。
- `backend/app/api/v1/endpoints/platform.py` 的泛雅 httpx 调用：`ExternalHTTPAdapter` 已建立并测试，端点迁移需要先补平台接口契约测试。
- `backend/app/api/v1/endpoints/video.py` 的远程视频 httpx 调用：`ExternalHTTPAdapter` 已建立并测试，端点迁移需要先确认远程视频响应契约。
- `backend/app/api/v1/endpoints/video_generation.py` 的健康检查：当前路由层仍直接调用 `digital_human_client.check_health`，本轮只迁移 service 生成主路径。

## 8. 回滚方法

回滚 R1 可执行：

```text
git checkout -- backend/app/platform backend/app/services/video_generation_service.py backend/app/services/ppt_generation_service.py backend/app/services/qa_service.py backend/app/api/v1/endpoints/document.py backend/tests/test_r1_adapters.py backend/tests/test_r1_adapter_migration.py docs/refactor/R1外部服务适配层设计.md docs/refactor/R1迁移报告.md
```

如果已经提交，可用：

```text
git revert <R1提交ID>
```

回滚后旧 client、公开 API、数据库结构、启动方式会恢复到 R1 前状态。

## 9. 对 8 月决赛的影响

R1 不改变公开 API、不改变数据库生产结构、不改变启动方式，不实现新业务能力。影响集中在外部服务调用的错误归一化和测试可控性：

- 降低真实付费服务被自动化测试误调用的风险。
- 保持 M4A/M4B 关键后端测试通过。
- 保持前端 build 通过。
- 让 business_failure 不再被误判为 success。

## 10. 对 9 月计算机垂类的复用价值

9 月若扩展计算机学科垂类能力，仍会复用 LLM、TTS、PPT、数字人和外部 HTTP 能力。R1 提供的价值是：

- 可插拔 provider/fake 结构。
- 统一外部服务错误模型。
- 可复用测试隔离能力。
- 可在不接入真实付费服务的前提下测试失败分支。
- 后续垂类能力可以先依赖 adapter 接口，而不是直接耦合具体云服务 SDK 或 httpx 调用。
