# R2D0 开源组件调研与选型

## 1. 方法与结论

调研时间：2026-07-12。只采用官方仓库、官方文档、论文和 license；活跃度仅作维护风险信号，不以 stars 决策。版本号会变化，实施时必须锁定并重新做许可扫描。

## 2. 文档解析能力细分

### Docling

优势是当前项目已经接入且原生对象可表达结构和 provenance。主要问题来自本项目把结果降为 Markdown，而不是 Docling 本身完全不具备结构。V2 应新增 `DoclingParserProvider -> DocumentIR`，冻结 provider 版本并保存 raw result 引用。

### 原生 PPTX

普通 PPTX 的 slide、shape、notes、table 是确定性源，应优先使用 python-pptx。建议：

1. python-pptx 产生 slide/block/asset 基线。
2. slide 文本覆盖率低、图片占比高时，仅对该 slide 渲染图执行 OCR。
3. 复杂流程图/图表且 OCR 仍不足时，才进入 VLM 候选。
4. Docling 结果用于补充与交叉校验，不覆盖高置信原生坐标。

### PP-StructureV3 与 PaddleOCR-VL

官方文档说明 PP-StructureV3 增强布局、表格、公式、图表和阅读顺序，并可输出 JSON/Markdown；CPU 可运行但 GPU 更合适，[官方介绍](https://www.paddleocr.ai/main/en/version3.x/algorithm/PP-StructureV3/PP-StructureV3.html)给出的硬件数据只能作为上游参考，必须用本项目样本复测。PaddleOCR-VL 是复杂页面的增强候选，[官方介绍](https://www.paddleocr.ai/main/en/version3.x/algorithm/PaddleOCR-VL/PaddleOCR-VL.html)不能替代本地成本、隐私和幻觉评测。


## 3. 图谱组件判断

本项目近期瓶颈是“没有可信 DocumentIR、证据、本体和评测”，不是“缺少图数据库”。因此：

- 采用自有 `GraphStore` 接口和关系库第一实现。
- 借鉴 KAG/OpenSPG 的 schema 约束与逻辑，LlamaIndex 的 extractor/retriever contract，LightRAG 的混合检索与删除，GraphRAG 的 global query 与评估。
- 不在 R2D1 安装任何图框架；避免框架默认 prompt、存储 schema 和模型依赖反向控制业务。

## 4. 推荐组合

| 场景 | 默认 | 条件增强 | 最后 fallback |
|---|---|---|---|
| 普通 PPTX | python-pptx | Docling reconciliation | V1 parser |
| 图片型 PPTX | python-pptx + slide render | PP-StructureV3 OCR；难页 VLM trial | V1 + 人工标记低质量 |
| 文本 PDF/DOCX | Docling | PP-StructureV3 对低质量页 | 格式级 V1 parser |
| 扫描/表格/公式 PDF | Probe 后 PP-StructureV3 trial | 后续可选 PaddleOCR-VL/VLM | V1 + needs_review |
| 图存储 | 关系库 | Neo4j/OpenSPG provider 试验 | 只读 V1 KnowledgePoint |
| 检索 | 自有 BM25/向量/受控图扩展接口 | 可对照 LightRAG/LlamaIndex | V1 tree RAG |

最终采用组合为：`python-pptx`（PPTX 原生结构）、Docling（通用 ParserProvider）、PaddleOCR/PP-StructureV3（按需 OCR 与复杂页增强）；PaddleOCR-VL/VLM 只作为后续质量门禁触发的可选能力。

## 5. 引入门禁

任何 Trial 升级为 Adopt 前必须：许可复核、锁定版本和模型哈希、离线安装清单、Windows/Linux 兼容验证、CPU/GPU P95、内存/显存、50MB 文档上限、无网测试、卸载回滚、基准集指标超过 V1。不得根据上游宣传数据直接宣称本项目效果提升。
