# R2D0 目标解析器架构

## 1. 总体数据流

```text
SourceArtifact -> DocumentProbe -> ParsePlan -> ParserRegistry
  -> ParserRun records -> ParserOutput -> DocumentIR
  -> Reconciliation -> OCR/VLM Enrichment -> QualityReport
  -> EducationalUnit -> SemanticChunk
  -> ontology-constrained candidates -> canonicalization/validation/evidence
  -> GraphSnapshot -> hybrid retrieval
```

V2 不直接改写 V1 的 `DoclingDocument/CourseScript/ScriptNode`。shadow 产物进入独立 SourceArtifact/run/DocumentIR/graph tables；通过验收后由兼容投影器生成 V1 所需结构。

这 20 层表示职责和契约边界，不表示 20 个微服务，也不要求一层一个类、一个目录或一个 provider。R2D1 只实现其最小闭环实际使用的类型与实现，不为未来阶段预建空接口、空 provider 或空目录。

## 2. 二十层边界

| 层 | 职责 | 输入 -> 输出 / 接口 | 失败方式 | AI | 持久化 | 现有连接点 |
|---|---|---|---|---|---|---|
| 1 SourceArtifact | 保存不可变源文件身份、哈希、mime | upload -> `SourceArtifact` | hash/存储失败 | 否 | 是 | 上传保存、`Course.source_file_path` |
| 2 Document Probe | 低成本探测页数、文本/图片比例、加密、格式 | artifact -> `ProbeResult` | unsupported/corrupt/encrypted | 否 | 是 | LibreOffice/PyMuPDF/python-pptx |
| 3 ParsePlan | 按特征、预算和策略选择 provider | DocumentProbe+policy -> `ParsePlan` | no viable provider | 否 | 是 | 替代 `parse_file` 内隐式 fallback |
| 4 ParserRegistry | 注册能力、版本、健康和 factory | `ParserProvider` contract | unavailable/version mismatch | 否 | 配置/运行快照 | 复用 adapter/registry 思路 |
| 5 DocumentIR | 屏蔽 provider 私有 schema | ParserOutput -> `DocumentIR` | schema violation | 否 | 是 | 替代 Markdown 作为唯一中间层 |
| 6 Reconciliation | 对齐多个 ParserOutput 的 blocks、去重、冲突裁决 | DocumentIR candidates -> reconciled DocumentIR | unresolved conflict | 否 | 是 | 新增；保留全部候选 provenance |

| 11 Educational Ontology | 定义节点、边、约束和版本 | ontology spec | incompatible version | 否 | 是 | 替代自由关系字符串 |
| 12 Entity Extraction | 生成 schema 严格的候选节点/mention | chunk+schema -> candidates | malformed/business failure | 可选 | 是 | 不直接发布最终图 |
| 13 Relation Extraction | 只在候选实体及证据范围内产边 | entities+chunks -> edge candidates | invalid endpoints | 可选 | 是 | 不允许无 evidence edge |

| 17 Graph Storage | 发布不可变快照、切换 active pointer | validated graph -> snapshot | transaction/conflict | 否 | 是 | 关系库优先；可选 provider |

## 3. 核心接口

```python
class ParserProvider(Protocol):
    name: str
    version: str
    capabilities: ParserCapabilities
    async def parse(self, source_artifact: SourceArtifact, parse_plan: ParsePlan) -> ParserOutput: ...

class IRMapper(Protocol):
    def to_document_ir(self, output: ParserOutput, parser_run: ParserRun) -> DocumentIR: ...

class GraphStore(Protocol):
    def write_candidate(self, run_id, nodes, edges, evidence): ...
    def publish_snapshot(self, course_id, candidate_run_id) -> str: ...
    def activate_snapshot(self, course_id, snapshot_id) -> None: ...
    def query(self, scope, seeds, edge_types, max_hops, limits): ...
```

Provider 不得返回 ORM；业务不得读取 Docling/PaddleOCR 私有对象。所有失败映射为结构化 error code，raw result 只通过 artifact URI 和 checksum 引用。

### 术语基线

- `SourceArtifact`：稳定源文件身份；不是一次上传请求或本地路径别名。
- `ParserProvider`：实现统一 `parse` 契约的解析器；其返回值统一称为 `ParserOutput`。
- `ParserRun`：一次 ParserProvider 调用的执行记录，使用 `parser_run_id`；所属流水线执行使用 `run_id`。
- `DocumentIR`：唯一 canonical 中间表示；`DocumentUnit` 通过稳定 `block_id` 引用其顶层 `blocks`。
- `runtime mode`：`v1_only`、`v2_shadow`、`v2_preferred_with_v1_fallback`、`v2_only` 的运行选择。
- `pipeline version`：冻结 parser/config/schema/prompt 等语义版本的版本标识；不是 `run_id`。

## 4. DocumentProbe 与路由

`DocumentProbe` 只做低成本、确定性检查：真实 mime、文件签名、大小、页/slide 数、加密/损坏、每页原生字符数、图片占比、shape/table/chart/formula hint、可提取文本页比例。

| 类型 | 默认 plan | 并行/增强触发 |
|---|---|---|
| 普通 PPTX | native-pptx + Docling 可选校验 | slide 字符 < 20 且图片占比 > 0.6 -> render + OCR |
| 图片型 PPTX | native-pptx 保存 slide/asset，OCR 图片页 | OCR 低置信或流程图/图表 hint -> 预算内 VLM |
| 文本 PDF | Docling | `text_coverage < 0.85` 或复杂表格/公式页 -> PP-Structure trial |
| 扫描 PDF | page render + OCR provider | 低置信页可试 VLM；不得全书默认 VLM |
| 公式 PDF | Docling + formula-capable provider 对目标页融合 | LaTeX 缺失或 formula_coverage < 0.8 -> review/fallback |
| 表格 PDF | Docling + table-capable provider | TEDS 代理质量低/跨页表 -> trial provider |
| DOCX | Docling；必要时 native package metadata | 图片页/嵌入对象按需 OCR |
| 图片 | OCR/layout provider | 图表/流程图才 VLM |
| 不支持/加密/损坏 | 明确拒绝或人工处理 | 不生成伪成功 DocumentIR |

阈值是首轮拟议值，必须由内部基准校准。

## 5. 融合算法

1. 按 `page_or_slide` 分桶；使用坐标归一化到 `[0,1]`。
2. 以 native PPTX 或高置信 layout provider 为 anchor；候选块用 IoU、文本相似度、类型和 reading-order 邻域匹配。
3. `match_score = 0.35*IoU + 0.35*text_similarity + 0.15*type_compatibility + 0.15*order_similarity`；>=0.75 自动对齐，0.5-0.75 保留冲突，<0.5 新块候选。
4. 同页重复：文本归一化相似度 >=0.95 且 IoU>=0.7 合并；保留全部 provenance。
5. 冲突优先级不是固定 provider 排名：原生结构优先 slide/table/notes；OCR 优先图片内文字；公式 provider 优先 LaTeX；其他按 calibrated confidence 和完整性。
6. 冲突无法裁决时，不覆盖；生成 `ParseWarning(CONFLICT)` 与多候选，质量报告降分。

## 6. 质量指标与门禁

```text
text_coverage = 有有效文本的预期文本区域或页面 / 预期总量
reading_order_confidence = 无逆序对的标注/规则一致比例
heading_confidence = 标题类型与层级信号的校准置信度均值
ocr_ratio = OCR 来源字符 / 全部有效字符
formula_coverage = 成功结构化公式 / 探测公式
table_coverage = 成功结构化表格 / 探测表格
visual_coverage = 已描述或已关联视觉资产 / 需处理视觉资产
duplicate_ratio = 被判重复的 block / 全部候选 block
empty_unit_ratio = 无有效 block 的 page/slide/unit / 总量
overall_score = 按文档类型动态加权，并设置硬失败项
```

初始 fallback：`text_coverage<0.85`、`empty_unit_ratio>0.05`、`duplicate_ratio>0.08`、扫描页 OCR confidence<0.75、探测到表/公式但对应 coverage<0.70。任何硬失败触发次级 provider；次级仍失败则 `needs_review`，不能假装成功。

## 7. AI 成本控制

- 先确定性 parser，再 OCR，再 VLM；只处理失败页/资产。
- 每 run 保存 `max_vlm_pages/max_tokens/max_cost`；超过预算返回 `BUDGET_EXCEEDED`。
- 按 artifact hash + provider/model/prompt/version + page hash 幂等缓存。
- 自动化测试全部使用 FakeParser/FakeOCR/FakeVLM，不读取真实 key，不联网。
