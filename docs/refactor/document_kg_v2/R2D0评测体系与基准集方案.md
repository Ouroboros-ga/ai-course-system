# R2D0 评测体系与基准集方案

## 1. 目标与证据边界

评测回答“V2 是否在本项目数据上优于 V1”，不是复述上游 benchmark。以下数量和阈值是拟议验收标准，尚未测量，禁止写成现有准确率或性能。

## 2. 基准集

首版最少 60 份已授权文档、600 页/slide；每类至少 6 份，并保证中英文、简单/复杂层级交叉覆盖：普通 PPTX、图片型 PPTX、文本 PDF、扫描 PDF、公式密集、表格密集、流程图/图表、DOCX、中英混排、复杂章节层级。另设 10 份不支持/损坏/加密/超限负样本。

划分：`dev 20 / test 30 / challenge 10`，同一模板/课程不得跨集合。test 金标冻结，challenge 仅切换评审使用。样本只存脱敏或明确授权内容；记录 license/owner/用途/截止日期。

目录建议：

```text
backend/tests/benchmarks/document_kg_v2/
  manifest.jsonl
  samples/<sample_id>/source.*
  gold/<sample_id>/{document_ir.json,entities.json,relations.json,qa.json}
  fixtures/provider_outputs/
  reports/<run_id>/
```

R2D1 只建立目录、manifest schema 和微型无版权 fixture，不放真实比赛材料。

## 3. 标注规范

- 两名标注者独立标 page/block/type/order/heading/table/formula/entity/relation/evidence；分歧由第三人裁决。
- block 坐标归一化；文本保存规范化与原文两版；阅读顺序为序列。
- 图节点遵守 ontology version；关系必须有 source/target/evidence，先修边写理由。
- 记录 inter-annotator agreement；若 block/entity F1 一致性低于 0.9 或 relation 低于 0.8，先修订指南，不拿不稳定金标评系统。

## 4. 解析指标

| 指标 | 定义 |
|---|---|
| 文本覆盖率 | 与金标字符/词对齐后的召回；中英文分别报告 |
| 标题层级 F1 | heading detection + level 一致的 micro/macro F1 |
| 阅读顺序 | 按匹配 block 的 Kendall tau，并报告完全正确页比例 |
| 页码映射 | block/unit 映射到正确 page/slide 的准确率 |
| 表格 TEDS | 结构化 table HTML 与金标 TEDS |
| 公式准确率 | normalized LaTeX exact match + edit score |
| OCR 准确率 | 中文 CER、英文 WER/CER |
| 空块率 | 无有效内容 block / 全部 block |
| 重复率 | 与金标相比多出的重复 block / 预测 block |
| 耗时 | 冷/热启动 P50/P95，按页和文档 |
| AI 成本 | VLM/LLM 页数、tokens、请求数、估算费用；本地模型报告 GPU seconds |

## 5. 图谱与检索指标

| 指标 | 定义 |
|---|---|
| 实体 P/R/F1 | type + canonical span/key 匹配；exact 与 relaxed 均报 |
| 关系 P/R/F1 | source canonical、type、target canonical 全匹配 |
| 先修 F1 | 仅 `PREREQUISITE_OF`，方向必须正确 |
| 实体重复率 | 应归一实体被拆成多个 canonical node 的比例 |
| 孤立节点率 | 除允许类型外，无结构/语义边的 accepted 节点比例 |
| 无证据边 | accepted edge 无有效 evidence 的比例 |
| 幻觉边 | 金标否定或证据不支持的边比例 |
| 教师修改率 | 审核中被修改/拒绝的自动候选比例 |
| 图谱问答准确率 | 教师标注答案要点命中率；同时报告 no-answer |
| 引用正确率 | 引用 block/page 确实支持回答的比例 |
| 检索指标 | Recall@5/10、MRR、nDCG、evidence coverage |

## 6. V1/V2 实验

同一 source bytes、相同机器和冷/热条件分别运行 V1、V2；V2 保存 provider/config/model/prompt hash。任何人工修正必须分“自动结果”和“审核后结果”两栏。解析器失败也计入分母，不删除困难样本。

必须有 ablation：native PPTX only、Docling only、Docling+OCR、reconciliation、VLM enrichment；图谱侧比较关键词 RAG、BM25+vector、再加 graph expansion，证明每层的增益与成本。

## 7. 最小切换门槛

V2 从 shadow 进入 preferred 必须全部满足：

### 解析硬门槛

- 全集文本覆盖率 `>=0.92` 且较 V1 绝对提升 `>=0.08`；任一类型不得回退超过 0.02。
- 标题层级 F1 `>=0.85` 且较 V1 提升 `>=0.10`。
- 阅读顺序 Kendall tau `>=0.90`；页码映射准确率 `>=0.95`。
- 有表样本 TEDS `>=0.85`；有公式样本 normalized score `>=0.80`。
- 扫描件中文 CER `<=0.08`、英文 WER `<=0.12`。
- 空块率和重复率均 `<=0.02`。
- 默认 route P95 不超过 V1 的 2 倍；单文档资源不得超过已批准部署上限。

### 图谱/检索硬门槛

- 实体 F1 `>=0.85`、关系 F1 `>=0.80`、先修 F1 `>=0.75`。
- 实体重复率 `<=0.05`、非允许孤立节点率 `<=0.05`。
- accepted 无证据边 `=0`，幻觉边 `<=0.02`。
- 教师修改/拒绝率 `<=0.15`，引用正确率 `>=0.95`。
- 图谱问答准确率较 V1 绝对提升 `>=0.08`，no-answer precision `>=0.90`。
- evidence Recall@10 `>=0.90`，且每个回答 citation contract 100% 完整。

### 工程硬门槛

- M4/M7/R1/R2 关键回归全通过；无真实付费服务测试。
- shadow 至少连续运行 7 天或 100 个成功 run，无跨课程污染、不可回滚或数据泄漏。
- 100% failed run 不改变 active V1/V2 pointer；回滚演练在 5 分钟内恢复。
- 许可、安全、离线部署、磁盘容量和数据清理审核通过。

任一硬门槛失败即保持 `v1_only` 或 `v2_shadow`。`v2_only` 需要额外人工批准，不因 preferred 稳定自动开启。

## 8. 自动化层次

1. schema/ID/quality 纯单元测试。
2. 每个 provider mapper 使用冻结 fixture 的 contract test。
3. FakeParser 五类模式：success/timeout/service_unavailable/malformed/business_failure，另加 partial/conflict。
4. 小型真实开源/自建 fixture 集成测试，不联网。
5. benchmark 命令生成 machine-readable JSON 和 Markdown 报告。
6. shadow 对比只读生产副本或授权演示数据，绝不调用真实付费 LLM/VLM。

OmniDocBench 的 schema 和指标可参考[官方仓库](https://github.com/opendatalab/OmniDocBench)，但其数据使用限制必须单独遵守，不能未经授权混入比赛或商业测试集。
