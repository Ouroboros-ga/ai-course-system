# R2D0 质量问题根因分析

## 1. 根因总览

效果差不是单一模型问题，而是“输入探测不足 -> 结构信息降维 -> 无质量门禁 -> 无 schema 抽取 -> 无证据图谱 -> 无隔离检索 -> 缺少真实评测”的连续放大。以下结论均指当前代码事实，不把规划能力视为实现。

| 维度 | 当前证据 | 影响 | 根因 | 修复层级 | 必须重建 | 优先级 |
|---|---|---|---|---|---|---|
| 文件类型路由 | `DocumentParser.parse_file:106` 先统一 Docling，异常后按扩展名 fallback | 普通与扫描、公式、表格文档走相近路径 | 没有 `DocumentProbe/ParsePlan` | Probe/Planner | 是 | P0 |
| PPTX 原生结构 | `PPTParser:70` 无生产引用；mapping 又直接调用 python-pptx | 文本框、备注、表格、图片关系分裂 | 没有 ParserRegistry 和统一 DocumentIR | ParserProvider/DocumentIR | 是 | P0 |
| 图片型 PPT | 当前没有按 slide 文本覆盖率触发 OCR | 空页或极少文本被当成正常解析 | 无 page-level quality/fallback | DocumentProbe/Enrichment | 是 | P0 |

## 2. 关键因果链

### 2.1 结构降维

Docling 或原生格式可能提供页、块、坐标和类型，但当前链路主要导出 Markdown，再由 `StructureParser` 正则恢复。降维一旦发生，后续脚本、映射、RAG 和知识抽取无法可靠恢复坐标、阅读顺序、表格结构或图片关联。

### 2.2 质量失败被当作成功

当前逻辑主要处理“解析器抛异常”，不处理“解析器返回结构化但覆盖率很低”。没有 `text_coverage`、`empty_unit_ratio` 等门禁，图片型 PPT 或扫描 PDF 可以技术成功、业务失败，并继续生成低质量脚本和已发布课程。

### 2.3 抽取早于可信知识底座

上传主链直接从全文生成脚本，RAG 也从 Markdown 标题树构建；知识抽取并未形成严格中间层。即使更换 LLM，输入仍有截断、错序、重复和缺证据问题。

### 2.4 图谱概念与存储不完整

`KnowledgePoint/KnowledgeRelation` 能保存基本节点和边，但没有 ontology version、candidate state、mention/evidence、review、snapshot。它适合保留 V1 兼容，不足以承载可审核图谱。

### 2.5 检索存在跨课程污染风险

`RAGPipeline` 是全局单例，`TreeRAGRetriever.build_index` 清空索引并写入当前树；`QAService.retrieve_rag_context` 未传 course/document filter。结果由“最后一次建立的树”决定，无法证明当前问答使用当前课程。

## 3. 不是根因的简化解释

- “换成更大 LLM”：不能修复缺页、错序、表格展平、跨课程索引覆盖。
- “直接上 Neo4j”：数据库不会自动产生正确的实体、边和证据。
- “直接接新的外部解析器或 OCR/VLM”：若没有 DocumentIR 与评测，只会把 provider 私有结构扩散到业务层。
- “一次 prompt 输出整张图”：不可分阶段验证、去重、环检测和教师审核。

## 4. 修复顺序

1. P0：建立 SourceArtifact、DocumentProbe、ParserProvider contract、DocumentIR、持久化 run 和基准集。
2. P0：实现按文档类型的路由、质量评分、fallback 与 V1/V2 shadow。
3. P0：建立 EducationalUnit、本体、证据模型、schema-guided candidate 抽取和验证。
4. P1：加入 OCR、表格/公式增强和受预算控制的 VLM。
5. P1：加入审核队列、图快照、混合检索和引用。
6. P2：仅在关系库实现达到瓶颈且评测证明收益后，再试验 Neo4j/OpenSPG/GraphRAG 类 provider。

## 5. 验收原则

任何替换都必须同时满足：相同样本可重跑、输出有版本、指标可比较、边有证据、课程隔离、失败可解释、V1 可一键回退。R2D0 中出现的阈值均为拟议门槛，不是已测结果。
