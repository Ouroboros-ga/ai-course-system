# R2D0 迁移发布与回滚方案

## 1. 双轨配置

建议配置：

```text
DOCUMENT_PIPELINE_VERSION=v1|v2
KNOWLEDGE_GRAPH_PIPELINE_VERSION=v1|v2
DOCUMENT_KG_RUNTIME_MODE=v1_only|v2_shadow|v2_preferred_with_v1_fallback|v2_only
```

配置解析必须 fail-closed：未知值拒绝启动或回到明确的 `v1_only`，不能静默开启 V2。两个 pipeline version 可独立选择，但 `v2 graph` 只能消费兼容版本的 V2 DocumentIR。

## 2. 模式语义

| 模式 | 用户可见写入 | V2 行为 | 失败处理 |
|---|---|---|---|
| `v1_only` | 完全由现有 V1 生成 | 不运行 | 现有 M7 fallback |
| `v2_shadow` | 完全由 V1 生成 | 异步/后台生成独立 `run_id`、DocumentIR、graph、评测，不写 V1 业务表 | V2 失败仅记录，不影响用户 |
| `v2_preferred_with_v1_fallback` | V2 通过质量门禁后投影兼容输出 | V2 为首选，必须保留 run/snapshot | 运行/业务/质量失败进入 V1，记录 fallback reason |
| `v2_only` | V2 投影 | 不执行 V1 | 仅在长期验证和人工批准后；失败明确返回，不伪造结果 |

## 3. M7 冻结保护

- M7 演示分支、账号、数据、预生成视频、脚本和测试不修改。
- 决赛前默认 `v1_only`；即使 V2 shadow 运行，也不能更新 Course status、ScriptNode、TTS/PPT/数字人任务或全局 RAG。
- 演示前检查必须验证三个 V2 变量未意外开启 preferred/only。
- 任何 V2 provider、模型或容器故障不得占用 M7 必要端口和 GPU 配额。

## 4. Shadow 隔离

1. 同一源文件通过 hash 关联，但 V2 使用独立 `run_id`。
2. V2 只写 V2 tables/artifact prefix，例如 `artifacts/document-v2/<run_id>`。
3. V2 不调用 `rag_pipeline.build_index`，不写 `document_cache`，不改 `Course/DoclingDocument/ScriptNode/KnowledgePageMap`。
4. 对比任务读取冻结的 V1 输出快照，生成 diff，不反写 V1。
5. shadow 的日志、metrics、模型配置去敏并按 run 隔离。

## 5. 已有课程迁移

| 阶段 | 动作 | 门禁 |
|---|---|---|
| 盘点 | 按 source 是否存在、格式、大小、课程状态分类 | 无源文件课程只保留 V1 |
| 小批 shadow | 先演示副本/内部课程 | 不触发用户可见生成 |
| 全量 shadow | 限流重解析，支持 pause/resume | 资源配额和失败率门禁 |
| 教师 review | 对实体、关系、页码、引用做抽样 | 修改率低于阈值 |
| candidate publish | 创建 graph snapshot，不切用户入口 | 回滚演练通过 |
| preferred canary | 1%/5%/25% 课程白名单 | 指标连续稳定 |
| 扩大 | 50%/100% preferred | 每级人工批准 |

不重新解析没有合法源 artifact 的历史课程；不得从旧脚本文本反推并宣称等价于原文图谱。

## 6. 发布前冻结

每次发布冻结：SourceArtifact hash、DocumentIR schema_version、ontology、ParserProvider package、模型权重 hash、prompt/schema、quality scorer、feature flags、migration version。任何一项变化都产生新 pipeline version/run，不能复用旧评测结论。

## 7. 回滚

### 应用回滚

1. 将 runtime mode 切回 `v1_only`。
2. 禁止新 V2 run，等待正在写 artifact 的任务安全结束或标 cancelled。
3. 保持 V2 数据只读供审计，不立即删除。
4. 验证 M7 冒烟主链、课程页面和问答 V1 fallback。

### 图回滚

原子切换 `active_graph_snapshot_id` 到上一个 active/retired snapshot；验证 course scope 和 version。不可修改旧 snapshot 内容。

### 兼容投影回滚

读取 projection manifest，仅恢复 hash 未发生用户后续变化的行；有冲突的进入人工清单。禁止 `git reset` 或数据库整库覆盖作为常规回滚。

### 数据清理

只按明确 `run_id` 删除未发布 shadow 数据，先 dry-run 输出 block/node/edge/artifact 数与绝对根目录校验；published/review/benchmark 引用使用 RESTRICT。源文件和 V1 数据不随 shadow 清理删除。

## 8. 触发回滚的 P0/P1

P0：跨课程数据污染、accepted 无证据边、公开 API/用户行为变化、V1 数据被 shadow 修改、无法回到旧 snapshot、敏感数据外传。立即关闭 V2。

P1：某文档类型指标回退 >2pp、P95/资源超预算、fallback 率超过 10%、教师修改率超过 15%、引用正确率低于 95%。停止扩量，回到 shadow 调查。

## 9. 验证与审计

每次模式切换记录操作者、时间、旧值/新值、版本、样本指标、验证命令、结果、限制和回滚方法。最低验证：M7 冒烟、关键后端回归、同一 artifact V1/V2 diff、跨课程隔离、failed run pointer 不变、snapshot 回滚、shadow 清理 dry-run。
