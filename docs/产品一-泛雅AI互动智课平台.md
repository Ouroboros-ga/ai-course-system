# 产品一：基于泛雅平台的 AI 互动智课生成与实时问答系统

副标题：**基于可追溯文档智能与教育知识结构的互动智课生成系统**。

产品阶段：8 月决赛主产品。本文是功能说明与重构清单，不以规划代替代码事实。

## 1. 产品目标与边界

### 1.1 要解决的问题

高校教师通常已有 PPT、PDF、Word、教案和题目，但它们仍是静态资料：建设在线课程成本高、讲授内容难复用、学生学习过程不可追踪。产品将资料转化为一条可编辑、可播放、可互动、可回看学习状态的课程链路。

```text
教学资料
-> 解析与课程结构
-> 教学脚本和页面映射
-> 音频 / 数字人 / PPT 表现层
-> 发布与分屏学习
-> 问答、测验、进度和前置知识跳转
```

### 1.2 目标用户与权限

| 用户 | 核心目标 | 应可完成的操作 |
|---|---|---|
| 教师 | 快速把存量资料建设成可教、可改、可发布的课程 | 上传资料、维护脚本/节点、映射页面、生成音视频、发布、查看课程状态 |
| 学生 | 在课程上下文中理解、提问、复习和补学 | 选课、分屏学习、播放节点、保存进度、问答、测验、前置知识跳转 |
| 平台/学校 | 复用课程资产并对接既有教学流程 | SSO、课程/选课同步、进度回调；外部调用可控、可审计 |
| 运维/演示人员 | 保持比赛现场稳定 | 使用预置数据、一键检查、外部服务降级和人工恢复 |

### 1.3 当前范围外

本产品当前不应被描述为已具备：计算机学科代码执行、BKT/HMM/LSTM、GraphRAG、复杂多智能体、自动教育知识图谱构建、真实 Duix 部署验收或经过量化证明的问答准确率。这些不属于 8 月决赛主链。

## 2. 产品信息架构与用户流程

### 2.1 教师建课流程

```text
教师登录
-> 管理素材（可选）
-> 上传 PPT/PDF/Word 等课程资料
-> 创建课程与解析记录
-> 生成/编辑课程脚本和节点
-> 节点与课件页面映射
-> 单节点或批量 TTS
-> 数字人 / AI PPT 任务（可选）
-> 预览、发布、下架、删除或版本回滚
```

### 2.2 学生学习流程

```text
学生登录
-> 选课
-> 初始化分屏播放器
-> 播放 PPT、音频或数字人节点
-> 保存/恢复课程与节点进度
-> 在当前课程提问或完成测验
-> 识别前置知识缺口
-> 跳转补学并返回原节点
```

### 2.3 决赛演示流程

演示和人工验收应按 [PageDesign 待打通能力清单](phase1/PageDesign待打通能力_配置与开发分工清单.md) 执行。真实外部服务不可用时，使用 Fake Provider 或明确的降级状态；不得把外部服务未验收表述为正式能力。

## 5. 必须重构项

重构项不是“立刻加功能”。每项必须保持公开 API、生产数据库、启动方式和用户可见行为兼容，先有契约/影子验证，再替换默认路径。

| 编号 | 重构项 | 现状问题与证据 | 目标能力 | 约束与完成标准 |
|---|---|---|---|---|
| R01 | 文档解析主链 | `upload_document` 在请求内串联文件、课程、解析、脚本、RAG 和后台 TTS；`DocumentParser` 先转 Markdown 再用标题正则降维 | SourceArtifact -> ParserProvider -> DocumentIR -> 教育单元的可追溯链路 | V1 双轨、影子运行、质量评测、可回滚；不直接替换当前上传 API |
| R02 | 结构化内容持久化 | 主链仅稳定落 `DoclingGroup/DoclingText`；表格、图片、坐标和阅读顺序未成为统一事实 | 保留 block、页面、坐标、表格、公式、图片和证据指针 | 先建立 DocumentIR/测试集，再决定 migration；不得直接改生产表语义 |
| R03 | 课程范围检索与证据 | R2D0 审计记录了进程内 RAG 与全局树风险；M4B/M7 fake 不验证检索质量 | 课程/文档作用域、来源引用、可复现检索和拒答边界 | 任何未评审工作树改动不算已交付；必须加跨课程隔离与来源测试 |
| R04 | 问答与学习证据 | QA 路径与全局 RAG、LLM prompt 耦合；引用、拒答和错误解释缺少稳定契约 | 有课程上下文、来源、置信/拒答和学习事件的问答服务 | 不伪造准确率；先定义答案、来源和失败响应 schema |
| R05 | 任务状态耐久性 | `tts_generation_status` 为内存兼容状态，重启丢失；不同任务状态模型不一致 | 统一内部 TaskResult 语义与可解释错误 | 保留旧状态接口；不新建复杂调度器或任务表，除非另有授权 |
| R06 | 超大 endpoint/service | `document.py`、`document_service.py` 责任集中，边界不清 | 以契约为先拆编排与纯逻辑 | 当前阶段不得大规模拆分；后续每次只迁移一条已覆盖链路 |
| R07 | 泛雅同步外部边界 | `platform.py` 存在 endpoint 内业务与 HTTP 调用混合、部分依赖占位 | 可 mock、可重试、可观察的同步边界 | 不在自动化中调用真实泛雅；先补平台契约测试 |

详细设计与回滚方案见 `docs/refactor/document_kg_v2/`，其中仍属设计中的内容不得提前计入完成项。

## 6. 调整与改善项

| 编号 | 改善项 | 当前问题 | 建议调整 | 验收方式 |
|---|---|---|---|---|
| I01 | 解析失败可见性 | Office 转 PDF 等局部失败可能继续流程，教师难判断资料质量 | 在兼容响应外补明确告警、失败原因与人工处理入口 | 上传异常、部分解析、空内容三类人工检查 |
| I02 | 脚本质量控制 | LLM 失败可降级默认脚本，教师可能误以为是高质量生成 | 脚本显示生成来源、降级标记和待编辑状态 | fake 业务失败、解析失败和默认脚本均可辨识 |
| I03 | 页面映射可编辑性 | 自动/AI/均匀 fallback 的来源不直观 | 在编辑器中显示映射方法、未映射节点与人工确认状态 | 手工修改后播放器、保存和重新加载一致 |
| I04 | 音视频任务反馈 | 前端只读旧字段时信息有限，真实服务也待验收 | 保留旧字段并可补失败节点、错误码、时长等兼容字段 | success/timeout/business_failure/partial 的状态显示一致 |
| I05 | 发布质量门禁 | 上传主链可能自动发布，解析/脚本质量未形成发布前检查 | 在不改变现有默认行为前提下提供演示/教师预检清单 | M7 预检通过且失败可人工回退 |
| I06 | 学生问答体验 | 答案与当前节点、来源、下一步学习动作关联不稳定 | 显示课程/页面来源、无法确认说明和前置补学入口 | 人工题集检查，不以单次模型回答代替验收 |
| I07 | 学习进度可靠性 | 多端、异常退出、重试后的进度语义需要明确 | 定义最后播放节点、时间点和完成度的冲突规则 | 选课、播放、离开、续学的 API 集成回归 |
| I08 | 教师配置与安全库 | 教师需要控制课程关键词、禁答范围、提示语和资料可见性 | 先设计课程级配置、审核记录和默认安全策略 | 未授权前不实现复杂审核系统；先给出 schema/流程与测试 |

### 7.2 学生专属记忆的最小产品定义

该能力不是 BKT/HMM/LSTM，也不在当前阶段实现。未来可按四层、可删除、可审计的数据模型设计：

1. 稳定学习画像：课程、专业、偏好、无障碍偏好等由用户或教师明确提供的信息。
2. 课程掌握状态：基于测验、完成度、练习和明确反馈形成的课程内状态，不推断不可解释的心理结论。
3. 学习过程证据：观看、提问、答题、跳转、代码/练习结果等带时间、课程、来源的事件。
4. 策略记忆：系统为何推荐补学、为何降低提示层级的可复核理由；允许用户查看、修正和删除。

## 11. 事实先行：可追溯与个性化的不可变依赖

这一节不是开发排期，而是产品语义约束：系统必须先保存“教材内容从哪里来”和“学生实际做过什么”这两类事实，才能可靠地产生可追溯答案、知识关系和个性化策略。

### 11.1 DocumentIR 是可点击引用的前提

学生问“二分查找为什么要求序列有序？”时，可点击引用需要的不是一段相似文本，而是一条完整的回原文路径：

```text
答案
-> 检索到的 EvidenceSpan
-> 文本块 block_003
-> 教材第 186 页
-> 页面坐标与字符范围
-> 前端打开页面并高亮
```

普通 RAG 若只保留“二分查找要求序列有序”的文本，最多显示文件名，不能确定它来自哪一页、哪个文本框或哪段字符。`DocumentIR` 因而必须保存稳定 `artifact_id/document_id/unit_id/block_id`、页/幻灯片、字符范围、坐标、解析来源和 raw reference；`EvidenceSpan` 只负责把答案、检索命中或后续知识关系锚到这些既有事实。

```text
DocumentIR：保存原始结构和稳定 block
EvidenceSpan：建立回原文的证据路径
课程范围检索：返回相关 evidence/block
可点击引用：根据 evidence 打开并高亮原文
```

没有前两层结构，任何“可追溯”都只能是粗粒度文件级链接。当前该能力仍在 R2D 设计/实现阶段，不能写入已完成项。

### 11.2 知识图谱建立在证据之上，而不是挡在 RAG 前面

可追溯 RAG 本身不依赖知识图谱：教材解析后，可先在课程范围内完成切块、关键词/BM25/向量检索，并返回教材、页码、段落和证据。知识图谱解决的是另一件事，例如“二分查找”的前置知识、使用方法和复杂度之间的关系。

```text
原文证据
├─ 支撑 RAG 答案
└─ 支撑知识图谱节点和关系
```

正确顺序是先有可验证的原文证据，再用它支持图谱候选节点/关系和教师审核；不能先由模型自由生成一张图，再补来源。GraphRAG 不是这一阶段的实现目标。

### 11.3 学习事件先于学生记忆

学生记忆不能只是“似乎不擅长二分查找”的聊天总结。应先把完成课程、测验错误、查看三级提示、重复边界错误、点击引用、补学循环不变量和重新测试通过等行为记录为标准 `LearningEvent`；再从事件形成可复核的 `LearningEvidence`，最后才派生 `StudentMemory`、`MasteryState` 和教学策略。

```text
LearningEvent
-> LearningEvidence
-> StudentMemory
-> MasteryState
-> 个性化教学策略
```

每个记忆或薄弱点都应能回答“由哪些事件得出、何时得出、是否可更正或删除”。这避免 LLM 仅根据聊天记录任意总结，也使教师和学生可以纠错。该链路不等同于 BKT/HMM/LSTM，当前尚未实现。
