## 1. 如何阅读本说明

系统同时存在两层能力：

1. **V1 主链**：当前默认启用、面向教师和学生的课程生产与学习闭环。
2. **Product 1 V2 Shadow**：默认关闭或无操作的旁路验证能力。它会在明确开启 Feature Flag 时产出独立 artifact 或 trace，但不得改变 V1 响应、V1 业务表、正式 QA Prompt 或学生页面体验。

因此，本文件使用以下状态口径：

| 状态 | 含义 |
| --- | --- |
| 默认可用 | V1 主链已注册并可用于演示；外部服务实际效果仍以对应人工验收为准。 |
| 离线回归 | 使用隔离数据库和受控 Fake 验证调用链、状态和兼容契约；不代表真实外部服务通过。 |
| Shadow | 旁路运行或技术入口已实现，默认不影响用户；结果仅用于对比、审计和后续审批。 |
| 技术占位 | API、DTO、前端组件或契约已准备，但尚未提供真实业务数据或默认用户能力。 |
| 待真实验收 | 需要授权环境、硬件、模型或人工质量检查，当前不得表述为已通过。 |

## 3. V2 Shadow 的总原则

V2 Shadow 是“采样和验证新能力”，不是替换主产品。实现位于 `backend/app/platform/shadow/`，共同规则如下：

1. 默认配置为 V1 或 disabled，系统行为等价于 M7 V1 基线。
2. 非法 Flag 值在启动时 fail-fast；合法配置下的 Shadow 运行异常 fail-closed，记录 `fallback_reason` 并继续 V1。
3. Shadow 不得调用第二次生成模型，不得写 V1 业务表，不得注入正式 QA Prompt，也不得阻断 V1 请求。
4. Shadow 结果写入独立的 artifact/trace 存储；这些运行时文件被 `.gitignore` 忽略。
5. 开启 Shadow 不等于 V2 已发布。G6 才是可能进入 preferred 模式的审批阶段，而 G6 尚未获准。

Feature Flag 的依赖关系为：

```text
DOCUMENT_PIPELINE_VERSION
  -> DOCUMENT_KG_RUNTIME_MODE
       -> EVIDENCE_CITATION_MODE
       -> KNOWLEDGE_GRAPH_PIPELINE_VERSION

LEARNING_EVENT_MODE
  -> STUDENT_MEMORY_MODE

SAFETY_GOVERNANCE_MODE
```

所有 pipeline Flag 只接受 `v1_only` 或 `v2_shadow`；Memory 和 Safety toggle 只接受 `disabled` 或 `shadow`。当前默认值为所有 pipeline `v1_only`、Memory/Safety `disabled`。实现见 [feature_flags.py](/E:/smartcarb/ai-course-system/backend/app/core/feature_flags.py)。

## 5. Shadow-1：可见但默认关闭的检索演示

`Shadow-1` 与上述 G3-G5 Product 1 V2 Shadow 完全独立。它是为答辩录屏、调试和观察设计的管理员本地页面，不嵌入学生聊天、课程播放器或教师建课主链。

| 项目 | 当前事实 |
| --- | --- |
| 入口 | 管理员登录后访问 `/demo/retrieval`；前端还需显式设置 `VITE_ENABLE_RETRIEVAL_DEMO=true`。 |
| 后端门控 | `DEMO_RETRIEVAL_MODE` 默认为 `v1_only`；可见模式仅在 `development`、`demo`、`test` 环境有效。生产环境强制关闭。 |
| 实验检索 | 运行冻结的课程范围 `BM25 + 本地 BGE Dense + RRF`，命中保留课程、页码、`block_id`、Evidence ID 和 citation key。 |
| 图谱展示 | 只展示冻结 `GraphSnapshot` 的 accepted 结构边；不导入 R3，不执行 GraphRAG 或图扩展检索。 |
| V1 隔离 | 不调用 V1 聊天、上传、进度、掌握度或 Memory；V1 参考回答只能由操作者手工粘贴，页面不会自动请求 V1。 |
| 运行记录 | 只写被 Git 忽略的 `research/product1_graph_retrieval/demo_runs/`，不使用 ORM、Migration 或生产数据库。 |

这是受限的研究展示，不是正式问答质量功能。当前 Reviewed Silver 测试素材的无答案误答率记录为 `1.0000`，尚无可用拒答阈值或校准器；页面只能展示带免责声明的 Evidence 文本摘录，不能宣传准确率、优于 V1 或“已验证的智能问答”。完整操作、风险和回滚见 [Shadow-1 Demo 操作与回滚手册](/E:/smartcarb/ai-course-system/docs/research/graph_retrieval/Shadow-1_Demo_操作与回滚手册.md)。

## 6. 与 Shadow 相关但不是学生正式功能的入口

### 6.1 Evidence Viewer 与 Evidence V2 API

前端已挂载 `/evidence-viewer/:documentId?`，后端已注册 `/api/v1/evidence-v2`。它们用于验证 Evidence、Citation、页码和坐标展示的接口契约，当前限制是：

1. 仅 ADMIN 可访问；普通学生不能通过它读取跨课程证据。
2. Flag 未开启时返回 `503 SHADOW_FEATURE_DISABLED`，不是空的成功响应。
3. G4 返回的是 DTO 兼容的空 Evidence/Citation 或 `no_evidence` abstain；真实文档 Evidence 和页图渲染仍未接入。
4. 前端已具备证据卡、坐标叠加、多个区域、高亮、缺坐标和 stale 版本提示的渲染能力，但当前不能对外宣称“所有课程已支持原文点击高亮”。

契约和边界见 [internal-evidence-api/1.0](/E:/smartcarb/ai-course-system/docs/refactor/product1/contracts/internal-evidence-api.md)、`backend/app/api/v1/endpoints/evidence_v2.py` 与 `frontend/src/features/evidence-viewer/`。

### 6.2 Canary V2 质量门禁

`/api/v1/canary-v2/run` 和 `/report` 是 ADMIN 专用的内部验证入口，需显式 course allowlist，并在 Evidence Shadow 未开启时返回 503。G5A 的 canary 会用 fixture/Fake 依次触发六条 G3 路径，汇总：

1. execution safety：是否二次调用 LLM、写 V1 表、注入 Memory 或阻断 V1；
2. contract integrity：Evidence、Citation、课程作用域和 Graph Evidence 不变量；
3. model quality：G5A 始终为 `NOT_EVALUATED`。

空样本、缺失样本和零分母现在显示为 `INSUFFICIENT_DATA`，不会再被表述为 PASS。G5A.1 记录的 31 项专项测试是质量门禁框架的回归证据，不是对真实 Docling/OCR/Embedding/LLM 的效果评估。详见 [G5A.1 复核报告](/E:/smartcarb/ai-course-system/docs/refactor/product1/reviews/p1-10-g5a1-verification.md)。
