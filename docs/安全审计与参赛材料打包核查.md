> 审计日期：2026-09-09 ｜ 基线：`dev-liu`（HEAD `48ad5327`）
> 目的：判定仓库当前内容与 Git 历史是否可作为参赛材料包（05—作品代码）下载后打包交给评委，是否存在密钥/环境变量泄露风险。
> 方法：只读扫描 Git 跟踪文件、未被 `.gitignore` 忽略的未跟踪文件、磁盘真实敏感文件，以及 Git 全历史曾出现过的 `.env`/密钥文件；输出仅含路径与命中类别，不暴露密钥原文。

## 内容扫描的误报说明

`secret_scan` 在源码/测试中命中的多为误报，已在审计中逐个核验排除：

- 测试文件中的 `api_key="...sensitive..."`、`setenv("...API_KEY", "dummy-key-for-*")`、`"secret-worker-token"`、`ghp_ + "a"*30`——均为**测试假值/自定义脱敏函数**；
- `password` 命中集中在 schema 字段名、请求体字段（如 `password: str`）、注释示例，非真实口令；
- `deploy/`、`backend/docs/` 中的 `DOUBAO_API_KEY=your_...`、`JWT_SECRET_KEY=your-jwt-...` ——示意占位符；

**未发现当前代码库中存在可用真实密钥。**

## 打包给评委的操作建议

1. **只打包无历史的快照，不打包 `.git` 目录。** 推荐 `git archive HEAD` 或在提交后克隆导出，确保 `.git/` 历史不进入压缩包，从而规避历史 `.env` 泄露。
2. 打包前再次运行 `python competition/preflight.py`（exit 0）与 `git status` 核实无 `.env`/密钥/数据库文件。
3. **不要**将仓库作为带 `.git` 的 Git 仓库直接发给评委；若评委要求源码仓库链接，先确认目标仓库不含上述历史 `.env`（或先清理历史）。
