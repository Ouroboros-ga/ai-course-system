# 产品介绍

SmartCarb 是一套面向泛雅平台的证据驱动课程建设、互动学习与教学分析系统，核心思想是让课程回应学习。系统以课程知识图谱为技术基座，把课件与文档带来源地解析为可信、可用、可追溯的知识结构；教育智能体依据六维认知数据理解学生怎么学、学到什么程度、学习意愿如何，据此促学、导学、督学与办学。

## 一、要解决的问题

在线教学平台已经完成课程资源的线上迁移，但资源被存储不等于资源被理解。大量 PPT、PDF 与 Word 文档仍以面向人类阅读的版面形式存在，机器难以稳定提取标题层级、知识结构与前后依赖；生成式 AI 虽然能生成内容，但通用生成范式并不天然适合正式教学——模型可能补充原材料中不存在的内容，检索可能混入其他课程或过期版本，智能体可能在权限与证据不足时执行动作。

系统因此确立三个核心问题：内容能否进入可审核、可追溯、可回滚的课程工程过程；检索结果能否同时满足课程、版本与来源约束；学习行为能否形成可靠的教学判断而不被弱信号误导。

## 二、三项核心机制

**证据锚定与教师审核双门控的智课生成机制**

课件经原生解析与 OCR 置信度加权融合后形成稳定的结构化中间表达（DocumentIR），证据片段与知识候选必须通过两道门控才能进入正式课程：证据门要求引用能够解析到当前课程的有效证据，教师审核门要求生成结果以草稿或提案形式呈现并由教师批准。课程发布版本不可变，支持回滚；同一机制应用于 AI 出题（草稿 → 教师批准 → 正式题库）。

**知识图谱驱动的可追溯精确检索知识包**

知识图谱是检索体系的基座：节点是知识点，边是前置、从属、支撑、关联等类型化关系，每条关系经教师确认，图谱快照发布后不可变。图谱之上融合 BM25 稀疏检索、本地语义向量、排名融合与图谱关系增强，检索结果再经课程隔离、版本一致与引用闭包三重约束才允许进入正式回答。索引不可用时失败关闭，不回退到跨课程或未经审核的候选。

**交互—测评双源证据分层驱动的学情反馈机制**

将交互信号（访问、进度、提问）与正式测评证据（服务端评分、代码实验终态）分域治理：交互信号描述学习过程，不能单独写成掌握结论；正式证据写入学习证据记录并绑定课程发布版本。系统在课程与知识点范围内输出六维认知状态，每维有独立样本门槛，证据不足时保持「未知」而非武断下结论，并叠加认知衰减、学习轨迹与图谱驱动的学习路径推荐。

## 三、系统架构

系统采用五层架构：平台接入与应用交互层（Vue 3 前端与泛雅兼容接口）、课程业务与发布层（草稿、质量门、发布与回滚）、智能体协作层（四类智能体与统一治理）、课程知识与证据层（DocumentIR、证据、图谱快照、知识包与向量索引）、基础设施与外部能力层（大语言模型、OCR、数据库、对象存储与代码沙箱）。

后端基于 FastAPI 与 SQLModel，数据库结构通过 Alembic 显式迁移管理；云端数据库为 PostgreSQL 16 + pgvector，SQLite 仅用于本地演示与测试。学生代码只能在独立沙箱中执行，不进入主应用进程。

## 四、四类智能体

备课智能体（Prep Agent）负责把材料转化为课程草稿并生成受控修改提案；教学智能体（TeachingAgent）负责课程内教学问答与受控教学动作；代码教学智能体（CodingEduAgent）基于沙箱真实结果提供代码诊断；科研智能体（ResearchAgent）提供课程内学术资料检索。四者物理分离、状态独立，通过受控接口协作，均受工具治理与安全围栏约束。

## 五、安全边界

AI 能力的安全围栏贯穿三个层面：智能体安全围栏（课程类型安全收敛、政治敏感审查、平台级屏蔽词、工具失败关闭）、沙箱安全围栏（代码执行独立隔离、命令黑名单、认证边界）、数据安全围栏（数据域隔离、对象标识签名访问、课程权限唯一入口、密钥不进入前端与仓库）。

## 六、当前部署状态

系统已完成云端演示环境部署：主服务器运行 Nginx、FastAPI 后端、PostgreSQL 16 + pgvector 与文档解析服务，独立实验服务器运行代码沙箱。课程材料解析、证据审核与发布、知识包构建与激活、跨课程隔离、实时问答、代码沙箱、学习调整与续学、学情分析与泛雅兼容问答等核心场景已完成端到端验证。该环境用于演示与验收，不代表已获准处理真实生产数据；能力状态的详细口径见项目技术文档。

## 七、与泛雅平台的衔接

系统通过防腐适配层接入泛雅平台：外部请求经签名校验、字段转换与权限解析后映射到内部服务，课程权限、证据、版本与智能体治理不被外部协议绕过。已部署的适配能力包括文本问答与学习进度追踪；语音转写等预留接口在未完成真实接入前返回结构化不可用语义，不以空结果伪造成功。
