# 面向编程教育智能体的多源认知证据驱动细粒度知识追踪方法研究

**Fine-grained Knowledge Tracing Driven by Multi-source Cognitive Evidence for Programming Educational Agents**

> CodeNexus 团队围绕编程教育智能体的认知建模方向开展系统研究。本文档介绍该研究的总体目标、技术路线、方法设计、预期结果与实验计划。

## 一、研究摘要

随着生成式人工智能和教育智能体的发展，在线学习环境能够记录的学生信息已经从传统的题目作答结果扩展到智能体对话、代码提交、测试用例、编译运行、代码修改、提示使用、自我解释以及学习路径等更加丰富的过程性学习证据。传统知识追踪通常以"知识点—题目—正确性"序列为主要输入，可以动态预测学生后续答题表现，但对于开放式学习过程中产生的语义信息、具体错误机制以及证据的不确定性利用仍然有限。

CodeNexus 的认知处理链按照 `LearningEvent → LearningEvidenceRecord → CognitiveState → Recommendation` 组织，并围绕 observed performance、evidence confidence、confusion risk、inquiry depth、hint dependency、explanation need 维护多维度认知状态。既有认知状态主要依赖规则、统计指标与固定阈值形成，更接近学习状态的统计投影；团队正研究将认知机制升级为长期、动态、可学习的 Learner Model。

本研究面向编程与基础算法学习场景，将学生答题结果、代码执行与测试用例、修改轨迹、提示行为以及与教育智能体之间的自然语言对话统一建模为多源学习证据，并进一步区分"客观学习事件""模型推断出的认知证据"和"长期学生状态"，形成：

**Observable Learning Event → Evidence Claim → Reliability-aware Temporal Learner State → Selective Diagnosis**

的学生认知建模框架。

研究不试图直接根据一次行为判断学生真实心理状态，而将 mastery、misconception 等变量视为由长期、多源学习证据支持的潜在状态后验。研究重点包括：轻量级语义认知证据抽取、多源证据可靠性融合、时序知识状态更新、题目难度测量、misconception 生命周期建模、证据冲突与不确定性分析以及允许输出 Unknown 的选择性认知诊断。

研究预期形成一套多源 CognitiveEvidence 数据规范、一个轻量认知语义编码模型、一个可靠性感知多源证据知识追踪模型以及面向 CodeNexus 教育智能体的 Learner Model 集成方案，并通过消融实验、跨学生与时间外测试、风险覆盖评估以及针对性教学干预实验验证模型的预测能力、可靠性与教学价值。

## 二、研究背景与研究意义

### 2.1 从"答题数据"向"完整学习过程数据"演进

传统在线学习平台最容易获得的数据主要包括题目、知识点以及学生回答正确或错误，因此经典知识追踪问题通常被表述为：

$$P(y_{t+1}=1\mid x_1,x_2,\ldots,x_t)$$

即根据学生过去的学习交互序列估计下一次回答正确的概率。

Deep Knowledge Tracing（DKT）使用循环神经网络从学习交互序列中学习隐式知识状态，代表了深度学习知识追踪的重要起点；此后 AKT 等注意力模型进一步利用注意力和时间衰减机制建模学习历史，并引入 Rasch 思想表示同一知识点下不同题目的差异。

然而，在教育智能体和编程学习环境中，学生一次学习过程能够产生的信息已经明显超过二元 Correct/Incorrect。

例如：

```
学生提交一道二分查找程序
        ↓
基础测试通过
        ↓
边界 Test Case 失败
        ↓
修改 l = mid + 1 为 l = mid
        ↓
再次出现死循环
        ↓
请求提示
        ↓
询问 Agent：
"为什么 l=mid 会死循环？mid 不是已经变了吗？"
        ↓
经过解释后重新修改程序
        ↓
新的边界测试通过
```

如果最终仅记录：

```
Correct = 1
```

大量能够解释学习过程的信息都会消失。

因此，本研究把知识追踪的基本单位从单纯的 **Response Sequence** 扩展为 **Learning Evidence Sequence**。

### 2.2 传统知识追踪的研究基础

从 BKT 到 DKT，再到 SAKT、AKT 等方法，知识追踪已经形成较为成熟的时序学生建模框架。DKT 证明了循环神经网络可以通过学生历史交互学习隐式知识状态；AKT 又引入 context-aware monotonic attention，并借鉴 Rasch 模型表示题目差异。

本研究没有必要将"重新设计一种 Transformer KT Backbone"作为主要创新目标。更合理的研究策略是使用 BKT、DKT、simpleKT、AKT 等已有模型作为基础和对照，将研究资源集中于传统 KT 尚不能充分解决的多源证据问题。

### 2.3 Agent 对话进入知识追踪的研究进展

2024 年提出、后发表于 LAK 的 Dialogue-KT 工作已经研究如何利用 LLM 对 tutor-student dialogue 中的知识组件和学生回答正确性进行标注，再将这些信息输入知识追踪模型；其 LLMKT 直接利用对话文本进行学生表现预测。

因此，"将教育智能体对话用于 Knowledge Tracing"本身已经不能作为本研究的独立创新点。本研究需要进一步回答的问题是：

> 对话中产生的语义推断，与正式答题、代码测试、修改行为等证据可靠性不同，当这些信息共同存在甚至相互矛盾时，应如何更新学生认知状态？

### 2.4 题目难度与能力建模的研究进展

Difficulty-Aware Conversational Knowledge Tracing 已经显式联合建模学生能力、任务难度和对话历史，并使用 IRT 将能力与难度映射到学生表现概率。

因此本课题中的 IRT/Rasch 不应被描述为主要方法创新。本研究将其定位为 **Measurement Layer**，即让 KT 产生动态 concept proficiency $m_{k,t}$，再通过题目难度 $\beta_i$ 估计：

$$\sigma(m_{k,t}-\beta_i)$$

当数据充分时再扩展到具有区分度参数的 2PL 形式：

$$\sigma(a_i(m_{k,t}-\beta_i))$$

其主要作用是避免把"简单题做错"和"高难迁移题做错"解释为完全相同的认知证据。

## 三、编程教育场景的特殊研究价值

编程学习相比普通选择题环境天然拥有更丰富的认知证据。已有研究（TIKTOC）证明，对开放式编程任务，只使用最终得分会损失大量学生知识信息；代码本身以及每个 Test Case 的通过情况能够提供更加细粒度的状态信息。

因此本研究选择编程和基础算法学习作为主要实验场景。每一次学习过程可以产生：

- Question Attempt；
- Code Submission；
- Compile Result；
- Runtime Result；
- Test Case Result；
- Revision；
- Hint Request；
- Agent Dialogue；
- Student Explanation；
- Learning Path；
- Time Interval。

这些数据共同构成传统 KT 数据集通常不具备的多源过程证据。

CodeNexus 的学习事件、代码实验与认知处理链路，为渐进构建 Learner Model 提供了工程基础。团队确定以新增 `EvidenceClaim` 与 `InternalLearnerState` 两层的方式完成认知升级，而不是推翻既有架构。

## 四、Misconception 建模的研究现状

传统 mastery 主要回答"学生对知识点掌握得怎么样"，但无法直接区分"学生为什么会错"。例如二分查找中的错误可能分别来自：

```
binary_search
│
├── search_space
├── interval_representation
├── loop_invariant
├── mid_calculation
├── boundary_update
└── termination
```

进一步可能存在：

```
Misconception
│
├── mid_always_progresses
├── closed_halfopen_confusion
├── wrong_left_boundary_update
├── wrong_right_boundary_update
└── off_by_one_boundary
```

已有研究直接从 Student-Tutor Dialogue 中生成、检索和重排 misconception 候选，表明"从对话识别 misconception"本身已经形成独立研究方向；ConceptKT 也将传统正确性预测扩展到 concept-level deficiency prediction，说明细粒度认知缺失诊断已经成为 KT 的重要扩展方向。

因此本研究不将"识别 misconception"本身作为主要创新。真正需要研究的是：

> 一个 misconception hypothesis 是否能够在 Answer、Code、Test Case、Revision 和 Dialogue 等不同事件中持续得到支持或反驳，并随着学习过程发生形成、增强、纠正和衰减？

也就是 **Temporal Misconception Tracking**。

## 五、不确定性与选择性诊断研究现状

UKT 已经使用概率分布表示学生交互和知识状态的不确定性，说明 uncertainty-aware KT 本身也已有研究基础。更进一步，已有研究专门将 selective prediction 引入 Knowledge Tracing，使模型能够基于 epistemic uncertainty 选择预测或 defer，而非始终输出结论。

因此本研究不能声称"首次让 KT 可以拒绝判断"。本课题真正关注的是：

> 能否根据学习证据本身的充分性、来源可靠性和冲突程度来决定是否进行认知诊断？

即进一步区分四类情况：

### Evidence Scarcity

数据过少。

### Extractor Uncertainty

语义证据抽取器本身不确定。

### State Uncertainty

Learner Model 对潜在状态不确定。

### Evidence Conflict

已有大量数据，但不同来源互相矛盾。

这四种情况不能简单地被表示成同一个 `confidence = 0.5`。

## 六、CodeNexus 认知处理链路基础

CodeNexus 的认知处理链按如下方式组织：

```
LearningEvent
      ↓
LearningEvidenceRecord
      ↓
CognitiveState
      ↓
Recommendation
```

并维护多维度认知状态：

- observed performance；
- evidence confidence；
- confusion risk；
- inquiry depth；
- hint dependency；
- explanation need。

其设计理念是：证据不充分时，允许输出 Unknown，而不是为每个学生生成伪精确诊断。

既有认知状态主要通过错误率、提示比例、重复错误和统计聚合得到，研究视角下仍存在以下问题：

1. 缺少深层时序建模；
2. 难以学习长期知识状态变化；
3. confusion 不能区分具体 misconception；
4. 对 Agent 对话语义利用较浅；
5. 没有系统考虑 Item Difficulty；
6. confidence 更接近"证据数量"而不是严格模型不确定性；
7. 不能显式区分证据不足和证据冲突。

因此本研究不推翻既有链路，而是在证据处理链中新增认知建模层。

## 七、核心研究思想

本研究最重要的设计原则为：

**Evidence ≠ State**

即：**观察到的学习事实，不等于学生认知状态。** 系统严格区分三个层次。

### 7.1 Observable Learning Event

表示客观发生的学习事实。例如：

```
{
  "event_type": "code_test",
  "concept": "binary_search_boundary",
  "result": "failed",
  "test_case": "two_element_boundary",
  "hint_used": false
}
```

这一层不进行心理解释。

### 7.2 Evidence Claim

表示模型基于某个事件提出的认知假设。例如：

```
{
  "claim_type": "misconception_evidence",
  "concept": "binary_search_boundary",
  "candidate": "mid_progress_assumption",
  "polarity": "support",
  "strength": 0.72,
  "confidence": 0.81,
  "source": "dialogue",
  "source_event_id": "evt_10241",
  "support_span": "mid不是已经变了吗",
  "extractor_version": "encoder_v1"
}
```

这里的含义不是"学生存在 mid_progress_assumption"，而是"当前证据对这一 hypothesis 提供了一定程度支持"。

### 7.3 Internal Learner State

长期融合多个 Evidence Claim 后形成：

```
{
  "concept": "binary_search_boundary",
  "mastery": 0.64,
  "misconceptions": {
    "mid_progress_assumption": 0.73,
    "closed_halfopen_confusion": 0.18
  },
  "state_uncertainty": 0.21,
  "evidence_conflict": 0.12,
  "effective_evidence": 8.7
}
```

这一层才属于模型产生的潜在学生状态。

### 7.4 Cognitive Projection

对外只输出完成教学任务必要的信息。例如：

```
{
  "concept": "binary_search_boundary",
  "state": "partial",
  "confidence": "medium",
  "teaching_focus": "boundary_update"
}
```

原始对话和细粒度内部推断原则上不直接暴露给普通教师页面或外部系统。

## 八、总体研究目标

总体目标为：

> 建立一个能够利用答题、代码、测试、修改、提示和教育智能体对话等多源学习证据，持续估计学生知识掌握状态和潜在 misconception，并能够表达证据可靠性、证据冲突及自身不确定性的细粒度 Learner Model。

具体目标包括：

### 目标 1：统一多源认知证据表示

构建 `CognitiveEvidence / EvidenceClaim Schema`。

### 目标 2：建立轻量语义证据抽取模型

从学生自然语言和必要上下文中提取 Concept、Misconception、Reasoning、Help Seeking、Self Correction 等信息。

### 目标 3：建立多源时序知识追踪模型

联合 Answer、Code、Test、Hint、Dialogue、Time 和 Difficulty。

### 目标 4：建立动态 misconception 状态

跟踪误区的出现、重复、强化、纠正和衰减。

### 目标 5：建立可靠性感知证据融合机制

避免简单 feature concatenation。

### 目标 6：区分多种不确定性

特别是区分 Evidence Scarcity 与 Evidence Conflict。

### 目标 7：实现 Selective Cognitive Diagnosis

证据不足时输出 Unknown。

### 目标 8：验证认知变量的教学意义

研究：

```
Specific Diagnosis
        ↓
Specific Intervention
        ↓
Corresponding Error Reduction
```

是否成立。

## 九、核心研究问题

### RQ1：多源学习证据是否提供传统答题记录之外的有效认知信息？

比较：

```
Response Only
Response + Code
Response + Dialogue
Response + Hint
Response + Code + Dialogue + Hint
```

重点观察：下一题预测、同类错误复发、misconception、迁移题、提示需求。

### RQ2：结构化 Evidence Claim 是否优于直接使用原始语义 Embedding？

比较：

```
Raw Dialogue Embedding
        VS
Structured Evidence Claim
```

如果后者能够在预测性能、数据效率、模型稳定性、可解释性或推理成本上产生优势，才能说明 CognitiveEvidence abstraction 具有实际意义。

### RQ3：可靠性感知融合是否优于简单特征拼接？

比较：

```
Naive Concatenation
        VS
Source-aware Attention
        VS
Reliability-aware Gating
```

验证模型是否能够学习：Test Case、正式答题和 Dialogue Evidence 应该以不同权重参与状态更新。

### RQ4：Temporal Misconception Tracking 是否能够预测重复错误和迁移错误？

重点预测：same-error recurrence、same-misconception recurrence、near transfer、far transfer、hint requirement。

### RQ5：证据冲突感知的选择性诊断能否降低错误认知判断？

比较：

```
Always Predict
Confidence Threshold
Uncertainty-based Abstention
Evidence-aware Selective Diagnosis
```

重点评估 Risk-Coverage。

### RQ6：模型中的 misconception 是否具有真实教学价值？

验证：

```
模型诊断
      ↓
针对性教学
      ↓
对应错误显著减少
```

而不是只评价 Prediction Accuracy。

## 十、拟提出的算法模型

研究模型暂定名称：

**RE-KT（Reliability-aware Evidence Knowledge Tracing）**

中文名称：**可靠性感知多源认知证据知识追踪模型**。

该名称仅作为研究阶段工作名称，不提前主张该名称或全部结构具有首创性。

## 十二、模块一：Semantic Cognitive Evidence Encoder

候选模型：MiniLM、DistilBERT、BERT、RoBERTa/MacBERT 类小型 Encoder。不要求一开始确定最终 Backbone。

### 输入

主要包括：

```
当前学生 utterance
+ 必要的上一轮 Agent 信息
+ 当前知识点
+ 当前题目
+ 可选代码/错误摘要
```

原则是不把整个会话无限输入模型。

### 输出任务

采用 Multi-task Learning。

**Task A：Concept Classification**，识别学生当前讨论的 Concept。

**Task B：Misconception Candidate Classification**，识别当前文本是否支持某个 misconception。

**Task C：Reasoning Depth**，例如：

```
surface
procedural
relational
causal
transfer
```

**Task D：Help Seeking**，例如：

```
answer_seeking
hint_seeking
concept_explanation
debugging
verification
```

**Task E：Self Correction**，判断是否出现主动纠正。

**Task F：Evidence Confidence**，估计当前语义证据可靠程度。

## 十三、LLM Teacher + Small Model Student

研究初期使用：

```
Raw Dialogue
      ↓
LLM Teacher
      ↓
Silver Label
```

但 **LLM Label 不作为 Ground Truth**。建立：

```
Human Annotation → Gold
LLM Annotation   → Silver
```

并训练轻量 Student Encoder。优先人工审核 Human ≠ LLM、Model uncertainty high、Rare misconception、New misconception candidate 的数据。

最终形成：

```
Gold + Silver
      ↓
Lightweight Encoder
```

研究运行的高频状态更新尽可能使用小模型，LLM 主要承担离线辅助标注和困难样本分析。

## 十四、Misconception Ontology

Misconception 不能由 LLM 任意生成标签。拟建立层级化 ontology。例如：

```
Binary Search
│
├── Interval Representation
│   ├── closed_halfopen_confusion
│   └── boundary_semantics_confusion
│
├── Mid Calculation
│   ├── midpoint_rounding_confusion
│   └── mid_progress_assumption
│
├── Boundary Update
│   ├── wrong_left_update
│   └── wrong_right_update
│
└── Termination
    ├── infinite_loop_condition
    └── termination_invariant_confusion
```

Ontology 允许版本演化。对于无法映射的新情况，可先标记为 `unknown_misconception`，避免为了标签完整性强行归类。

## 十五、模块二：Reliability-aware Evidence Fusion

这是本研究最重要的方法研究部分之一。每个 Evidence Claim 表示为：

$$e_t=(z_t,s_t,c_t,p_t,r_t,\Delta t)$$

其中：$z_t$ 为内容表示，$s_t$ 为 source，$c_t$ 为 concept，$p_t$ 为 polarity，$r_t$ 为 reliability，$\Delta t$ 为时间信息。

模型学习：

$$r_t = \sigma(W[e_t^{source}; e_t^{confidence}; e_t^{quality}; e_t^{consistency}])$$

形成：

$$\tilde{e}_t = r_t \cdot \phi(e_t)$$

意味着：Evidence 是否存在是一回事，Evidence 应当改变状态多少是另一回事。

## 十六、Evidence Reliability 的来源

可靠性至少考虑：

### Source Reliability

例如正式考试、Code Test、自我解释、普通对话、Hint 后表现，可靠程度不同。

### Extractor Confidence

小模型对语义标签的信心。

### Cross-source Consistency

是否得到其他来源支持。

### Temporal Persistence

相同模式是否重复。

### Evidence Independence

防止连续重复事件被错误理解为大量独立证据。

## 十七、模块三：Temporal Knowledge Tracing Backbone

研究初期不重新发明 Backbone，优先比较 BKT、DKT、simpleKT、AKT。DKT 与 AKT 分别代表典型循环时序和注意力 KT 家族。

最终 Backbone 选择原则：在统一研究数据上性能、稳定性、成本和解释性综合最优。

主模型输入：

$$x_t = [concept, response, difficulty, time, hint, codeEvidence, dialogueEvidence, misconceptionEvidence]$$

但输入并非简单拼接，而经过前述 reliability-aware fusion。

## 十八、模块四：Difficulty Measurement Layer

IRT 不独立维护另一套与 KT 竞争的学生能力系统。推荐：

$$\sigma(m_{k,t}-\beta_i)$$

其中 $m_{k,t}$ 为 KT 动态 proficiency，$\beta_i$ 为 Item Difficulty。数据充分后：

$$\sigma(a_i(m_{k,t}-\beta_i))$$

加入 item discrimination $a_i$。主要研究：Difficulty 是否能够降低由于题目差异造成的错误 mastery 判断。

## 十九、模块五：Temporal Misconception State

对每个 misconception $m$ 建立状态 $M_{m,t}$。一种可研究的初始更新方式为：

$$u_{m,t} = \lambda(\Delta t) u_{m,t-1} + \sum_j r_j p_j$$

并：

$$M_{m,t} = \sigma(u_{m,t})$$

其中：正向证据提高 misconception posterior，反向证据降低 posterior，时间衰减使长期未出现的旧误区逐渐失效，重复跨来源证据增强状态。随后可以将该显式更新与 neural recurrent state 进行比较。

## 二十、Misconception 生命周期

设计：

```
Candidate
   ↓
Suspected
   ↓
Persistent
   ↓
Correcting
   ↓
Resolved
```

但该生命周期不是教师直接看到的标签，而是 Internal State。例如：

```
第一次错误
↓
Candidate

代码 + Dialogue 重复支持
↓
Suspected

不同题型继续出现
↓
Persistent

能够正确解释 + 新题正确
↓
Correcting

一段时间及多个迁移任务均无复发
↓
Resolved
```

研究重点是：单次 mistake 与稳定 misconception 是否可以在数据上区分。

## 二十一、模块六：Uncertainty Modeling

拟将不确定性拆分为：

$$U = (U_{extract}, U_{state}, U_{scarcity}, U_{conflict})$$

而不是输出一个统一 confidence。

### 21.1 Extractor Uncertainty

来自认知语义 Encoder。

### 21.2 State Uncertainty

来自 Temporal Learner Model。候选实现包括 ensemble、MC dropout、distributional representation、predictive entropy。UKT 的分布式知识状态表示可作为重要对照。

### 21.3 Evidence Scarcity

基于有效证据量 $N_{eff}$，而非简单 event count。

### 21.4 Evidence Conflict

例如：

```
Answer：正确
Code：边界持续失败
Dialogue：解释正确
```

这种情况不是"什么都不知道"，而是"存在相互冲突的证据"。拟建立 Conflict Score：

$$C_t = Disagreement(E_1,E_2,\ldots,E_n)$$

并与普通不确定性分离。

## 二十二、模块七：Selective Cognitive Diagnosis

模型最终具有 Predict / Abstain 两种动作。已有研究将 selective prediction 用于 KT，因此本研究的重点不是 reject option 本身，而是利用多源 Evidence Sufficiency + Reliability + Conflict 共同决定是否诊断。

初始策略：如果 $N_{eff}<\tau_n$ 或 $U_{state}>\tau_u$ 或 $C_t>\tau_c$，则：

```
state = unknown
reason =
insufficient_evidence
/
conflicting_evidence
/
model_uncertainty
```

随后再研究 learned selector 是否优于 rule-based selector。

## 三十、评价指标

不能只使用 Accuracy 和 AUC。

### 30.1 Knowledge Tracing

ROC-AUC、PR-AUC、ACC、F1、NLL。

### 30.2 Misconception

Macro-F1、Precision、Recall、false positive、recurrence prediction、transition accuracy。

### 30.3 Transfer

near-transfer prediction、far-transfer prediction。

### 30.4 Calibration

ECE、Brier Score、NLL。

### 30.5 Selective Diagnosis

重点使用 **Risk-Coverage Curve**。定义 Coverage：

$$Coverage = \frac{N_{accepted}}{N}$$

Risk：

$$Risk = Error(AcceptedSamples)$$

并评价 AURC、Error@80% Coverage、Misconception FP@Coverage、high-confidence wrong diagnosis。

## 三十一、构念效度与教学干预实验

这是本研究区别于普通预测模型的重要部分。选择若干高频 misconception（例如 `mid_progress_assumption`）开展针对性干预实验设计，验证 Diagnosis → Targeted Intervention → Corresponding Error Reduction 是否成立：

$$Diagnosis \rightarrow Targeted\ Intervention \rightarrow Corresponding\ Error\ Reduction$$

实验设计示意（以下数值仅为设计示意，不代表实际结果）：假设模型对某学生给出 $P(mid\_progress\_assumption)=0.81$ 的 misconception 后验，则将其分入：

### Control 组

接受普通二分查找解释。

### Treatment 组

接受针对该误区设计的干预，例如：

```
长度为 2 的区间
↓
手算 mid
↓
观察 l = mid 后区间
↓
发现 mid == l
↓
分析为什么区间无法缩小
```

之后测试原题、同结构题、近迁移、远迁移。真正希望验证的是诊断到针对性教学再到对应错误减少的因果链路，而不是只有模型相关性。

## 三十二、预期算法成果

研究预期形成四个算法级成果。

### 成果一：Cognitive Evidence Encoder

一个轻量级语义认知证据抽取模型。输入 Student Utterance + Local Context + Concept，输出 Concept、Misconception Candidate、Reasoning、Help Seeking、Self Correction、Confidence。

### 成果二：Reliability-aware Evidence Fusion

学习不同来源 Evidence 的有效权重，目标避免所有行为等价进入 KT。这是预计最主要的方法创新之一。

### 成果三：Temporal Misconception Tracker

建立 misconception posterior 的时间变化模型，输出 candidate / suspected / persistent / correcting / resolved 及其概率状态。

### 成果四：RE-KT Learner Model

完整实现：

```
Multi-source Evidence
        ↓
Reliability-aware Fusion
        ↓
Temporal KT
        ↓
Mastery + Misconception
        ↓
Difficulty Measurement
        ↓
Uncertainty + Conflict
        ↓
Selective Diagnosis
```

## 三十三、预期模型效果

以下数字属于项目研究目标和验收门槛，不是提前保证的实验结果。

### 33.1 Semantic Evidence Encoder

期望在 Gold Test Set 上：

- Concept：Macro-F1 不低于 0.85；
- Help Seeking / Self Correction：Macro-F1 不低于 0.80；
- Misconception：由于任务明显更困难，第一阶段目标 Macro-F1 不低于 0.70，理想区间 0.75–0.85；低频类别必须单独报告。

### 33.2 Knowledge Tracing

如果最强 Response-only baseline AUC 为 0.80，不应将目标设为 0.95。比较现实的科研目标是：

- Difficulty：相对强 baseline 提升 +0.5～2 pp；
- Semantic / Code Evidence：额外提升 +1～3 pp；
- Full Multi-source：相较 Response-only 目标提升 +1.5～4 pp AUC。

但只要 AUC 没明显提高，而 calibration、misconception、transfer、error recurrence 显著改善，也可认为研究具有价值。

### 33.3 Misconception

相比只依据当前错误进行静态诊断，希望 Temporal Misconception Modeling：

- Misconception Macro-F1 相对提高不低于 3 pp；
- 或 Recurrence Prediction AUC 提高不低于 3 pp。

同时重点降低 Misconception False Positive，因为教育场景中错误地给学生贴认知错误标签可能比漏掉一次诊断更危险。

### 33.4 可靠性融合

主要假设不是 Reliability Fusion 一定提高大量 AUC，而是同时产生：noisy dialogue robustness 上升、missing-source robustness 上升、conflicting evidence 下错误率下降、calibration 改善、false misconception diagnosis 下降。理想实验结果为：在普通 Test Set 中性能与 Naive Fusion 至少相当，而在 Noisy、Missing、Conflict、Cold Start 条件下明显优于简单拼接。

### 33.5 Uncertainty / Calibration

建议工程验收目标：ECE 达到 $ECE \leq 0.05$，或者较未校准模型下降不低于 30%。

### 33.6 Selective Diagnosis

希望在 80% Coverage 条件下，相对 Always Predict，错误认知诊断风险下降不低于 20%，理想目标 20%–30%。

示意场景（仅用于说明机制，非实验结果）：若模型原本 100 个判断全部输出、其中错误 20 个，通过选择性诊断变为 80 个有依据的判断（错误 8–12 个）与 20 个 Unknown，即使总体 Coverage 降低，教育可靠性仍然可能显著提高。

## 三十四、工程性能目标

研究原型中 Evidence Extractor 采用小型 Encoder，而不是持续调用 LLM。目标为普通 CPU 服务：

- Evidence Extraction：P95 100–300 ms；
- KT State Update：P95 小于 100 ms；
- 单学生状态存储：增量更新，而非每次重算全部历史。

LLM 主要用于 Offline Teacher Annotation 与 Hard Case Review，而不是实时主链。

## 三十九、预期创新点

### 创新点一：面向教育智能体的可追溯多源认知证据表示

不同于直接把 Answer、Code 和 Dialogue 特征拼接输入模型，本研究显式区分 Observable Event、Evidence Claim、Learner State，使每个认知推断能够追溯到具体学习事件、模型版本和支持证据。

### 创新点二：可靠性感知的多源认知证据融合

研究来自 Assessment、Code、Test、Revision、Hint、Dialogue 的 Evidence 如何根据来源质量、语义置信度、重复性和跨源一致性动态参与知识状态更新。核心问题是不同 Evidence 应该改变 Learner State 多少，而不是单纯增加更多输入特征。

### 创新点三：跨事件、跨来源的 Temporal Misconception Tracking

不根据单次错误给学生贴标签，而研究 misconception hypothesis 如何形成、增强、重复、受到反证、纠正、衰减，并联合代码行为和 Agent Dialogue 建立长期状态。

### 创新点四：证据冲突感知的选择性认知诊断

选择性 KT 本身已有研究基础。本研究进一步关注 Evidence Scarcity、Extractor Uncertainty、State Uncertainty、Evidence Conflict 的显式区分，并利用多源 Evidence Sufficiency 和 Conflict 决定是否输出认知诊断。研究重点不是"让模型可以 Unknown"，而是让 Unknown 有明确的证据学原因。

## 四十一、项目风险及备选方案

### 风险一：真实数据规模不足

解决：

```
公开 KT Dataset
        ↓
验证 Backbone

公开 Programming Dataset
        ↓
验证 Code/Test

CodeNexus Data
        ↓
验证核心 Multi-source Research Question
```

不能使用公开数据替代 CodeNexus 对话增益结论。

### 风险二：Misconception 标签一致性低

这可能意味着 Ontology 有问题，而不是标注员有问题。采用 hierarchical label、unknown、multi-label、candidate hypothesis、expert adjudication。

### 风险三：LLM Silver Label 有系统噪声

采用 Gold + Silver + Disagreement Review，而不是 LLM Label = Truth。

### 风险四：Multi-source Model 没有明显提高 AUC

这不一定意味着研究失败。继续分析 misconception、calibration、transfer、robustness、risk-coverage。如果所有指标均无增益，则得出"当前 Agent Dialogue 并未提供足够额外 Learner Modeling 信息"的结论，这本身也是有效研究结论。

### 风险五：复杂模型不如简单模型

保留 Rule、BKT、AKT/simpleKT 作为 fallback。复杂模型必须支付"复杂度税"，如果增益不足则不进入集成。这一原则与团队系统工程方案提出的"成熟模型先建立强基线，只有出现结构性失败后再增加理论复杂度"路线一致。

## 四十二、研究展望

本课题最终并不是研究"怎样使用一个更大的 AI 模型判断学生"，也不是"怎样读取学生思想"，而是研究：

> 面对一个学生不断产生的答题、代码、测试、修改、提示和对话等不完全、异质甚至相互矛盾的学习证据，一个教育智能体应当如何形成谨慎、动态、可追溯的学生模型？

理想系统不是 `Student Mastery = 0.637291` 这种伪精确数字制造器，而应当能够说明：我观察到了什么；这些证据支持什么；哪些证据相互冲突；我对哪个知识点有多少依据；某个 misconception 是否持续出现；哪些判断可信；哪些判断目前还不知道。

因此，本课题最终希望建立的不是一个单纯追求下一题 AUC 的 Knowledge Tracing 网络，而是一个 **Evidence-grounded Learner Model**：依据可追溯学习证据持续更新，能够识别细粒度知识状态和潜在 misconception，显式表达证据可靠性与冲突，并在证据不足时主动拒绝进行伪精确诊断的学生认知模型。

研究的推进方向是推动 CodeNexus 认知建模从规则统计投影向证据驱动学生模型（Learner Model）演进，并形成：

```
Student
   ↓
Learning
   ↓
Observable Evidence
   ↓
Evidence Claims
   ↓
Reliable Learner Modeling
   ↓
TeachingAgent
   ↓
Adaptive Intervention
   ↓
New Evidence
   ↓
State Update
```

的完整教学智能闭环。
